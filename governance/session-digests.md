# Session Digests — Mango BA Prompts

Единая точка хранения **суммарий длинных сессий** с внешними агентами
(ChatGPT, Claude, другие LLM-чаты) для передачи контекста между чатами в
`mango_ba_prompts`. Файл создан в рамках Smart Sync issue #72 по механизму,
добавленному в Хабе PR #226.

> 🧭 **Назначение в одну строку.** Репозиторий — источник истины; суммарии
> сессий тоже живут в репозитории, а не только в памяти LLM или в пересказе
> Пользователя.

## Кому это нужно (и кому НЕ нужно)

| Роль | Использует механизм? | Почему |
| --- | --- | --- |
| **Пользователь** | Да | Решает, когда пора сохранить summary и какой контекст передать в новый чат. |
| **Внешний агент** | Да | Помогает Пользователю сжать длинный диалог и затем читает индекс перед продолжением. |
| **Исполнитель / агент-исполнитель** (например, Конард) | Нет | Получает задачу, исполняет её через issue → PR → review и не должен жечь токены на суммаризацию во время исполнения. |

> ⛔ **Явное ограничение.** Механизм суммаризации **НЕ влияет на работу
> Исполнителя** при исполнении задач. Если ты читаешь этот файл как
> агент-исполнитель в рамках задачи в репозитории — он для тебя справочный
> артефакт, а не триггер действий.

## Как пользоваться (экономия токенов)

1. При передаче контекста в новый чат читай сначала только **Индекс** ниже.
2. Полную суммарию читай только когда тема релевантна текущей задаче.
3. Не пересказывай контекст из памяти: ссылайся на якорь суммарии и на
   артефакты репозитория.

## Как добавить суммарию

1. Внешний агент спрашивает Пользователя, нужно ли суммаризировать сессию
   (ориентир из handover prompt: ~30 обращений или ~50К токенов).
2. При согласии формируется issue на сохранение суммарии; правки проходят через
   `issue → PR → review`.
3. Добавляется строка в **Индекс** и блок суммарии с якорем
   `## YYYY-MM-DD — тема`.
4. Структура блока: **Контекст**, **Решения**, **Открытые вопросы**,
   **Следующие шаги**. Все ссылки — на артефакты репозитория, не на обсуждения
   в чатах.
5. Если в суммарии есть открытые вопросы, Исполнитель добавляет их в
   [`governance/BACKLOG.md`](BACKLOG.md#запланированный-спринт-открытые-вопросы), если они ещё не
   зафиксированы там. Это консолидирует вопросы из разных чатов в единый
   трекер.

## Как удалять решённые вопросы (Traceability)

- Когда открытый вопрос зафиксирован в артефакте (стандарт, ADR, RFC,
  governance-файл), удали его из блока «Открытые вопросы» и оставь ссылку на
  артефакт в «Решениях».
- Когда вся суммария отражена в артефактах, её можно удалить из файла или
  пометить статусом `решено` со ссылкой на артефакты. Файл хранит актуальный
  контекст, а не архив.

## 2026-06-14: Синхронизация сессий: Чат Хаба → Чат БА Манго

### Контекст

Синхронизация решений, принятых в Чате Хаба, с проектом `mango_ba_prompts`.
PR #73 замержён — синхронизация с Хабом выполнена полностью (PR #224, #226,
#229, #230).

### Ключевые решения (релевантные для mango_ba_prompts)

**1. Правило "молчание = согласие" (применяется при мерже PR в mango):**

- Молчание при мерже PR = согласие на применение изменений из PR.
- Переход Draft → Canonical требует ЯВНОГО подтверждения Пользователя.
- RFC остаются в `governance/rfc/` со статусом Draft до явного подтверждения.

**2. Терминология (уже синхронизирована в PR #73):**

- Пользователь — тот, кто ставит задачи и принимает решения.
- Исполнитель — агент-исполнитель.
- Не привязываемся к конкретным именам в контрактах.

**3. Механизм суммаризации сессий (уже синхронизирован в PR #73):**

- Единая точка хранения: `governance/session-digests.md`.
- Порог: 30 обращений или 50К токенов.
- Агент инициирует суммаризацию только при передаче контекста в чат.
- НЕ влияет на агента-исполнителя (не жжёт токены).
- Решённые вопросы удаляются из суммарий, когда фиксируются в артефактах.

**4. Архитектура GitHub Pages (согласована, задача на исполнении):**

- Статическая генерация данных при билде (GitHub Actions → JSON).
- Браузер читает JSON-файлы (0 вызовов GitHub API, нет rate limit).
- Без PAT (ИБ), без создания issue из интерфейса.
- MVP: каталог промптов, фильтры, копирование, дашборд, roadmap.
- Стек: свобода выбора Исполнителя (VitePress/Astro/Tailwind).

### Что НЕ передаётся (релевантно только для Хаба)

- Архитектурные контракты Хаба (Traceability, Framework vs Template,
  Resolver scope).
- Исследование внешних источников знаний.
- Обсуждения архитектуры документации (L0/L1/L2, графы vs таблицы).
- Баланс Anti-Inflation vs атомарность.

Эти улучшения Хаба будут проверены через механизм Smart Sync при необходимости.

### Открытые вопросы

- Утверждение Vision/Concept Хаба (Draft → Canonical) — отложено в техдолг.
- Баланс Anti-Inflation vs атомарность арх документации — требует исследования.
- Ecosystem Registry при 10+ спок-репозиториях — отложено.
