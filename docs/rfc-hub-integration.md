# RFC: рекомендации по переносу лучших практик из `mango_ba_prompts` в Хаб

> **Статус: Draft.** RFC выносится на решение Пользователя
> ([AI_GOVERNANCE.md](../ai-governance/ai-governance.md)). До утверждения — предложение,
> не обязательное правило. Формат сознательно выбран **RFC, а не ADR**:
> перенос практик в Хаб — стратегическое governance-направление
> (по практике Хаба такие решения живут в `docs/rfc/`), а ADR в
> `docs/adr/` фиксируют локальные архитектурные решения спока.
>
> **Рамка применения.** Хаб — источник лучших практик и обмена опытом, не ограничитель
> для спок-репозиториев и HTOM-команд. Этот RFC описывает рекомендательный маршрут
> передачи зрелой практики в Хаб и не блокирует локальные решения `mango_ba_prompts`.

## 1. Контекст

`mango_ba_prompts` — **тактическая база** автоматизации бизнес-анализа в
Mango: библиотека паттернов и промптов, организованная
[таксономией](taxonomy.md). Хаб
(`hybrid-Intelligence-lab`) — **стратегический дом** общих практик,
стандартов и исследований.

Сегодня существует только поток **Хаб → спок**: research-зависимости через
[docs/hub-research-dependencies.md](hub-research-dependencies.md) и
осознанная синхронизация стандартов (см.
[README.md](../README.md), раздел «Связь с Хабом»). Этот RFC фиксирует
обратный поток — **спок → Хаб**: как наработка, доказавшая ценность в
Mango, становится общей практикой Хаба.

### 1.1 Два адресата исходящего потока

ADR-009 v0.3 ([`#adr-009-repo-split`](hub-research-dependencies.md#adr-009-repo-split))
зафиксировал модель двух репозиториев. У исходящего потока спока стало два
адресата с разными назначениями:

| Адресат | Что уходит | Форма передачи |
| --- | --- | --- |
| Хаб `hybrid-Intelligence-lab` | Методология, governance-практики, стандарты общего применения. | RFC + human decision gate (разделы §3–§5 ниже). |
| [`ai-ba-playbooks`](https://github.com/G-Ivan-A/ai-ba-playbooks) | Универсальные и специализированные плейбуки: паттерны, обобщённые промпты, публичные примеры. | Отбор Пользователем по критериям C1–C5 как чек-листу готовности. Проект `ai-ba-playbooks` развивается от универсальных плейбуков к возможности кастомизации (конструктору); целевая форма определяется по мере развития проекта. |

Нормы, общие для обоих адресатов:

1. **Поток строго односторонний:** `mango_ba_prompts → наружу`. Обратный поток
   `ai-ba-playbooks → mango_ba_prompts` запрещён ADR-009 §3: он вернул бы
   смешение ролей, ради устранения которого выполняется разделение.
2. **Синхронизация неавтоматическая.** Хаб собирает практику **по запросу**, а
   публикация в `ai-ba-playbooks` — ручной отбор Пользователем. Автоматизация
   (Smart Sync с фильтрацией) вводится только под доказанную операционную боль.
3. **Обезличивание обязательно.** Критерий C4 (чистота данных) — жёсткий шлюз:
   `kb/`, `runs/`, боевые промпты и внутренние записи `pr-ops/` наружу не
   уходят в исходном виде.
4. **Проверяемость сохраняется.** Практика передаётся вместе с объявленным
   механизмом проверки (чек-лист, evals-метрика или human-in-the-loop gate);
   практика без процесса проверки считается незавершённой и не номинируется.
   Пока evals в репозитории отсутствуют
   ([`AI_GOVERNANCE.md`](../ai-governance/ai-governance.md#статус-механизмов-проверки-на-сегодня)),
   номинируемая практика называет чек-лист или human-in-the-loop gate.
5. **Создание `ai-ba-playbooks` не входит в scope спока:** этот RFC описывает
   маршрут передачи, а не выполняет её.

## 2. Что считается практикой-кандидатом

- **Паттерны** из `patterns/` — воспроизводимые способы решения класса
  задач БА (см. [standards/pattern-standard.md](../standards/pattern-standard.md)).
- **Обобщённые промпты** — промпты `prompts/`, очищенные от
  Mango-специфики.
- **Стандарты и контракты** из `standards/`, полезные за пределами Mango
  (например, стандарт frontmatter промптов).
- **Workflow и шаблоны** — процессы фидбека, шаблоны issue, форматы
  фиксации тестов.

**Не предлагается к переносу без отдельной очистки:** артефакты с корпоративной
спецификой Mango (внутренние термины без обобщения, закрытые данные), сырые
прогоны из `runs/`, архивные промпты.

## 3. Критерии переноса

Практику-кандидат рекомендуется оценивать по критериям ниже. Они помогают
подготовить сильное предложение в Хаб, но не являются запретом на локальное
использование практики и не блокируют локальные решения.

| ID | Критерий | Как проверяется |
| --- | --- | --- |
| C1 | **Повторная ценность.** Применена в ≥ 2 реальных задачах БА с зафиксированным результатом. | Записи в `runs/` и/или issues `prompt:feedback` |
| C2 | **Обобщаемость.** Не содержит Mango-специфики, либо специфика отделена в параметры/контекст. | Review обобщённой версии |
| C3 | **Зрелость.** Прошла human review; для промптов — `status: canonical`. | Frontmatter, история PR |
| C4 | **Чистота данных.** Не содержит закрытых корпоративных данных и ссылок на закрытые документы. | Review перед публикацией |
| C5 | **Документированность.** Есть назначение, примеры и quality gates (для паттернов — все 8 полей). | Соответствие стандартам `standards/` |

## 4. Рекомендуемый процесс переноса

1. **Номинация.** Любой участник создаёт в споке issue с label
   `hub-candidate`: что переносим, какие критерии C1–C5 уже выполнены.
2. **Подготовка.** AI-агент или contributor готовит обобщённую версию
   артефакта (без Mango-специфики) в PR спока; review подтверждает C1–C5.
3. **RFC в Хабе.** В Хабе предлагается RFC в `docs/rfc/`
   (для governance-практик) или issue по `issue-workflow` Хаба
   (для прикладных артефактов) со ссылкой на исходник в споке.
4. **Решение Пользователя.** Принять / отклонить / доработать — финальное
   решение за человеком (правило 4 AI_GOVERNANCE Хаба).
5. **Перенос с provenance.** Артефакт размещается в Хабе с полями
   `source_spoke` + `source_sha` (permalink на коммит спока) — зеркально
   практике `source_hub`/`source_sha` при миграции из Хаба.
6. **Фиксация.** Если перенос принят, он отражается в `CHANGELOG.md` обоих
   репозиториев. Спок продолжает использовать локальную версию, а источник
   истины для общей версии переходит к Хабу только после явного принятия;
   синхронизация остаётся осознанным действием, как для `standards/GLOSSARY.md`.

## 5. Роли

| Роль | Ответственность |
| --- | --- |
| Пользователь | Финальное решение о переносе (шаг 4); приоритеты. |
| Human reviewer | Проверка критериев C1–C5 и чистоты данных (C4). |
| Contributor / AI agent | Номинация, подготовка обобщённой версии, черновики RFC. |

## 6. Что этот RFC не делает

- Не запрещает `mango_ba_prompts` принимать локальные решения до переноса в Хаб.
- Не создаёт `ai-ba-playbooks` и не переносит в него артефакты: это отдельная
  задача после успешных прогонов.
- Не вводит автоматическую синхронизацию ни в одном направлении.
- Не требует автоматически менять спок после каждого изменения Хаба.
- Не превращает критерии C1–C5 в gate для Creative-mode задач.
- Не передаёт практику в Хаб сам по себе: это отдельная follow-up задача.
