# Roadmap: четыре этапа автоматизации процессов БА

Порядок этапов задан владельцем в [#409](https://github.com/G-Ivan-A/mango_ba_prompts/issues/409).
Роль n8n на этапе 3 закреплена в [ADR-017](adr/2026-10-adr-017-four-stages-n8n-orchestration.md)
по решению владельца в [#413](https://github.com/G-Ivan-A/mango_ba_prompts/issues/413).
Сроки и бюджет здесь не указаны: их задаёт владелец.

Этот файл — источник раздела «Дорожная карта» на
[сайте](https://g-ivan-a.github.io/mango_ba_prompts/#roadmap). Генератор
`scripts/generate-pages-data.mjs` читает три таблицы ниже, поэтому их
заголовки переименовывать нельзя.

## Этапы

Процесс БА, его шаги и гейты не меняются при смене этапа: меняется только
исполнитель маршрута. Переход на следующий этап доказывается новой
статистикой прогонов в `runs/`, а не сменой технологии. Историческая
статистика не пересчитывается.

| Этап | Как работает | Роль БА | Вход | Выход (доказательство) | Статус |
| --- | --- | --- | --- | --- | --- |
| 1. Промпты в чате LLM | БА открывает сайт, копирует промпты процесса шаг за шагом в один чат с моделью, переносит состояние между шагами и сам решает на гейтах. | Исполнитель и проверяющий каждого шага. | Промпты процесса и инструкция опубликованы на сайте. | Серия новых прогонов по всему процессу с решениями на гейтах; базовая линия метрик; утверждённый golden set процесса. | current |
| 2. Агентный клиент | Агентный клиент типа OpenCode читает пакет правил и файловое состояние задачи, выполняет шаги и останавливается на гейтах. | Проверяющий результата и владелец решений на гейтах. | Выход этапа 1; профиль клиента ([ADR-016](adr/2026-10-adr-016-ide-client-process.md)); проверенная версия клиента. | Кейсы golden set дают вердикт не хуже этапа 1; статистика прогонов этапа 2 сопоставима с этапом 1. | planned |
| 3. Оркестрация в n8n | Поток n8n ведёт процесс: запускает шаги, хранит состояние, вызывает модель, ждёт решения человека на гейтах и подключает почту и трекер. | Собирает и сопровождает потоки визуально, решает на гейтах. | Выход этапа 2; [ADR-017](adr/2026-10-adr-017-four-stages-n8n-orchestration.md); доступы к корпоративным системам. | Требования ADR-017 выполнены; повтор и возобновление без двойных решений; статистика сопоставима с этапом 2. | planned |
| 4. Промышленная эксплуатация | Потоки работают на выделенном сервере в контуре Манго для всей команды БА, с мониторингом и восстановлением. | Владелец решений и точка эскалации. | Выход этапа 3; решения по серверу, данным и лицензии n8n. | Эксплуатационные метрики, проверенное восстановление, решение службы безопасности. | planned |

## Запуск этапа 1

Этап 1 запущен: промпты процесса BCREQ и инструкция к ним опубликованы на
сайте. Ниже — порядок работы БА от первого входа до итога этапа.

| Шаг запуска | Что сделать | Где | Результат |
| --- | --- | --- | --- |
| 1. Войти на сайт | Ввести пароль сайта. Пароль выдаёт владелец; он не записывается в репозиторий. | [Сайт](https://g-ivan-a.github.io/mango_ba_prompts/), [доступ](site-access.md) | Открыты каталог промптов и раздел «Процессы». |
| 2. Подготовить задачу | Собрать карточку задачи (номер, название, продукты) и обезличенный запрос Заказчика. Ссылки на закрытые документы не нужны. | Рабочие системы БА | Вход для первого шага процесса. |
| 3. Пройти процесс | Открыть раздел «Процессы» и выполнять шаги по порядку в одном чате с моделью. Промпт копируется кнопкой ⧉, состояние переносится между шагами. | [Раздел «Процессы»](https://g-ivan-a.github.io/mango_ba_prompts/#processes) | Разделы документа требований. |
| 4. Решить на гейтах | Решение на гейте принимает человек из колонки «Кто решает». Модель только рекомендует. Решение записывается в журнал решений документа. | [«Процессы» → «Согласование»](https://g-ivan-a.github.io/mango_ba_prompts/#processes) | Журнал решений с автором и основанием. |
| 5. Зафиксировать прогон | Открыть issue по шаблону «Прогон задачи: Исполнение процесса» и приложить обезличенные вход и результат. Исполнитель оформляет новую запись `runs/`. | [Шаблоны issue](https://github.com/G-Ivan-A/mango_ba_prompts/issues/new/choose) | Новая запись статистики этапа 1. |
| 6. Сообщить о проблеме промпта | Если шаг дал неверный результат, открыть issue «Фидбек по промпту». Промпт меняется только через RFC по промптам. | [Шаблоны issue](https://github.com/G-Ivan-A/mango_ba_prompts/issues/new/choose) | Наблюдение для улучшения промптов. |
| 7. Подвести итог этапа | После серии прогонов сравнить метрики с критериями выхода этапа 1 и решить, переходить ли к этапу 2. | `docs/analysis/` | Решение владельца о выходе из этапа 1. |

## Следующие шаги

Полный список предложений с обоснованием — в
[отчёте #413](report/2026-10-31-repository-action-plan.md).

| Следующий шаг | Почему важен | Артефакт или решение |
| --- | --- | --- |
| Серия реальных прогонов этапа 1 | Без новых прогонов нельзя доказать выход из этапа 1 и задать базовую линию метрик. | Новые записи `runs/` по шаблону issue |
| Golden set процесса | Конкретные вопросы и фразы задач не должны попадать в промпты; им нужен отдельный проверочный набор. | Решение о месте golden set (вопрос Q1 стандарта evals), затем файл `golden-set-<процесс>.md` |
| Очистка промптов от частных случаев | В промпте конституции остались ссылки на отдельные прогоны и issue; правило обобщения уже введено. | Задача по промптам [#411](https://github.com/G-Ivan-A/mango_ba_prompts/issues/411) |
| Решения владельца по RFC модернизации | Видимость, роль runtime, пакет этапа 2, архетип, политика истории и KB-конвейер ждут выбора. | DEC-01, DEC-03, DEC-04, DEC-06, DEC-07, DEC-09, DEC-10 в [RFC](rfc/2026-10-repository-modernization.md) |
| Квалификация агентного клиента | Вход в этап 2 требует проверенной версии клиента на тех же кейсах. | Проверка P01–P08 по ADR-016 |
| Требования к потокам n8n | Этап 3 должен стартовать с готовыми правилами экспорта, гейтов и проверки ответов. | Валидатор экспорта потоков по ADR-017 |
| Указатель для агентов-исполнителей | Стандарт экосистемы требует единую точку входа для AI-исполнителя. | ADR о корневом `AGENTS.md` (DEC-07) |

## Связь с уровнями зрелости

Уровни L1–L4 из [`docs/ba-ecosystem.md` §7](ba-ecosystem.md#7-уровни-зрелости-автоматизации)
описывают зрелость автоматизации процесса, а этапы — смену исполнителя.
Соответствие не один к одному.

| Уровень зрелости | Этапы | Комментарий |
| --- | --- | --- |
| L1 «ручной запуск промптов» | 1 | Текущее состояние |
| L2 «системный prompt + KB/RAG» | 1–2 | Полный набор правил и переносимое состояние |
| L3 «агент управляет workflow» | 2–3 | Агентный клиент, затем поток n8n |
| L4 «мультиагентная система» | 3–4 | Несколько ролей под одной оркестрацией и человеческими гейтами |
