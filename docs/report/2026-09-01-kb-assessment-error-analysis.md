# Ошибка использования БЗ в оценке RUN-0062 и RUN-0065

## Контракт поиска и эскалации

Первичная точка входа — вся БЗ: [`kb/processed/README.md`](../../kb/processed/README.md).
Модульный фильтр допустим только после поиска по полному индексу. Если данных БЗ
недостаточно для однозначного вывода, следующий шаг — web-поиск только по доверенным
доверенным доменам и поддоменам Mango (`mango-office.ru`, `mango-office.ru/support`,
`wiki.mango-office.ru`). «Нет данных» легитимно лишь с записью вида: «проверил БЗ:
[файл, раздел]; проверил web: [домен, запрос]; ни БЗ, ни web не дали результата».

## Корневые причины

RUN-0062 заранее сузил SSOT до Роботов, Речевой аналитики и TWIN. Из-за этого поиск
не достиг руководства ВАТС/LK и превратил отсутствие данных в выбранных трех модулях
в массовое отсутствие capability. RUN-0065 добавил пять аналитических колонок,
переименовал шкалу и применил эвристику по ключевым словам вместо анализа полной БЗ.
Оба валидатора закрепили ошибку: один разрешал «Нет данных» без журнала web-эскалации,
второй требовал восемь колонок и самодельные статусы. Причина системная — контракт
поиска, контракт вывода и regression gate расходились с заданием.

## Изменения стандарта исполнения

1. Поиск начинается с полного индекса, затем фиксируется релевантный документ и
   атомарный раздел; список «ожидаемых модулей» не является SSOT boundary.
2. Составные требования декомпозируются: `Частично` обозначает подтвержденную
   атомарную часть, а не неопределенную уверенность.
3. Ссылки ведут непосредственно на объект и содержат `[файл, §, с.]`.
4. Технический критик проверяет границы capability, договорные гарантии,
   интеграционные зависимости и блок-факторы; формальный флаг проверки запрещен.
5. Валидатор проверяет источник, ширину, шкалу, атомарные ссылки и журнал
   эскалации. Это делает повторение обеих исходных ошибок машинно обнаружимым.

Дом `docs/report/` выбран по действующему контракту репозитория: это единый
межпрогонный RCA, а не output одного run; сами исправленные результаты остаются
в существующих RUN-0062 и RUN-0065.
