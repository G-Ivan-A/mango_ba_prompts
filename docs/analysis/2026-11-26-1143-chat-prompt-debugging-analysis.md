# Чат 1143: проблемы промптов для отладки

## 1. Коротко

БА провёл задачу 1143 («Подключение SFTP по ключам для передачи записей
разговора») по маршруту Ш-0 → AIN-01…24 → Ш-3 → Ш-4 → Ш-5 в декомпозированном
формате. Чат шёл в веб-интерфейсе DeepSeek. Результат получен: раздел 2, ФТ,
НФТ, UC и список вопросов Заказчику. Маршрут, гейты Г-IN и «допуск» Ш-3
удержаны.

Отладка нужна по 16 проблемам (ПР-01…ПР-16). Шесть из них высокого уровня.
Они сводятся к **одной верхнеуровневой проблеме:**

> Промпты A-IN написаны так, что честность о доступе к БЗ и полнота памяти
> держатся на повторении правил в каждом ответе. В чате это даёт обратный
> эффект. Модель отказывается от инструментов, которые у неё есть. Служебные
> маркеры уходят к БА. Длинный контекст размывает принятые решения.

Главная причина избыточности — **общий контракт A-IN (17 132 символа)
вставляется в каждую из 24 карточек.** Уникальная часть шага — от 9,8 до
15,9 % карточки. На маршруте Ш-0 → AIN-24 → Ш-3…Ш-5 БА вставляет около
582 тыс. символов промптов. Если давать контракт один раз, выйдет около
188 тыс., то есть на 68 % меньше
([`prompt-redundancy.json`](../../runs/2026/RUN-0096/logs/prompt-redundancy.json)).

Что и почему правим — [RFC-BCREQ-PROMPT-DEBUG-001](../rfc/2026-11-bcreq-prompt-debugging-1143.md).

## 4. Верхнеуровневая проблема и гипотезы

**ВП.** Честность о доступе и полнота памяти держатся на правилах, которые
повторяются в каждом ответе и каждой карточке. В чате это вызывает отказ от
инструментов, жаргон для БА и размывание решений.

| Гипотеза | Закрывает | Суть правки |
| --- | --- | --- |
| Г-01 | ПР-01, ПР-04 | Доступ: «если в среде есть поиск или чтение URL — используй его для публичных источников, переданных БА». Блок «Доступ к БЗ» заменить одной строкой «Источники» и выводить на шагах чтения 07–12 или при смене доступа. Запрет изображать чтение сохранить. Вложение может быть прочитано частично — указать, какие страницы реально прочитаны |

## 7. Избыточный контент: замер

Скрипт [`prompt_redundancy.py`](../../experiments/issue_505/prompt_redundancy.py)
сравнивает 24 карточки AIN построчно. «Общие» строки — непустые строки,
которые есть во всех 24 карточках.

| Показатель | Значение |
| --- | --- |
| Общих строк | 212 |
| Общий контракт в карточке | 17 132 символа |
| — «Вход и полномочия» | 1 398 |
| — «Границы, вопросы и гейты» | 1 728 |
| — «Источники, память и изменения» | 2 081 |
| — «Доказательная нормализация и фактический доступ» | 3 921 |
| — «Взаимодействие и квитанция каждого ответа» | 2 655 |
| 24 карточки AIN, всего | 469 305 символов |
| Уникальная часть шагов, всего | 58 137 символов |
| Доля уникального в карточке | 9,8–15,9 % |
| Конституция Ш-0 | 40 424 |
| Ш-3 ФТ / Ш-4 НФТ / Ш-5 UC | 29 580 / 19 711 / 23 181 |
| Маршрут как вставлено в чат 1143 | 582 201 |
| Маршрут, если общий контракт один раз | 188 165 (−67,7 %) |

**Избыточность в ответах** (по чату):

- служебные блоки в каждом ответе: 5–7 блоков, receipt 12–17 строк;
- пакет памяти выдан 11 раз вместо 3, по 30–36 строк;
- повтор шага перепечатывает весь результат (ПР-10);
- пустые поля атомов и широкие таблицы (ПР-14).

**Риск сокращения.** Если общий контракт вставлен один раз, в длинном чате
он может «уйти» из внимания модели так же, как ушли решения AIN-13 (ПР-05).
Поэтому в RFC карточка шага сохраняет короткий «якорь»: версию контракта и
5–7 правил, нарушенных в 1143. Защита от выдуманного чтения остаётся в
якоре.
