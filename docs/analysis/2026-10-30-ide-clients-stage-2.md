# Перенос BCREQ в IDE-клиент: Goose, OpenCode и Cline

Исследование для [issue 405](https://github.com/G-Ivan-A/mango_ba_prompts/issues/405).
Все итерации входят в один [PR 406](https://github.com/G-Ivan-A/mango_ba_prompts/pull/406).
Статус результата — проект для review; merge и организационное утверждение
остаются за человеком. Разрабатывается способ работы Этапа 2; итоговый roadmap
четырёх этапов не является результатом этой задачи.

## Результат и область применения

Рекомендуемый базовый профиль — **OpenCode V1** с явными deny/ask и отдельным
read-only reviewer. **Goose Desktop** — поддержанная альтернатива с подробным
обучением БА; **Cline** — вариант для принятой корпоративной IDE. Выбор основан
на документированных политиках, не на измеренном качестве моделей или UX.

Правила и native skills переносят все 39 классов; файловые baseline/slices
сохраняют состояние, агент готовит контекст. Бизнес-переходы, согласование и
выпуск остаются решениями уполномоченных людей. Native permissions ограничивают
инструменты, но не доказывают смысловую сохранность или полномочия в JSON.
Python-код не требуется в работе БА; Python этого PR проверяет артефакты офлайн.

Все три исследовательские итерации выполнены в одном PR. Клиенты с моделью
не запускались: actual runtime, корпоративный rollout и статистический LLM-eval
не выдаются за выполненные проверки. Для внедрения определены наблюдаемые
P01–P08 и остаточные риски. Это предел доказательств исследования, а не
отложенный пункт анализа из issue.

## Проектные вопросы и безопасное поведение

Неопределённые параметры применения не заполняются исследованием от имени
организации: provider/model и допустимость данных утверждает ИБ; полномочия
выпуска определяет владелец процесса; version/channel и capabilities проверяет
администратор; качество модели измеряется на сопоставимом корпусе.
По умолчанию нет допуска корпоративных данных, внешних записей/исполнения
и release при неизвестной роли. Анализ каждого параметра, owner, последствия
и критерии проверки приведены в операционной модели; открытых требований
самой исследовательской задачи этим не скрывается.
