## Метод и границы достоверности

На 2026-10-30 прочитаны официальные страницы, а не обзоры инструментов.
[Реестр источников](2026-10-30-sources.md) связывает ID с адресом и заголовком;
[HTTP-наблюдения](../../../experiments/issue_405/source-observations.json)
сохраняют время UTC, конечный URL, content type, размер и SHA-256 байтов.
Хэш идентифицирует прочитанный ответ, но не доказывает истинность документации.
Сырые страницы остаются в игнорируемом кэше. Повторная загрузка может изменить
хэш: сайт развивается; для воспроизведения выводов нужны и дата, и локатор.

GitHub releases на дату исследования: Goose **v1.57.0** (2026-10-28),
OpenCode **v1.19.5** (2026-10-28), Cline **v4.1.26** (2026-10-26).
Ссылки на release — в реестре. Это ориентиры выбора версии, а не заявление,
что все функции движущейся документации проверены в этих бинарных версиях.
Клиенты с моделью не запускались, платные API и корпоративные endpoints
не использовались. Все выводы о возможностях имеют уровень **documented**;
проект переноса — **design**; runtime-проверки перечислены отдельно.

OpenCode `/docs/` явно описывает **V1** и предупреждает о отдельном V2.
Сравнение и JSON-примеры ниже относятся к этому профилю V1. Пакеты могут
установить V2 под тем же именем `opencode`; перед пилотом сверять `--version`
и канал дистрибутива. Перенос разрешений на V2 без отдельной сверки запрещён
проектом. Исторические ссылки Goose на Block перенаправляются в актуальный
AAIF-репозиторий; исходная точка `goose-docs.ai` сохранена (G16, O09).

## Как устроен цикл работы

Общий цикл: сообщение БА + доставленные правила + выбранные данные → запрос
модели → предложение ответа или вызова инструмента → проверка разрешений
клиента → результат инструмента → следующий запрос модели. Несколько
инструментальных шагов могут произойти за одну реплику БА. Поэтому «диалоговый
агент» не означает «одна реплика — одна операция». Наш проект вводит границу
одного класса и receipt, затем возвращает управление БА.

Goose — самостоятельный Desktop/CLI-клиент с расширениями, в том числе MCP.
OpenCode — клиент с TUI/desktop/IDE-интерфейсами, агентными профилями и
конфигурируемыми правами. Cline — агент с интеграцией в редактор и другими
оболочками; здесь рассматривается рабочий процесс БА через IDE.
Эти формы интерфейса не меняют ответственности модели, владельца источника
и человека, уполномоченного согласовать бизнес-результат (G01, G11, O04, O09,
L04, L07). Наличие SDK/API не требует использовать их на Этапе 2.

## Что следует из фактов

1. **Поставка правил переносима, полномочия — нет.** Во всех трёх клиентах
   можно доставить постоянное ядро и подгрузить подробный класс. Нет основания
   считать `SKILL.md` исполнимым типизированным контрактом. Права относятся к
   инструментам, не к значению `approved` в созданном JSON.
2. **Файловая память полезнее скрытого продолжения диалога.** Baseline и
   журнал slices дают переносимость между клиентами. После compaction
   состояние перечитывается с диска. Глобальная memory подходит предпочтениям,
   но опасна для локальных решений и клиентских данных.
3. **Самая управляемая текстовая политика инструментов здесь у OpenCode V1.**
   Основание — документированные glob-права по edit/read/skill/task и профили.
   Это сравнительный вывод об удобстве конфигурирования, не доказательство
   безопасности реализации. В Goose требуется отдельно учитывать классификацию
   действий и смешанный editor; в Cline safe-команда не равна allowlist.
4. **Удобство БА следует проверять отдельно.** Desktop Goose снижает зависимость
   от IDE-терминов; Cline удобен команде с принятой IDE; OpenCode даёт явно
   версионируемый профиль. Это гипотезы применимости для пилота, а не измеренный
   рейтинг UX. Числа GitHub stars не используются как оценка качества БА.

## Приёмка итерации 1

Критерии: официальные адреса доступны и идентифицированы; восемь измерений
покрывают три клиента; утверждения имеют source ID; документированный факт,
вывод и будущий runtime-тест различаются; движущиеся страницы и V1/V2
не смешаны. Проверка: `python3 scripts/validate_issue_405_ide_research.py --stage 1`.
Результат фиксируется в [журнале](../../../experiments/issue_405/acceptance.md).
Вход следующей итерации — эта матрица и реестр, после успешной проверки.
