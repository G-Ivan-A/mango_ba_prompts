# Аудит нарушений naming convention

## Контекст

Issue #221 требует провести аудит имён артефактов и каталогов без переименования файлов и без изменения стандартов. Проверка выполнена по tracked content репозитория через `git -c core.quotepath=false ls-files -z`; из tracked files дополнительно восстановлены tracked directories. Внутренний `.git/` и untracked локальные файлы не входят в результат, потому что они не являются поставляемыми артефактами репозитория.

Критерии срабатывания: заглавные латинские буквы `A-Z`, `_` как snake_case, пробелы, символы вне набора `A-Za-z0-9._-`. Расширительная точка в имени файла не считается отдельным нарушением, но uppercase в stem или расширении фиксируется. Пробелы не найдены.

Воспроизводимая команда:

```bash
python3 experiments/issue-221/naming-audit-scan.py --format summary
python3 experiments/issue-221/naming-audit-scan.py --format markdown
```

Scan helper возвращает exit code `1`, пока найден хотя бы один naming hit. Для
этой audit-only задачи это сигнал воспроизведения проблемы, а не требование
исправить имена в текущем PR.

Основные причины повторяются:

- legacy и внешние convention names (`README.md`, `CONTRACT.md`, `REGISTRY.md`, `CHANGELOG.md`, `LICENSE`, `Makefile`);
- осознанные контрактные исключения, прежде всего `runs/YYYY/RUN-XXXX/`;
