# Проверка готовности BL-156 и BL-157 (комментарий владельца к PR #439)

## Summary / BLUF

Владелец в [комментарии к PR #439](https://github.com/G-Ivan-A/mango_ba_prompts/pull/439#issuecomment-6628365523)
выдвинул две гипотезы. Обе **подтверждены**.

- **Гипотеза 1: «BL-156 запущена раньше срока».** Подтверждена. Отдельной
  постановки BL-156 нет. Явного «Р-15 да» нет. Зависимости BL-151…BL-155
  в статусе `review`, а не `DONE`. RFC-RT-001 ставит BL-156 после BL-163,
  РТ-4 и РТ-3, а у BL-163 уже сработал триггер (РТ-1 слита в runtime
  2026-11-04).
- **Гипотеза 2: «предусловия BL-157 не готовы».** Подтверждена. Р-15
  ждёт ответа. В бэклоге BL-157 зависит от BL-156. «Готово» у BL-157
  требует первого прогона BL-111, а для него нет Р-01, BL-101…BL-103,
  новой задачи и БА.

Что сделано в PR #439, чтобы слияние не стало преждевременным
согласованием (вариант Б, раздел 4):

- Запись «Р-15 принято» возвращена в «ждёт». Поправка 0.6 RFC — проект,
  DEC-427-04 и 12 — `proposed`.
- Правка типа гейта в 14 опубликованных промптах снята: `prompts/`
  совпадает с `main`.
- BL-156 и BL-157 переведены в `deferred (triggered)` с триггером «ответ на
  Р-15 и отдельная постановка».
- Черновики, сборщик, RUN-0080 и проект комплекта остаются **заготовкой**:
  БА их не видит как опубликованные.

Нужны ответы владельца одной строкой (раздел 5).

## Findings / Options

### 1. Правила старта задачи

[Инструкция бэклога](../../pr-ops/backlog-instruction.md), поле
«Зависимости»: «Задача стартует, когда зависимости `DONE` и решения
приняты.»

Статус `DONE`: «Результат слит или принят; есть ссылка на доказательство.»

Решение владельца — ответ одной строкой («Р-01 да»). Только после него
исполнитель ставит «принято» со ссылкой
([раздел «Решения владельца»](../../pr-ops/backlog-instruction.md#решения-владельца)).

### 3. Порядок BL-157 и BL-156: три источника расходятся

| Источник | Порядок | Цитата |
| --- | --- | --- |
| PR #435, процитирован в issue #438 | Р-15 → BL-157 → BL-156 | «Владелец: решение Р-15 → BL-157 (комплект прогона), затем BL-156 (промпты шагов)» |
| Бэклог и [RFC #427, раздел 12](../rfc/2026-11-bcreq-flow-processes-prompts.md#12-план-реализации) | BL-156 → BL-157 (BL-157 зависит от BL-156); шаг 0 — Р-13, Р-14, Р-15 | «\| 4 \| Промпты и комплект прогона \| BL-156, BL-157 \|» |
| [RFC-RT-001, раздел 11](../rfc/2026-11-runtime-product-catalog-golden-set.md#11-рекомендуемые-следующие-шаги-после-согласования) | BL-163 → РТ-4 → РТ-3 → BL-156 → BL-157 | «Почему: тогда BL-156 выйдет без заглушек З-1 и З-3.» |
| Комментарий владельца к PR #439 | BL-157, затем отдельной постановкой BL-156 | «выполнить 157 задачу, а потом отдельной постановкой пользователя - запустить 156» |

**Вывод.** Намерение владельца (BL-157, потом BL-156 отдельной
постановкой) совпадает с цитатой PR #435. Оно расходится с зависимостью
в бэклоге: BL-157 ссылается на промпты BL-156, а «Готово» BL-157 требует
прогона BL-111. Без правки зависимостей BL-157 нельзя закрыть первой.
Рекомендация П-П — в разделе «Recommendations».

### 5. Р-16

Р-16 перепроверено отдельно
([анализ](2026-11-03-silence-consent-gates-r16.md), вариант А+). В PR #439
оно не принималось: ADR-003 не правился, BL-162 заблокирована,

### 6. Смежные отклонения

- **Р-14** записано «принято» в issue #432 по той же формуле поручения
  («выполнить рекомендованные действия (решение Р-14, см. цитата)»).
  Владелец слил PR #435 с этой записью, и по правилу ADR-0003 слияние
  — согласие на документы PR. Риск низкий, но для однозначности нужно
  подтверждение одной строкой.
- **BL-150…BL-155 и BL-159** — `review`, хотя их PR слиты. По
  инструкции «слит» = `DONE`. Пока статусы не обновлены, формально
  BL-156 не может стартовать даже после Р-15.
- **Нижняя граница golden set Ш-В.** В RFC #427 записано «RUN-0079
  (49/62 → 61/62)». 49 — опубликованный v0.1, 61 — неопубликованная
  редакция с уроками. RUN-0080 дал 55/62 для обеих версий A и D, разброс
  судьи при N = 1 — около ±6. Это вопрос к Р-03.

## Recommendations

Порядок действий владельца. Каждый шаг — одна строка в PR #439 или новая
постановка.

1. **Слить PR #439 как заготовку** (после проверки). Почему: слияние
   ничего не принимает — Р-15 ждёт, `prompts/` не меняются, BL-156/157
   `deferred (triggered)`.
2. **Ответ на порядок (П-П).** Варианты:
   - «П-П: BL-157 сначала» — разделить BL-157 на BL-157а (комплект без
     промптов «по тесту», режим v0.1) и BL-157б (колонка «по тесту» и
     прогон BL-111 после BL-156);
   - «П-П: по RFC-RT-001» — BL-163 → РТ-4 → РТ-3 → BL-156 → BL-157.

   **Рекомендация:** первый вариант. Он совпадает с вашей целью из
   комментария, и комплект с v0.1 нужен БА уже сейчас.
3. **«Р-15 да»** (или другой вариант). Почему: последний блокер решений
   для BL-156, BL-157, BL-230, BL-231.
4. **Статусы BL-150…BL-155, BL-159 → `DONE`.** Одна строка «закрыть
   слитые» — отдельной задачей исполнителю. Почему: без этого BL-156
   формально не стартует.
5. **BL-163** — отдельной постановкой: её триггер сработал (runtime
   `2db0ef5`). Почему: снимает З-1 в черновиках до старта BL-156.
6. **Отдельная постановка BL-156** — после шагов 3–5. Входы: эта
   заготовка, `prompt-typing.json`, RUN-0080.
7. **Р-03 и граница golden set (49 или 61)**, **Р-16** — без изменений,
   повторяются из PR #436 и #439.
8. **«Р-14 подтверждаю»** — для однозначности (п. 6).
