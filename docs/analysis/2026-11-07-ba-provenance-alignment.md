# Согласование provenance БА с aether-orbis: критическая проверка #474

**Рекомендация: сейчас ввести небольшой локальный профиль для draft A-IN;
не заменять исполнимость тройкой статусов.** Происхождение, достаточность
доказательства, доступ/актуальность и работоспособность продукта — разные оси.
Простая замена «да/нет/частично» на verified/conflict/partial теряет смысл «нет»
и неизвестность, а conflict ошибочно превращает противоречие в отрицание.
Изменение всех стадий/экосистемы не обосновано. [RFC-PROV-001](../rfc/2026-11-ba-evidence-provenance.md)
описывает профиль и решение для review; draft A-IN уже содержит его как пилот.

## Постановка и метод

Как есть: запрос на единый «индустриальный стандарт» опирается на гипотезу о
двух соседних проектах. Как должно быть: поля БА имеют явную семантику,
доказанные соответствия, безопасные отображения и цену внедрения. Creative;
цель — проверить гипотезу, а не подтвердить её по названию статуса.
Критерии: оба репозитория проверены по закреплённому SHA; первичный стандарт
прочитан; три роли рассмотрели пользу/риск; unknown/конфликт/отрицание/устаревание
не теряются; момент внедрения и последствия для выпуска определены.

он не считается полным источником. Суждение основано на прямом чтении файлов,

## Три роли и альтернативы

| Роль | Критика первоначальной гипотезы | Решение |
| --- | --- | --- |
| БА CBAP / RE | VERIFIED может относиться к доказанному отсутствию функции. CONFLICT не значит «Нет». Для клиента важна возможность сейчас | Принять раздельные поля; выпускать исполнимость по evidence, unknown оставлять явным |
| Архитектор данных | Сверка источников не покрывает derivation/agent/version. Автоматическая двусторонняя конверсия enum необратима | Принять профиль с source_kind, derivation и loss-aware адаптерами; не менять соседние репозитории |
| ИИ-инженер | Три статуса без UNKNOWN вынуждают модель «доподтверждать». Источник может быть недоступен, stale или содержать injection | Принять явные UNKNOWN/REFUTED/NOT_APPLICABLE и отдельные access/freshness; human gate сохраняется |

Варианты: (1) заменить шкалу сейчас — отклонить (семантическая потеря);

миграции — выбрать. Затраты: несколько полей в уже создаваемых записях,

## Граничные случаи и критерии review

- Прочитанный документ доказывает «невозможно»: evidence VERIFIED, feasibility Нет.
- Полностью доказана только часть сценария: evidence PARTIAL с остатком;
  feasibility Частично только если реализованная часть сама доказана.
- Источники расходятся: CONFLICT, выпускной вердикт UNKNOWN до разрешения,
  а не Нет. Решение БА не стирает исходные цитаты и область применимости.
- Нет результата поиска/доступа: UNKNOWN; empty/access_gap сохраняются отдельно.
- Принятая гипотеза остаётся ba_hypothesis + UNKNOWN, допускает только явно
  ограниченное продолжение. Полномочия и критические риски не обходятся.
- Новая версия отзывает snapshot/допуск и зависимые выводы; VERIFIED старой
  версии остаётся в истории, текущая запись stale и не служит допуском.
- Клиентское намерение нельзя подтвердить продуктовой БЗ и наоборот.
- Выпускной текст скрывает служебные поля, но сохраняет условность неизвестного.
