# Проверка готовности BL-156 и BL-157 (issue #444)

## Summary / BLUF

Issue [#444](https://github.com/G-Ivan-A/mango_ba_prompts/issues/444)
просит продолжить BL-156 или BL-157 после проверки готовности. Итог
проверки:

- **BL-157б не готова.** Она зависит от BL-156 и от первого прогона
  BL-111, а для BL-111 нет Р-01, новой задачи и БА. BL-157а уже `DONE`
  (PR #439).
- **BL-156 готова к этапу BL-156а.** Runtime PR #21 слит
  (`f31dcde3`): РТ-3, РТ-4, РТ-6 и проверки ХАБ-1 в `main` runtime.
  Причины заглушек З-3 и З-4 сняты, каталог runtime равен каталогу
  спицы без дрейфа `lifecycle`.
- **BL-156 целиком не закрывается.** Её «Готово» требует 11 промптов в
  `prompts/`, а DEC-427-11 пускает туда только редакцию «не хуже»
  RUN-0079. Golden set есть только для Ш-В. Поэтому BL-156 делится на
  этапы: BL-156а (этот PR) и BL-156б (публикация после замера).

Исполнено в BL-156а: реестр справочников 0.4 на `f31dcde3`, пересборка
11 черновиков, звено М-4 в Ш-2, ссылки по SHA в 14 промптах v0.1,
прогон RUN-0081. Тип гейта в `prompts/` не опубликован: ядро 9/11
против 10/11 RUN-0079 (подробно — раздел 4).

### 3. Расхождение «логика PR #17 не интегрируется» и комментарий к PR #21

Комментарий владельца к
[runtime PR #21](https://github.com/G-Ivan-A/mango-ba-ai-runtime/pull/21#issuecomment-6633420940)
просил перенести в PR #21 логику PR #17, которой там нет. Issue #444
принимает строгий вариант PR #21. Сверка по коммитам runtime: норма
PT-5, проверки `check_taxonomies` и `check_golden` и тесты привязки
перенесены (`11fad36`, `09cc684`, `23d2a4b`, `449d772`). Отвергнута
только форма PR #17 — маркер `# намеренно вне каталога` в поле
`atomic_function`. Расхождения нет, полная таблица — RFC-RT-001,
раздел 13.2.

| **Б. Этапы (выбран)** | BL-156а: реестр, черновики, SHA, замер; BL-156б: публикация после замера | соблюдает DEC-427-11, двигает всё, что можно измерить | BL-156 остаётся открытой |

Замер варианта Б —

По правилу, заданному до прогона, тип гейта не публикуется. Провал ядра
GS-BCREQ-01 — по K5, при той же правке, которую судья RUN-0080 зачёл.
Это довод в пользу разброса судьи, но не основание менять оценку
(Р-03).

### 5. Граничные случаи кейсов runtime

- Кейсы runtime `structural_only: true` проверяют форму, а не смысл.
  Ш-В по-прежнему измеряется golden set BCREQ этапа 1 (62 кейса), а
  кейсы runtime в метрику не входят. Содержательная проверка — BL-165.
- 46 кандидатов RUN-0074 (30 с `confirmed_by: user`) размечены полем
  `product` (`lk`, `cross`, `cc`), а не классами runtime. Перенос без
  сопоставления класса и функции нарушит строгую форму PR #21. Задача —
  BL-166.

## Recommendations

1. **Слить PR #445** — этап BL-156а: реестр 0.4, черновики, SHA,
   RUN-0081. Молчание = согласие.
2. **BL-156б: замер, устойчивый к разбросу.** Три повтора или три судьи,
   решение по медиане; порог — Р-03 владельца. Тогда же — решение о типе
   гейта и ответ П-Ш-В.
3. **BL-157б — после BL-156а `DONE` и старта BL-111.** До этого прогон
   на новых задачах не с чем сравнивать.
4. **BL-165 и BL-166 — `deferred (triggered)`.** BL-165 — до первой
   метрики на кейсах runtime; BL-166 — до переноса RUN-0074 в golden set.
