# Доступ к сайту и ручная публикация

> **Пароль временно отключён (issue #460, отладка BL-157в).** Сайт открывается
> без пароля: константа `GATE_DISABLED = true` в
> [`site/gate.js`](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/site/gate.js),
> рядом комментарий-напоминание. Форма входа, код проверки, соль и хэш остались на
> месте, значение пароля не менялось. Описание ниже действует после возврата пароля.
>
> **Как вернуть.** Выполните `git revert` коммита отключения: он возвращает и код
> входа, и хэш `site/gate.js` в проверке `test_issue_395_site`. Затем опубликуйте сайт
> по процедуре ниже. Менять пароль не нужно. Задача — BL-169 в [бэклоге](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/pr-ops/BACKLOG.md).
>
> **Отчёт RUN-0060 в сайт не входит (issue #462, вариант А).** Клиентский пароль не
> защищает данные: файлы на GitHub Pages скачиваются по прямой ссылке. Генератор
> `scripts/generate-pages-data.mjs` удаляет `reports/run-0060/` из `site/` при каждой
> сборке, запись `run-0060` убрана из `site/password-hashes.json`, а
> `scripts/validate_issue_462_report_exclusion.py` проверяет результат. Не защищайте
> паролем реальные данные и не возвращайте их в `site/`.

[Сайт](https://g-ivan-a.github.io/mango_ba_prompts/) без действующего входа
перенаправляет на отдельную страницу `login.html`. На ней одно поле пароля
и кнопка «Войти». Неверное значение оставляет форму с сообщением «Неверный
пароль». Регистр и каждый пробел значимы. Успешный вход по умолчанию ведёт на
[каноническую главную](https://g-ivan-a.github.io/mango_ba_prompts/).
Для явной ссылки на вложенную страницу сохраняется адрес внутри этого сайта.

Значение системного пароля зафиксировано владельцем в
[issue #391](https://github.com/G-Ivan-A/mango_ba_prompts/issues/391).
Его нельзя менять без отдельного явного решения пользователя. Не записывайте
значение в код, документы, историю shell, PR, логи или скриншоты.

Пароль задаётся **только**
[скриптом установки](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/scripts/set-site-password.mjs):
в записи `site` файла `site/password-hashes.json` сохраняются случайная соль
и `SHA-256(salt + password)`, прочие записи сохраняются. Передать уже
согласованное значение можно скрытым вводом (Bash):

```bash
read -r -s -p 'Согласованный пароль: ' site_password_input
printf '%s' "$site_password_input" | node scripts/set-site-password.mjs
unset site_password_input
```

Не добавляйте перевод строки к stdin. Скрипт не исправляет регистр и пробелы.
После изменения соли/хэша опубликуйте файл вместе с сайтом по процедуре ниже.

Вход хранится в `sessionStorage` текущей вкладки; функция «запомнить меня»
отсутствует. Кнопка выхода очищает вход. На каждой защищённой странице
проверяется актуальный хэш; замена записи делает прежний вход недействительным.
При недоступной конфигурации вход закрыт, на форме можно повторить попытку.
Это клиентский барьер интерфейса GitHub Pages: статические файлы доступны
по URL и не шифруются. Исходники промптов остаются в репозитории.

## Ручной деплой

Для этого изменения деплой ручной; workflow-файлы и настройки Actions
не меняются. Историческая отметка об отключённых Actions не доказывает их
текущее состояние: в форке разрешены отдельные проверочные запуски CI. Не запускайте
workflow публикации. Действующие настройки Actions нужно проверять отдельно
учётной записью администратора: чтение настроек требует соответствующих прав.

1. На исходной ветке запустите `node scripts/generate-pages-data.mjs`,
   `make validate-full` и браузерную проверку, указанную в
   [отчёте проверки](https://github.com/konard/G-Ivan-A-mango_ba_prompts/blob/issue-391-da7041d0d7c3/docs/reviews/issue-391-bcreq-review.md).
2. Зафиксируйте исходники и данные в PR. Для публикации исходного сайта нужны
   права записи в `G-Ivan-A/mango_ba_prompts`; права записи только в форк
   канонический сайт не обновляют.
3. Из отдельного checkout ветки `gh-pages` исходного репозитория замените её
   содержимое **содержимым** `site/` проверенного исходного коммита (без
   обёртки `site/`), добавьте пустой `.nojekyll`. Проверьте diff: HTML,
   CSS, JS, `data/`, отчёты и хэши должны соответствовать исходному коммиту.
4. Сделайте коммит и push в `gh-pages`, сохранив историю ветки. GitHub Pages
   должен использовать `gh-pages`, каталог `/`. Не меняйте настройки Actions.
5. В чистой вкладке канонического сайта проверьте отдельную форму, ошибку
   пароля, точный согласованный пароль, редирект на главную, только BCREQ
   в каталоге, два блока «Процессов» и копирование каждого из 14 шагов.
   Пока пароль отключён (issue #460), проверки формы заменяет открытие сайта и
   `login.html` без запроса пароля.
   Сравните опубликованные файлы с исходным коммитом, а не только внешний вид.
   Адреса `reports/run-0060/` и `reports/run-0060/detailed-gap-report.html` должны
   отвечать 404. CDN Pages может отдавать старую версию несколько минут.

Не объявляйте публикацию выполненной по локальному превью. Если push или
проверка канонического сайта недоступны, зафиксируйте блокер и оставьте PR
без слияния.
