# RFC-MR-001: машинная база сравнения для прогона БА по задачам 1135 и 1137 (#458)

## Summary / BLUF

Новые промпты (PR #451) прошли весь поток BCREQ на двух новых задачах, каждая —
отдельным RUN. **Документ из 8 разделов получен по обеим, вердикт обоих прогонов —
`partial-success`.** `success` в машинном прогоне недоступен по пред-регистрации: он
требует проверки БА.

| | [RUN-0090](../../runs/2026/RUN-0090/outputs/report.md) (задача 1135) | [RUN-0091](../../runs/2026/RUN-0091/outputs/report.md) (задача 1137) |
| --- | --- | --- |
| Результат | [`bcreq.md`](../../runs/2026/RUN-0090/outputs/bcreq.md), 174 669 байт | [`bcreq.md`](../../runs/2026/RUN-0091/outputs/bcreq.md), 149 498 байт |
| Шаги | 12 и возврат | 12 и возврат |
| Скриптовые проверки | 8/8 | 8/8 |
| Слепой судья | 10 из 14; провалены J01, J02, J03 (критические), J07 | 8 из 15; провалены J01, J02, J03 (критические), J07, B4, B5, B7 |
| Вопросы в 8.4 | 107, блокирующих 79 | 70, блокирующих 37 |
| Замечания Ш-В | 39 | 33 |
| Гейты | все `pending` | все `pending` |
| К-31, К-33 | FAIL; не готово к выпуску | FAIL; не готово к выпуску |
| Токены | 534 248 | 488 543 |

Что RFC предлагает:

1. Считать RUN-0090 и RUN-0091 **машинной базой сравнения**, а не приёмкой. Приёмку
   даёт только прогон БА (BL-157в).
2. Закрыть расхождение маршрута каталог ↔ база знаний (BL-170) — единственная находка,
   которая исправляется уже сейчас и меняет результат прогона БА.
3. Не править промпты до данных БА; пакет правок (BL-171) ждёт подтверждения.
4. Не запускать платный повтор: он не даст приёмки и съест около 0,5 млн токенов.

## 1. Постановка и границы

Полная постановка, граничные случаи Г-1…Г-13 и WBS —
[`task-statement.md`](../../experiments/issue_458/task-statement.md). Правило вердикта
и критерии записаны [до запуска](../../experiments/issue_458/preregistration.md),
реплики БА заданы заранее [политикой симулятора](../../experiments/issue_458/ba-policy.md).

Границы, которые прогон не переходит:

- LLM не проходит гейт. Гейты Г-IN, Г-С1, Г-W и «Выпуск» имеют запись К-34 со значением
  `pending`; `approved` нет ни в одном файле прогонов.
- Документ — кандидат. `ba_reviewed: false`, ничего не отправлено.
- Промпты в ходе прогона не менялись (C08), а дефекты записаны в форму обратной связи.
- Runtime не менялся; срез `68ad8fcf`, реестр 0.5.

## 3. Протокол сравнения с прогоном БА

Сравнение выполняется в прогоне BL-157в. Без этого RUN-0090 и RUN-0091 останутся просто
двумя документами.

**Защита от якоря.** БА проводит задачу по сайту, **не читая** RUN-0090 и RUN-0091 по этой
задаче, и открывает их только после своего варианта. Если БА уже прочитал, это отмечается
в карточке, а такой прогон не идёт в сравнение как независимый.

**Тексты.** База снята на комплекте 0.5. В комплекте 0.7 (PR #455) основная кнопка отличается на
9 шагах из 12: [сверка](../../experiments/issue_454/kit_vs_machine_base.json). Карточка прогона БА хранит версию
комплекта, а разницу на этих шагах читают с учётом текста:
[DEC-454-09](2026-11-bcreq-prompts-publication-roadmap.md#7-решения-на-согласование).

**Что БА делает со своей стороны.** Проходит гейты сам: `approved` ставит только человек.
Для 1137 отвечает на Q-01, разрешая `mango-lk-manual` и `rolevaya-model-vats`, если BL-170
ещё не слита. Заполняет форму обратной связи по шагам.

**Что сравнивается** (разбор идёт отдельным коммитом после прогона БА):

| Показатель | Как считать | Что показывает |
| --- | --- | --- |
| Вопросы 8.4 | всего и блокирующих; сколько БА снял без Заказчика | польза ответов БА и цена инфляции (Н-2) |
| Факты As-Is | совпало, упущено машиной, упущено БА | вклад базы знаний (Н-1, Н-5) |
| Запреты задачи | для 1137: прямая ссылка, API, отчёты, выгрузка — закрыты ли | B5, B7 |
| Проверяемость | J07 на той же выборке разделов | что снимается ответами БА (Н-4) |
| Правки | сколько правок БА внёс и по какому шагу | калибровка судьи |
| Судья | вердикт судьи против решения БА по J01…J08 | калибровка судьи по человеку |

**Как читать итог.** Это наблюдение при N = 2, без статистических выводов. Метрики экономии
из него не выводятся. Подтверждённой считается находка, которую БА отметил в форме обратной
связи или которая видна в его правках.

## 6. Пределы

- N = 1 на задачу; один исполнитель и один судья одной модели, судья не откалиброван.
- Реплики БА — симулятор, поэтому часть провалов J07 ожидаема.
- Ссылки на RUN-0075 не вошли в снимок Хаба; заголовок карточки 1137 с «сотрудник партнёра»
  задан обвязкой (Q-11). У гейта «Выпуск» не было правила в политике симулятора.
- Отклонения записаны в журналах
  [RUN-0090](../../runs/2026/RUN-0090/logs/experiment-log.md) и
  [RUN-0091](../../runs/2026/RUN-0091/logs/experiment-log.md).

## Operating Mode

- `Creative`: режим задан issue #458. Статус `accepted` ставит только владелец.

## Специфика работы с Конардом

- **молчание = согласие:** если Пользователь мержит PR без комментариев, решения приняты;
- **комментарий + ручной перезапуск:** доработка в том же PR;
- **close:** закрытие PR означает отказ от решения;
- draft PR используется как место отложенной проверки до acceptance.

## Обоснованные обходы

- Симулятор БА вместо человека. Обходит только получение ответов, но не гейты: все записи
  К-34 — `pending`. Issue #458 просит машинный прогон; приёмка остаётся за BL-157в.
