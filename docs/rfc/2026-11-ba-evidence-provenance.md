# RFC-PROV-001 — происхождение и сверка evidence в БА

**Решение на review: сейчас применять локальный профиль в draft A-IN.**
Основание — [анализ двух aether-проектов и W3C](../analysis/2026-11-07-ba-provenance-alignment.md).
Проблема: одна шкала смешивает источник, достаточность и исполнимость.
Цель: не терять unknown, конфликт, отрицание и цепочку derivation.
Creative; производственный статус стандарта и глобальная миграция не заявляются.

## Контракт v0.1

| Ось | Поля / значения | Правило |
| --- | --- | --- |
| Происхождение | claim_id, source_ids, source_kind, locator, source_version, retrieved_at, published_at (или null), read_range, activity, agent, derivation, supersedes | Есть у каждого утверждения, включая гипотезу; ID стабильны, версии различаются |
| Сверка | evidence_status: VERIFIED / PARTIAL / CONFLICT / UNKNOWN / REFUTED / NOT_APPLICABLE | Локальный профиль по отношению evidence к точному утверждению и его области |
| Доступ и актуальность | access: read / partial / empty / access_gap; freshness: current / stale / unknown | Недоступное или stale не обеспечивает текущий допуск |
| Исполнимость | feasibility: yes / partial / no / unknown; conditions, delta, evidence_ids | Отдельная оценка AIN-12; без прямого преобразования evidence_status |
| Принятие | result_status, ba_decision{actor,date,locator,object_version}, hypothesis | VERIFIED не принимает результат и не проходит гейт `гибрид`, решение БА |

VERIFIED — evidence достаточно для точного утверждения; PARTIAL — доказана
названная часть, остаток явен; CONFLICT — применимые источники противоречат;
UNKNOWN — достаточных evidence нет; REFUTED — evidence опровергает именно
данное утверждение; NOT_APPLICABLE — проверка неприменима с причиной.
Это предметное расширение на концептах PROV, не стандартный enum W3C.
Реализация RDF/OWL и обещание полной PROV-conformance не требуются.

## Отображения и совместимость

В выпуске feasibility yes/partial/no/unknown → Да/Частично/Нет/Не подтверждено.
Перевод VERIFIED → Да и CONFLICT → Нет **запрещён**. VERIFIED может доказывать
отсутствие функции. REFUTED не означает отрицание существования продукта.
Частичную исполнимость подтверждают по условиям атома, не по названию статуса.

GRA VERIFIED/PARTIAL/CONFLICT соответствует одноимённым статусам только при
той же области и прочитанном evidence. Неразмеченный остаток — UNKNOWN.
В Orbis concept статусы относятся к утверждению/связи, а extraction schema
закрепляет их только у relation.state (у claim поля state нет).
Orbis OBSERVED — кандидат VERIFIED, но требует проверки достаточности;
NOT_OBSERVED/UNCERTAIN → UNKNOWN с сохранением исходного значения и причины;
CONTRADICTED → CONFLICT, а не REFUTED. Обратное отображение не гарантируется;
original_status и original_schema_version сохраняются. Confidence не
превращается в доказательство. Исторические артефакты не переписываются.
