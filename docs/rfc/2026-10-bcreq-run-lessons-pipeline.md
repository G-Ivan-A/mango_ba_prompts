# RFC: уроки прогонов в конвейере промптов BCREQ — от замечания БА к правилу и регрессии


> **Решение владельца (комментарий к PR #412, 31.10.2026).** Сайт — только интерфейс БА (каталог, стандарты, процессы) и статистика применения на дашборде; данные об ошибках и успехах промптов на сайт не выводятся. Изменения сайта, процесса БА и текстов промптов откачены. Промпты и классы меняются отдельными задачами только после принятия этого RFC/ADR (`python3 scripts/build_bcreq_lessons.py --apply-prompts`).

## Summary

Модель повторяет ошибки, на которые БА уже указывал. Причина не в отдельных
формулировках промптов. Опыт прогонов не имел адреса: у кодов ошибок не было
единого словаря, у урока — адресата и статуса, у прогона — версии промпта, у
правил — эталонного кейса. Поэтому при каждой смене структуры уроки терялись
незаметно.

PR #412 строит недостающее звено: реестр уроков → сгенерированные блоки в
промптах → golden set и рубрика → прогон по версиям. RFC просит владельца
утвердить это звено (DEC-411-01) и принять одиннадцать решений, которые PR
реализовать не может или не должен без согласования: поля контракта прогона,
порог приёмки, урок L-42, развитие 39 классов, бюджет токенов, восстановление
контракта эталонов и поправки к дорожной карте.

> **Пометка #420, риск 11.** «14 промптов» — снимок сайта и каталога
> `prompts/` на 31.10.2026, а не целевой состав. После PR #404 ручной
> конвейер BCREQ описан 39 классами (38 исходных и C39), и в изменённый
> проект переносятся они, а не 14 промптов. Классы улучшаются вместе с
> процессами, которые их запускают. Решения, опирающиеся на число 14,
> читаются с этой поправкой; пересмотр — задача BL-134 бэклога
> ([комментарий владельца к PR #422](https://github.com/G-Ivan-A/mango_ba_prompts/pull/422#issuecomment-6560476938)).

## Motivation

Числа из [аналитического отчёта](../analysis/2026-10-31-bcreq-pipeline-run-experience-review.md):

| Факт | Число |
| --- | --- |
| Прогонов, из которых нельзя восстановить ни диалог, ни вердикт БА (уровень L0) | 55 из 78 |
| Прогонов с замкнутым циклом «урок → промпт → повторный прогон» (L4) | 0 |
| Прогонов с реальной обратной связью БА | 15 из 78 |
| RFC на промпты, выведенных из прогонов и реализованных | 0 из 8 |
| Инцидентов в счётных реестрах; из них повтор после замечания БА | 851; 524 |
| Кандидатов в эталоны, переведённых из `draft` | 0 из 200 |
| Уроков, ослабленных или потерянных при переходе к 39 классам | 17 |
| Уроков, которым до PR #412 не было нормы нигде | 6 |
| Задач подряд с требованием «не упрощать и не терять» | 5 |

Повтор требования «не терять» в пяти задачах показывает: текстовый запрет в
постановке не работает как механизм. Нужен артефакт, который можно проверить
автоматически.

## Goals and Non-goals

Цели:

1. Каждое замечание БА и каждый код ошибки прогона адресованы уроку, уроку —
   промпт и эталонный кейс.
2. Правило урока доставляется модели в том же сообщении, что и промпт: в
   ручном чате ссылка на внешний файл не работает.
3. Регрессия измеряется по версиям: golden set, рубрика, промпт.
4. Смена структуры промптов не теряет уроки: генератор и валидатор
   останавливают сборку.

Не цели:

- Переписать нормы конституции BCREQ. Уроки ссылаются на нормы, а не
  заменяют их.
- Менять прошлые прогоны. Их статистика заморожена.
- Автоматизировать этап 1. Этап 1 — ручной чат; исполнение этапов 2–4 —
  предмет RFC модернизации.

## Proposal

### Решения на согласование

#### DEC-411-01. Утвердить ADR-017: реестр уроков — SSOT

**PROPOSED.** Перевести [ADR-017](../adr/2026-10-adr-017-run-lessons-ssot.md)
из `proposed` в `accepted`. Тогда `standards/bcreq-lessons/lessons.json` —
единственный источник правил «как делать и как не делать». Промпты в части
уроков не правятся вручную. Номера задач и прогонов живут только в реестре
свидетельств.

Варианты: (А) принять; (Б) принять, но держать блоки уроков только в
конституции, а не в каждом промпте; (В) отклонить и вернуться к ручным
правкам. Рекомендация — А. Вариант Б уже был в работе: правила АД-1…АД-11
стояли в конституции, а 39 классов их не унаследовали.

#### DEC-411-02. Четыре поля контракта прогона

**PROPOSED.** Добавить в `standards/runs-contract-standard.md` для новых
прогонов (начиная со следующего после утверждения):

| Поле | Содержание | Закрываемый разрыв |
| --- | --- | --- |
| `prompt_ref` | Путь, версия и SHA каждого применённого промпта | Нет версии промпта ни в одном прогоне |
| `lessons[]` | ID урока из реестра, адресат, статус `open/applied/rejected`, ссылка на изменение | Урок не адресован и не закрывается |
| `golden_promotion` | Для кандидатов в эталоны: статус продвижения и ID кейса golden set | 200 кандидатов остаются `draft` |
| `ba_reviewed` | Подтвердил ли человек-БА вердикт; кто и когда | Разметку делает один AI-разметчик |

Стандарт зафиксирован базовым снимком сайта, поэтому поля предложены, но не
внесены. Старые прогоны не размечаются задним числом. RUN-0079 ведёт эти поля
в `metadata.yaml` как добровольное расширение и показывает формат.

#### DEC-411-03. Единый словарь кодов ошибок

**PROPOSED.** Новые счётные реестры ошибок используют ID уроков L-NN как
словарь кодов. Локальные коды допускаются только с колонкой «урок».
Сейчас четыре реестра используют четыре словаря, и один и тот же код означает
разные ошибки. Сведение выполнено в `lessons.json` (`run_taxonomies`), и
валидатор не пропускает несопоставленный код.

#### DEC-411-04. Порог приёмки по golden set

**PROPOSED.** Рубрика бинарная, но порог не назначен: это решение владельца.
Предлагаемые значения:

| Набор | Порог | Почему |
| --- | --- | --- |
| Ядро (11 кейсов) | 11 из 11 по K1–K6 | Самые частые уроки и удержание замечаний БА — повтор именно этих ошибок назван в постановке |
| Полный набор (62 кейса) | Не ниже 90% по K1–K3 и K5; K4 и K1 на негативных кейсах — без исключений | K4 и K1 на негативных кейсах — ложное срабатывание на корректном тексте. Модель, которая «находит» дефект везде, бесполезна для БА |
| Изменение промпта | Не хуже предыдущей версии ни на одном кейсе ядра | Регрессия по версии — главная цель |

Пока порог не утверждён, прогон фиксирует числа без вердикта «пройдено».

#### DEC-411-05. Урок L-42: канонические пункты раздела 6

**PROPOSED.** Прежний стандарт ограничений начинал раздел 6 с неизменных
пунктов. В текущем стандарте раздела 6 их нет. Урок оставлен в статусе
`proposed` и в промпты не попадает. Владелец стандарта решает: (А) вернуть
пункты в стандарт раздела 6 — тогда урок становится `active` и получает кейс;
(Б) отклонить — урок получает `rejected` с причиной.

#### DEC-411-06. Бюджет токенов промптов этапа 1

**PROPOSED.** Блок уроков добавляет к каждому промпту 29–44 КБ (до 46–78 КБ
на промпт). Владелец поставил качество выше экономии. Предложение:

1. Этап 1 работает с полными блоками.
2. Сокращение блока допускается только по данным: урок убирается из промпта
   шага, если его кейс проходит без блока в двух прогонах подряд, и
   остаётся в конституции.
3. Генератор уже разделяет общие уроки и уроки шага. Сокращение выполняется
   в реестре (поле `prompts`), а не в тексте промпта.

#### DEC-411-07. 39 классов — цель этапов 2–3

**PROPOSED.** 39 классов ручного конвейера получили блоки уроков из реестра.
Перед тем как классы станут исполняемыми промптами:

1. Вынести общий шаблон (около 95% текста каждого класса) в один файл и
   оставить в классе только специфику и блок уроков.
2. Переименовать ID классов `C01…C39`: они совпадают с кодами ошибок
   `C01…C25` в реестрах прогонов. Предлагаемый префикс — `К-`.
3. Перенести в классы 17 уроков, которые там ослаблены, явными правилами
   (сейчас их доставляет блок уроков).
4. Прогнать golden set на классах и сравнить с 14 промптами.

> **Пометка #420, риск 11.** «14 промптов» — снимок сайта и каталога
> `prompts/` на 31.10.2026, а не целевой состав. После PR #404 ручной
> конвейер BCREQ описан 39 классами (38 исходных и C39), и в изменённый
> проект переносятся они, а не 14 промптов. Классы улучшаются вместе с
> процессами, которые их запускают. Решения, опирающиеся на число 14,
> читаются с этой поправкой; пересмотр — задача BL-134 бэклога
> ([комментарий владельца к PR #422](https://github.com/G-Ivan-A/mango_ba_prompts/pull/422#issuecomment-6560476938)).

#### DEC-411-08. Восстановить контракт жизненного цикла эталонов

**PROPOSED.** Контракт Golden Examples был принят в июне. После очистки
истории при удалении LFS его файл отсутствует в `main`, вместе с изменениями
PR #128–#258. Предложение: восстановить контракт из сохранённых веток или
описания PR, сверить с `standards/evals-contract-standard.md` и назначить
один документ, который определяет переход «кандидат → эталон». Отдельно
проверить, какие ещё документы того периода утрачены.

#### DEC-411-09. Правило сессии (П-9) и его проверка

**PROPOSED.** 62% инцидентов — повтор после замечания БА. Правило П-9
процесса и урок L-32 требуют записывать замечание в 8.5 и проверять каждый
следующий ответ по всем правилам сессии. Предложение для этапа 2: агентный
клиент сам добавляет правила сессии из 8.5 в каждый запрос. Тогда П-9 будет
выполняться механически, а не на внимании БА.

#### DEC-411-10. Навигация README промптов и стандартов

**PROPOSED.** `prompts/README.md` и `standards/README.md` зафиксированы
базовым снимком сайта и не ссылаются на реестр уроков. Предложение: в
задаче, которая обновляет снимок, добавить в оба README ссылку на
`standards/bcreq-lessons/` и правило «блоки уроков не править вручную».

#### DEC-411-11. Поправки к RFC модернизации репозитория

**PROPOSED.** Дорожная карта четырёх этапов из
[RFC модернизации](2026-10-repository-modernization.md) не называет уроки
прогонов и регрессию по версиям критерием выхода этапа. Поправки — в
разделе [«Поправки к RFC модернизации»](#поправки-к-rfc-модернизации).

#### DEC-411-12. Метаданные ADR-015

**PROPOSED.** ADR-015 не проходит проверку frontmatter: значение
`decision-type: architecture` не входит в допустимый список. Исправление —
задача T-07 RFC модернизации, где решается судьба статусов ADR.

### Режимы прогона

Опыт прогонов проверяется двумя режимами. Они отвечают на разные вопросы,
поэтому один не заменяет другой.

| Режим | Что на входе | Что измеряет | Оценка | Статус |
| --- | --- | --- | --- | --- |
| 1. Рецензент на golden set | Обезличенные фрагменты golden set; промпт проверки этапа 1 | Удерживает ли промпт правило урока на коротком фрагменте: верный вердикт, верное правило, нет ложных срабатываний | Рубрика K1–K6, слепая, по версиям промпта | Вводится этим RFC; первый прогон — RUN-0079 |
| 2. Генерация документа | Реальный вход БА (материалы Заказчика, черновики разделов); цепочка промптов этапа 1 | Удержание уроков на длинной дистанции: повторы после замечаний, правила сессии, согласованность разделов | Счётчики уроков по реестру (`lessons[]` в метаданных прогона) и отзыв БА | Будущие прогоны с `ba_reviewed: true` |

Правила обоих режимов:

- в отчёте прогона указываются версии golden set, рубрики и промпта;
- метаданные прогона указывают `prompt_ref` (коммит) и `lessons[]` (какие
  уроки повторились, DEC-411-02);
- урок, повторившийся в режиме 2, получает новый кейс golden set, если
  режим 1 его не ловит (`golden_promotion`);
- режим 1 без режима 2 не доказывает качество документа, а режим 2 без
  режима 1 не воспроизводим: реальные входы разные.

### Поправки к RFC модернизации

Независимая проверка данных PR #410 (раздел 4 [отчёта](../analysis/2026-10-31-bcreq-pipeline-run-experience-review.md#4-независимая-оценка-данных-pr-410))
подтвердила структурные числа аудита. Она нашла, что цикл «опыт прогонов →
правила → эталоны → повторный прогон» описан только декларацией: у него нет
решения, задачи и артефакта. Поправки:

| Пункт RFC модернизации | Поправка | Причина |
| --- | --- | --- |
| DEC-01 (роль спицы) | В роль «практика этапа 1» явно включить цикл качества промптов: реестр уроков, golden set, прогоны по версиям | Без этого цикл остаётся без владельца |
| DEC-02 (границы #263) | Фразу о пробеле evals и golden set не удалять, а заменить точным статусом из реестра уроков и golden set | Пробел по существу не закрыт: эталоны в статусе `draft` |
| DEC-06 (пакет этапа 2) | Реестр уроков и golden set входят в пакет этапа 2 как регрессионный набор | Этап 2 должен пройти те же кейсы |
| DEC-09 (разметка истории) | Реестр уроков и кандидаты в эталоны не относятся к историческим по умолчанию | Это рабочие входы цикла качества |
| T-02 | Исправить утверждение, что валидатор #263 закрепляет «уровни 3–4 не являются планом работ»: в `REQUIRED_TEXT` такой строки нет | Ошибка аудита; сам RFC модернизации формулирует верно |
| T-04, T-09 | Путь каталога классов — `standards/bcreq-manual-classes/catalog.json`, а не `prompts/catalog.json` | Неверный путь; валидатор #409 не проверяет пути в code-span |
| T-07 и критерии приёмки | Вместо «`git diff` для `runs/` пуст» — «существующие прогоны не изменены» | Пустой diff запрещает добавлять новые прогоны, а этап 1 их требует |
| T-06 (контракты) | Включить DEC-411-02 (поля прогона) и DEC-411-08 (контракт эталонов). Контракт `runs/README.md` не считать статистикой | Иначе формат прогона нельзя развивать |
| T-07 (метаданные) | Включить DEC-411-12 | Дефект frontmatter ADR-015 |
| Критерий выхода этапа 1 | Реестр уроков без несопоставленных кодов; golden set и рубрика в статусе `reviewed`; прогон по версиям прошёл порог DEC-411-04 | Без этого на этапе 2 не с чем сравнивать |
| Критерий выхода этапа 2 | Клиент подставляет правила сессии (DEC-411-09); тот же golden set проходит не хуже этапа 1 | Перенос в агентный клиент не должен терять уроки |
| Изменение промптов «только через RFC или ADR» | ADR-017 вводит класс изменения «урок из реестра → генерируемый блок → прогон golden set». Отдельный RFC на каждый урок не нужен | Восемь RFC на промпты так и не были реализованы: цикл останавливался на согласовании |
| Уроки через Хаб | Локальный дефект промпта исправляется в спице; в Хаб уходит обобщённое наблюдение в форме LG-5 ADR-014 Хаба, без блокировки локальной правки | Урок, ждущий решения Хаба, не доходит до промпта |
| Новая задача: 39 классов | Перевод классов по DEC-411-07 | Классы — кандидат на исполняемые промпты этапов 2–3 |
| Новая задача: эталоны | Перевести golden set этапа 1 в `reviewed`; кандидатов из прогонов продвигать через подтверждение БА; перевести `standards/evals-contract-standard.md` в `accepted` | Эталоны ни разу не прошли утверждение |
| Новая задача: вход этапа 1 | Принять RFC ручного конвейера и ADR-015 как вход этапа 1 | Ни одна T-задача их не принимает |

## Alternatives

| Вариант | Почему не выбран |
| --- | --- |
| Только аналитический отчёт без реализации | Выбран частично по решению владельца: реестр, golden set и прогон — доказательная база RFC; изменения промптов — после согласования. Отчёт без механизма повторил бы восемь нереализованных RFC |
| Переписать 14 промптов заново с учётом уроков | Повторило бы деградацию: без реестра нельзя проверить, что ничего не потеряно |
| Сразу перейти на 39 классов как промпты этапа 1 | Классы не исполняются без ручной сборки контекста и не прошли ни одного прогона |
| Хранить уроки в отдельных файлах прогонов | Прогоны неизменяемы; словари несовместимы |

## Trade-offs

- Размер промптов растёт примерно втрое. Компенсация — DEC-411-06.
- Golden set синтетический. Он проверяет удержание правила, а не качество
  реального документа. Реальные кейсы добавляются после подтверждения БА.
- Судья в прогоне — модель. До `ba_reviewed` вывод прогона — сигнал, а не
  приёмка.
