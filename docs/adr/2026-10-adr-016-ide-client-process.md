# ADR-016: файловое состояние и native skills для Этапа 2

Проблема: ручной перенос 39 классов требует от БА собирать контекст, а IDE
может читать/сохранять его сама. Одновременно свободное исполнение tools
и скрытая память способны обойти сохранение требований и human gates.

Проектное решение для review: полный versioned rule bundle, native skill
на каждый локальный класс, файловый baseline+slices, C12 FULL, отдельный
reviewer, explicit human records и ограниченное поручение до гейта.
Python/скриптовый оркестратор в работе БА не нужен. Технический контекст
переключает агент; бизнес-переход и возврат остаются решением БА.

Предпочтительный профиль — OpenCode **V1** из-за явных deny/ask/tool/path
и agent permissions. Альтернативы: Goose Desktop с shell Never Allow и
editor Ask Before; Cline в принятой корпоративной IDE с Plan/Act, auto-approve
off и внешним ограничением исполнения. Обучающая инструкция Goose покрывает
полный цикл работы. Критерии выбора и ограничения версий описаны в
[операционном анализе](../analysis/ide-clients-stage-2/2026-10-30-operations.md).

Отвергнуты: один универсальный «выполни всё» без class contracts; recipes
как якобы детерминированные бизнес-гейты; scripts с unrestricted shell;
Telegram-relay; память сессии как единственный SSOT; 1:1 равенство C-ID,
SKILL.md и операции мета-модели. Основания — разные I/O, полномочия и
документированные пределы клиентов.

Следствия: БА меньше переносит тексты вручную, но проверяет evidence,
новый результат и реальные решения; сохраняются затраты на review и
контекст. Native policy ограничивает tools, смысловой контракт требует
I/O discipline и человеческого контроля. OS/IAM/egress/retention нужны
снаружи клиента. Квалификация выбранной версии по P01–P08 обязательна до
корпоративных данных; runtime этой квалификации в исследовании не выполнен.

Это draft архитектуры, не утверждение rollout или change действующих
промптов/мета-модели Хаба. Итоговый roadmap четырёх этапов не пересобирается.
Все источники, 39 отображений и последовательная приёмка доступны в
[основном отчёте](../analysis/2026-10-30-ide-clients-stage-2.md).
