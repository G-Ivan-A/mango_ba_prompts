# ADR-020: IDE-слой runtime — оркестратор-агент, гейты с журналом решений, MCP только на чтение

## Статус

`proposed` — на утверждение владельцу. Это решение M0 миграции
[RFC-RT-003](../rfc/2026-11-runtime-ide-orchestrator.md#8-миграция-и-откат-фт-4).
Принятие происходит слиянием PR #508 (молчание = согласие) или комментарием
владельца с номерами решений Р-RT-10…Р-RT-21.

ADR-016 (`draft`) уточняется, а не отменяется. Его положения сохраняются:

- оркестратор — агент, не скрипт;
- отдельный рецензент;
- явные записи решений человека;
- ограниченное поручение до гейта.

Р-RT-5 RFC-RT-002 («агентов не вводить») заменяется решением Р-RT-11 для
IDE-слоя.

## Контекст

**Целевая модель этапа 2 из
[#506](https://github.com/G-Ivan-A/mango_ba_prompts/issues/506):**

- локальный клон runtime — единственный источник;
- MCP — единственный канал к Jira, Confluence и вебу;
- команды `/a-in`, `/a-core`, `/a-work`, `/a-release` запускают
  оркестратор, который идёт автономно до гейтов;
- на гейте — конкретный вопрос и явное адресное одобрение;
- возврат предлагает агент, подтверждает БА;
- песочница и экспорт через PR.

**Что показал
[аудит](../audit/2026-11-26-runtime-stage2-ide-readiness.md) на 2026-11-26.**
В runtime (`main` `fe623c6b`, PR #29 `9421edad`) нет:

- `opencode.json`;
- `.opencode/agents`;
- `.opencode/commands`;
- MCP;
- карты гейтов.

Исполняемый маршрут RG-BCREQ-v1 — не маршрут этапа 1: в нём нет AIN-01…24
и гейтов Г-IN, Г-С1, Г-W, AIN-21.

**Прогон 1143** дал 56 проблем шагов. Две критические — ложный допуск на
гейтах:

- П-1143-38: допуск AIN-21 выведен из ответа на AIN-20;
- П-1143-44: Г-IN одобрен на основе этого ложного допуска.

Около 36 % ходов БА — чистый транспорт промптов.

**Нормы этапа 1, которые нельзя ослаблять:**

- Р-09 — явный ответ БА по конкретному результату и редакции;
- Р-19 — `BLOCKED` при `ACCESS_GAP`;
- LE-04 — «ок» подтверждает только последний прямо заданный вопрос;
- 14 технических шагов: Ш-0; AIN-01, 03–10, 12, 15, 19, 22;
- таблицы «Решения гейтов» и «Возвраты маршрута».

## Решение

1. **Оркестратор — первичный агент OpenCode `bcreq-orchestrator`.** У него
   два субагента:
   - `bcreq-step` — один шаг в отдельном контексте;
   - `bcreq-reviewer` — только чтение.

   Команды `.opencode/commands/a-*.md` выбирают оркестратор полем `agent`.
   Внешнего скриптового оркестратора нет.
2. **Автономно идут только 14 технических шагов.** Каждый шаг с проверкой
   БА — остановка с вопросом о конкретной редакции. Каждый гейт —
   остановка с вопросом решения, исходами и ролью. Тип шага меняет только
   процесс спицы.
3. **Подтверждение — только явный ответ на текущий вопрос.**
   - Решение пишется в журнал `work/<ключ>/decisions.jsonl` с полями
     таблицы «Решения гейтов».
   - Предпосылки гейтов проверяются по журналу, а не по тексту чата.
   - Вставка промпта, «дальше», ответ на другой вопрос и молчание
     решением не являются.
   - Неоднозначный ответ получает один уточняющий вопрос.
   - Общий вопрос «Продолжаем?» запрещён.
4. **Возврат.** Агент предлагает точку из таблицы возвратов с основанием,
   БА подтверждает. Зависимые результаты помечаются устаревшими, старые
   редакции не удаляются.
5. **MCP только на чтение.**
   - Серверы по умолчанию `disabled`.
   - Инструменты записи — `deny`, встроенный веб — `deny`.
   - Секреты — в окружении.
   - БЗ читается из файловой системы.
   - Недоступный источник даёт `ACCESS_GAP`, затем `BLOCKED`.
6. **Песочница.**
   - Состояние прогона — в `work/` под `.gitignore` или во внешнем
     каталоге.
   - Запись вне песочницы — `deny`.
   - Контракты, маршруты, навыки, `AGENTS.md` и конфигурация IDE меняются
     только через PR.
7. **Маршрут для оркестратора** — переданный SSOT этапа 1 (BL-185…BL-188)
   и карта гейтов, сгенерированная в спице. RG-BCREQ-v1 не расширяется.
8. **Производство** — этап Э5 «IDE-слой» задачи BL-192 после слияния PR
   runtime #29. Задачу описывает RFC-RT-003, раздел 11, issue создаёт
   владелец. Правки текстов промптов по 1143 идут в
   [#505](https://github.com/G-Ivan-A/mango_ba_prompts/issues/505).

## Что не менялось

- Runtime, тексты промптов, SHA реестра и сайт. Деплоя и модельных
  прогонов не было.
- Нормы этапа 1: Р-09, Р-19, LE-01…LE-13, состав технических шагов,
  гейты и их роли.
- RG-BCREQ-v1, защищённые пути runtime, зеркало навыков BL-192.
- Веб-канал этапа 1 (сайт) работает параллельно до решения владельца (M7).

## Последствия

- **БА.** Из диалога уходит транспорт. Остаются только решения на
  остановках P и G, их число не уменьшается.
- **Гейты.** Ложные допуски, выведенные из текста, становятся
  невозможными по построению: допуск есть только в журнале.
- **Runtime.** Появляются `.opencode/`, `opencode.json` и раздел
  `AGENTS.md`. Smoke нужно поправить. Откат — удаление `.opencode/` и
  `opencode.json`.
- **Зависимости.**
  - BL-132: версия OpenCode и диалект V1 или V2.
  - BL-185…BL-188: маршрут этапа 1 в runtime.
  - PR runtime #29.
- **Стоимость и эффект.** Тестовые прогоны в IDE (M6) требуют разрешения
  владельца на стоимость. Эффект — гипотеза до замеров.

## Альтернативы

| Вариант | Почему нет |
| --- | --- |
| Внешний скриптовый оркестратор (Python, n8n) поверх чата | ADR-016: «Python/скриптовый оркестратор в работе БА не нужен»; n8n — оркестратор этапа 3, а не этапа 2 ([ADR-017](2026-10-adr-017-four-stages-n8n-orchestration.md), `accepted`); второй мастер маршрута |
| Расширить RG-BCREQ-v1 шагами этапа 1 | второй мастер маршрута в runtime; противоречит манифесту #492 и ролям репозиториев |
| Один агент без субагентов (Р-RT-5) | сжатие контекста и несколько шагов в одном ответе (LE-01, LE-02); самопроверка в том же контексте (П-1143-43) |
| Гейт через `ask` в разрешениях | `ask` подтверждает вызов инструмента, а не бизнес-решение роли; нет записи решения |
| Автономия до гейтов, включая шаги Р-09 | ослабляет этап 1, запрещено постановкой #506 |
| MCP с правом записи в Jira и Confluence | MCP Tools: «human in the loop»; запись вне песочницы — только через PR или вручную |
| Править тексты промптов, чтобы убрать удалённые URL | #506 запрещает; вместо этого — слой сборки навыков (Р-RT-17) |
