# ADR-007: Стандарт базы знаний (KB) до настоящего RAG — формат цитирования, синхронизация с глоссарием, pre-RAG механизм

> **Статус:** Proposed · **Дата:** 2026-06-16 · **Issue:**
> <https://github.com/G-Ivan-A/mango_ba_prompts/issues/97> · **Стандарт-контракт:**
> <https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/standards/kb-standard.md>

> **Numbering note.** ADR-007 — трёхзначная дорожка стандартов. См.
> [ADR-002](002-pattern-standard.md).

## Контекст

В репозитории есть папка [`kb/`](../../kb/) — по её `.gitkeep` это место для
«практик, примеров и справочников, не являющихся стандартами». Сейчас она пуста.
Глоссарий [`standards/GLOSSARY.md`](../../standards/GLOSSARY.md) — `canonical`,
его source of truth — Хаб `hybrid-Intelligence-lab`, синхронизация только явным
действием спока на закреплённый `source_sha`.

Issue #97 (ФТ-5) требует **до внедрения настоящего RAG**:

1. задать **формат цитирования** источников;
2. описать **синхронизацию глоссарий ↔ KB**;
3. предложить механизм работы с **лучшими практиками до RAG**;
4. **жёстко обязательно**: предложить решение для best practices до настоящего
   RAG;
5. **доказательство** — LLM-эксперимент с проверкой цитирования и без неё.

Жёсткие ограничения issue, влияющие на решение: каждое предложение **обязательно
доказывать**, **обязательно приводить полные URL всех источников**, **не
использовать выдуманные источники**. Эти ограничения сами по себе суть
требований к цитированию — стандарт KB их операционализирует.

Проблема, которую решает дисциплина цитирования, — не гипотетическая. При
подготовке ADR-003/004/005 обнаружено, что **«ГОСТ 34.602-2015» не существует**
(есть редакции -89 и -2020), хотя такой шифр встречается в формулировке самой
issue. Без обязательной проверки источника правдоподобная, но ложная ссылка
проходит незамеченной. Это и есть целевой класс ошибок (см. эксперимент-
доказательство).

## Решение

Вводим контракт [kb-standard.md](../../standards/kb-standard.md) и наполняем
`kb/` минимальным реальным корпусом ([`kb/README.md`](../../kb/README.md) —
индекс-карта ручного поиска; [`kb/practices/source-backed-analysis.md`](../../kb/practices/source-backed-analysis.md)
— первая практика). Ключевые решения:

### 1. Формат цитирования (три типа ссылок + блок «Источники»)

Любое нормативное утверждение в артефакте/выводе промпта **ДОЛЖНО** нести
цитату. Три типа (все — Markdown-ссылки, согласовано с правилом 6
[prompt-standard.md](../../standards/prompt-standard.md)):

| Тип | Инлайн-форма | Назначение |
| --- | --- | --- |
| **KB** | `[KB: <slug>](kb/<path>#<anchor>)` | Внутренняя практика/пример из `kb/`. |
| **Стандарт** | `[<ID стандарта>](<полный-URL>)` | Внешний стандарт; URL **полный** (НФТ доказуемости). |
| **Глоссарий** | `[Глоссарий: <термин>](standards/GLOSSARY.md#<anchor>)` | Определение термина. |

Артефакт **ДОЛЖЕН** заканчиваться разделом `## Источники`, где каждая цитата
повторена с полным URL (внешние) или путём от корня репозитория (внутренние).
Этот **общий блок цитирования** — та самая сквозная способность, на которую
ссылается [ADR-006 §3](006-prompt-naming.md): он подключается к любому промпту,
не добавляя оси в имя.

### 2. Синхронизация глоссарий ↔ KB (направленная)

- Глоссарий — **источник истины для терминов**; KB **использует** термины, но
  **НЕ переопределяет** их.
- Термин, встретившийся в KB и отсутствующий в глоссарии, **ДОЛЖЕН** быть
  предложен в глоссарий через issue (правило «Как использовать» №2 глоссария);
  до принятия — помечается `⚠️ требует уточнения`.
- KB-запись, зеркалящая внешний/хабовый материал, **ДОЛЖНА** нести `source_sha`
  (как сам глоссарий) — это сохраняет воспроизводимость на закреплённом коммите.
- Направление потока: Хаб → `GLOSSARY.md` (термины) → KB (практики, ссылающиеся
  на термины) → промпты/артефакты (цитаты). Обратная запись в глоссарий — только
  через issue в Хаб.

### 3. Pre-RAG механизм (жёсткое требование)

«Ручной RAG» без векторного хранилища:

1. **Корпус.** Каждая KB-запись — отдельный файл с frontmatter (`id`, `status`,
   `sources`), пригодный как самостоятельный chunk.
2. **Карта поиска.** [`kb/README.md`](../../kb/README.md) — детерминированный
   индекс (таблица «тема → файл → когда применять»). Это замена retrieval-шага:
   агент/человек находит запись по индексу.
3. **Стабильные адреса.** Цитата = путь от корня + якорь (`kb/practices/x.md#h`).
   Адрес не зависит от эмбеддингов и не «плывёт».
4. **Принудительная дисциплина.** Чек-лист DoD и валидатор
   `scripts/validate_issue_97_ontology_standards.py` проверяют наличие блока
   «Источники» и полноту URL.

**RAG-готовность (НФТ масштабируемости).** Когда появится настоящий RAG, те же
пути/якоря становятся chunk-id, тот же формат цитаты эмитится ретривером —
переписывать артефакты не нужно. Подход согласуется с исходной идеей RAG
(Lewis et al., 2020): ответ снабжается ссылкой на извлечённый источник.

### 4. KB ≠ стандарт ≠ глоссарий (границы)

- **Стандарт** (`standards/*-standard.md`) — обязательное правило формата.
- **Глоссарий** — определения терминов (canonical, из Хаба).
- **KB** (`kb/`) — практики, примеры, справочники; **не** обязательны как
  правила, но **цитируемы**. KB не дублирует стандарты — ссылается на них.

## Доказательная база

- **Источниковая дисциплина BA.** BABOK Guide v3 требует прослеживаемости и
  опоры требований на проверяемые источники (Reference в Requirements Life Cycle
  Management): <https://www.iiba.org/career-resources/a-business-analysis-professionals-foundation-for-success/babok/>
- **Верифицируемость и трассируемость.** ISO/IEC/IEEE 29148:2018 (характеристики
  «verifiable», «traceable»): <https://www.iso.org/standard/72089.html> ·
  <https://standards.ieee.org/ieee/29148/6937/>
- **RAG как принцип «ответ + источник».** Lewis et al., 2020, “Retrieval-
  Augmented Generation for Knowledge-Intensive NLP Tasks”:
  <https://arxiv.org/abs/2005.11401>
- **Реальный анти-кейс.** ГОСТ 34.602-2020 (действует) —
  <https://docs.cntd.ru/document/1200181804>; ГОСТ 34.602-89 (исторический) —
  <https://standards.narod.ru/gosts/gost34/34-602-89.htm>. Редакции «-2015» не
  существует — это и проверяет эксперимент.
- **Эксперимент-доказательство (ФТ-5):**

## Примеры

**A. Инлайн-цитаты в выводе:**

> Структура ТЗ опирается на [ГОСТ 34.602-2020](https://docs.cntd.ru/document/1200181804)
> и практику [KB: source-backed-analysis](kb/practices/source-backed-analysis.md#правило).
> Термин см. [Глоссарий: Artifact](standards/GLOSSARY.md#термины).

**B. Блок «Источники» в конце артефакта:** перечисляет те же три ссылки с
полными URL.

**C. Анти-пример (ловится проверкой):** «согласно ГОСТ 34.602-2015 …» — источник
не находится в KB/реестре стандартов → утверждение помечается
`needs-clarification`, цитата отклоняется.

## Self-test

1. **Дано:** утверждение без `## Источники`. **Ожидаемо:** не проходит DoD.
   **Acceptance:** валидатор.
2. **Дано:** ссылка на «ГОСТ 34.602-2015». **Ожидаемо:** отклонена (нет реального
   источника). **Acceptance:** эксперимент, вариант B.
3. **Дано:** новый термин в KB, которого нет в глоссарии. **Ожидаемо:**
   `⚠️ требует уточнения` + issue в Хаб. **Acceptance:** §2.

Локально: `python3 scripts/validate_issue_97_ontology_standards.py`.

## Последствия

**Положительные:**

- Дисциплина цитирования снижает ложные/невыверенные ссылки (доказано
  экспериментом) — прямой вклад в НФТ доказуемости.
- Pre-RAG механизм работает уже сейчас, без инфраструктуры; формат цитат
  переносится в настоящий RAG без переделки (НФТ масштабируемости).
- Чёткие границы KB/стандарт/глоссарий снимают дублирование определений.

**Отрицательные / технический долг:**

- Ручной индекс `kb/README.md` нужно поддерживать при росте корпуса (до RAG).
- Дисциплина цитат повышает трение написания артефактов (компромисс ради
  доказуемости).

## Альтернативы (отклонены)

1. **Ждать настоящего RAG, не вводя формат сейчас.** Отклонено: нарушает жёсткое
   требование ФТ-5 «решение для best practices до RAG» и оставляет ошибки
   источников неотлавливаемыми.
2. **Определять термины прямо в KB.** Отклонено: конфликт с canonical-глоссарием
   из Хаба; нарушает единый source of truth.
3. **Свободный формат цитат.** Отклонено: непроверяемо валидатором, не
   RAG-готово.
