# ADR-015: отдельные классы ручных BCREQ-промптов

Контекст: #403 требует полноты четырёх фаз и различения задач по цели и I/O.
Прежняя архитектура фиксировала 14 упаковок и антиинфляцию, а контракт гейтов
не определял содержимое A-RELEASE. Это реальные границы старого решения.

Проектное решение: [RFC](../rfc/2026-10-bcreq-manual-pipeline.md) вводит 39
классов с отдельными стандартами, общий протокол FULL/SLICE и проект выпуска.
Класс не равен продукту, фазовой упаковке или числу кликов БА. Прямое
требование #403 приоритетнее прежнего ограничения числа промптов для этой
новой архитектуры. Новых фаз и автоматического оркестратора нет.

Альтернативы: универсальный промпт отвергнут из-за смешения задач; разделение
по каждому продукту отвергнуто при одинаковой цели и I/O; переписывание
действующих промптов сейчас преждевременно, задача — сначала стандарты.

Последствия: больше подробных контрактов и явная стоимость ручного переноса,
зато различимы генерация, извлечение, критика, полномочия и выпуск. Новый RUN
проверяет практическую применимость; не измеряет статистически улучшение
модели. Существующие промпты, восемь мета-стандартов, runtime и human gates
сохраняются. Утверждение и миграция промптов не подразумеваются авто-приёмкой
работы над этим проектом. Вопросы release-политики и орг-ролей указаны явно.
