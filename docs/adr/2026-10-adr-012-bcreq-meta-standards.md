# ADR-012: Мета-стандарты разделов BCREQ, правила композиции и архитектура промптов

> **Статус:** Proposed · **Дата:** 2026-10-23 · **Issue:**
> <https://github.com/G-Ivan-A/mango_ba_prompts/issues/387>

> **Numbering note.** ADR-012 — трёхзначная дорожка стандартов (ADR-001…011).
> См. [ADR-002](002-pattern-standard.md).

## Контекст

Задача 2 программы пересборки промптов BCREQ. Задача 1 (issue #384) дала аудит
каталога `prompts/`:
[2026-10-23-prompts-catalog-audit.md](../analysis/2026-10-23-prompts-catalog-audit.md).
Его вывод: активные промпты реализуют старую модель «ТЗ» и антипаттерны АП1–АП9.
Структура 2.1–2.14 — информационная; 12 наблюдений для Задачи 2 — в §3.7.3
аудита, вектор Задачи 2 — в §3.8.

В чатах 21–23.10.2026 БА согласовал восемь разделов BCREQ, стили разделов,
стадии A-IN / A-CORE / A-WORK и кто решает на выходе каждой стадии. Дословные
цитаты — в реестре
[chat-2026-10-22-23-register.md](../../experiments/issue_387/chat-2026-10-22-23-register.md)
(55 строк, проверены скриптом, результат — `chat-quote-check.json`).

Чего не было в репозитории:

1. Стандарта содержания раздела: что в разделе необходимо и достаточно, как
   проверить и когда остановиться. [bcreq-process-standard](../../standards/bcreq-process-standard.md)
   задаёт процесс П1–П6 и гейты G1–G3, но не содержание разделов.
2. Правил для доработки сразу в 2+ продуктах: где применяется доменный
   стандарт, как раздел 3 остаётся одним списком ФТ.
3. Связи стадий БА с гейтами и шагами промптов.
4. Архитектуры промптов: Промпт 0, общий шаблон шага, семантика stepwise и
   oneshot.

## Решение

Принять четыре нормативных артефакта и два сопровождающих.

README — стили (определение короткого стиля КС1–КС7), общие правила Р1–Р7, общие CB-0.x. Раздел 1 — восстановленные словари D1–D11 и механизм сверки С0–С4. Ключевые решения:

1. **Восемь разделов не меняются.** Дополнения ＋2.5, ＋8.4, ＋8.5 оформлены
   RFC-387-05 и откатываются без изменения разделов 1–8.
2. **Один стандарт раздела + доменные профили как данные.** Отдельных
   промптов под продукт нет (композиция §6). Доменный стандарт применяется к
   подпункту 5.2.x, а не ко всему разделу (К1–К3).
3. **TM Forum ODA сохранён** альтернативой с явными условиями ODA-1…ODA-3; он
   заменяет C4 L2 и собственную дельту OpenAPI в L2 раздела 5, структура L1
   остаётся прежней.
4. **Все гейты — человеческие.** Модель выдаёт отчёт по критериям; гейт
   проходит роль из контракта (правило B3).
5. **Промпт 0 + 14 файлов.** Шаги 2.1–2.14 сохранены как шаги `Ш-`; файлы
   объединены по М1–М4. Добавлен один шаг Ш-В (валидация второй ролью).
   Отклонение от предложения БА — около 7 %, в пределах правила 20 %.

## Последствия

- Задача 3 (сборка промптов) получает проверяемую спецификацию: каждый промпт
  шага ссылается на мета-стандарт своего раздела и повторяет конституцию.
- Валидатор `scripts/validate_issue_387_bcreq_meta_standards.py` проверяет
  состав разделов стандартов, размер чек-листов, словари, гейты, примеры
  композиции, RFC и ссылки на реестр цитат.
- Цифровые пороги (бюджеты слов КС7, 3–7 пунктов чек-листа) — расчётные
  допущения. Их калибруют прогоны Задачи 3; изменение порога — правка
  мета-стандарта с записью в CHANGELOG.
- Существующие промпты не меняются в этом решении. Их статусы определены
  аудитом Задачи 1.

## Рассмотренные альтернативы

| Альтернатива | Почему не выбрана |
| --- | --- |
| Один документ на все 8 разделов | Шаг промпта читает только стандарт своего раздела; один файл даёт лишний контекст (Liu et al. 2023, эффект середины длинного контекста). |
| Отдельный стандарт и промпт под каждый продукт | Антипаттерн «один стандарт на продукт» с обратным знаком: 6 профилей × 8 разделов. Нарушает анти-инфляцию issue #387. Разбор — в [третьем мнении](../analysis/2026-10-23-bcreq-standards-third-opinion.md#3-findings). |
| TM Forum ODA основным стандартом раздела 5 | Mango — не оператор связи в большинстве задач; SID/eTOM закрыты для не-членов. Issue #387 требует ODA альтернативой. |
| Стандарты разделов в `docs/contracts/` | Мета-стандарт — норма формы артефакта, как `prompt-standard`; место — `standards/`. Контракт — только стадии и гейты, где есть роли и обязательства. |
