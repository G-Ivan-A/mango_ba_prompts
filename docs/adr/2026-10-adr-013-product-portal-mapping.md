# ADR-013: четырёхуровневый каталог и отдельная карта документации

Контракт классификации: https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/standards/product-classification-contract.md

## Контекст

Runtime содержит три класса поиска, а исторический Product Layer — семь Domain,
42 Capability, 132 Feature и 98 Atomic Function. Портал группирует статьи по
приложению, версии интерфейса, аудитории и коннектору. Считать глубину URL
глубиной классификации нельзя: один документ описывает несколько операций,
одна операция встречается в нескольких приложениях и руководствах.

Источники:

- https://github.com/G-Ivan-A/mango-ba-ai-runtime/blob/b67410f627801345309281faa15e7219722bfb1a/taxonomy/products.yaml
- https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/cd5d6e4b72700e43ccca6c96119308ab5a6d7379/research/mango/2026-05-22-classification.md
- https://www.mango-office.ru/support/1_nachat-zdes/

## Решение

Сохраняем ровно Domain → Capability → Feature → Atomic Function. Каталог —
ориентированный граф с родителями только предыдущего уровня. Исторический
cross-domain блок связывается с существующими доменами; platform не становится
восьмым Domain. Коммерческие атрибуты остаются полями, версии приложений и
портальные разделы — измерениями карты. Исходные идентификаторы сохраняются
в `legacy_id`; сегменты `/feature/` и `/function/` в составном ID различают
одноимённые ключи и не вводят уровни.

Отдельная JSONL-карта связывает URL со множеством кандидатов Capability и
проверенными локаторами Feature/Atomic Function. Совпадение названия или URL
является кандидатом поиска. Для атомарной операции нужны источник и точный
заголовок; документирование операции ещё не подтверждает все её условия или
коммерческую доступность. Карта хранит HTTP, дату/хэш, читаемость, визуальные
зависимости, коннектор, приоритет ФТ/НФТ/интеграций и наблюдаемые связи продуктов.

Метаданные используются для короткого адресного плана чтения. При запросе
статусов/WFM/API отдельные места в плане сохраняются для КЦ, web-КЦ, ЛК,
прав и нужного коннектора. БА выбирает смежные классы перед их чтением согласно
действующему контракту; план не добавляет требований и не утверждает поведение.
Визуальная зависимость ведёт к адресному runtime fallback с проверкой наличия
описания изображения. Недоказанный As-Is остаётся вопросом продуктовой команде.

## Последствия и проверка

Полный каталог и аудит крупнее маленького runtime-словаря, поэтому в рабочий
контекст передаётся выбранная ветвь и несколько локаторов. JSONL позволяет
читать строки без загрузки всего корпуса. Частота обновления остаётся unknown
до нескольких наблюдений. Тесты проверяют сохранность исторического состава,
ровно четыре уровня, источники добавлений, покрытие снимка и предотвращение
подмены коннектора. Они не измеряют качество генерации LLM.

Creative-расширение ограничено каталогом, воспроизводимым HTML-аудитом и
регрессиями. Действующие промпты, runtime-словарь, сайт и настройки Actions
не меняются. Новый каталог подготовлен к review в рамках этой issue.
