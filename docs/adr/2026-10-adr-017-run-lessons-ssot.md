# ADR-017: реестр уроков прогонов — единый источник правил «как делать и как не делать»

## Контекст

Каждый прогон промптов фиксирует ошибки модели и замечания БА в `runs/`.
Эти данные не превращались в правила промптов. При каждой смене структуры
промптов правила, выведенные из прогонов, терялись. При переходе от 14
промптов этапа 1 к 39 классам ручного конвейера 17 уроков стали общими
формулировками или исчезли. Ни один класс не ссылается на уроки прогонов.

Опыт хранился в четырёх местах, и ни одно из них не было источником для
промптов:

- реестры инцидентов и статистика ошибок отдельных прогонов (у каждого
  прогона свой словарь кодов, номера кодов не совпадают);
- свободный текст отзывов БА;
- правила АД-1…АД-11 внутри одного промпта (конституции);
- кандидаты golden set в статусе `draft`.

Контракт прогона не содержит ни версии использованного промпта, ни
адресата урока, ни статуса его закрытия. Замкнутого цикла «урок → правило
промпта → проверка повторным прогоном» не было ни разу. Полный разбор
приведён в [аналитическом отчёте](../analysis/2026-10-31-bcreq-pipeline-run-experience-review.md).

## Решение

1. **SSOT уроков — `standards/bcreq-lessons/lessons.json`.** Урок — это
   правило, вопрос для проверки ответа, пара «Не так / Так», адресат
   (промпты этапа 1) и ссылка на эталонный кейс golden set. Каждый код
   ошибки из статистики прогонов сопоставлен ровно одному уроку.
2. **Нормы остаются в нормативных документах.** Конституция BCREQ (Р, АД,
   АП, КС, БС, CB) по-прежнему определяет правила. Урок ссылается на них
   якорями и не вводит конкурирующих норм. Урок, которому нет нормы,
   получает статус `proposed` и ждёт решения владельца.
3. **Промпты не правятся вручную в части уроков.** Блоки «Уроки прогонов»
   в 14 промптах и блоки уроков в 39 классах генерирует
   `scripts/build_bcreq_lessons.py`. Ручная правка блока обнаруживается
   проверкой `build --check`.

   > **Пометка #420, риск 11.** «14 промптов» — снимок сайта и каталога
   > `prompts/` на 31.10.2026, а не целевой состав. После PR #404 ручной
   > конвейер BCREQ описан 39 классами (38 исходных и C39), и в изменённый
   > проект переносятся они, а не 14 промптов. Классы улучшаются вместе с
   > процессами, которые их запускают. Решения, опирающиеся на число 14,
   > читаются с этой поправкой; пересмотр — задача BL-134 бэклога
   > ([комментарий владельца к PR #422](https://github.com/G-Ivan-A/mango_ba_prompts/pull/422#issuecomment-6560476938)).

4. **Правило «розовых слонов» действует для текста, а не для связи.**
   В правилах, примерах, промптах, golden set и выводах нет номеров задач,
   чатов и прогонов. Связь «код прогона → урок» хранится только в реестре
   свидетельств (`lessons.json`, README реестра, исследования). Так сразу
   выполняются два требования: модель не видит исторических кейсов, а
   прослеживаемость урока не теряется.
5. **Golden set и рубрика — контракт регрессии.** На каждый активный
   урок — один дефектный кейс, плюс негативные кейсы на ложные
   срабатывания. Входы кейсов синтетические и не копируют примеры из
   промптов. Рубрика бинарная, K1–K6. Ядро — самые частые уроки, урок
   удержания правил сессии и два негативных кейса. Порог приёмки назначает
   владелец.
6. **Проверка.** `scripts/validate_issue_411_lessons_pipeline.py` входит в
   `make validate-full`. Он проверяет схему реестра, свежесть
   сгенерированных блоков, отсутствие несопоставленных кодов, golden set,
   рубрику и отсутствие уроков на сайте.
7. **Применение — после принятия.** Блоки уроков в промпты и классы
   вносятся отдельной задачей (`--apply-prompts`) после принятия ADR/RFC.
   Сайт уроки не показывает: он — интерфейс БА и статистика применения,
   не отладчик (решение владельца, комментарий к PR #412).

## Рассмотренные варианты

| Вариант | Почему отвергнут |
| --- | --- |
| Править тексты 14 промптов и 39 классов вручную | Так уже было: уроки терялись при каждой смене структуры, и никто не мог проверить полноту переноса |
| SSOT — классы ручного конвейера | Классы на 95% состоят из общего шаблона и не исполняются без ручной сборки контекста. Этап 1 работает на 14 промптах сайта |
| SSOT — реестры инцидентов в `runs/` | Прогоны неизменяемы, а их словари несовместимы. Свести их можно только во внешнем реестре |
| Вынести уроки в отдельный файл, на который промпт ссылается | В ручном чате БА вставляет один промпт. Ссылка на файл не доставляет правило модели |
| Вставлять в промпт сами истории ошибок с номерами | Нарушает правило «розовых слонов» и прайминг-риск. Конкретика уходит в golden set, а в промпт — нейтральная пара «Не так / Так» |

## Следствия

- Каждый промпт этапа 1 вырос на 29–44 КБ, всего до 46–78 КБ. Владелец
  назвал качество приоритетом по сравнению с экономией токенов. Блок
  разделён на общие и специальные уроки шага, поэтому его можно сжать без
  потери связи с реестром (см. RFC).
- Новый прогон со статистикой ошибок нельзя добавить, не сопоставив его коды
  урокам. Валидатор останавливает сборку.
- Изменение урока — это изменение реестра, golden set и (при необходимости)
  рубрики в одном PR. Затем идёт повторный прогон по рубрике.
- Классы ручного конвейера получают те же уроки из того же источника. Их
  переработка в самостоятельные промпты — задача этапов 2–3 и в этот ADR не
  входит.
- Эталонный набор — синтетический. Он измеряет, удерживает ли промпт
  правило, а не качество реального документа. Реальные кейсы с
  согласованием БА пополняют набор через RFC.
