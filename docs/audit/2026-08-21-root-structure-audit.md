# Аудит структурного дрейфа корня и исправление свалки файлов

Operating Mode: `Creative` · Task Type: `Audit` · Issue:
[#291](https://github.com/G-Ivan-A/mango_ba_prompts/issues/291)

Аудит отвечает на вопрос issue #291: **почему ИИ-исполнитель оставил файлы в
корне и почему онбординг не поймал это раньше** — и фиксирует, что именно
перенесено, что заархивировано и что сознательно оставлено на месте.

---

## 0. Главная находка: часть исходной посылки не подтвердилась

Issue #291 исходит из того, что наличие `AI_GOVERNANCE.md`, `AI_QUICK_RULES.md`
и `AI_SESSION_HANDOVER_PROMPT.md` в корне — нарушение стандартов Хаба, а
объяснение «это точки входа» — недопустимая рационализация.

Проверка по SSOT, названным в самой задаче, даёт обратный результат: **эти три
файла обязаны лежать именно в корне**, и это жёсткое ограничение Хаба.

`.hub-profile.json` спицы объявляет `"target_type": "HTOM"`, то есть геном
проекта — [`templates/htom/`](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/tree/main/templates/htom).
Валидатор генома
[`templates/htom/tools/validate-repository-structure.sh`](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/templates/htom/tools/validate-repository-structure.sh)
требует их наличия в корне и отдельно повторяет требование комментарием:

```bash
required_files=(
  "AI_GOVERNANCE.md"
  "AI_QUICK_RULES.md"
  "AI_SESSION_HANDOVER_PROMPT.md"
  ...
)

# AI_GOVERNANCE.md обязателен в корне каждой HTOM-команды (жёсткое ограничение Хаба).
require_file "AI_GOVERNANCE.md"
```

То же зафиксировано в самом артефакте спицы,
[`AI_GOVERNANCE.md`](../../AI_GOVERNANCE.md): «Этот файл — **ядро генома**
HTOM-команды: обязателен в корне (жёсткое ограничение)».

`standards/project-structure-inheritance.md`, названный в SSOT задачи, к этому
вопросу не применяется: он описывает подкаталоги `projects/{project}/` **внутри
Хаба**, а не корень отдельного репозитория-спицы.

**Вывод.** Перенос этих трёх файлов из корня, буквально требуемый контрактом 4
issue #291, сломал бы соответствие геному Хаба — тому самому SSOT, ради которого
задача заведена. Поэтому они оставлены в корне, а контракт 4 исполнен для
файлов, которые действительно оказались в корне вне генома (§3).

При этом вторая половина посылки задачи **подтвердилась полностью**: беспорядок
реален, просто он был не там, где искали. Это `AI_SESSION_HANDOVER_PROMPT.executable.md`
в корне и `superseded`-архив, лежавший вплотную к активному протоколу в
`ai-rules/`. Ответ «это точки входа» был дефектен не тем, что ложен, а тем, что
**одним аргументом накрывал два разных класса файлов**: обязательные по геному и
выросшие локально. Ниже — как этот дефект возник.

## 1. Пошаговая реконструкция: как корень дрейфовал

Каждый шаг — реальный коммит/PR репозитория.

### Шаг 1 — bootstrap (`0c10eda6`): корень собран корректно

Репозиторий инициализирован из генома HTOM. В корне — ровно канонический набор:
`AI_GOVERNANCE.md`, `AI_QUICK_RULES.md`, `AI_SESSION_HANDOVER_PROMPT.md`,
`README.md`, `CONTRIBUTING.md`, `CHANGELOG.md`. Нарушения нет.

**Важно для дальнейшего:** вместе со структурой геном **не был перенесён его
валидатор** `tools/validate-repository-structure.sh`. Спица получила скелет, но
не получила иммунную систему. Это первопричина; всё остальное — следствия.

### Шаг 2 — issue #125 (`c4163a15`): в корне появляется файл вне генома

Каскадная загрузка контекста ([`standards/cascading-context-loading-standard.md`](../../standards/cascading-context-loading-standard.md))
вводит правило: у тяжёлого документа есть лёгкий executable-слой, и агент читает
**соседний** `.executable.md`. Слово «соседний» механически означает «в том же
каталоге». Для корневого `AI_SESSION_HANDOVER_PROMPT.md` это дало
`AI_SESSION_HANDOVER_PROMPT.executable.md` — в корне.

**Причина сбоя:** локальный стандарт спицы сгенерировал корневой файл, которого
нет в геноме Хаба. Конфликт «локальное правило ↔ закрытость корня» никем не
разрешался, потому что правила «корень закрыт» не существовало. Файл появился не
по решению, а как побочный эффект другого решения.

### Шаг 3 — issue #265 / PR #266 (`2f56205e`): архив садится рядом с активным

Реструктуризация `governance/` → базовая структура Хаба. Карта переноса в
[`experiments/restructure_governance_dirs.py`](../../experiments/restructure_governance_dirs.py)
кладёт локальную адаптацию протокола в тот же каталог, что и будущую актуальную
версию:

```python
"governance/agent-onboarding-protocol.md": "ai-rules/agent-onboarding-protocol_old.md",
```

**Причина сбоя:** карта оптимизировала один критерий — «каталог-дом как в Хабе».
Критерий «архив не соседствует с активным артефактом» в неё не входил, потому
что нигде не был записан. Суффикс `_old` был принят за достаточную маркировку
статуса; на деле в листинге каталога он не отличим от рабочего файла.

### Шаг 4 — issue #267 / PR #285: корень проверен, но по другому измерению

PR #285 прямо проверял корневые файлы — и нашёл там реальные дефекты
(запрещённое поле `ai-generated`, отсутствующее `temperature`). Область проверки
была **frontmatter**, то есть содержимое файлов. Вопрос «какие файлы вообще
имеют право лежать в корне» в область не входил.

Архив `_old` в том же PR был помечен `status: superseded`, лишён `entrypoint` и
снабжён баннером «АРХИВ» — то есть проблема была **увидена и решена на уровне
метаданных**, но не на уровне размещения.

**Причина сбоя, и это ключевой момент:** новый регрессионный тест
[`scripts/validate_issue_267_onboarding_v15.py`](../../scripts/validate_issue_267_onboarding_v15.py)
захардкодил тогдашние пути (`ai-rules/agent-onboarding-protocol_old.md`,
`AI_SESSION_HANDOVER_PROMPT.executable.md`) как ожидаемое состояние. Дрейф
перестал быть дрейфом и стал **проверяемым контрактом**: с этого момента
исправление структуры автоматически ломало CI. Так временное состояние
зацементировалось.

### Шаг 5 — рационализация «это точки входа»

Когда вопрос о корне был задан прямо, у агента был под рукой аргумент, который
**верен для трёх файлов из четырёх**: геном действительно требует
`AI_GOVERNANCE.md`, `AI_QUICK_RULES.md`, `AI_SESSION_HANDOVER_PROMPT.md` в
корне. Агент применил его ко всему корню целиком, не разделив набор на
«обязательное по геному» и «выросшее локально», и не проверив геном как SSOT.

**Причина сбоя:** ответ строился как оправдание существующего состояния, а не как
проверка состояния против источника истины. Валидный аргумент был растянут за
границы своей области применимости — классическая over-generalization, а не
выдумка.

## 2. Причины по классам: почему онбординг не поймал это

| # | Причина | Класс | Как проявилась | Чем закрыта |
| --- | --- | --- | --- | --- |
| 1 | Геном перенесён без иммунной системы: `validate-repository-structure.sh` не был скопирован при bootstrap. | Инструментальная | Ни один прогон CI не мог заметить лишний файл в корне. | Добавлен [`tools/validate-repository-structure.sh`](../../tools/validate-repository-structure.sh) в `make validate` и CI. |
| 2 | Валидатор генома проверяет **наличие** обязательных файлов, но не **закрытость** корня. Даже перенесённый один-в-один, он бы этот дрейф пропустил. | Дефект контракта (в т.ч. Хаба) | `AI_SESSION_HANDOVER_PROMPT.executable.md` прошёл бы проверку генома. | Локальная дельта: корень закрыт allowlist'ом. Возврат дельты в Хаб — [`pr-ops/BACKLOG.md`](../../pr-ops/BACKLOG.md). |
| 3 | Правило «архив не соседствует с активным» нигде не было записано. | Пробел в норме | `_old` рядом с v1.5 в `ai-rules/`. | [`.archive/README.md`](../../.archive/README.md) + проверка `*_old*.md` вне `.archive/` в валидаторе. |
| 4 | Регрессионные тесты фиксировали пути «как есть» и превращали дрейф в контракт. | Методологическая | Валидатор #267 требовал `_old` именно в `ai-rules/`. | Пути валидаторов обновлены миграционным скриптом; в аудите зафиксировано, что тест фиксирует *инвариант* (архив помечен и не является точкой входа), а не *адрес*. |
| 5 | Аудит корня в #267 был ограничен frontmatter; измерение «состав корня» не проверялось ни в одной задаче. | Скоуп ревью | Файл был у всех на виду четыре PR подряд. | Измерение добавлено в CI, а не в чек-лист человека. |
| 6 | Онбординг агента (`ai-rules/agent-onboarding-protocol.md`) велит прочитать README и governance, но **не велит сверить фактическое дерево с геномом Хаба**. | Пробел в протоколе | Агент читал документы о структуре вместо проверки структуры. | `make validate` теперь делает эту сверку машинно на каждый PR — надёжнее, чем шаг чек-листа. |
| 7 | Локальный стандарт (`cascading-context-loading-standard.md`) порождал корневые файлы как побочный эффект, без разрешения конфликта с геномом. | Коллизия стандартов | `.executable.md` в корне. | Executable-слой перенесён в `prompts/`; §3 фиксирует, что «соседний» читается как «связанный ссылкой», а не «в том же каталоге». |

**Сквозной вывод.** Ни один шаг не был злонамеренным или единичной галлюцинацией.
Дрейф — результат того, что **каждая задача проверяла своё измерение и ни одна не
проверяла состав корня**, а отсутствующая проверка не оставляет следов: нет
падающего теста — нет сигнала. Дефект инфраструктурный, а не дисциплинарный,
поэтому и закрывается инфраструктурой (валидатор в CI), а не обещанием быть
внимательнее.

## 4. Что сделано против рецидива

| Мера | Где | Что ловит |
| --- | --- | --- |
| Замок на корень | `tools/validate-repository-structure.sh`, проверка 2 | Любой новый `*.md` в корне вне канонического списка. |
| Обязательный минимум генома | там же, проверка 1 | Пропажу `AI_GOVERNANCE.md` и других файлов ДНК HTOM. |
| Замок на архив | там же, проверка 3 | `*_old*.md` где угодно, кроме `.archive/`. |
| Защита неприкосновенных домов | там же, проверка 4 | Исчезновение `runs/` или `kb/`. |
| Итог миграции как контракт | [`scripts/validate_issue_291_root_structure.py`](../../scripts/validate_issue_291_root_structure.py) | Откат любого решения этого аудита: возврат файла в корень, потерю баннера или ссылки в архиве, разрыв связи слоёв handover, отключение замка от CI, выхолащивание отчёта. |
| Прогон на каждый PR | `make validate-structure`, `.github/workflows/validate.yml` | Дрейф в момент внесения, а не через четыре PR. |
| Воспроизводимость миграции | [`experiments/restructure_root_and_archive.py`](../../experiments/restructure_root_and_archive.py) | Ручное копирование ссылок — источник дефектов из issue #265. |

Проверка работоспособности замка (negative test):

```bash
touch AI_NOTES.md && ./tools/validate-repository-structure.sh   # ERROR: root markdown file is not in the canonical HTOM root set
touch ai-rules/foo_old.md && ./tools/validate-repository-structure.sh  # ERROR: superseded artifact outside .archive/
```

## 5. Целостность `runs/` и `kb/` (контракт 2)

Проверяется командой:

```bash
git diff --stat main -- runs/ kb/   # пусто
```

Дополнительно: миграционный скрипт исключает эти каталоги из обхода на уровне
кода, а валидатор структуры падает, если каталог-дом исчез.
