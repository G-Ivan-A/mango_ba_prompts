# Аудит зависимостей от runtime и передача SSOT этапа 1

## Summary / BLUF

**Вывод.** Защищённые пути runtime теперь перечислены. Из 447 путей
защищены 445: их читает сайт, сборка или валидатор. 14 из них читает и
модель через текст промпта: это двойные потребители, и менять их можно
только согласованной миграцией. Свободны 2 пути. В текстах промптов 543
ссылки на спицу. Из них 225 — governance-ссылки (а), они допустимы. 318
нормативны для модели (б). 25 целей класса (б) не читаются внешним чатом. Для одной цели — реестра
справочников — замена есть уже сейчас: сами справочники лежат в runtime. Остальных
24 в runtime нет: они входят в манифест передачи и закрыты карточками
BL-185…BL-188. Единственная действующая заглушка реестра, З-2, — карточка
BL-189. Правка ссылок в промптах — отдельная BL-190.

Runtime, тексты промптов, сайт и прогоны в этой задаче не менялись.
Модельных прогонов не было. Рекомендация — принять PR #493 и передать
манифест в RFC-задачу runtime (раздел 8).

## Scope / Target

**Объект.** Все ссылки репозитория `mango_ba_prompts` на репозиторий
`mango-ba-ai-runtime` (ФТ-1), ссылки текстов промптов `prompts/` на спицу
`mango_ba_prompts` (ФТ-2), состав SSOT этапа 1 для передачи (ФТ-3) и
пробелы, которые из этого следуют (ФТ-4).

**Вне объёма.** Репозиторий runtime не меняется. Тексты промптов не
редактируются. Деплоя и модельных прогонов нет. Клиентские данные и
вложения в манифест не входят: только пути, версии и хэши.

анализы и эксперименты: они фиксируют срез на свою дату и приведены

  runtime, а видимость спицы может измениться.

Просмотрены 90 файлов `prompts/**/*.md` (кроме README), ссылки на спицу

| Правило | Класс | Признак | Вхождений |
| --- | --- | --- | --- |
| А-0 | (а) | frontmatter промпта | 2 |

| А-3 | (а) | служебный промпт сопровождения | 7 |
| А-4 | (а) | абзац происхождения (provenance) | 132 |
| А-5 | (а) | governance-документы спицы | 1 |
| А-6 | (а) | ссылка на промпт комплекта без якоря (навигация) | 37 |
| Б-1 | (б) | конституция Ш-0 | 85 |
| Б-2 | (б) | RFC-AIN-001 | 24 |
| Б-3 | (б) | промпт комплекта с якорем нормы | 6 |
| Б-4 | (б) | реестр справочников runtime | 43 |
| Б-5 | (б) | стандарты `standards/` | 104 |
| Б-6 | (б) | контракты `docs/contracts/` | 15 |
| Б-7 | (б) | процессы `docs/ba-processes/` | 41 |

Решение по каждой цели (б) — раздел 3 [`prompt-links.md`](../../experiments/issue_492/prompt-links.md#3-цели-класса-б-решение),
по каждому вхождению — раздел 7. Цель (б) сверяется с runtime побайтно
(blob git) на main и на SHA реестра.

- Есть в runtime: `standards/bcreq-runtime-references.md` — сам реестр не
  перенесён, но его нормативная функция для модели — указать справочники
  И-1…И-8, а они есть в runtime на SHA реестра. Кандидат на замену — BL-190.
- Нет в runtime: 24 цели. Частичные аналоги в runtime не заменяют норму:
  для контракта гейтов есть только чек-лист G-human, для мета-стандартов
  разделов — только шаблон документа, для контракта классификации —
  только значения таксономии.
- Граничный случай (а): ссылка ведёт на спицу, но цель — governance
  (issue, PR, provenance, комментарий исполнителю). Она не переносится,
  основание — номер правила в строке вхождения.

## 4. ФТ-3: манифест передачи SSOT

[Манифест](../contracts/ssot-stage1-handoff-manifest.md) собран с
коммита `7dea8f716d69e55c183865630d10f40cdb6e46b1` (слияние PR #491) и
содержит 133 артефакта в 15 группах: всё, что issue перечисляет в составе,
и ещё нормы исполнения из ФТ-2 (композиция, архитектура промптов,
классификация продукта, гейты, поток CS). Для каждого артефакта указаны
путь, версия и её источник, sha256 байтов, blob git, коммит-источник,
последний коммит изменения, статус цепочки и карточка переноса. Маршрут
A-IN — 24 контракта: версия маршрута, версия и sha256 промпта, sha256
инструкции.

Цепочка эволюции: 14 промптов v0.1 → черновики Ш-ХХ «по тесту» →
комплект 2.7.0 (архив) → AIN v0.3 по умолчанию и системный формат по
выбору БА. Статусы: действует — 121, заменён — 6 (Ш-1, Ш-2 и A-IN
one-shot v0.1, черновики Ш-А, Ш-1, Ш-2 — по манифесту архива), архив — 6.

Политика синхронизации повторяет hub-sync этой спицы (ADR-0004,
`scripts/sync_from_hub.py`) и копию БЗ в runtime
(`compilation-manifest.yaml`, `hub_access_required_at_runtime: false`):
копия закреплена на коммит, локальные правки копии запрещены, обновление
— только новой закреплённой передачей с новыми sha256.

Клиентских данных и вложений в манифесте нет: только пути, версии и
хэши. Пути `runs/`, `kb/`, `inputs/`, `attachments/` запрещены сборщиком
и валидатором.

## 5. ФТ-4: карточки пробелов

Карточка заводится на единицу переноса, а не на файл: 24 цели (б) и 133
артефакта манифеста дают четыре карточки переноса. Файл без карточки
валидатор не пропускает.

| Карточка | Что | Целевой репозиторий | Артефактов |

| BL-185 | Конституция Ш-0, промпты v0.1, черновики, системный формат, архив 2.7.0 | `mango-ba-ai-runtime` | 38 |
| BL-186 | Маршрут A-IN, 24 контракта, итог шага, нормализация доказательств | `mango-ba-ai-runtime` | 31 |

| BL-188 | Контракт гейтов и заглушка потока CS | `mango-ba-ai-runtime` | 2 |
| BL-189 | Справочник И-4 (РТ-2), снимает заглушку З-2 | `mango-ba-ai-runtime` | новый |

## 8. Рекомендация (Remediation / Deviation)

1. Принять PR #493: у манифеста, классификации и аудита есть скрипты и
   проверка, тексты промптов и runtime не менялись.
2. Владелец создаёт в `mango-ba-ai-runtime` RFC-задачу на универсальный
   агентный контекст и добавляет cross-repo ссылку в PR #493. Вход RFC —
   манифест; перенос — группами BL-185…BL-188 побайтно с проверкой sha256.
   Начинать с BL-186 и BL-188: без маршрута A-IN и гейтов этап 2 не
   исполнит формат шагов по умолчанию.
3. Задачу РТ-2 (BL-189) можно создать в runtime сразу, она не ждёт
   манифеста.
4. BL-190 — после слияния переносов; ссылки на реестр справочников можно
   заменить раньше, их цели в runtime уже есть.
5. Если до передачи меняется SSOT этапа 1, манифест пересобирается
   `SOURCE_COMMIT=<коммит> python3 experiments/issue_492/build_ssot_manifest.py`.
   Правка вручную запрещена.

## 9. Ограничения

- Классификация по правилам статическая. Правило А-4 (абзац
  происхождения) опирается на ключевые слова абзаца, а правило А-6 считает
  ссылку на промпт без якоря навигацией. Обе эвристики проверены
  по вхождениям раздела 7 `prompt-links.md`, но не на модели.
- Наличие в runtime проверено побайтно. Переименованная или
  отредактированная копия будет считаться отсутствующей. На main
  `90f08233` таких копий нет: манифест показывает 0 артефактов в runtime.
- Хэши манифеста относятся к коммиту `7dea8f71`. Более поздние правки
  SSOT не роняют валидатор: `ISSUE_492_VERBOSE=1 python3
  scripts/validate_issue_492_ssot_handoff.py` печатает их списком
  «дрейф от source_commit». Это сигнал пересобрать манифест перед
  передачей.
