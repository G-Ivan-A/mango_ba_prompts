# Альтернативная веб-БЗ: доступность, полнота КЦ и выбор источников

По снимку 29 октября 2026 г. альтернативный сайт доступен для извлечения
статического HTML: **3533 страницы, 3533 HTTP 200**, очередь обхода исчерпана.
Это не доказывает полноту контекста BCREQ. Лексическое расхождение с приложенным
руководством КЦ составляет **25,31% для docs и 25,09% для портала #399**.
Оба результата превышают заданные 5%; решение — **комбинированное обращение
к вебу, версионному PDF и проверенному runtime-контексту**.

Процент характеризует текстовое выравнивание, включая порядок таблиц,
структурные перестановки и добавления. Это не процент отсутствующих функций
и не измерение правильности ответов LLM. Даже при исключении двух приложений
с матрицами прав остаются 22,01% и 21,76% соответственно. Самодостаточность
веба не подтверждена и для эталонного КЦ; распространять этот вывод как
измеренную полноту остальных продуктов нельзя.

Запрет скачивания применяется к аудируемым сайтам Mango: PDF, картинки,
архивы, установщики и иные вложения не загружались. Проверяются URL, MIME,
редиректы и HTML-метаданные до чтения тела; запрещённый редирект не следует
дальше. Явно приложенный к issue PDF — необходимый локальный вход сравнения,
а не разрешение скачивать руководства с сайта. Исторический текст из issue
прочитан только как контекст; продуктовые утверждения и конкретные эпизоды
из него не используются. Исходные файлы, полные тексты и кэш игнорируются Git.

Обход охватывает все HTML-страницы, достижимые из корня и пяти разрешённых
ветвей; не утверждается обнаружение скрытых, несвязанных URL. Навигационные
и внутритекстовые ссылки обходятся; файлы, внешние сайты, query-endpoints,
поддержка, архивные и явно устаревшие ветви исключаются. Их 502 уникальных
URL сохранены с причинами. Ссылки на медиа остаются только метаданными.
HTTP-проверка охватывает разрешённые страницы, не внешние ресурсы или
корректность каждого якоря. Обращений в поддержку и тикеты не было.

Аудитор ограничен четырьмя запросами, 4 MiB на ответ и 10 000 страницами;
достижение лимита завершает запуск ошибкой. Есть возобновляемый локальный кэш
и адресный повтор неудачных ответов с сохранением предыдущей попытки.
Дата, HTTP, итоговый URL, заголовки и хэш сохранены для каждой страницы.

## Карта и совместимость

https://github.com/konard/G-Ivan-A-mango_ba_prompts/blob/issue-401-be292b53210f/docs/taxonomy/docs.mango-map.jsonl

Одна JSON-строка соответствует одной странице. Общие с #399 поля сохраняют
типы: `url`, `title`, `http_status`, `observed_at`, `source_sha256`,
`source_urls`, `relevance_for_BA` (FT/NFT/integrations, шкала 0…3),
`is_llm_readable`, `has_visual_context`, `readability`, `update_frequency`.
Оценки релевантности — редакционная эвристика маршрутизации.

Расширения: `hierarchy` с абсолютными URL и названиями, `content_type`,
`tags` с продуктовой/функциональной ветвью, `cross_references`, хэш текста,
HTTP-заголовки, метаданные таблиц и изображений. Для промежуточного URL,
название которого не наблюдалось, установлен `title_observed=false`.
Cross-references могут указывать на исключённый ресурс: это ссылка, а не
свидетельство его загрузки. Новый документный индекс не переносит автоматически
curated-связи продуктовой таксономии #399 и не подменяет runtime-каталог.

## Сравнение с руководством

В PDF **590 страниц**, 168 пунктов оглавления и **194 фактических
нумерованных раздела**: в тексте есть подразделы глубже оглавления.
Все 168 ID найдены; повторов и пустых тел нет. Извлечены 769 339 символов
тел разделов, 101 002 нормализованных токена. Обложка и оглавление прочитаны
и хэшированы, но исключены из сравнения содержания; заголовки сохранены
отдельно, повторяющиеся номера страниц удалены. Тела разделов эксклюзивны:
текст подраздела не дублируется в родительском разделе. OCR изображений
не выполнялся; полнота визуального содержания не установлена.

Постраничный манифест и все разделы:
https://github.com/konard/G-Ivan-A-mango_ba_prompts/blob/issue-401-be292b53210f/docs/taxonomy/cc-pdf-manifest.json

У #399 закреплена карта 3918 URL, но полные тексты не опубликованы.
Поэтому для сравнения обновлены только разрешённые URL этой карты:
3562 наблюдения, 3558 HTTP 200 и четыре остановленных на границе HTTP 301.
Из 34 ответов без текста 30 имеют HTTP 200: старый экстрактор не нашёл тело
статьи, что не доказывает отсутствие текста на сайте. Для сравнения доступны
3528 непустых статей. Исключены 356 архивных/неразрешённых записей карты.
Изменения HTML относительно старого хэша могут быть изменениями обёртки:
совпали только два ненулевых хэша. Сравнение исторического текста #399
побайтно восстановить нельзя; сравнивается **закреплённый набор адресов
с обновлённым текстом**, а не воображаемая историческая версия.

Наблюдения и ограничения обновления:
https://github.com/konard/G-Ivan-A-mango_ba_prompts/blob/issue-401-be292b53210f/docs/taxonomy/portal-comparison-audit.jsonl
и https://github.com/konard/G-Ivan-A-mango_ba_prompts/blob/issue-401-be292b53210f/docs/taxonomy/portal-comparison-summary.json

Для каждого раздела поиск по точным пятисловным последовательностям ищет
кандидатов во всём корпусе, затем ограничивает их продуктом/интерфейсом:
КЦ desktop; для главы 16 — обе ветви речевой аналитики, включая встроенную
в Контроль качества; для 17 — ЛК ВАТС и администрирование ролей; для 18 —
КЦ и роли. Дополнительная страница должна давать не менее 5% новых
пятисловных совпадений (первая — 1%, минимум три); слабый лучший кандидат
и точное название короткого раздела сохраняются с явным статусом.
Чужой SIP Trunk/коннектор не удостоверяет поведение КЦ.

Нормализация: NFKC, регистр, е/ё, мягкий перенос и перенос слова через
дефис в конце строки; слова и числа сохраняются, отрицания не удаляются.
Упорядоченные совпадения длиной ≥5 токенов задают окно статьи; края
достраиваются на длину несовпавшего префикса/суффикса PDF. Без якоря остаётся
вся статья-кандидат. Это приближённое выравнивание; разбиение коротких
родительских списков и разорванных слов в таблицах может завышать отличие.

Формула для раздела и суммарных счётчиков:
`100 × (1 − 2M / (P + W))`, где P — токены PDF, W — токены выбранных окон
веба, M — совпавшие по порядку токены (`SequenceMatcher`, autojunk=False).
Суммарная метрика использует суммы счётчиков, не среднее процентов.
Повторно выбранная веб-страница учитывается в каждом сопоставлении;
это сравнение разделов PDF, не размер уникального корпуса веба.

## Что различается по существу и структуре

PDF объединяет пользовательские главы КЦ, речевую аналитику, ЛК ВАТС и
приложения с ролями. Веб разделяет эти материалы по продуктам и отдельным
статьям; короткий раздел PDF может вести к нескольким страницам и наоборот.
Считать URL-иерархию PDF-оглавлением или приравнивать найденное название к
полному тексту нельзя. Перечень всех соответствий приведён в индексе выше.

- §2.4.1, стр. 36–43: в описаниях показателей меняются размещение и объём
  пояснений; расхождение 27,46%. Табличный порядок вносит вклад в метрику,
  поэтому числовые определения требуют чтения строки вместе с колонками.
- §16.4, стр. 506: прежний перечень трёх способов загрузки заменён перечнем
  настроек, включая основные настройки. Совпадение заголовка сохранилось,
  длинных точных фраз нет; 73,58% не означает утрату загрузки файлов.
- §16.6, стр. 512: «Текстовые коммуникации» найдены во встроенной речевой
  аналитике docs, с добавленным условием настройки аналитики. Соответствующего
  URL нет в закреплённой карте #399. Это пробел **карты**, а не доказательство
  недоступности всего основного сайта: запрос вне карты не выполнялся.
- §§17.6–17.7, стр. 555: отдельные матрицы доступа к вкладкам «Смена версии»
  и «Виджеты» не удалось надёжно сопоставить. Поиск названий обнаруживает
  навигацию/настройки виджетов, но они не подтверждают матрицу ролей PDF.
  Обе записи остаются кандидатами пробела, с 100% лексического отличия.
- §§17.1 и 18: длинные матрицы PDF имеют разорванные по колонкам слова;
  выбранная страница отчётов КЦ покрывает только фрагмент предмета.
  Высокое расхождение нельзя целиком считать утратой прав. Полная
  эквивалентность ролей требует отдельной проверки ячеек и версии интерфейса.

Прямые PDF-локаторы и обе группы веб-URL для этих наблюдений находятся в
`cc-difference-checks.json`; необоснованное семантическое отсутствие нигде
не объявляется фактом. Все прочие лексические расхождения сохраняются в
машинном журнале, даже если их причина не классифицирована вручную.

Из 3533 новых страниц 3526 имеют маршрутный аналог в разрешённой карте
#399; у 3504 извлечённый текст идентичен, у 22 различается, семь адресов
не входят в неё. Полный перечень исключений и пар:
https://github.com/konard/G-Ivan-A-mango_ba_prompts/blob/issue-401-be292b53210f/docs/taxonomy/web-source-pairs.json
Это свидетельство большого пересечения текстов в момент проверки;
независимость процессов публикации или резервирование отказов не доказаны.

## Инструменты и относительная надёжность

| Источник | Проверенный путь извлечения | Ограничения и оценка |
| --- | --- | --- |
| docs | Python urllib + HTMLParser; проверка браузером Playwright MCP | Статическое тело найдено у всех 3533 страниц. `<base>` и leading layout требуют учёта. В текущем снимке удобнее для первичного чтения. |
| Портал #399 | Тот же HTMLParser предыдущего аудита, отдельный кэш и безопасные редиректы | 3528 непустых статей из 3562 разрешённых адресов. Старые aliases/landing могут не распознаваться. Это ограничение наблюдения/экстрактора, не отказ всего сайта. |
| Приложенный PDF | Локальный PyMuPDF 1.28.2: текст страниц и типографские заголовки | Версия фиксирована, outline отсутствует; таблицы и переносы требуют проверки. OCR не делался. Устойчивый локальный вход, но не доказательство актуальности поведения продукта. |
| Runtime | Адресное чтение существующей подготовленной БЗ по версии и локатору | Наличие нужного описания изображения/таблицы проверяется до использования. Этот аудит не удостоверяет, что runtime уже содержит версию 1.26.42. |

Стандартный urllib User-Agent при первоначальной пробе получал 403;
явный описательный User-Agent и браузер дали 200. Признак WAF/клиентской
зависимости учтён; авторизация и обход защиты не применялись. При четырёх
параллельных запросах после адресных повторов у docs нет ошибок; предел
rate limiting, нагрузочная устойчивость и долгосрочный uptime не измерялись.
Предпочтение docs основано на текущей извлекаемости, а не прогнозе стабильности.

Библиотеки BeautifulSoup/lxml могут заменить разбор HTML, но здесь не
бенчмаркировались. Selenium/Playwright нужны как дополнительный браузерный
путь при реально динамическом содержимом; MCP — интерфейс к инструменту,
не способ автоматически восстановить смысл картинки. Общедоступный API
для выгрузки всей документации не установлен; продуктовый API не считается
документационным endpoint. HTTP-метаданные PDF-вложения не раскрывают его текст.

https://docs.python.org/3/library/urllib.request.html,
https://docs.python.org/3/library/html.parser.html,
https://playwright.dev/docs/api/class-browser,
https://pymupdf.readthedocs.io/en/latest/recipes-text.html

## Принципы комбинированного обращения для BCREQ

1. Зафиксировать продукт, desktop/web-интерфейс, версию, коннектор, роль,
   требуемую операцию и вопрос FT/NFT/интеграции. По карте выбрать небольшой
   план чтения с URL и заголовками; название продукта не доказывает функцию.
2. Начать с актуального разрешённого HTML docs. При HTTP/структурной ошибке
   использовать соответствующую статью портала с проверкой хэша/даты;
   одинаковый текст второго сайта не является независимым подтверждением.
3. Для >5%, отсутствующего сопоставления, версии, прав, таблицы или визуальной
   зависимости адресно прочитать соответствующие разделы локального PDF.
   Сохранить URL/страницу/версию и обе формулировки. Более новая дата веба
   сама по себе не разрешает конфликт и не подтверждает удаление функции.
4. Для схем и разорванных матриц проверить существующее runtime-извлечение:
   исходный документ, версию, страницу, хэш и наличие проверенного описания
   нужной ячейки/изображения. Отсутствующее описание не подменять догадкой.
   При фундаментальной недоступности HTML возможен адресный runtime-план
   по заранее подготовленному корпусу с теми же проверками происхождения.
5. Разделять наблюдение, вывод и неизвестное. Непроверенный As-Is/конфликт
   направлять продуктовой команде или владельцу документации; потребность
   Заказчика выяснять у Заказчика. Нельзя переносить права/статусы между
   похожими коннекторами или выдавать неизвестную функцию за отсутствующую.
6. Передавать в контекст выбранные фрагменты, а не всю карту. Записывать
   использованные источники, противоречия и ограничения. Следующий снимок
   сравнивать по хэшам; рекомендуемая повторная проверка через 30 дней —
   политика аудита, не измеренная частота обновления Mango.

Проект решения, без изменения действующих промптов и runtime:

## Воспроизведение и приёмка

Код и локальные probes:
https://github.com/konard/G-Ivan-A-mango_ba_prompts/tree/issue-401-be292b53210f/experiments/issue_401
Зависимость PDF закреплена в requirements.txt; HTML и офлайн-регрессии
используют stdlib. Логи сохраняются в игнорируемом `experiments/issue_401/logs/`.
PDF и context.txt помещаются только из явных GitHub-вложений в `raw/`.
Для PDF перед обработкой проверяется MIME/валидность; Mango-вложения не нужны.

```bash
python3 -m venv /tmp/issue-401-venv
/tmp/issue-401-venv/bin/pip install -r experiments/issue_401/requirements.txt
python3 experiments/issue_401/audit.py --retry-errors
python3 experiments/issue_401/collect_portal.py
/tmp/issue-401-venv/bin/python experiments/issue_401/extract_pdf.py experiments/issue_401/raw/CC_manual_1.26.42_compressed.pdf
ulimit -v 1200000
python3 experiments/issue_401/build_comparison.py
python3 experiments/issue_401/compare_pairs.py
python3 experiments/issue_401/build_evidence.py
python3 scripts/test_issue_401_documentation.py
make validate-fast
make validate-full
```

Повторный запуск использует записанный кэш; для нового снимка нужен отдельный
каталог кэша. Изменённый вход или код сравнения инвалидирует его результат.
Проценты независимо пересчитываются из опубликованных токен-счётчиков;
для проверки самих текстовых операций нужны локальные исходники с указанными
хэшами. Это воспроизводимость наблюдения, не гарантия неизменности живого веба.
Регрессии воспроизводят ошибки `<base>`/leading layout, чтения бинарного тела,
выхода через редирект, смешения продуктов, полного текста статьи вместо
окна раздела, потери отрицаний/чисел и пропуска операции для отсутствующего
кандидата. Публичные артефакты проверяются на полноту, происхождение и баланс
операций. Новый тест включается существующим автопоиском в полный CI.
