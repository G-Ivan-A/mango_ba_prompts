# Шаг 4 — User Story и Use Case

> **Промпты:** `mango-us-modeling-stepwise` (Job Story + INVEST + BDD) и
> `mango-uc-modeling-stepwise` (Cockburn). Истории сформулированы как **ранние**:
> допущения, зависящие от ответов заказчика ([Шаг 3](./step-3-questions.md)),
> помечены `(?Bn)`.

## 4.1. User Story (Job Story)

**US-1 — Единый лимит активных контактов**
> **Когда** на меня как агента поступают обращения из разных каналов (голос, чат,
> e-mail), **я хочу**, чтобы система не давала мне больше N активных контактов
> одновременно (по требованию N=3 `?В3`), **чтобы** я мог вести каждое обращение
> качественно и не терять клиентов реального времени.

**US-2 — Приоритет каналов реального времени**
> **Когда** одновременно претендуют обращения разных каналов, **я хочу**, чтобы голос
> обслуживался раньше чата, а чат — раньше e-mail (`?В4`), **чтобы** клиенты «живых»
> каналов не ждали из-за фоновой работы.

**US-3 — Поведение при заполненном лимите и входящем звонке**
> **Когда** мой лимит активных контактов заполнен и поступает голосовой звонок,
> **я хочу** заранее определённое поведение (очередь/освобождение слота/уведомление
> супервизора `?В5`), **чтобы** не терять приоритетный звонок и не нарушать качество.

### Проверка INVEST

| Критерий | US-1 | US-2 | US-3 |
| --- | --- | --- | --- |
| Independent | ✅ | 🟡 (зависит от US-1) | 🟡 (зависит от US-1/2) |
| Negotiable | ✅ | ✅ | ✅ |
| Valuable | ✅ | ✅ | ✅ |
| Estimable | 🟡 после В1/В3 | 🟡 после В4 | 🟡 после В5 |
| Small | ✅ | ✅ | 🟡 (может дробиться) |
| Testable | ✅ (см. BDD) | ✅ | ✅ |

### BDD-критерии приёмки (Given–When–Then)

**US-1**
```gherkin
Дано: у агента уже 3 активных контакта (любой микс каналов)
Когда: в систему поступает новое обращение
Тогда: оно не распределяется на этого агента, а остаётся в очереди
   И:  слот освобождается только после закрытия одного из активных контактов
```

**US-2**
```gherkin
Дано: у агента есть свободный слот и в очереди ждут голос, чат и e-mail
Когда: система выбирает, что распределить агенту
Тогда: первым распределяется голосовой контакт, затем чат, затем e-mail
```

**US-3 (условно, до ответа на В5)**
```gherkin
Дано: лимит активных контактов агента заполнен (включая e-mail в фоне)
Когда: поступает входящий голосовой звонок с наивысшим приоритетом
Тогда: применяется согласованное правило ?В5
   (вариант: e-mail-слот освобождается/откладывается, звонок принимается)
```

## 4.2. Use Case (Cockburn)

**UC-1 — Обработка разно-канальных обращений с лимитом и приоритетом**

| Поле | Значение |
| --- | --- |
| Уровень | Пользовательская задача (sea-level) |
| Главный актор | Агент (Оператор КЦ) — Ф9 |
| Заинтересованные | Клиент (ждёт ответа), Супервизор (нагрузка), Руководитель/Администратор (настройка) |
| Предусловия | Каналы голос/чат/e-mail подключены (Ф1); лимит и приоритет настроены в ЛК ВАТС (Ф10) |
| Триггер | Поступает новое обращение любого канала |
| Гарантия успеха | Агент ведёт ≤N контактов; приоритетные каналы обслужены раньше |
| Минимальная гарантия | Обращение не теряется: либо распределено, либо в очереди |

### Основной поток (happy path)

1. Поступает обращение канала C.
2. Система проверяет число активных контактов агента-кандидата против лимита N (`?В3`).
3. Если есть свободный слот — среди ожидающих выбирается обращение по приоритету
   голос>чат>e-mail (`?В4`).
4. Обращение распределяется агенту, счётчик активных контактов увеличивается.
5. Агент закрывает обращение → счётчик уменьшается → слот освобождается (как Ф3).

### Альтернативные потоки

- **3a. Свободных слотов нет у всех агентов группы** → обращение остаётся в общей
  очереди до освобождения слота (поведение по аналогии с Ф3).
- **3b. Несколько обращений одного приоритета** → применяется текущий алгоритм
  распределения (наименее загруженный / равномерно, Ф4).

### Исключения

- **E1. Лимит заполнен, поступает голос (наивысший приоритет)** → правило `?В5`
  (очередь / освобождение слота e-mail / уведомление супервизора). **В БЗ не описано**
  — см. [`inputs/kb-files.md` → «не найдено»](../inputs/kb-files.md).
- **E2. E-mail не распределён за таймаут** → авто-закрытие (существующее поведение Ф7
  [CC, §4.2, с.128]).
- **E3. Агент уходит в звонок при выключенном чекбоксе Ф5** → возможна перегрузка;
  новый механизм должен это предотвращать (это и есть боль из 2.2).
