# Финальное ТЗ: BCREQ-1059 — Email-маршрутизация по Точке входа в КЦ

> **Статус:** Готово к передаче в разработку.
> **Сформировано:** Цепочкой из 3 промптов в ходе ~30+ итераций согласования.

## Раздел 1. Термины и определения

| Термин | Определение |
| --- | --- |
| **Точка входа** | Почтовый ящик (email-адрес), на который поступило входящее письмо от клиента. Используется как основа для маршрутизации ответа. |
| **Канал** | Логическая единица в КЦ, объединяющая тип взаимодействия (email) и привязанные к нему почтовые ящики. Настраивается в ЛК ВАТС. |

## Раздел 2. Постановка задачи

### 2.1 Проблема (As-Is)

При ответе оператора на входящее email-обращение система не гарантирует отправку
ответа с того почтового ящика, на который пришло исходное письмо (Точка входа).
Письмо может уйти с ящика «по умолчанию» для Канала, что нарушает деловую
переписку.

### 2.2 Цель (To-Be)

Обеспечить автоматическое определение ящика-отправителя при ответе оператора
на email-обращение на основе Точки входа (ящика, на который пришло входящее
письмо). Цель реализуется через настройки и механизмы КЦ; ручной выбор ящика
в Редакторе писем не предусмотрен.

### 2.3 Задачи

1. Реализовать автоматическую фиксацию Точки входа при поступлении входящего
   email-обращения.
2. Реализовать автоматическую подстановку ящика-отправителя на основе Точки входа
   при формировании исходящего ответа.
3. Обеспечить отображение ящика-отправителя в Редакторе писем (только для чтения).
4. Реализовать fallback-механизм при недоступности ящика из Точки входа.

## Раздел 4. Функциональные требования

### 4.1 Автоматическое определение ящика-отправителя

Система должна определять ящик-отправителя для исходящего ответа на основе
Точки входа входящего обращения.

**4.1.1** При создании исходящего ответа система подставляет адрес ящика,
на который поступило входящее письмо (Точка входа).

**4.1.2** Если Точка входа определена, ручной выбор ящика-отправителя в
Редакторе писем недоступен (см. 6.1.5).

**4.1.3** Если Точка входа не определена (отсутствует техническая возможность),
система использует ящик по умолчанию для активного Канала.

### 4.2 Маршрутизация по Каналу и Ящику

Система должна корректно передавать информацию о Точке входа между компонентами
ЛК ВАТС ↔ КЦ ↔ Редактор.

**4.2.1** При поступлении входящего email-обращения система фиксирует Точку входа
(ящик-адресат входящего письма) как атрибут обращения.

**4.2.1.1 Матрица приоритетов (условия подстановки ящика):**

| Приоритет | Условие | Ящик-отправитель |
| --- | --- | --- |
| 1 | Точка входа определена → ящик активен | Ящик из Точки входа |
| 2 | Точка входа определена → ящик неактивен | Ящик по умолчанию для Канала |
| 3 | Точка входа не определена | Ящик по умолчанию для Канала |

**4.2.2** Оператор выбирает Канал в КЦ; ящик-отправитель определяется
автоматически на основе Точки входа — без дополнительных действий оператора.

**4.2.3** Система должна передавать Точку входа из входящего обращения в
контекст исходящего ответа без потери при переключении между обращениями.

### 4.3 Обеспечение возможности просмотра ящика-отправителя

Система обеспечивает возможность оператору видеть, с какого ящика будет
отправлен ответ.

**4.3.1** В интерфейсе Редактора писем система отображает ящик-отправитель,
определённый на основе Точки входа (только для чтения).

**4.3.2** При неактивном или недоступном ящике система уведомляет оператора
и отображает ящик по умолчанию.

## Раздел 6. Ограничения

### 6.1 Технические ограничения

**6.1.1** Настройка почтовых ящиков выполняется исключительно в ЛК ВАТС.
КЦ использует уже настроенные ящики — создание или изменение через КЦ недоступно.

**6.1.2** Канал в КЦ является единицей выбора для оператора; прямой выбор
конкретного Ящика внутри Канала операторским интерфейсом не предусмотрен.

**6.1.3** Связка Канал → Ящик настраивается в ЛК ВАТС Администратором.
Изменение этой связки во время обработки обращения невозможно.

**6.1.4** Автоматическая подстановка ящика-отправителя работает только для
email-обращений; для голосовых и чат-обращений этот механизм не применяется.

**6.1.5** В Редакторе писем ручной выбор ящика-отправителя недоступен
(As-Is UI-ограничение). Ящик-отправитель отображается только для чтения
и определяется системой автоматически на основе Точки входа.

**6.1.6** Если ящик из Точки входа деактивирован или удалён из Канала, система
применяет ящик по умолчанию для Канала (fallback). Оператор уведомляется.

**6.1.7** Доступность ящиков-отправителей зависит от корректности настроек
SMTP в ЛК ВАТС. Ответственность за работоспособность SMTP несёт Администратор.

### 6.2 Ролевые ограничения (As-Is)

**6.2.1** Оператор не имеет доступа к настройкам Каналов и Ящиков в ЛК ВАТС.

**6.2.2** Оператор не может изменять логику маршрутизации email-ответов.
Все правила маршрутизации задаются Администратором в ЛК ВАТС.

**6.2.3** Руководитель группы может просматривать настройки Каналов, но не
изменять их без прав Администратора.
