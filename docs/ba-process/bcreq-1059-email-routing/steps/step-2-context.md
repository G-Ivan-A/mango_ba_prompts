# Шаг 2 — Проблема, Цель, Задачи (Раздел 2)

> Результат работы промпта `mango-glossary-context-understanding-stepwise`,
> часть 2: формирование постановки задачи.

## 2.1 Проблема (As-Is)

При ответе оператора на входящее email-обращение система не гарантирует отправку
ответа с того почтового ящика, на который пришло исходное письмо (Точка входа).
Письмо может уйти с ящика «по умолчанию» для данного Канала, а не с ящика-источника
входящего обращения.

**Следствия:**
- Клиент получает ответ с «чужого» адреса, не совпадающего с тем, на который он
  писал, что нарушает деловую переписку.
- Нарушается принцип «ящик ответа = ящик входящего письма», критичный для
  клиентской коммуникации.
- У оператора нет ни автоматического, ни ручного механизма выбора нужного ящика
  в Редакторе писем.

## 2.2 Цель (To-Be)

Обеспечить автоматическое определение ящика-отправителя при ответе оператора
на email-обращение на основе Точки входа (ящика, на который пришло входящее
письмо).

> ⚠️ **Примечание (Паттерн Э5 — ложные обещания):** Цель реализуется через
> **настройки КЦ (Канал)**, а не через прямой выбор ящика в контексте конкретного
> обращения. Это ограничение зафиксировано в Разделе 6.

## 2.3 Задачи

1. Определить механизм передачи информации о Точке входа от входящего обращения
   к исходящему ответу.
2. Реализовать автоматическую подстановку ящика-отправителя на основе Точки входа.
3. Убедиться, что изменение не затрагивает ручной выбор Канала оператором в КЦ.
4. Зафиксировать UI-ограничения и ролевую модель As-Is как явные ограничения
   системы (Раздел 6).
