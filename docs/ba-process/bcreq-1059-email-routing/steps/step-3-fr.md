## 4. Функциональные требования

### 4.1 Автоматическое определение ящика-отправителя

Система должна определять ящик-отправителя для исходящего ответа на основе
Точки входа входящего обращения.

**4.1.1** При создании исходящего ответа система подставляет адрес ящика,
на который поступило входящее письмо (Точка входа).

**4.1.2** Если Точка входа определена, ручной выбор ящика-отправителя в
Редакторе писем недоступен (см. 6.1.5).

**4.1.3** Если Точка входа не определена (отсутствует техническая возможность),
система использует ящик по умолчанию для активного Канала.

### 4.2 Маршрутизация по Каналу и Ящику

Система должна корректно передавать информацию о Точке входа между компонентами
ЛК ВАТС ↔ КЦ ↔ Редактор.

**4.2.1** При поступлении входящего email-обращения система фиксирует Точку входа
(ящик-адресат входящего письма) как атрибут обращения.

**4.2.1.1 Матрица приоритетов (условия подстановки ящика):**

| Приоритет | Условие | Ящик-отправитель |
| --- | --- | --- |
| 1 | Точка входа определена → ящик активен | Ящик из Точки входа |
| 2 | Точка входа определена → ящик неактивен | Ящик по умолчанию для Канала |
| 3 | Точка входа не определена | Ящик по умолчанию для Канала |

**4.2.2** Оператор выбирает Канал в КЦ; ящик-отправитель определяется
автоматически на основе Точки входа — без дополнительных действий оператора.

**4.2.3** Система должна передавать Точку входа из входящего обращения в
контекст исходящего ответа без потери при переключении между обращениями.

### 4.3 Обеспечение возможности просмотра ящика-отправителя

Система обеспечивает возможность оператору видеть, с какого ящика будет
отправлен ответ.

**4.3.1** В интерфейсе Редактора писем система отображает ящик-отправитель,
определённый на основе Точки входа (только для чтения).

**4.3.2** При неактивном или недоступном ящике система уведомляет оператора
и отображает ящик по умолчанию.
