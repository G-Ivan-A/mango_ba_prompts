# Шаг 4 — Ограничения (Раздел 6)

> Результат работы промпта `mango-constraints-documentation-stepwise`.

## 6. Ограничения

### 6.1 Технические ограничения

**6.1.1** Настройка почтовых ящиков (адресов, SMTP/IMAP-параметров) выполняется
исключительно в ЛК ВАТС. КЦ использует уже настроенные ящики — создание новых
или изменение параметров существующих через КЦ недоступно.

**6.1.2** Канал в КЦ является единицей выбора для оператора; прямой выбор
конкретного Ящика внутри Канала операторским интерфейсом не предусмотрен.

**6.1.3** Связка Канал → Ящик настраивается в ЛК ВАТС Администратором.
Изменение этой связки во время обработки обращения невозможно.

**6.1.4** Автоматическая подстановка ящика-отправителя работает только для
email-обращений; для голосовых и чат-обращений этот механизм не применяется.

**6.1.5** В Редакторе писем ручной выбор ящика-отправителя недоступен
(As-Is UI-ограничение). Ящик-отправитель отображается только для чтения
и определяется системой автоматически на основе Точки входа.

**6.1.6** Если почтовый ящик, соответствующий Точке входа, деактивирован
или удалён из Канала, система применяет ящик по умолчанию для Канала (fallback).
Оператор уведомляется об использовании ящика по умолчанию.

**6.1.7** Доступность ящиков-отправителей зависит от корректности настроек
SMTP в ЛК ВАТС. Ответственность за работоспособность SMTP несёт Администратор.

### 6.2 Ролевые ограничения (As-Is)

**6.2.1** Оператор не имеет доступа к настройкам Каналов и Ящиков в ЛК ВАТС.

**6.2.2** Оператор не может изменять логику маршрутизации email-ответов.
Все правила маршрутизации задаются Администратором в ЛК ВАТС.

**6.2.3** Руководитель группы может просматривать настройки Каналов, но не
изменять их без прав Администратора.

## Примечание

Перенос UI-ограничений (6.1.5) и ролевой модели (6.2.x) в отдельный раздел
«Ограничения» — **новая практика**, выявленная в ходе эксперимента (Паттерн У5
и М4). Ранее эти элементы смешивались с ФТ, что ухудшало читаемость Раздела 4.
