## 1. Ручной процесс БА

### 1.1. Общие правила ручного прогона

| № | Правило |
| --- | --- |
| П-1 | Один промпт — один класс операции. Шаг 1.2 — первое появление класса; в следующих стадиях класс повторяется по порядку 1.3 с тем же контрактом. |
| П-2 | Промпт копируется целиком кнопкой ⧉ на сайте; первая строка копии — комментарий с ID промпта, его не удалять. Вместе с промптом вставить контракт состояния, применимые мета-стандарты и конституцию: C36 проверяет их версии. |
| П-3 | Вход заполняется в JSON-блоке стандарта класса: task, phase, class, input_mode (START или CONTINUE), revision, rule_bundle. `null` — неизвестно, `[]` — проверено и пусто. |
| П-4 | Каждый ответ модели — один блок `BCREQ_OUTPUT`. БА проверяет receipt и recommendation и передаёт блок в следующий вызов; новый чат — через C12 FULL и проверку переноса C13. |
| П-5 | Модель только рекомендует следующий класс и гейт. Шаг, повтор, пропуск, возврат и гейт выбирает БА или согласующий; молчание не согласие. |
| П-6 | Вопросы C04 БА отправляет пакетом по адресатам, модель ответы не придумывает. Пробел источника блокирует только зависящие утверждения (WAITING). |
| П-7 | Цикл стадии: C12 собирает фазу, C20 предлагает гейт, человек решает, C34 фиксирует решение, C12 обновляет полный результат. |
| П-8 | Изменение кандидата: C29 помечает зависимое `stale`, C30 правит адресно, C28 и C31 проверяют, нужный объём согласуется заново. |
