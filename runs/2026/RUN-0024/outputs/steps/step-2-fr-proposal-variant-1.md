Понимание проблемы и контекста
Заказчик использует облачную ВАТС и продукт «Речевая аналитика» для оценки качества звонков, которые переадресуются внешним Партнерам. Поскольку сотрудники Партнеров не являются пользователями ВАТС, стандартная фильтрация отчетов по сотрудникам или группам сотрудников не работает. Единственный признак продуктового направления (мини-брус, ПРЕКАТ, ПРЕФАБ) привязан к входящему номеру ВАТС. Текущая функциональность не позволяет группировать номера ВАТС по направлениям и фильтровать отчеты (чек-листы, инсайты, дашборд) по этим группам. Это снижает прозрачность бизнес-показателей и усложняет работу бизнес-тренеров. Цель задачи — внедрить механизм группировки номеров ВАТС (группы-направления) и применить его как сквозной фильтр в отчетах Речевой аналитики.

4.1. Группировка номеров ВАТС по направлениям (FR-01)

4.1.1. Система должна позволять Администратору Речевой аналитики **создавать, редактировать и удалять** именованные группы-направлений.

. Система должна проверять уникальность наименования группы-направления **в рамках одного Заказчика**.

. **Система должна ограничивать создание групп-направлений только следующими продуктовыми направлениями: «мини-брус», «ПРЕКАТ», «ПРЕФАБ».**

4.1.2. Система должна позволять **добавлять** один или несколько номеров ВАТС **в состав** группы-направления.

. **Система должна запрещать добавление одного и того же номера ВАТС в несколько групп-направлений одновременно.**

4.1.3. Система должна позволять **изменять состав номеров внутри** группы-направления.

4.1.4. Система должна позволять **удалять** группу-направление.

. **При удалении группы-направления система должна сохранять сами номера ВАТС в реестре, удаляя только привязку к группе.**

4.1.5. Система **не должна допускать** включение номера 8800 в группу-направление.

4.2. Фильтрация «Анализа по чек-листам» по направлению (FR-02)

4.2.1. Система должна позволять Пользователю фильтровать отчёт «Анализ по чек-листам» по выбранной группе-направлению.

. Система должна **отображать элемент управления для выбора** группы-направления в параметрах отчёта.

4.2.2. Система должна **возвращать в результатах отчёта** только разговоры, **поступившие на** номера ВАТС **из** выбранной группы-направления.

. При выборе нескольких групп-направлений система должна применять **логику «ИЛИ»**.

4.2.3. **Система должна рассчитывать агрегированные показатели оценки по чек-листу исключительно на основе отфильтрованных разговоров.**

4.3. Фильтрация «Ловца инсайтов» по направлению (FR-03)

4.3.1. Система должна позволять Пользователю фильтровать отчёт «Ловец инсайтов» по выбранной группе-направлению.

. Система должна **отображать элемент управления для выбора** группы-направления в **блоке** параметров отчёта.

4.3.2. Система должна **возвращать в результатах отчёта** только инсайты **из** разговоров, **поступивших на** номера ВАТС выбранной группы-направления.

4.3.3. Система должна **группировать и анализировать** инсайты типов: вопрос, возражение, потребность, **в разрезе** выбранной группы-направления.

. **Система должна определять инсайт на основе распознавания интента (intent), а не по совпадению ключевых слов.**

4.4. Единый дашборд по направлению (FR-04)

4.4.1. Система должна предоставлять Пользователю единый дашборд **с результатами** оценки по чек-листам и инсайтов, **предусматривающий** фильтрацию по группе-направлению.

4.4.2. Система должна **применять выбранную группу-направление как сквозной фильтр** к блоку оценки по чек-листам и блоку инсайтов **на дашборде**.

4.4.3. Система должна **отображать на едином экране** результаты оценки по чек-листам и инсайты **исключительно для** выбранной группы-направления.
