## Анализ целесообразности требования

### **Критический вопрос: ЗАЧЕМ это в карточке лида?**

Вы правы — требование выглядит **избыточным**. Разберем почему:

---

### **1. Где уже есть эта информация:**

Согласно документации MANGO OFFICE:

**В Личном кабинете и Контакт-центре:**
- Отчеты "Детализация звонков" (раздел 3.4, Приложение А)
- Статистика Контакт-центра с тематиками и результатами (раздел 2.19)
- Постзвоночная оценка качества (раздел 2.19)

**В Битрикс24 уже фиксируется:**
- Факт пропущенного звонка
- Ответственный сотрудник
- Время и длительность
- История коммуникаций

---

### **2. Почему требование избыточно:**

| Проблема | Объяснение |
|----------|------------|
| **Дублирование данных** | Статистика уже доступна в отчетах ЛК MANGO OFFICE и КЦ |
| **Загрязнение названия лида** | Заголовок лида должен быть информативным для работы, а не для аналитики |
| **Сложность анализа** | Для аналитики нужны отчеты/фильтры, а не текст в названии |
| **Невозможность фильтрации** | Текст в названии нельзя использовать для умной аналитики |

---

### **3. Что МОЖНО сделать вместо этого:**

#### **Вариант А: Пользовательское поле (рекомендуется)**

Вместо изменения **названия** лида, добавить **пользовательское поле**:

```
Название поля: "Причина пропуска"
Тип: Список
Значения:
- Все операторы заняты
- Есть свободный оператор
- Пропущен в IVR
- Пропущен в группе
```

**Преимущества:**
- Можно фильтровать и строить отчеты
- Не загрязняет название лида
- Автоматическая аналитика через стандартные инструменты Битрикс24

#### **Вариант Б: Тег/Категория**

Использовать существующие механизмы классификации:
- Поле "Источник" (раздел 2.3 документации)
- Пользовательские поля CRM
- Теги (если используются)

#### **Вариант В: Интеграция с Контакт-центром**

Согласно разделу 2.19 документации:
- Включить **"Сохранять тематики Контакт-Центра"**
- Тематика автоматически сохранится в поле **"Тематики КЦ"** лида/контакта
- Это стандартный механизм, не требующий доработок
