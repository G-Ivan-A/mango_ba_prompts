# L1 — Executive Summary: интеграция чатов HH.ru с контакт-центром Mango Office

Консолидированный документ для согласования. Детализация — [`L2-gap-matrix.md`](L2-gap-matrix.md), план проверок — [`L3-technical-spike-notes.md`](L3-technical-spike-notes.md).

## Вердикт

**Осуществимо условно.** Продуктовая часть (канал в ЛК, маршрутизация, обращения, отчётность) реализуется по существующему в Mango Office паттерну канала «Авито Работа» и рисков не несёт. Интеграционная часть — получение и отправка сообщений в HH.ru — **не подтверждается публичной документацией hh.ru**: единственные документированные методы работы с сообщениями объявлены устаревшими, и в них прямо заявлено, что новые возможности чатов поддерживаться не будут.

Начинать разработку до получения от hh.ru доступа к актуальному API чатов **не рекомендуется**: ядро ФТ (ФТ-05…ФТ-08) опирается именно на этот функционал.

| GAP-4 | Признака «линейный персонал» у вакансии в API нет — автоматическая фильтрация ФТ-04 невыполнима. | ФТ-04 |
| GAP-5 | В анонимных резюме телефон, e-mail и ФИО скрыты; просмотр резюме квотируется. | ФТ-08, ФТ-09 |

## Что можно делать уже сейчас

Продуктовая часть не зависит от разрывов и может проектироваться параллельно: новый канал в ЛК (Текстовые коммуникации → Каналы → Группа каналов), обработчики приёма обращений, автозавершение неактивного диалога, переключатель «только отклики с сообщениями», добавление канала в отчёт «История обращений». Всё это существует в канале «Авито Работа» и переиспользуется.

## Ограничение достоверности

Интерактивная OpenAPI-спецификация hh.ru, сайт `dev.hh.ru` и база знаний `feedback.hh.ru` из среды выполнения прогона **недоступны по сети** (соединение отвергается на уровне TCP). Анализ выполнен по официальному репозиторию документации [`hhru/api`](https://github.com/hhru/api) (коммит `906d7b6`), которого достаточно для вердикта по 7 требованиям из 10; по ФТ-04, ФТ-06 и ФТ-10 вердикт частичный. Протокол проверки доступности — [`../logs/source-availability.md`](../logs/source-availability.md).
