# Предложение по целевой структуре хранения БЗ (контракт задачи №1)

## Решение: текущий каталог подтверждается как целевой

`kb/processed/<slug>/{index.md, meta.json, sections/, images/, verification.md}`
остаётся целевой структурой; вложенность применяется только там, где один
логический продукт описан несколькими самостоятельными PDF
(`processing_mode: multi_document`, как в `kb/processed/mtalker/`).

Три довода, почему группировка по продуктам/модулям была бы ухудшением:

1. **Адрес чанка — это контракт.** По ADR-007 R3 цитата в аналитике адресуется
   как `kb/processed/<doc>/sections/<file>#anchor`. Перегруппировка каталогов
   массово ломает уже выданные ссылки: вне самого каталога `kb/processed/`
   в репозитории 86 ссылок на эти пути.
2. **Это машинный слой, а не витрина.** Каталог читают retrieval-конвейер и
   валидаторы, а не человек глазами; человекочитаемую навигацию даёт
   `kb/processed/README.md` и коллекционные `index.md`, где группировка по
   продуктам стоит дёшево и меняется без миграции ссылок.
3. **Группировка по продуктам неустойчива.** Документы Mango Office
   пересекаются по продуктам (ВАТС/КЦ/ЛК/мобильный клиент), и один и тот же
   PDF пришлось бы либо дублировать, либо произвольно приписывать одному узлу.
