# Анализ функциональных требований: Оформление подписи в канале email

## 🔍 Понимание проблемы

### Контекст
В омниканальном контакт-центре Mango Office (КЦ) операторы отправляют ответы клиентам через канал email. В текущей реализации отсутствует инструмент централизованной настройки подписей писем.

### Корневая проблема
| Аспект | Описание |
|--------|----------|
| **Функциональный разрыв** | Нет возможности добавить в подпись изображение (логотип, фото оператора, баннер) |
| **Бизнес-потребность** | Заказчикам требуется брендированная коммуникация: единый корпоративный стиль в исходящих письмах |
| **Пользовательская боль** | Операторы вынуждены вручную копировать подписи, что ведёт к ошибкам, несогласованности и потере времени |
| **Ограничение платформы** | Текстовая подпись без форматирования и медиа-элементов не соответствует современным стандартам деловой переписки |

---

## 🎯 Понимание решения

### Целевое состояние
В разделе **ЛК → Диалоги → Канал email → Настройки → Подпись** появляется расширенный редактор подписи с поддержкой:

```
✅ Загрузка изображения:
   • По внешней ссылке (URL)
   • Из локального файла (с валидацией формата/размера)

✅ Вставка готового HTML-кода подписи
   • Для продвинутых пользователей / интеграции с внешними генераторами

✅ Инструменты форматирования текста:
   • Жирный / Курсив / Подчёркивание
   • Маркированные и нумерованные списки

✅ Юзабилити-улучшения:
   • Строка прокрутки в окне редактирования
   • Тултип с подсказкой о возможностях
   • Увеличение лимита символов до 1000
   • Предпросмотр подписи (WYSIWYG)
```

### Архитектурная логика решения
```
[Настройка в ЛК] 
       ↓
[Хранение шаблона подписи: текст + изображение + HTML] 
       ↓
[Применение при отправке письма из КЦ] 
       ↓
[Рендеринг в почтовом клиенте получателя]
```

## ⚠️ Ключевые аспекты для реализации (аналитический комментарий)

| Категория | Вопрос / Риск | Комментарий |
|-----------|---------------|-------------|
| **Безопасность** | Вставка HTML-кода | Требуется санитизация кода для предотвращения XSS-инъекций |
| **Валидация** | Параметры изображений | Необходимо чётко документировать допустимые форматы, размеры, вес файла |
| **Совместимость** | Предпросмотр ≠ рендер в почте | Разные почтовые клиенты (Gmail, Outlook) по-разному интерпретируют HTML/CSS — требуется тестовая матрица |
| **Производительность** | Хранение и отдача изображений | При загрузке файла: где хранится изображение? Как обеспечивается доступность при отправке письма? |
| **UX** | Баланс «простота / мощность» | Редактор должен быть интуитивным для оператора, но не ограничивать возможности для кастомизации |
| **Поддержка** | Ошибки загрузки | Сообщения об ошибках должны быть конкретными: «Файл >2 МБ», «Недопустимый тег <script>» и т.п. |

**Решение логично и полно**: покрывает как базовые сценарии (загрузка картинки + форматирование), так и продвинутые (HTML-вставка), с учётом юзабилити (предпросмотр, подсказки).

**Рекомендация к следующему шагу**: перед разработкой уточнить нефункциональные требования — ограничения по форматам изображений, политику хранения медиа, список поддерживаемых почтовых клиентов для тестирования рендеринга.

### 2. Подпись компании (корпоративная)
**Где настраивается:** Личный кабинет ВАТС → Виджет «Манго Диалоги» → Настройки канала коммуникации E-mail

**Функционал:**
- Указывается **единая подпись для всей компании**
- Применяется при ответах **с электронной почты компании** (не персональной)
- Используется, если:
  - e-mail сотрудника не авторизован в Контакт-центре, **ИЛИ**
  - в настройках виджета установлено: *«Отвечать с электронной почты компании»*

> *«Подпись к письму, подставляемая при ответе с почты компании, указывается в настройках канала коммуникации E-mail в виджете в Личном кабинете.»*

## ⚠️ Выявленные ограничения текущей реализации

| Требование | Поддержка в текущей версии |
|------------|---------------------------|
| Администратор задаёт шаблон подписи для всей организации в ЛК | ✅ Частично (только для ответов с почты компании) |
| Подпись автоматически подставляется в письмо | ✅ Да |
| **Оператор не может редактировать подпись** | ❌ **Не поддерживается** для подписи сотрудника; для корпоративной — зависит от сценария отправки |
| Единая подпись применяется ко всем исходящим письмам независимо от отправителя | ❌ Нет (разделение: почта сотрудника / почта компании) |

---

## 🔍 Ключевые выводы

1. **Разделение контекстов отправки:**
   - Если оператор отвечает с **авторизованной личной почты** → используется его индивидуальная подпись (редактируемая)
   - Если оператор отвечает с **почты компании** → используется корпоративная подпись из настроек виджета

2. **Отсутствие функции «заблокированной» подписи:** В текущей версии нет механизма, который бы позволял администратору задать подпись, **недоступную для редактирования оператором** при отправке с персональной почты.

3. **Потенциальное решение:** Для реализации вашего сценария потребуется:
   - Либо отправка всех писем **только с почты компании** (через настройки виджета), чтобы применялась корпоративная подпись
   - Либо доработка продукта: добавление флага «Заблокировать редактирование подписи» в настройках подписи сотрудника
