## Факт 1 — ни одна страница не была прочитана

Единственный вызов `web_extractor` вернул по всем трём URL один и тот же ответ:

> «The provided webpage content could not be accessed. Please check the URL or
> file format. … The webpage content could not be processed, and therefore, no
> information is available.»

Метрики самого инструмента подтверждают это машиночитаемо:

```json
"tool_call_metrics": {"cache_hit": [0, 0, 0], "extract_page_success": [0, 0, 0]}
```

`extract_page_success = [0, 0, 0]` — **текст страниц не получен ни разу**, в том
числе со страницы руководства по интеграции с amoCRM. Всё, чем реально
располагала модель, — сниппеты поисковой выдачи (1–2 предложения на документ).

Тем не менее реплика [7] открывается словами «**Результаты проверки документации
подтверждают ваше наблюдение**» — формулировка сообщает читателю уровень
достоверности «прочитано в документации», которого в прогоне не было.

## Факт 2 — куда указывают сноски `[[30]][[40]][[49]]`

Списка источников в ответе нет, поэтому сопоставление восстанавливается по
сквозной нумерации документов выдачи в порядке их появления (первый поиск —
`[[1]]`…`[[29]]`, второй — `[[30]]`…`[[58]]`). При такой нумерации:

| Сноска | URL | Сниппет (дословно) |
| --- | --- | --- |
| `[[30]]` | `mango-office.ru/support/integratsiya-api/amocrm/integratsiyaysykontakty/` | «открыть окно настройки digital-воронки: · включить флаг «Совершать автоперезвон»; · в поле «Добавить условие» указать, при каких условиях совершать автоперезвон» |
| `[[40]]` | `amocrm.ru/extensions/mango_phone` | «В меню настроек amoCRM найдите раздел «Интеграции» и установите виджет MANGO OFFICE…» |
| `[[49]]` | `mango-office.ru/support/integratsiya-api/amocrm/integratsiyaysykontakty/` | «Благодаря виджету интеграции можно настроить автоматическое добавление номера Клиента в кампанию исходящего обзвона (ИО) Контакт-центра MANGO OFFICE» |

Совпадение номеров правдоподобно, но **не доказано**: собственной нумерации
модель не показала. Содержательно же вывод «настройка живёт в виджете интеграции
в интерфейсе amoCRM, а не в ЛК MANGO OFFICE» сниппетам `[[40]]` и `[[49]]` **не
противоречит и ими поддержан на уровне сниппета**. То есть ошибочен не вывод, а
заявленный источник и уровень уверенности: вывод сделан по сниппетам поиска, а не
по руководству, на которое сослался БА.

## Почему проверить макет и руководство нельзя внутри прогона

- **Скриншот.** В экспорте у реплики [14] хранится только метаданные вложения и
  подписанная ссылка на CDN провайдера; байтов изображения в JSON нет, ссылка из
  окружения фиксации недоступна. Поэтому метка поля из реплики [15] помечена как
  **непроверяемая**, а не как доказанная выдумка.
- **Руководство.** Документ «Интеграция Виртуальной АТС и amoCRM. Инструкция по
  настройке» (153 стр.) зарегистрирован в
  [`kb/sources/integration_amocrm/meta.json`](../../../../kb/sources/integration_amocrm/meta.json),
  но сам PDF в репозиторий не загружен и в `kb/processed/` не обработан
  (`grep -ri "Перенести в воронку" kb/` → 0 вхождений). Сверить стр. 127 нечем.

`site/data/`, `patterns/` этим прогоном не изменяются); зафиксировано как
