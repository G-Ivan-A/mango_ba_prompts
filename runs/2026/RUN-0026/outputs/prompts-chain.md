## Сопоставление с библиотечным промптом

Ближайший по назначению библиотечный промпт —
[`prompts/fr-documentation-stepwise.md`](../../../../prompts/fr-documentation-stepwise.md)
(«ФТ: Генерация требований», пошаговый). Совпадения велики, и это само по себе
наблюдение: ad-hoc-рамка БА независимо воспроизвела структуру библиотечного
промпта.

| Элемент | Ad-hoc [0] | `fr-documentation-stepwise.md` |
| --- | --- | --- |
| Роль | «команда сертифицированных БА», телеком, TM Forum | «ведущий бизнес-аналитик (CBAP)», Телеком SaaS, TM Forum |
| Пошаговость | 3 шага: контекст → оптимизация структуры → согласование | 4 шага с ожиданием ответа после каждого |
| ODA | «валидация через ODA Capability Map» появилась только в [14] | Шаг 4 — обязательная ODA-валидация с флагом scope creep |
| Формат требования | «Система должна предоставить возможность пользователю… / Система должна обеспечить…» | «Система должна [глагол] [объект] [при условии]» на уровне 4.x |
| Иерархия | не задана (плоская нумерация 4.x) | 4.x / 4.x.1 / 4.x.1.1 с разными стилями |
| Запрет техдеталей | «без детализации реализации, UI, API, алгоритмов» | «избегай… технического сленга разработчиков (API, БД, классы, методы)» |
| Защита скоупа | «не расширять функциональность за пределы контекста» | «креативность направлена ИСКЛЮЧИТЕЛЬНО на граничные случаи» |
| Гейт достоверности | нет | нет |

Два расхождения объясняют два дефекта прогона:

1. **Плоская нумерация против иерархии.** Библиотечный промпт разводит строгий
   шаблон (уровень 4.x) и свободное описание поведения (уровень 4.x.1). В
   ad-hoc-рамке уровень один, поэтому указание [18] «все требования — по
   классике» пришлось применить и к описаниям автоматического поведения
   Системы — отсюда Д1 (см. [`quality-findings.md`](quality-findings.md)).
2. **Момент ODA-валидации.** В библиотеке она — обязательный шаг 4 после
   генерации; здесь она возникла как разовая просьба в [14], уже после сборки
   документа v1.0, и вылилась в переписывание всего раздела 4.

Гейта достоверности («не выдавай непроверенное за факт», «помечай
предположения») нет **ни в ad-hoc-рамке, ни в библиотечном промпте** — Г1–Г4
этим прогоном ничем не блокировались.

## Гипотезы для Пользователя (не реализованы)

Прогон их только фиксирует; изменение промптов и БЗ — отдельная задача
Пользователя.

- **Г-A. Гейт заземления.** Требование: любое утверждение о содержимом
  документации сопровождать пометкой источника («прочитано» / «по сниппету
  поиска» / «со слов БА») и маркером ⚠️ при отсутствии проверки. Основание —
  Г1, Г2, Г4 ([`../logs/grounding-check.md`](../logs/grounding-check.md)).
- **Г-B. Разделение шаблона по типу требования.** Шаблон «Система должна
  предоставить Пользователю возможность…» применим к пользовательским
  возможностям; автоматическое поведение формулировать «Система должна
  выполнить/обеспечить…». Основание — Д1.
- **Г-C. Протокол цитирования интерфейса.** Метки элементов UI приводить только
  дословно из приложенного макета или руководства, иначе помечать как
  предложение БА. Основание — Г3.
- **Г-D. Загрузка руководства по интеграции с amoCRM в БЗ.** Документ
  зарегистрирован в
  [`kb/sources/integration_amocrm/meta.json`](../../../../kb/sources/integration_amocrm/meta.json)
  (153 стр.), но PDF в репозитории нет и в `kb/processed/` он не обработан,
  поэтому ссылка БА «стр. 127» непроверяема ни человеком, ни моделью.
