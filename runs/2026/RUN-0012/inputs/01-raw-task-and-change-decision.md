# Вход 1 — Первоначальная постановка задачи и решение об изменении области доработки

> Сырой вход задачи. Текст приведён дословно из вложения issue #180

## 1. Первоначальная постановка задачи (входные данные)

Описание кейса, который хочет решить клиент на языке бизнес-потребности, а не
только список доработок.

Проблема в том, что при групповых звонках в «звонилке» виден только один абонент,
посмотреть других нет возможности. Такое поведение приложения небезопасно, тк не
позволяет контролировать участников звонка. Кроме того это отличается от
привычного поведения, от того как работают другие приложения звонков — показывают
всех участников.

## 3. Решение об изменении области доработки (обновления/правки)

Заказчик просил по результатам встречи направить резюме встречи и согласовать
действия. Ниже текст резюме встречи для согласования с заказчиком:

### 1. Контекст

- **Цель встречи:** По итогам комментариев к ФТ на доработку аудиоконференций
  выявлено значительное усложнение. На встрече исполнитель инициировал
  согласование концепции и критических требований к групповым звонкам
  (аудиоконференциям), чтобы сузить границы доработки и повторно обсудить корневую
  потребность.
- **Предметная область:** Корпоративные коммуникации Mango Talker, групповые
  звонки между сотрудниками.

### 2. Решения

- Отказаться от доработки существующих аудио конференций.
- Реализовать потребность через развитие функциональности видеоконференций в
  Mango Talker, а именно:
  - Добавить в раздел «Встречи» элемент интерфейса «Начать групповой звонок (с
    возможностью видео подключения)» (нативно понятнее).
  - Реализовать сценарий: инициация «Начать групповой звонок …» в один клик →
    интерфейс — множественный выбор сотрудников → инициация звонка → старт звонка
    со списком активных участников и элементами управления.
  - Обеспечить отображение всех приглашённых сотрудников (участников) и
    динамическое обновление списка при подключении/отключении участников; при
    длинном списке — возможность прокрутки.
  - В процессе звонка — звуковые сигналы о подключении/отключении участников.

### 3. Обсуждение

- **Корневая потребность и проблема аудиоконференций:** Аудиоконференции изначально
  выбраны из-за простоты инициации («позвонил — собрал группу — начали»). Однако в
  процессе группового звонка отсутствовало отображение списка участников, что
  создавало риск потери контроля над составом разговора и расходилось с привычным
  UX аналогов (например, Телемост, мессенджеры).
- **Почему не использовали готовые видеоконференции Mango Talker:** Текущий сценарий
  «Создать ссылку на видеоконференцию» критически неудобен — требует распространения
  ссылки, избыточен при приоритете голосового общения и не оптимизирован для
  быстрого старта с мобильных устройств.
- **Почему не задействовали чаты для группового звонка:** Функционал чатов в Mango
  Talker отключён политикой Компании, поэтому исключён сценарий инициации группового
  звонка одним нажатием через чат, хотя технически это позволило бы использовать
  текущие видеоконференции без доработки.
- **Опыт с внешними сервисами:** Использование Телемоста показало, что формат
  видеоконференции приемлем при условии быстрой инициации группового звонка без
  ссылок. Важно голосовое общение, видео не принципиально, но допустимо.
- **Итоговый выбор:** Доработка видеоконференций признана более перспективным
  продуктовым решением, способным повысить интуитивную понятность интерфейса Mango
  Talker (гипотеза), и одновременно закрывающим корневые требования к групповым
  звонкам (большую часть — «из коробки»).

### 4. Риски

- Гипотеза о повышении юзабилити интерфейса через новый сценарий требует валидации
  (UX-тестирование).
- Архитектурный риск: инициация группового звонка из раздела «Встречи» должна
  бесшовно интегрироваться с текущей логикой видеоконференций.

### 5. Шаги (совместно с Заказчиком)

- Заказчику — подтвердить, что описанное в резюме встречи решение корректно и/или
  дополнить его.
- Исполнителю:
  - согласовать с продуктовой командой возможность реализации доработки на основе
    видеоконференций Mango Talker;
  - после внутреннего согласования направить Заказчику обновлённые функциональные
    требования (ФТ) на доработку видеоконференций для согласования.
