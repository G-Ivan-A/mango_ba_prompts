# Шаг 5 — Раздел 4. Функциональные требования

> **Промпт:** [`fr-documentation-stepwise`](../../../../../prompts/fr-documentation-stepwise.md),
> Шаг 3. Иерархия — максимум 3 уровня: `4.x` (строгий формат «Система должна…»),
> `4.x.1` (детализация/бизнес-правило), `4.x.1.1` (атомарные значения). Задача —
> доработка существующей ВАТС, поэтому на уровне возможностей используется
> ключевое слово **«возможность»**.

## 4.1. Жизненный цикл ограниченного API-ключа

**4.1.1.** Система должна предоставлять Пользователю возможность создавать в Личном
кабинете дополнительный (ограниченный) API-ключ, отдельный от основного API-ключа.

- 4.1.1.1. Ограниченный ключ создаётся как самостоятельный секрет, не совпадающий с
  основным ключом.
- 4.1.1.2. При создании Пользователь обязан задать область действия ключа
  (Раздел 4.3); создание ключа с пустой областью действия не допускается (E4).

**4.1.2.** Система должна предоставлять Пользователю возможность просматривать в
Личном кабинете перечень созданных ограниченных ключей и их текущую область
действия.

**4.1.3.** Система должна предоставлять Пользователю возможность отзывать
(удалять) ограниченный ключ.

- 4.1.3.1. После отзыва любое обращение по отозванному ключу отклоняется (E5).

**4.1.4.** Система должна сохранять полный доступ основного API-ключа независимо от
наличия и настроек ограниченных ключей.

- 4.1.4.1. Ограничения области действия ограниченного ключа не изменяют права
  основного ключа (закреплено ответом Заказчика В3).

## 4.2. Ограничение области действия по методу

**4.2.1.** Система должна предоставлять по ограниченному ключу возможность получения
записей разговоров и только её.

- 4.2.1.1. Прочие методы API для ограниченного ключа закрыты по умолчанию
  (закреплено ответом Заказчика В2).
- 4.2.1.2. Обращение ограниченным ключом к методу, отличному от получения записей
  разговоров, отклоняется (E1).

## 4.3. Ограничение области действия по источникам записей

**4.3.1.** Система должна предоставлять Пользователю возможность ограничивать
множество сотрудников — источников записей, доступных по ограниченному ключу.

- 4.3.1.1. Способы задания области: выбор одной группы сотрудников, нескольких групп
  сотрудников, списка отдельных сотрудников или их сочетания (Happy Path, A1–A3;
  оба способа — допущение Д1, вопрос В-СКОП).
- 4.3.1.2. Итоговая область действия при комбинировании источников есть объединение
  выбранных групп и сотрудников (A3).

**4.3.2.** Система должна возвращать по ограниченному ключу только записи разговоров
сотрудников, входящих в область действия ключа.

- 4.3.2.1. Запрос записи сотрудника вне области действия отклоняется как выход за
  область (E2).
- 4.3.2.2. При изменении состава выбранной группы область действия ключа
  пересчитывается по актуальному составу группы (допущение Д2, вопрос В-ИЗМ; E3).
  `#поведение подлежит подтверждению Заказчиком (В-ИЗМ): динамическая vs`
  `#зафиксированная на момент выдачи область`

## 4.4. [ОПЦИЯ — отдельная оценка] Наблюдаемость использования ключа

> Опция по ответу Заказчика В5 («желательно, оценку отдельно»). Вне MVP (Д4).

**4.4.1.** Система должна предоставлять Пользователю возможность просматривать
статистику использования ограниченного ключа.

- 4.4.1.1. Минимальный состав показателей уточняется вопросом В-СТАТ (факт
  обращения, число выгрузок, дата последнего доступа).

## 4.5. [ОПЦИЯ — отдельная оценка] Временная деактивация ключа

> Опция по ответу Заказчика В6 («желательно, оценку отдельно»). Вне MVP (Д4).

**4.5.1.** Система должна предоставлять Пользователю возможность временно
приостанавливать действие ограниченного ключа без его удаления.

- 4.5.1.1. В период приостановки обращения по ключу отклоняются, а заданная область
  действия сохраняется для последующей повторной активации (E6).

## Матрица приоритетов

| ФТ | Приоритет | Обоснование |
| --- | --- | --- |
| 4.1.1, 4.1.4, 4.2.1 | **MUST** | Ядро задачи: отдельный ключ + только записи + неприкосновенность основного ключа. |
| 4.3.1, 4.3.2 | **MUST** | Без фильтрации по сотрудникам/группам цель (2.2) не достигается. |
| 4.1.2, 4.1.3 | **SHOULD** | Управляемость жизненного цикла ключа (просмотр/отзыв). |
| 4.4, 4.5 | **COULD** | Опции В5/В6 — отдельная оценка, вне MVP. |

Приоритеты по RFC 2119 / BCP 14 (см. [ADR-009](../../../../../docs/adr/009-bcreq-formation-process.md)).
