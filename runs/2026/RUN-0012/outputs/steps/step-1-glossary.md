# Шаг 1 — Раздел 1. Терминология (глоссарий)

> **Промпт:** [`glossary-context-understanding-stepwise`](../../../../../prompts/glossary-context-understanding-stepwise.md),
> Шаг 1. Базовые термины взяты из сырого запроса Заказчика как эталон; добавлены
> только критически важные для однозначного прочтения Раздела 4 (правило 4
> промпта — не плодить сущности).

## 1. Термины и определения

| № | Термин | Определение |
| --- | --- | --- |
| 1.1 | **ВАТС** | Виртуальная АТС MANGO OFFICE — облачная телефония, на которой работают сотрудники Клиента. |
| 1.2 | **Личный кабинет (ЛК)** | Веб-интерфейс управления ВАТС, в котором Пользователь Клиента настраивает сотрудников, группы и ключи доступа. |
| 1.3 | **Запись разговора** | Аудиофайл телефонного разговора сотрудника Клиента, сохранённый в ВАТС и доступный для выгрузки. |
| 1.4 | **API-ключ** | Секретный идентификатор, предъявляя который внешняя система получает программный доступ к данным Клиента в ВАТС. |
| 1.5 | **Основной API-ключ** | Действующий API-ключ Клиента с полным доступом ко всем разрешённым методам API; в рамках задачи не изменяется. |
| 1.6 | **Ограниченный API-ключ** | Новый, дополнительный API-ключ, область действия которого сужена: доступ только к получению записей разговоров и только по заданному перечню сотрудников/групп. |
| 1.7 | **Область действия ключа (scope)** | Набор ограничений ключа: разрешённые методы (только получение записей) и разрешённое множество сотрудников — источников записей. |
| 1.8 | **Сотрудник** | Учётная запись работника Клиента в ВАТС, за которой закреплены записи его разговоров. |
| 1.9 | **Группа сотрудников** | Объединение сотрудников в ЛК; используется как единица выбора при настройке области действия ограниченного ключа. |
| 1.10 | **Сторонний сервис (РА)** | Внешняя система Клиента (речевая аналитика / кастомная интеграция), которая по ограниченному ключу забирает записи разговоров. |
| 1.11 | **Пользователь** | Сотрудник Клиента с правами администрирования в ЛК, который создаёт и настраивает ограниченный ключ. |

## 2. Предложенные термины (обоснование)

- **1.6 «Ограниченный API-ключ»** и **1.7 «Область действия ключа»** — введены,
  потому что без них Раздел 4 не отделяет права нового ключа от основного (1.5) и
  требования становятся критически неоднозначными (правило 4 промпта). Разведение
  «основной / ограниченный» прямо следует из ответа Заказчика на вопрос 3.

## 3. Термины вне глоссария (сознательно не вводим)

- **«Роль», «политика доступа», «токен», «OAuth-scope»** — техническая/архитектурная
  лексика, запрещена на уровне Разделов 1–2 (правило 2 промпта). Механизм
  реализации ограничения — предмет технического дизайна, не ФТ.
