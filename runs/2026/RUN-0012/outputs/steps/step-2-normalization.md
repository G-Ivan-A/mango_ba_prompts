# Шаг 2 — Раздел 2. Проблема, Цель, Задачи

> **Промпт:** [`glossary-context-understanding-stepwise`](../../../../../prompts/glossary-context-understanding-stepwise.md),

## 2.1. Проблема

Сегодня программный доступ к данным Клиента в ВАТС предоставляется **единым
API-ключом** с полным набором прав. Для передачи записей разговоров стороннему
сервису РА Клиент вынужден передавать этот ключ целиком, что открывает внешней
системе доступ ко **всем** записям всех сотрудников и к прочим методам API. Клиент
оценивает это как неприемлемый риск разглашения данных: отсутствует возможность
сузить доступ до записей конкретных сотрудников или групп. Бизнес-последствие —
интеграция со сторонним сервисом РА блокируется или ведётся с избыточным уровнем
доступа, повышая риски по персональным данным и деловой информации.

## 2.2. Цель

Предоставить Клиенту возможность выдавать сторонней системе доступ к записям
разговоров **только по заданному перечню сотрудников или групп** и **только к
методу получения записей**, не затрагивая права основного API-ключа.

## 2.3. Задачи

- **2.3.1.** Обеспечение возможности создания дополнительного (ограниченного)
  API-ключа в Личном кабинете, независимого от основного ключа.
- **2.3.2.** Ограничение области действия такого ключа единственным методом —
  получением записей разговоров, с закрытием прочих методов API по умолчанию.
- **2.3.3.** Управление составом источников записей, доступных по ключу, на уровне
  списка сотрудников и/или групп сотрудников.
- **2.3.4.** Сохранение полного доступа основного API-ключа без влияния на него
  ограничений нового ключа.
- **2.3.5.** *(опционально, отдельная оценка — ответ В5)* Обеспечение наблюдаемости
  использования ограниченного ключа.
- **2.3.6.** *(опционально, отдельная оценка — ответ В6)* Обеспечение временного
  приостановления действия ограниченного ключа без его удаления.

## Разведение «боль ↔ решение»

| Боль (что болит у Клиента) | Решение (что даём) — НЕ подменять на этом уровне |
| --- | --- |
| Единый ключ = «всё или ничего» | Отдельный ключ с суженной областью действия (2.3.1–2.3.2) |
| Доступ ко всем записям всех сотрудников | Фильтрация источников по сотрудникам/группам (2.3.3) |
| Риск затронуть текущую интеграцию | Независимость от основного ключа (2.3.4) |
