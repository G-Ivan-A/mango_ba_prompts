# Шаг 1 — Глоссарий и контекст As-Is

> **Промпт:** `mango-glossary-context-understanding-stepwise` (ШАГ 0 — контекст из
> БЗ; ШАГ 1 — глоссарий; ШАГ 2 — проблема/цель/задачи в [Шаге 2](./step-2-normalization.md)).
> **Источник фактов:** только выжимка [`inputs/kb-files.md`](../../inputs/kb-files.md).

## ШАГ 0. Контекст As-Is (из выжимки БЗ)

Кратко, со ссылками на факты выжимки (Ф#) и первоисточник:

- В продукте есть голос, текстовые каналы (MANGO Диалоги/мессенджеры), e-mail, SMS,
  заказы обратного звонка — Ф1 [CC, §4.3, с.131].
- Очереди звонков и текста **независимы** — Ф2 [CC, §4.2, с.127].
- Есть настраиваемый лимит **одновременных текстовых** обращений на сотрудника — Ф3
  [LK, с.129].
- Кросс-канальная координация ограничена **одним чекбоксом** «не давать текст во время
  звонка» — Ф5 [LK, с.130].
- Есть одновременность **внутри голоса** (статус «Все звонки») — Ф6 [CC, §2.1, с.24].
- E-mail трактуется как фоновый канал (таймаут, авто-закрытие) — Ф7 [CC, §4.2, с.128].
- Межканального приоритета каналов **нет** — Ф8.
- Любой механизм затрагивает 2 слоя: настройка (ЛК ВАТС) и исполнение (КЦ) — Ф10.

> **Что это значит для разбора.** Требование заказчика — не «с нуля», а **обобщение и
> объединение** уже существующих частичных механизмов в единый межканальный механизм
> «лимит + приоритет». Это формирует фокус всех последующих шагов.

## ШАГ 1. Глоссарий

Термины разбиты на три группы: **из требования**, **из продукта (БЗ)**,
**неоднозначные** (требуют согласования — переходят в [Шаг 3](./step-3-questions.md)).

### Термины из требования

| Термин | Рабочее определение | Привязка к продукту / статус |
| --- | --- | --- |
| Агент | Сотрудник, обрабатывающий обращения на рабочем месте КЦ. В продукте — роль **Оператор** | Ф9 [CC, §2.3.1, с.30] |
| Обращение | Единица коммуникации «клиент ↔ компания» в модуле «Обращения» | Ф1 [CC, §4, с.124] |
| Канал связи | Среда обращения: голос / чат / e-mail (в требовании — эти три) | Ф1 |
| Голосовой звонок | Звонковый канал реального времени | Ф1 [CC, §2.3.1, с.28] |
| Чат | Текстовый канал реального времени (MANGO Диалоги/мессенджеры) | Ф1 [CC, §4.3, с.131] |
| E-mail | Асинхронный текстовый канал, обрабатываемый в фоне | Ф7 [CC, §4.2, с.128] |
| Приоритетность | Порядок обслуживания каналов: голос > чат > e-mail (в требовании) | **Нет в продукте** — Ф8 |
| Активный контакт | Обращение, одновременно находящееся «в работе» у агента (см. неоднозначные) | частично — Ф3 |
| Механизм | Совокупность правил распределения/лимита/приоритета (настройка ЛК + исполнение КЦ) | Ф10 |

### Термины из продукта (БЗ), нужные для разбора

| Термин | Определение (из БЗ) | Источник |
| --- | --- | --- |
| Очередь обращений | Панель с раздельными вкладками «Вызовы»/«Текст»/«Заказы обратного звонка» | Ф2 [CC, §2.3, с.27] |
| Лимит текстовых обращений | Макс. число одновременных текстовых обращений на сотрудника (0 = без лимита) | Ф3 [LK, с.129] |
| Статус «Все звонки» | Одновременная обработка входящих + обзвона (только голос) | Ф6 [CC, §2.1, с.24] |
| Алгоритм распределения | «Наименее загруженный» / «равномерное» (для текста) | Ф4 [LK, с.129] |
| Ответственный оператор | Оператор, закреплённый за клиентом для авто-распределения | Ф4 [CC, §4.2, с.128] |
| Роли | Оператор / Супервизор / Администратор / Руководитель компании | Ф9 [CC, §4, с.124] |
| Слой настройки | ЛК ВАТС — где задаются правила/лимиты/каналы | Ф10 |
| Слой исполнения | Контакт-центр — рабочее место оператора | Ф10 |

### Неоднозначные термины (→ вопросы заказчику)

| Термин | В чём неоднозначность | Куда вынесено |
| --- | --- | --- |
| «активный контакт» | Считается ли удержанный звонок? Открытый, но «спящий» чат? Назначенный, но не открытый e-mail? | [Шаг 3](./step-3-questions.md), В1 |
| «одновременная работа» | Параллельно в один момент времени или переключение между обращениями? | Шаг 3, В2 |
| «максимум 3» | Жёсткий потолок на агента или настраиваемый параметр (как Ф3)? Считается ли голос в эти 3? | Шаг 3, В3 |
| «приоритетность» | Порядок распределения, право прерывания или порядок отображения в UI? | Шаг 3, В4 |
