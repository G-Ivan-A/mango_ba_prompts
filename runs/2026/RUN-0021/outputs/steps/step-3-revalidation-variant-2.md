Анализ исходных требований

Полнота покрытия кейсов. В исходном тексте не учтены пограничные случаи (edge cases). Во-первых, не указано, как система должна вести себя, если комментарий к номеру ВАТС пустой. Во-вторых, не определена чувствительность поиска к регистру (что критично для UX). В-третьих, не зафиксировано время жизни сохраненного состояния выбранных номеров (до конца сессии или до явного сброса).

Однозначность. Формулировка «доступных для отчёта» в п. 4.1.1 допускает двоякое толкование. Необходимо явно указать, что доступность определяется правами доступа Пользователя. Также термин «мастер-выбор» требует четкого привязывания к текущему результирующему списку, чтобы избежать путаницы с общим списком номеров.

Дублирование. Пункты 4.2.1 и 4.2.2 фактически дублируют друг друга (поиск по вхождению и формирование списка — это единый процесс). Пункт 4.4.3 полностью дублирует логику состояния по умолчанию, уже описанную в п. 4.1.4. Пункт 4.3.4 описывает бизнес-логику фильтрации (логика ИЛИ), а не поведение UI-элемента, поэтому его логичнее перенести в раздел 4.4.

Противоречия. Явных логических противоречий не выявлено, однако структура нумерации в исходнике нарушает стандарт (используется нумерация 4.2.1.1, тогда как по стандартам четвертый уровень и далее должен оформляться списком с разметкой точкой).

Предлагаемые изменения и формулировки

Все содержательные изменения выделены жирным шрифтом. Структура нумерации приведена в соответствие со стандартом.

4.1. Фильтр по номерам ВАТС в «Анализе по чек-листам» (FR-01)

4.1. Система должна отображать в блоке фильтров отчёта «Анализ по чек-листам» фильтр по номерам ВАТС.

4.1.1. Система должна отображать в фильтре список номеров ВАТС Заказчика, **доступных Пользователю согласно его правам доступа**.

4.1.2. Система должна отображать рядом с каждым номером ВАТС его комментарий из Личного кабинета ВАТС.

. **При отсутствии комментария к номеру ВАТС система должна отображать пустую строку или соответствующий плейсхолдер.**

4.1.3. Система должна использовать комментарий к номеру ВАТС в текущем виде (As-Is), без изменения поля «Комментарий» в ЛК ВАТС.

4.1.4. Состояние по умолчанию: ни один номер ВАТС в фильтре не выбран, поле поиска пустое, фильтр по номерам не применяется.

4.2. Гибридный поиск по номеру и комментарию (FR-02)

4.2. Система должна предоставлять в фильтре по номерам ВАТС поле поиска по номерам и комментариям.

4.2.1. Система должна выполнять **регистронезависимый** поиск по вхождению введённой строки: включать в результат номера ВАТС, у которых введённая строка встречается в номере телефона или в комментарии.

. Между полями «номер» и «комментарий» при поиске действует логика ИЛИ (совпадение хотя бы по одному полю включает номер в результат).

4.2.2. **Система должна динамически обновлять** результирующий список номеров ВАТС **по мере ввода** строки поиска.

4.2.3. При пустой строке поиска система должна отображать полный список доступных номеров ВАТС без фильтрации по вхождению.

4.3. Мультивыбор и мастер-выбор (FR-03)

4.3. Система должна предоставлять Пользователю выбор нескольких номеров ВАТС в фильтре.

4.3.1. Система должна позволять отметить или снять отметку с отдельного номера ВАТС (чекбокс).

4.3.2. Система должна предоставлять мастер-выбор (мастер-чекбокс), отмечающий или снимающий отметку сразу со всех номеров ВАТС текущего результирующего списка поиска.

4.3.3. Система должна сохранять ранее отмеченные номера ВАТС при изменении строки поиска, чтобы Пользователь мог собрать выбор в несколько заходов по разным запросам.

. **Сохранение состояния выбранных номеров действует до явного сброса фильтра или завершения пользовательской сессии.**

4.3.4. Система должна применять фильтр по выбранным номерам ВАТС при инициации Пользователем действия «Выбрать» и запоминать состояние выбранных номеров.

4.3.5. Система должна предоставлять возможность сбросить выбранные номера ВАТС и вернуть фильтр в состояние по умолчанию (4.1.4).

4.4. Результаты оценки по чек-листам по выбранным номерам (FR-04)

4.4. Система должна предоставлять Пользователю результаты оценки по чек-листам по выбранному набору номеров ВАТС.

4.4.1. **Внутри фильтра по номерам ВАТС между выбранными номерами действует логика ИЛИ: в отчёт попадают разговоры по любому из выбранных номеров.**

4.4.2. Система должна включать в результат отчёта «Анализ по чек-листам» только разговоры по выбранным в фильтре номерам ВАТС.

4.4.3. Система должна отображать результаты оценки по выбранным номерам ВАТС на странице статистики отчёта «Анализ по чек-листам**. Раздел 5 и 6 остаются без изменений, так как они не содержат функциональных требований и корректно описывают контекст.**
