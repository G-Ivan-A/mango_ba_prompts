# Отчёт RUN-0083: синтетический прогон A-IN, v0.1 против черновиков «по тесту»

## Зачем прогон

Владелец просит короткий путь к тестированию промптов этапа 1 на сайте
«даже при использовании синтетических прогонов», минимум на A-IN
(issue #446, пункт 4). Новые задачи до готовности набора не
прогоняются. Черновики «по тесту» Ш-0, Ш-1, Ш-2 golden set не измерял:
до RUN-0083 они были в run kit только справочно.

RUN-0083 отвечает на один вопрос: можно ли дать БА эти черновики для
теста (режим `by-test` в run kit v0.3), или на сайт идёт только v0.1.
Правило решения записано и закоммичено до запуска подагентов:
[`preregistration.md`](../logs/preregistration.md).

## Версии

- задача: SIM-1106 из сида [RUN-0078](../../RUN-0078/inputs/seed.json):
  уведомление о записи исходящего разговора; вход —
  [`input-pack.md`](../inputs/input-pack.md);
- сценарий БА: [`ba-script.md`](../inputs/ba-script.md);
- база знаний: runtime `f31dcde33f0bc120244128faab98fc0162e45701` (срез
  реестра runtime 0.4);
- P: опубликованные v0.1 Ш-0, Ш-1, Ш-2 (`prompts/`);
- T: черновики BL-156 «по тесту» тех же шагов (`prompts/drafts/`, реестр 0.4);
- SHA-256 шести текстов — поле `prompts` в [`summary.json`](summary.json).

## Правило решения (из пред-регистрации)

1. T идёт в run kit v0.3 как `by-test`, если сдал **не меньше**
   критериев, чем P, **и** у T нет провала по критическим J03, J07, J11
   (доказательства, вымысел, гейт).
2. Каждый провал T правится в `prompts/drafts/` в этом PR или переносится
   в бэклог с обоснованием.
3. Иначе на сайт идёт только v0.1.
4. N = 1 — дымовой тест пригодности; публикацию в `prompts/` он не решает.

Полужирным выделены критические критерии. Обоснования и цитаты судьи —
[`judge-scores.json`](judge-scores.json). Судья сверил ключевые цитаты
As-Is, узлы каталога и глоссарий с клоном runtime: совпадают.

## Решение

| Проверка | Факт | Итог |
| --- | --- | --- |
| T сдал не меньше P | 12 ≥ 10 | да |
| У T нет провала по J03, J07, J11 | провалов нет | да |

**По правилу, заданному до прогона, черновики A-IN (Ш-0, Ш-1, Ш-2) идут
в run kit v0.3 как `by-test`.** Остальные шаги остаются `published`: их
черновики не мерил ни golden set, ни синтетический прогон. Провалов T
нет, поэтому п. 2 правила ничего не правит
(`t_fail_handling: {}` в [`summary.json`](summary.json)). В `prompts/`
ничего не меняется (п. 4).

Сравнение решает судья (`overall: T`): T доводит Ш-2 до рабочего
результата. Он классифицирует термины по С0–С4 с локаторами, даёт
рекомендацию по гейту Г-IN и разводит двусмысленности поправки БА
(«ручной режим», «клиентское плечо») на варианты, ничего не выбирая
молча.

## Что показал прогон

### Где черновик лучше v0.1

1. **Гибридный гейт Г-IN (J11).** v0.1 Ш-2 перечисляет факты по
   критериям Г-IN.1–Г-IN.5 и оставляет решение БА без рекомендации. Блок
   «по тесту» несёт тип гейта и колонку «Что делает модель». По ней T
   дал рекомендацию «доработать A-IN» с основаниями и записал решение в
   8.5 как ожидающее БА. Это поведение гейта типа `гибрид` по базовому
   стандарту, раздел 4: модель рекомендует, решает человек.
2. **Сверка терминов (J10).** v0.1 при недоступных словарях D1…D11 не
   классифицировал ни одного термина («не проверено — словарь
   недоступен»), хотя руководства runtime их описывают. T классифицировал
   термины по базе знаний и глоссарию И-6 с локатором. Пример: «Запись
   разговора — ЛК §4.5.3, Mango Talker §6.11 — С4, термин продукта». Вывод:
   правило реестра 0.4 «читать глоссарий класса и руководства runtime»
   закрывает пробел, когда стандарты спицы недоступны.

### Что одинаково у обоих плеч

- Оба соблюли стоп-гейты, scope-поправку S-56, исключения Заказчика и
  неизвестные команды (J01, J06, J08, J09).
- Оба честно вывели «Режим fallback: детальные стандарты недоступны» и
  перечислили недоступные ссылки (J12). В песочнице исполнителя не было
  веба, поэтому ссылки `blob/main` спицы не открывались.
- Ближе всего к провалу у обоих был J04 (релевантность): в дайджест
  попала цитата о стоимости записи по тарифу. С уведомлением о записи
  она связана слабо.

## Что исправить

| № | Наблюдение | Действие | Где |
| --- | --- | --- | --- |
| И-1 | Провалов T нет | Черновики A-IN не правятся | — |
| И-2 | Черновики вдвое больше v0.1: Ш-0 — 54 КБ против 35, Ш-1 — 44 против 20, Ш-2 — 41 против 20 | Ничего сейчас: окно модели вмещает. В run kit — проверка БА: «модель прочитала промпт целиком» (блок receipt). Сокращение блока «по тесту» — ADR обратного согласования (BL-158) | run kit, раздел 1 |
| И-3 | Строка «Режим fallback…» в ответе модели — норма поведения при недоступной ссылке, а не сбой | В run kit: БА записывает недоступные ссылки в карточку (`notes`) и при нужде прикладывает файл | run kit, раздел 1 |
| И-4 | J04 на грани у обоих (цитата о тарифе) | Не дефект текста по одному замеру. Повторить наблюдение в первом прогоне BL-111 | BL-157в |

## Runtime

Владелец: runtime — пока база знаний для обращения из промптов; если
нужны доработки — RFC или альтернатива (issue #446, пункт 5). RUN-0083
нашёл одну доработку runtime и два пробела среды.

| № | Пробел | Факт RUN-0083 | Чья зона | Что предлагается |
| --- | --- | --- | --- | --- |
| Р-1 | Карта разделов документа не читается за одно обращение | P: `maps/mango-lk-manual.json` — «частично: строки 1–60 и 560–1599; целиком файл не читается (превышен лимит)», `maps/mtalker--windows-mac-working.json` — строки 1–799. Из 25 карт 11 больше 32 КБ, крупнейшая — 156 КБ ([`kb-map-sizes.log`](../../../../experiments/issue_446/kb-map-sizes.log)) | runtime | РТ-7: компактное оглавление документа («раздел, название, файл») — у всех 25 документов не больше 28 КБ. Тело задачи — [RFC-RT-001, раздел 14.3](../../../../docs/rfc/2026-11-runtime-product-catalog-golden-set.md#143-рт-7--тело-задачи-для-mango-ba-ai-runtime-копировать-целиком). Альтернатива без runtime — БА прикладывает нужные разделы |
| Р-2 | Стандарты спицы, на которые ссылаются промпты, недоступны модели без веба | Оба плеча — «Режим fallback»; T: «ACCESS_GAP: тела словарей и стандарт композиции §4 недоступны» | спица, среда чата | Не runtime. Каталог `taxonomy/mango-products.yaml` (98 КБ) читался частями без
потерь: одна строка — один узел. Доработки не требует.

## Ограничения

1. N = 1 на плечо: прогон отличает «пригоден к тесту» от «не пригоден»,
   но не меряет качество. Разброс исполнителя на одном тексте RUN-0082
   показал большой (ядро 6…10 из 11).
2. Исполнитель и судья — одна модель (`claude-opus-5-5`), хотя и в
   изолированных подагентах.
3. Вход и реплики БА синтетические, задача одна (SIM-1106, класс
   `voice-ucaas`). Классы `contact-center` и `analytics-reporting` не
   проверены.
4. Остаток слепоты: транскрипт Y по содержанию упоминает блок «по
   тесту». Это свойство текста T, замаскировать его нельзя.
5. Человек оценки не подтверждал (`ba_reviewed: false`): владелец снял
   человеческий гейт на итерацию (issue #446, пункт 3).

## Вывод

Черновики «по тесту» A-IN пригодны к тесту БА: на синтетическом
диалоге они не хуже v0.1 ни по одному из 12 критериев и закрывают два
провала v0.1 — гибридный гейт Г-IN и сверку терминов без словарей
спицы. Run kit v0.3 назначает их режимом `by-test`, сайт показывает их
кнопкой копирования. Публикацию в `prompts/` решает только golden set с
одновременным контролем (Р-03). Доказательство на практике даст первый
прогон BL-111 с набором (BL-157в).
