## Сырой запрос Заказчика

- Проблема. В кабинете HeadHunter у Заказчика общий кабинет, у каждого рекрутера
  свой логин и пароль. Сотрудник видит только свои вакансии и чаты (обращения к
  нему). Рекрутер не может передать чат другому сотруднику. Чаты остаются без
  ответа, компания теряет кандидатов.
- Цель. Настроить интеграцию между HeadHunter и Контакт-центром Mango Office по
  подгрузке чатов в КЦ, чтобы оператор работал в одном окне и история общения с
  кандидатом не терялась.
- Финальная цель (вне scope текущей задачи). Отображение истории переписки с
  кандидатом в карточке Skillaz.
- As-Is. В КЦ Mango не подгружается переписка с кандидатом из HeadHunter.
- To-Be. Обращение от кандидата должно попадать в КЦ на группу «Чатеры». В
  карточке обращения должны быть минимальные данные о кандидате: ФИО, номер
  телефона, вакансия, на которую кандидат откликнулся и написал сообщение.

## Контекст и границы проекта (согласование с Заказчиком)

- Предпосылки. Каждый рекрутер закреплён за регионом и работает в индивидуальном
  личном кабинете HeadHunter без доступа к чатам других специалистов и без
  возможности передачи переписки другому рекрутеру. Отсутствие гибкости в
  распределении нагрузки затрудняет круглосуточную обработку откликов и приводит
  к потере кандидатов, особенно в сегменте массового подбора линейного персонала.
- Цель. Интегрировать чаты HeadHunter с Контакт-центром Mango Office для
  централизованного управления обращениями кандидатов.
- Задачи Заказчика:
  - обработка обращений кандидатов из HeadHunter в «Чате с клиентами» КЦ;
    синхронизация переписки (рекрутер пишет на стороне КЦ, кандидат — на стороне
    HeadHunter); все обращения из HeadHunter падают не на отдельного менеджера, а
    на группу в КЦ «Чатеры»;
  - фильтрация обращений по вакансиям; в КЦ передаются только обращения по
    линейному персоналу (вакансии на офисный персонал игнорируются); фильтруются
    только сообщения в чатах (не отклики);
  - перевод обращений из HeadHunter в КЦ на группу «Чатеры» (с возможностью
    настройки логики маршрутизации на сотрудников аналогично продуктам Mango
    Office для групп и каналов) с обработкой откликов 24/7.

## Дополнительный запрос Заказчика (новое требование)

- Учитывать, что в чате HeadHunter несколько акторов — перепроверить по
  документации HeadHunter.
- Ссылка на API HeadHunter: <https://api.hh.ru/openapi/redoc#tag/Chaty>.
- С чатами можно работать одним из двух путей (допускается комбинация):
  1. Через новый отклик/приглашение на вакансию: при создании отклика
     автоматически создаётся чат; в ответе метода получения отклика содержится
     `chat_id`; далее доступен метод получения сообщений чата.
  2. Через получение новых чатов из списка чатов авторизованного пользователя.
  3. Добавлен вебхук на новое сообщение в чате — событие `CHAT_MESSAGE_CREATED`.
- Ключевое уточнение по акторам: чат автоматически формируется только для
  менеджера, ответственного за вакансию (поэтому в списке чатов он есть только у
  этого менеджера). Если начать писать в чат от имени другого пользователя, он
  будет добавлен как участник чата.
