## 1. Термины и определения

**Система** — совокупность интегрированных продуктов Mango Office, участвующих в
реализации требований документа (Контакт-центр, Личный кабинет, текстовые
каналы).

**КЦ** — Контакт-центр Mango Office: SaaS-продукт для многоканального
взаимодействия с клиентами через единую платформу.

**ЛК** — Личный кабинет Mango Office: интерфейс управления сервисами и настройками
продуктов Mango Office.

**Внешняя система** — сторонняя платформа, интегрируемая с продуктами Mango
Office для обмена данными и управления взаимодействиями. В рамках задачи внешняя
система — HeadHunter.

**HeadHunter** — онлайн-платформа поиска работы и подбора персонала,
предоставляющая API чатов с кандидатами.

**Чат HeadHunter** — переписка между кандидатом и компанией на стороне
HeadHunter, привязанная к вакансии и кандидату.

**Актор чата HeadHunter** — участник чата HeadHunter со стороны компании;
автоматически создаётся для менеджера, ответственного за вакансию; иные
пользователи становятся участниками при отправке сообщения в чат.

**Чат с клиентом КЦ** — функциональность КЦ для обработки текстовых обращений из
интегрированных каналов коммуникации.

**Обращение** — текстовый запрос кандидата, обрабатываемый в КЦ как единица
работы оператора.

**Группа «Чатеры»** — группа КЦ, на которую маршрутизируются обращения кандидатов
из HeadHunter для обработки в режиме 24/7.

**Канал HeadHunter** — подключаемый в Mango Office текстовый канал, обеспечивающий
приём и синхронизацию чатов HeadHunter в КЦ.

**Адресная книга КЦ (АК)** — справочник контактов Mango Office для хранения
данных кандидатов.

**Кандидат** — физическое лицо (соискатель), коммуницирующее с компанией через
чат HeadHunter.

**Рекрутер** — сотрудник Заказчика из группы «Чатеры», обрабатывающий обращения
кандидатов в КЦ.

**Линейный персонал** — массовые вакансии Заказчика, обращения по которым
передаются в КЦ; вакансии на офисный персонал из синхронизации исключаются.

## 2. Проблема, цель, задачи

### 2.1. Проблема

Заказчик ведёт подбор персонала через чаты HeadHunter. Каждый рекрутер закреплён
за регионом и работает в индивидуальном личном кабинете HeadHunter. Рекрутер
видит только свои вакансии и чаты и не может передать переписку с кандидатом
другому сотруднику. При отсутствии или загрузке рекрутера чаты остаются без
ответа. Отсутствие гибкого распределения нагрузки затрудняет круглосуточную
обработку откликов и приводит к потере кандидатов, особенно в сегменте массового
подбора линейного персонала. Переписка с кандидатом из HeadHunter в КЦ не
подгружается, поэтому единое окно обработки и сохранение истории общения
недоступны.

### 2.2. Цель

Обеспечить централизованную круглосуточную обработку обращений кандидатов из
HeadHunter в Контакт-центре Mango Office в едином окне, с сохранением истории
общения и данных кандидата.

### 2.3. Задачи

2.3.1. Обеспечить передачу обращений кандидатов из чатов HeadHunter в Чат с
клиентом КЦ с маршрутизацией на группу «Чатеры».

2.3.2. Обеспечить двустороннюю синхронизацию переписки между чатом HeadHunter и
Чатом с клиентом КЦ без необходимости доступа рекрутеров в HeadHunter.

2.3.3. Обеспечить учёт нескольких акторов чата HeadHunter в рамках одного
обращения КЦ.

2.3.4. Обеспечить фильтрацию обращений по вакансиям и передачу в КЦ только
обращений по линейному персоналу.

2.3.5. Обеспечить передачу минимальных данных о кандидате и вакансии в обращение
КЦ и их сохранение в адресную книгу КЦ.

### 2.4. Ожидаемые результаты и эффект

2.4.1. Круглосуточная обработка обращений кандидатов силами группы «Чатеры» без
привязки к индивидуальному рекрутеру.

2.4.2. Снижение потерь кандидатов за счёт исключения чатов без ответа.

2.4.3. Сохранение истории общения и данных кандидата в едином окне КЦ.

> Числовые целевые метрики Заказчиком не подтверждены и в документ не вносятся.

## 3. Ожидаемое решение

### 3.1. Концепция решения

Решение добавляет в Mango Office канал HeadHunter, который принимает сообщения
кандидатов из чатов HeadHunter и создаёт обращения в Чате с клиентом КЦ.
Обращения маршрутизируются на группу «Чатеры». Рекрутер обрабатывает обращение в
КЦ, а его ответы синхронизируются обратно в чат HeadHunter; доступ рекрутера в
HeadHunter не требуется. Данные кандидата и вакансии передаются в обращение и
сохраняются в адресную книгу КЦ. Обращения фильтруются по вакансиям: в КЦ
передаются только обращения по линейному персоналу.

Поток (high-level, текстовая модель):

1. Кандидат пишет сообщение в чат HeadHunter по вакансии.
2. Система получает сообщение чата HeadHunter и проверяет вакансию по правилам
   фильтрации линейного персонала.
3. Система создаёт обращение в Чате с клиентом КЦ и маршрутизирует его на группу
   «Чатеры».
4. Рекрутер группы «Чатеры» берёт обращение в работу и отвечает в КЦ.
5. Система синхронизирует ответ рекрутера в чат HeadHunter, а новые сообщения
   кандидата — в обращение КЦ.
6. Система сохраняет данные кандидата в адресную книгу КЦ.

### 3.2. Границы решения (Scope)

| Элемент | В Scope | Вне Scope |
| --- | --- | --- |
| Канал | Канал HeadHunter в Mango Office (`messenger-channel-service`) | Иные источники откликов HeadHunter, кроме чатов |
| Обращения | Создание обращения по сообщению кандидата | Создание обращения по отклику без сообщения (продуктовая опция, не требование Заказчика) |
| Маршрутизация | На группу «Чатеры» (`cc-interaction-routing-service`) | Изменение текущей логики очередей КЦ |
| Синхронизация | Двусторонняя синхронизация сообщений чата | Перенос истории в карточку Skillaz (финальная цель Заказчика, вне задачи) |
| Данные | ФИО, телефон, вакансия кандидата; запись в адресную книгу КЦ | Управление статусами кандидата и блокировками (не требуется Заказчиком) |
| Доступ | Обработка без доступа рекрутеров в HeadHunter | Доступ группы «Чатеры» в личные кабинеты HeadHunter |

### 3.3. Затрагиваемые системы и компоненты

| Система / компонент | Тип воздействия |
| --- | --- |
| Канал HeadHunter в текстовых каналах (`messenger-channel-service`) | Новая разработка |
| Группа текстовых каналов и её настройки (`digital-channel-group-service`) | Изменение |
| Маршрутизация обращений КЦ на группу «Чатеры» (`cc-interaction-routing-service`) | Использование с настройкой |
| Синхронизация сообщений и сессий (`dialog-api-messaging-service`) | Изменение |
| Адресная книга КЦ (`mango-contact-center-official`) | Изменение |
| Чат с клиентом КЦ (очередь «Текст») | Использование без изменений |
| API чатов HeadHunter (внешняя система) | Интеграция |

### 3.4. Пользователи и заинтересованные стороны

| Роль | Влияние |
| --- | --- |
| Рекрутер группы «Чатеры» | Обрабатывает обращения кандидатов в КЦ |
| Администратор Заказчика | Подключает и настраивает канал HeadHunter в ЛК |
| Кандидат | Источник обращений; пишет в чат HeadHunter |
| HeadHunter | Внешняя система — источник и получатель сообщений чата |

### 3.5. Моделирование вариантов решения

3.5.1. Quick win. Передавать сообщения кандидата из HeadHunter в КЦ
односторонне, без обратной синхронизации ответов рекрутера. Не закрывает задачу:
рекрутер не может отвечать кандидату из единого окна.

3.5.2. Recommended. Новый текстовый канал HeadHunter в Mango Office по аналогии с
каналом «Авито Работа»: двусторонняя синхронизация чатов, маршрутизация на группу
«Чатеры», фильтрация по вакансиям, сохранение данных кандидата. Вариант
переиспользует подтверждённую модель текстовых каналов и сессий
(`dialog-api-messaging-service`) и закрывает все задачи раздела 2.3.

3.5.3. Target. Расширить канал двусторонним обновлением статусов откликов
HeadHunter и реакцией на отклики без сообщения. Требует уточнения статусной модели
откликов HeadHunter; источник не подтверждён и помечается как не подтверждённый.

Выбран вариант 3.5.2 (Recommended).

## 4. Функциональные требования и сценарии использования

### 4.1. Подключение и настройка канала HeadHunter (FR-01)

4.1. Система должна предоставлять Администратору возможность подключения и
настройки канала HeadHunter в Mango Office с авторизацией во внешней системе
HeadHunter.

* 4.1.1. Система должна предоставлять подключение канала HeadHunter в группе
  текстовых каналов аналогично другим текстовым каналам.
* 4.1.2. Система должна выполнять авторизацию в HeadHunter для доступа к чатам
  кандидатов.
  * 4.1.2.1. Способ авторизации определяется возможностями API HeadHunter и
    уточняется на этапе технического проектирования (см. раздел 8, открытые
    вопросы).
* 4.1.3. Система должна применять к каналу HeadHunter настройки приёма и
  обработки обращений, доступные для текстовых каналов: распределение обращений,
  автоматические ответы, приветствие, общие настройки, автоматическое завершение
  диалогов.
* 4.1.4. Система должна создавать обращение на основе сообщения кандидата в чате
  HeadHunter.
  * 4.1.4.1. Создание обращения на основе отклика без сообщения — продуктовая
    опция; в scope Заказчика не входит и по умолчанию выключена.
* 4.1.5. Система должна предоставлять Администратору возможность отключения
  канала HeadHunter.

### 4.2. Передача обращений в КЦ и маршрутизация на группу «Чатеры» (FR-02)

4.2. Система должна передавать обращения кандидатов из чатов HeadHunter в Чат с
клиентом КЦ и маршрутизировать их на группу «Чатеры».

* 4.2.1. Система должна создавать обращение в Чате с клиентом КЦ при поступлении
  сообщения кандидата в чат HeadHunter в соответствии с настройками канала.
* 4.2.2. Система должна маршрутизировать обращение на группу «Чатеры».
  * 4.2.2.1. Система должна допускать настройку логики маршрутизации на
    сотрудников группы аналогично текущим правилам распределения текстовых
    каналов.
* 4.2.3. Система должна обеспечивать обработку обращений в режиме 24/7
  независимо от индивидуального рекрутера HeadHunter.
* 4.2.4. Система должна создавать отдельное обращение для сообщения того же
  кандидата по другой вакансии.
* 4.2.5. Система должна создавать новое обращение при поступлении сообщения
  кандидата по вакансии, по которой предыдущее обращение закрыто.

### 4.3. Двусторонняя синхронизация переписки (FR-03)

4.3. Система должна обеспечивать двустороннюю синхронизацию переписки между чатом
HeadHunter и Чатом с клиентом КЦ без доступа рекрутеров в HeadHunter.

* 4.3.1. Система должна передавать сообщения кандидата из чата HeadHunter в
  обращение КЦ.
* 4.3.2. Система должна передавать ответы рекрутера из обращения КЦ в чат
  HeadHunter.
* 4.3.3. Система должна синхронизировать текстовые сообщения и вложения,
  поддерживаемые чатом HeadHunter.
* 4.3.4. Система должна закрывать обращение и сохранять сессию переписки при
  закрытии обращения по правилам обработки текстовых обращений, по настройкам
  канала или по завершению обращения рекрутером.

### 4.4. Учёт нескольких акторов чата HeadHunter (FR-04)

4.4. Система должна учитывать нескольких акторов чата HeadHunter в рамках одного
обращения КЦ.

* 4.4.1. Система должна синхронизировать в одно обращение КЦ все сообщения чата
  HeadHunter по паре «кандидат и вакансия» независимо от того, какой актор со
  стороны компании отправил сообщение.
* 4.4.2. Система должна различать в обращении сообщения кандидата и сообщения
  акторов со стороны компании.
* 4.4.3. Система должна сохранять автора каждого входящего сообщения со стороны
  компании (идентификатор или имя актора HeadHunter).
* 4.4.4. Система должна отправлять ответы рекрутера группы «Чатеры» в чат
  HeadHunter от имени авторизованного аккаунта интеграции.
  * 4.4.4.1. Аккаунт интеграции, отправивший сообщение, добавляется в чат
    HeadHunter как участник; это штатное поведение API HeadHunter.
* 4.4.5. Система должна получать сообщения чата HeadHunter способом, не зависящим
  от того, является ли аккаунт ответственным за вакансию менеджером.
  * 4.4.5.1. Чат HeadHunter автоматически создаётся только у менеджера,
    ответственного за вакансию; источником новых сообщений выступает событие
    нового сообщения чата и список чатов авторизованного аккаунта.

### 4.5. Фильтрация обращений по вакансиям (FR-05)

4.5. Система должна фильтровать обращения по вакансиям и передавать в КЦ только
обращения по линейному персоналу.

* 4.5.1. Система должна определять принадлежность вакансии к линейному персоналу
  по согласованному признаку вакансии HeadHunter.
  * 4.5.1.1. Признак фильтрации (например, «Код вакансии») согласуется с
    HeadHunter и Заказчиком (см. раздел 8, открытые вопросы).
* 4.5.2. Система должна исключать из передачи в КЦ обращения по вакансиям на
  офисный персонал.
* 4.5.3. Система должна фильтровать только сообщения в чатах; отклики без
  сообщения не передаются.

### 4.6. Передача данных о кандидате и вакансии (FR-06)

4.6. Система должна передавать в обращение КЦ минимальные данные о кандидате и
вакансии.

* 4.6.1. Система должна передавать в обращение данные кандидата:
  * 4.6.1.1. ФИО кандидата.
  * 4.6.1.2. Идентификатор кандидата в HeadHunter.
  * 4.6.1.3. Номер телефона кандидата при наличии.
* 4.6.2. Система должна передавать в обращение данные вакансии:
  * 4.6.2.1. Название вакансии.
  * 4.6.2.2. Ссылку на вакансию.
* 4.6.3. Система должна передавать текст сообщения или сообщений кандидата,
  поступивших до взятия обращения в работу.

### 4.7. Сохранение данных о кандидате в адресную книгу КЦ (FR-07)

4.7. Система должна сохранять данные о кандидате в адресную книгу КЦ.

* 4.7.1. Система должна сопоставлять кандидата с контактом адресной книги:
  * 4.7.1.1. По идентификатору кандидата в HeadHunter — основной ключ.
  * 4.7.1.2. По номеру телефона кандидата — дополнительная проверка.
* 4.7.2. Система должна создавать новый контакт, если данные о кандидате в
  адресной книге отсутствуют.
* 4.7.3. Система должна дополнять карточку контакта при частичном совпадении
  данных:
  * 4.7.3.1. При совпадении идентификатора HeadHunter и различии телефонов —
    добавлять новый телефон в карточку.
  * 4.7.3.2. При совпадении телефона и различии идентификаторов — добавлять
    идентификатор HeadHunter в карточку.
* 4.7.4. Система не должна обновлять карточку контакта при полном совпадении
  данных.

## 6. Особенности реализации

### 6.1. Ограничения

6.1.1. Рекрутеры группы «Чатеры» не имеют доступа в личные кабинеты HeadHunter;
обработка и ответы выполняются только на стороне КЦ (issue #237, Q4).

6.1.2. Чат HeadHunter автоматически создаётся только у менеджера, ответственного
за вакансию; получение сообщений других чатов опирается на событие нового
сообщения и список чатов авторизованного аккаунта (API HeadHunter).

6.1.3. Обработка обращений не зависит от статуса кандидата и блокировок:
обрабатываются все кандидаты массового подбора, поступающие в чат (issue #237,
Q6, Q7).

6.1.4. Чат-боты при обработке обращений из HeadHunter не используются ни в КЦ, ни
на стороне HeadHunter (issue #237, Q8).

6.1.5. Признак фильтрации вакансий линейного персонала зависит от возможностей
API HeadHunter и подлежит согласованию (issue #237, Q5).

6.1.6. Решение предоставляется под отдельной услугой Контакт-центра с тарификацией
по условиям продукта; состав и стоимость услуги — продуктовое и коммерческое
решение вне функциональных требований.

### 6.2. Используемые технологии

6.2.1. Текстовые каналы Mango Office (`messenger-channel-service`,
`digital-channel-group-service`) как основа канала HeadHunter по аналогии с
каналом «Авито Работа».

6.2.2. Модель сообщений и сессий текстовых коммуникаций
(`dialog-api-messaging-service`) для синхронизации чатов и обработки событий
новых сообщений.

6.2.3. Маршрутизация обращений КЦ (`cc-interaction-routing-service`) для передачи
обращений на группу «Чатеры».

6.2.4. Адресная книга Контакт-центра (`mango-contact-center-official`) для
хранения данных кандидата.

6.2.5. API чатов HeadHunter (внешняя система) как источник и получатель сообщений
переписки.
