## Сырой запрос заказчика (п.7 брифа)

Описание кейса на языке бизнес-потребности, а не списка доработок:

Оценить и увидеть фактическую работу сотрудников согласно скрипту, насколько
соблюдается. Далее информация идёт в сторону бизнес-тренера. Для клиента это
влияние на бизнес-процессы.

## Краткое резюме встречи с заказчиком

- Акторы и процесс: Клиент → номер ВАТС Заказчика (по одному из трёх продуктовых
  направлений) → переадресация на внешний телефон Партнёра. Сотрудники партнёров
  в ВАТС не заведены.
- Потребность: автоматическая оценка диалогов по чек-листам (скриптам продаж) в
  разрезе трёх направлений (мини-брус, ПРЕКАТ, ПРЕФАБ), а также выявление
  инсайтов (вопросы, возражения, потребности). Инсайт распознаётся не по
  «ключевому слову», а по интенту (потребность, соответствующая контексту).
- Номер 8800: внутренний канал Заказчика (не партнёр), отдельный чек-лист
  (скрипт), группировка номеров для него не требуется.
- Текущий функционал РА: «Анализ по чек-листам» с учётом кастомных промптов и
  «Ловец инсайтов» частично закрывают потребность. Частично: фильтрация As-Is по
  сотрудникам/группам недостаточна. Требуется возможность фильтрации по
  направлениям (группе номеров ВАТС).
