## 1. Термины и определения

**Система** — продукт Mango Office «Речевая аналитика» и связанные компоненты
Личного кабинета ВАТС, участвующие в реализации требований документа.

**ВАТС** — Виртуальная АТС Mango Office: облачная телефония, маршрутизация
звонков и управление номерами.

**Номер ВАТС** — телефонный номер линии ВАТС Заказчика, на который поступает
звонок Клиента.

**Речевая аналитика (РА)** — продукт Mango Office для распознавания речи,
тематик, тегов и аналитики разговоров.

**Анализ по чек-листам** — отчёт «Речевой аналитики» для автоматической оценки
разговора сотрудника с клиентом на соответствие стандартам компании (скрипту).

**Чек-лист** — настраиваемый автором набор критериев оценки разговора (скрипт
продаж), по которому «Речевая аналитика» выставляет оценку.

**Направление** — продуктовое направление Заказчика (мини-брус, ПРЕКАТ, ПРЕФАБ),
которому соответствует один или несколько номеров ВАТС.

**Группа-направление** — именованная группа номеров ВАТС, объединяющая номера
одного продуктового направления для фильтрации отчётов «Речевой аналитики».

**Партнёр** — внешняя организация, на телефон которой переадресуется звонок
Клиента; сотрудники Партнёра в ВАТС не заведены.

**Пользователь** — сотрудник Заказчика с правами доступа к «Речевой аналитике»,
который строит и просматривает отчёты.

## 2. Проблема, цель, задачи

### 2.1. Проблема

Клиенты звонят на номера ВАТС трёх продуктовых направлений (мини-брус, ПРЕКАТ,
ПРЕФАБ). Звонки переадресуются на телефоны ВАТС, ассоциированные с Партнёрами по
этим направлениям. Партнёры принимают переадресованные звонки и самостоятельно
ведут коммуникацию с Клиентами. «Речевая аналитика» оценивает разговоры по
чек-листам, но не позволяет получить результаты оценки отдельно по каждому
продуктовому направлению. Фильтрация по сотрудникам и группам сотрудников задачу
не решает: сотрудники Партнёров в ВАТС не заведены, а признак направления
выражен только номером ВАТС. В результате Заказчик не видит фактическое
соблюдение скрипта на стороне Партнёра в разрезе отдельного направления, что
снижает точность работы бизнес-тренера с Партнёрами и ограничивает влияние на
улучшение бизнес-процессов обработки обращений Клиентов.

### 2.2. Цель

Реализовать возможность просмотра результатов оценки по чек-листам «Речевой
аналитики» в разрезе продуктовых направлений за счёт группировки номеров ВАТС по
направлениям и фильтрации отчётов по выбранной группе-направлению.

### 2.3. Задачи

2.3.1. Обеспечить объединение номеров ВАТС в именованные группы-направления
(например: мини-брус, ПРЕКАТ, ПРЕФАБ).

2.3.2. Обеспечить фильтрацию отчёта «Анализ по чек-листам» по выбранной
группе-направлению.

2.3.3. Обеспечить просмотр и сохранение результатов оценки по чек-листам в
разрезе выбранной группы-направления.

### 2.4. Ожидаемые результаты и эффект

2.4.1. Прозрачность соблюдения скрипта в разрезе каждого продуктового
направления.

2.4.2. Снижение ручного труда на разнесение результатов по направлениям за счёт
фильтрации вместо ручной выборки по отдельным номерам ВАТС.

> Числовые целевые метрики Заказчиком не подтверждены и в документ не вносятся.

## 3. Ожидаемое решение

### 3.1. Концепция решения

Звонок Клиента поступает на номер ВАТС одного из трёх направлений и
переадресуется на телефон Партнёра. «Речевая аналитика» оценивает разговор по
чек-листу. Решение добавляет сущность «группа-направление» над номерами ВАТС и
признак направления в отчёте «Анализ по чек-листам». Пользователь объединяет
номера ВАТС в группы-направления, после чего фильтрует «Анализ по чек-листам» по
выбранной группе-направлению и получает результаты оценки в разрезе направления.

Поток (high-level, текстовая модель):

1. Клиент звонит на номер ВАТС направления.
2. ВАТС переадресует звонок на телефон Партнёра.
3. «Речевая аналитика» формирует оценку разговора по чек-листу.
4. Пользователь выбирает группу-направление как фильтр «Анализа по чек-листам».
5. Система показывает оценку по чек-листам в разрезе направления и позволяет
   сохранить результат.

### 3.5. Моделирование вариантов решения

3.5.1. Quick win. Сохранять и переиспользовать предустановленный набор номеров
ВАТС в фильтре «Номер ВАТС» отчётов как пресет направления. Не вводит новую
сущность, но не даёт именованного признака направления и переиспользуемой группы
между отчётами.

3.5.2. Recommended. Ввести сущность «группа-направление» над номерами ВАТС и
фильтр по направлению в «Анализе по чек-листам». Вариант опирается на отраслевую
возможность группировки маршрутизации (`voice-ucaas.cloud-pbx.call-routing-rules`)
и закрывает все три задачи без выхода за границы целесообразной доработки.

3.5.3. Target. Автоматически сопоставлять номер ВАТС направлению по правилам
маршрутизации ВАТС и наследовать направление во всех отчётах РА. Требует
интеграции с маршрутизацией ВАТС; источник правил автонаследования не
подтверждён и помечается как не подтверждённый.

Выбран вариант 3.5.2 (Recommended).

## 4. Функциональные требования и сценарии использования

### 4.1. Группировка номеров ВАТС по направлениям (FR-01)

4.1. Система должна предоставлять Пользователю с ролью «Администратор» или
пользовательской ролью на базе роли «Администратор» возможность объединять
номера ВАТС в именованные группы-направления в Личном кабинете ВАТС.

* 4.1.1. Система должна создавать группу-направление с названием и составом
  номеров ВАТС.
  * 4.1.1.1. Система должна требовать уникальное название группы-направления в
    пределах Заказчика.
  * 4.1.1.2. Название группы-направления задаёт Пользователь; на момент
    согласования у Заказчика три направления: «мини-брус», «ПРЕКАТ», «ПРЕФАБ».
* 4.1.2. Система должна добавлять в группу-направление один или несколько номеров
  ВАТС.
* 4.1.3. Система должна изменять состав номеров ВАТС в группе-направлении:
  добавлять и исключать номера.
* 4.1.4. Система должна переименовывать группу-направление с проверкой
  уникальности названия.
* 4.1.5. Система должна удалять группу-направление.
  * 4.1.5.1. При удалении группы-направления номера ВАТС сохраняются в реестре
    ВАТС и становятся доступными для включения в другие группы-направления.
* 4.1.6. Система не должна допускать включение одного номера ВАТС более чем в одну
  группу-направление одновременно.
* 4.1.7. Состояние по умолчанию: номер ВАТС не входит ни в одну
  группу-направление, пока Пользователь не включил его в группу-направление.

### 4.2. Фильтрация «Анализа по чек-листам» по направлению (FR-02)

4.2. Система должна предоставлять Пользователю возможность фильтровать отчёт
«Анализ по чек-листам» по выбранной группе-направлению.

* 4.2.1. Система должна отображать фильтр выбора группы-направления в параметрах
  отчёта «Анализ по чек-листам».
* 4.2.2. Система должна включать в результат только разговоры по номерам ВАТС
  выбранной группы-направления.
  * 4.2.2.1. При выборе нескольких групп-направлений внутри фильтра действует
    логика ИЛИ.
* 4.2.3. Состояние по умолчанию: при отсутствии выбранной группы-направления
  фильтр по направлению не применяется и отчёт показывает данные как в текущем
  поведении (As-Is).

### 4.3. Результаты оценки по чек-листам в разрезе направления (FR-03)

4.3. Система должна предоставлять Пользователю возможность получать и сохранять
результаты оценки по чек-листам по выбранной группе-направлению.

* 4.3.1. Система должна формировать оценку по чек-листу в разрезе выбранной
  группы-направления.
* 4.3.2. Система должна отображать результаты оценки по выбранной
  группе-направлению на странице статистики отчёта «Анализ по чек-листам».
* 4.3.3. Система должна сохранять выбранную группу-направление как параметр
  отчёта, чтобы Пользователь мог повторно получить результаты в том же разрезе.

## 6. Особенности реализации

### 6.1. Ограничения

6.1.1. Сотрудники Партнёров не заведены в ВАТС, поэтому фильтрация по сотрудникам
и группам сотрудников не выделяет направление; признак направления выражается
только номером ВАТС.

6.1.2. Номер 8-800 — внутренний канал Заказчика с отдельным чек-листом; он не
включается в группы-направления (issue #220, Q2).

6.1.3. Группировка по направлениям охватывает текущие три продуктовых направления
Заказчика (мини-брус, ПРЕКАТ, ПРЕФАБ); число направлений системой не ограничено.

6.1.4. Настройка групп-направлений доступна роли «Администратор» или
пользовательской роли на базе роли «Администратор» по ролевой модели ВАТС
(`Rolevaya-model-vats/sections/03-upravlenie-rolyami.md`).

### 6.2. Используемые технологии

6.2.1. Продукт «Речевая аналитика» (`speech-analytics-service`) — отчёт «Анализ по
чек-листам».

6.2.2. Реестр номеров ВАТС продукта «Виртуальная АТС» (`mango-virtual-pbx-official`)
как источник номеров для групп-направлений.

6.2.3. Ролевая модель ВАТС (`Rolevaya-model-vats`) — назначение прав на настройку
групп-направлений.
