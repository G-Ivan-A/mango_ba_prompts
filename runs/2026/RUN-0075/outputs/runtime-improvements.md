## 2. Словарь продуктов `taxonomy/products.yaml`

- ВАТС / ЛК ВАТС (`vpbx`, 57 вхождений) относится к `voice-ucaas`, который отмечен `in_slice: false`: золотые кейсы карточки Группы и отчётов ЛК сейчас вне среза runtime. Предложение: включить `voice-ucaas` в срез или завести профиль настроек ВАТС.
- Контакт-центр (`cc`, 62 вхождений) — `contact-center`, в срезе; большинство выдуманных атрибутов (столбец «Статус автоперезвона», «Заказы ЗОЗ») перенесены моделью из ЛК ВАТС в КЦ — нужна маршрутизация «один продукт — одно руководство».
- VPBX API (`vpbx-api`, 11 вхождений) — профиль `P-API`; в задаче API вне границ, вхождения — домыслы вопреки запрету БА.

## 3. Золотые кейсы `golden/cases.yaml`

Сейчас набор runtime синтетический (`origin: synthetic`, `structural_only: true`). Предложение: принять кейсы [`golden-set-candidates.json`](golden-set-candidates.json) со значением `origin: run-observed`, где `confirmed_by: user` — реакция БА в диалоге; `expect.outcome: refused` с `defect_class` для дефектных кейсов и `expect.outcome: completed` для негативных.

## 4. Маршрутизация в КБ для внешних API

67 вхождений категорий C01/C10/C11 — утверждения о текущем функционале без дословной опоры на КБ. Предложение: для слота S-ASIS каждое утверждение выводить парой «цитата + локатор (руководство, пункт, страница)» и сверять цитату с КБ до вывода (журнал — [`../logs/kb-verification.md`](../logs/kb-verification.md)).
