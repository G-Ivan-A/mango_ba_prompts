Кандидаты в golden-set по [`standards/evals-contract-standard.md`](../../../../standards/evals-contract-standard.md): наборы по **5–10 кейсов**, по одному набору на группу разделов шаблона, — под посекционную генерацию BCREQ-ФТ. Эталонный вердикт агента-проверяющего: для дефектного кейса — «дефект» с указанным классом, для негативного кейса — «дефекта нет».

Это **запись прогона**, а не контракт: стандарт запрещает смешивать эталон и факт, а контейнер golden-set в этом споке не выбран (см. [`../feedback/review-notes.md`](../feedback/review-notes.md)). Перенос в контейнер golden-set — после решения человека и ревью эталона (`draft → reviewed`).

Правило отбора (детерминированное): в наборе категории упорядочены по числу вхождений; для каждой из первых 8 берётся первое подтверждённое вхождение (если подтверждённых нет — первое вероятное); если категорий меньше 5, добираются следующие вхождения тех же категорий. Негативных кейсов — до 2, сначала подтверждённые БА.

Набор **не покрывает**: смысловую полноту ФТ относительно бизнес-цели, проверку по продуктам вне задачи 1104, многопродуктовые правила MP-1…MP-4.
