# Журнал RUN-0080

## Цель

Проверить условие DEC-427-11 для черновика BL-156: промпт шага Ш-В «по
тесту» (D) не хуже опубликованного v0.1 на golden set этапа 1. Опоры две:
RUN-0079 (A — 49/62) и A этого прогона под тем же судьёй.

## Почему только Ш-В

Ш-В — единственный шаг, где один кейс golden set равен одному
законченному вызову модели (см. журнал RUN-0079). Десять других файлов
шагов генерируют разделы. Их измеряет режим генерации на реальном входе
(BL-111). Заглушка Ш-Р промпта v0.1 не имеет.

## Процедура

Процедура повторяет RUN-0079. Отличаются версии и маскировка.

1. **Подготовка** — `python3 experiments/issue_438/run0080/prepare.py /tmp/run80`:
   - A и D читаются из рабочего дерева на коммите `18a98c97`, их SHA-256
     записываются в `mapping.json`;
   - карта T-NN пересобирается из golden set с seed 79 и сверяется с картой
     RUN-0079. Расхождение — остановка. Карты совпали;
   - пакеты кейсов совпадают с пакетами RUN-0079 байт в байт (сверено
     `diff` после снятия frontmatter).
2. **Исполнение** — 4 изолированных подагента `claude-opus-5-5`: A×2 пакета
   и D×2 пакета. Инструкция — [`executor-instruction.md`](executor-instruction.md).
   Она та же, что в RUN-0079, плюс запрет переходить по ссылкам внутри
   файлов: у D ссылки на runtime и стандарты.
3. **Слепая подготовка судьи** — `python3 experiments/issue_438/run0080/judge_prepare.py /tmp/run80`:
   - A и D случайно (seed 8080) становятся X или Y, ключ сохраняется в
     `judge-key.json`;
   - в ответах маскируются ID правил (`L-`, `БС-`, `К-`, `ПБ-`, `И-`, `З-`,
     `ТС-`, `ПР-`), коды профилей (TRANSFORM, VERIFY и т. п.) и служебные
     слова черновика (receipt, UNKNOWN, WAITING, G-self). Иначе словарь
     черновика выдал бы D;
   - после маскировки сценарий ищет остатки. Найдено 0, иначе код выхода 1;
   - судья видит вход, контекст, эталонный вердикт, тип кейса, правило
     урока, обоснование эталона и два выхода.
4. **Оценка** — 2 изолированных подагента-судьи `claude-opus-5-5`.
   Инструкция — [`judge-instruction.md`](judge-instruction.md). Правила
   реестра — те же, что [в RUN-0079](../../RUN-0079/logs/judge-rules.md).
   Пакеты — [`judge-input-batch1.md`](judge-input-batch1.md) и
   [`judge-input-batch2.md`](judge-input-batch2.md).
5. **Пересчёт** — `python3 experiments/issue_438/run0080/score.py /tmp/run80`.
   Сценарий раскрывает ключ, считает K1–K6, сданные кейсы, ядро и ложные
   дефекты. Он сравнивает D с A RUN-0079 и с A этого прогона и записывает
   поле `publication`.
6. **Фиксация** — `python3 experiments/issue_438/run0080/fixate.py /tmp/run80`.

## Воспроизведение

инструкциями. Ответы модели при повторе могут отличаться: температура
подагентов не управляется. Разброс видно по A — 49/62 в RUN-0079 и 55/62
здесь на почти том же тексте (см. отчёт, «Разброс судьи»).
