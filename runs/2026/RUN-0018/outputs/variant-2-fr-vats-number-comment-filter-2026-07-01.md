## 1. Термины и определения

**Система** — продукт Mango Office «Речевая аналитика» и связанные компоненты
Личного кабинета ВАТС, участвующие в реализации требований документа.

**ВАТС** — Виртуальная АТС Mango Office: облачная телефония, маршрутизация
звонков и управление номерами.

**Номер ВАТС** — телефонный номер линии ВАТС Заказчика, на который поступает
звонок Клиента.

**Комментарий к номеру** — текстовое поле произвольного содержания у номера ВАТС
в Личном кабинете ВАТС. Поле существует в текущей функциональности (As-Is) и
используется, в том числе, для поиска номера.

**Речевая аналитика (РА)** — продукт Mango Office для распознавания речи,
тематик, тегов и аналитики разговоров.

**Анализ по чек-листам** — отчёт «Речевой аналитики» для автоматической оценки
разговора сотрудника с клиентом на соответствие стандартам компании (скрипту).

**Чек-лист** — настраиваемый автором набор критериев оценки разговора (скрипт
продаж), по которому «Речевая аналитика» выставляет оценку.

**Направление** — продуктовое направление Заказчика (мини-брус, ПРЕКАТ, ПРЕФАБ),
которому соответствует один или несколько номеров ВАТС. В Варианте 2 направление
не является отдельным объектом системы: оно выражается наименованием в
комментарии к номеру ВАТС.

**Фильтр по номерам ВАТС** — новый компонент блока фильтров отчёта «Анализ по
чек-листам», позволяющий искать номера ВАТС по вхождению в номер и комментарий и
выбирать несколько номеров.

**Поиск по вхождению** — поиск, включающий в результат номера ВАТС, у которых
введённая строка встречается в номере телефона или в комментарии (логика ИЛИ).

**Мастер-выбор (мастер-чекбокс)** — элемент управления, отмечающий или снимающий
отметку сразу со всех номеров текущего результата поиска.

**Партнёр** — внешняя организация, на телефон которой переадресуется звонок
Клиента; сотрудники Партнёра в ВАТС не заведены.

**Пользователь** — сотрудник Заказчика с правами доступа к «Речевой аналитике»,
который строит и просматривает отчёты.

## 2. Проблема, цель, задачи

### 2.1. Проблема

Клиенты звонят на номера ВАТС трёх продуктовых направлений (мини-брус, ПРЕКАТ,
ПРЕФАБ). Звонки переадресуются на телефоны Партнёров по этим направлениям.
«Речевая аналитика» оценивает разговоры по чек-листам, но отчёт «Анализ по
чек-листам» не позволяет получить оценку отдельно по каждому направлению.
Фильтрация по сотрудникам и группам сотрудников задачу не решает: сотрудники
Партнёров в ВАТС не заведены, а признак направления выражен только номером ВАТС.
Отбор вручную по отдельным номерам ВАТС трудоёмок и подвержен ошибкам,
особенно при изменении состава Партнёров.

### 2.2. Цель

Реализовать возможность просмотра результатов оценки по чек-листам «Речевой
аналитики» в разрезе продуктовых направлений без создания отдельной сущности
группировки: за счёт нового фильтра «Анализа по чек-листам» по номерам ВАТС с
гибридным поиском по номеру и комментарию и мультивыбором результата поиска.

### 2.3. Задачи

2.3.1. Обеспечить в отчёте «Анализ по чек-листам» фильтр по номерам ВАТС со
списком номеров и их комментариев.

2.3.2. Обеспечить в этом фильтре гибридный поиск по вхождению одновременно в
номер ВАТС и комментарий к номеру (логика ИЛИ).

2.3.3. Обеспечить мультивыбор номеров ВАТС, включая мастер-выбор по
результирующему списку поиска, с сохранением выбора при применении фильтра.

2.3.4. Обеспечить просмотр результатов оценки по чек-листам по выбранному набору
номеров ВАТС (в разрезе направления).

### 2.4. Ожидаемые результаты и эффект

2.4.1. Прозрачность соблюдения скрипта в разрезе каждого продуктового
направления без ведения отдельных наборов номеров.

2.4.2. Снижение трудозатрат на поддержку: признак направления ведётся в уже
используемом комментарии к номеру ВАТС; при изменении состава Партнёров не
требуется поддерживать отдельные группы.

> Числовые целевые метрики Заказчиком не подтверждены и в документ не вносятся.

## 3. Ожидаемое решение

### 3.1. Концепция решения

Пользователь ведёт наименование направления в комментарии к номеру ВАТС в Личном
кабинете ВАТС (в текущем поле «Комментарий»). В отчёте «Анализ по чек-листам»
добавляется фильтр по номерам ВАТС: Пользователь вводит наименование
направления, система по вхождению находит номера ВАТС (совпадение по номеру или
по комментарию), Пользователь мастер-выбором отмечает весь результат и применяет
фильтр. Отчёт по чек-листу показывает оценку только по разговорам выбранных
номеров ВАТС — в разрезе направления.

Поток (high-level, текстовая модель):

1. Пользователь один раз указывает наименование направления в комментарии к
   номеру ВАТС в ЛК ВАТС.
2. Клиент звонит на номер ВАТС направления; ВАТС переадресует звонок Партнёру.
3. «Речевая аналитика» формирует оценку разговора по чек-листу.
4. Пользователь открывает фильтр по номерам ВАТС в «Анализе по чек-листам» и
   вводит наименование направления.
5. Система по вхождению формирует список номеров ВАТС (номер ИЛИ комментарий).
6. Пользователь применяет мастер-выбор и нажимает «Выбрать».
7. Система применяет фильтр и показывает оценку по чек-листам в разрезе
   выбранных номеров.

### 3.5. Моделирование вариантов решения

3.5.1. Вариант 1 (RUN-0014, Recommended ранее). Ввести именованную сущность
«группа-направление» над номерами ВАТС и фильтр по группе-направлению. Даёт

CRUD-операциями, правилами целостности и поддержкой наборов при изменении состава
Партнёров.

3.5.2. Вариант 2 (настоящий документ, альтернатива). Не вводить новую сущность:
вести направление в комментарии к номеру ВАТС и добавить в «Анализ по чек-листам»
фильтр по номерам ВАТС с гибридным поиском (номер ИЛИ комментарий) и
мультивыбором результата. Переиспользует существующее поле «Комментарий» и логику
поиска по нему. Компромисс — путь фильтрации на один шаг длиннее (ввод строки →
мастер-выбор → «Выбрать»), направление не является именованным объектом.

3.5.3. Соотношение вариантов. Вариант 2 выигрывает по простоте настройки и
отсутствию поддержки наборов; Вариант 1 выигрывает по скорости повторной
фильтрации (готовое направление в один клик). Итоговый выбор варианта — за
Заказчиком по результатам синхронизации; выбор системного ограничения (списка
направлений) правилом валидации не фиксируется.

## 4. Функциональные требования и сценарии использования

### 4.1. Фильтр по номерам ВАТС в «Анализе по чек-листам» (FR-01)

4.1. Система должна отображать в блоке фильтров отчёта «Анализ по чек-листам»
фильтр по номерам ВАТС.

* 4.1.1. Система должна отображать в фильтре список номеров ВАТС Заказчика,
  доступных для отчёта.
* 4.1.2. Система должна отображать рядом с каждым номером ВАТС его комментарий из
  Личного кабинета ВАТС.
* 4.1.3. Система должна использовать комментарий к номеру ВАТС в текущем виде
  (As-Is), без изменения поля «Комментарий» в ЛК ВАТС.
* 4.1.4. Состояние по умолчанию: ни один номер ВАТС в фильтре не выбран, поле
  поиска пустое, фильтр по номерам не применяется.

### 4.2. Гибридный поиск по номеру и комментарию (FR-02)

4.2. Система должна предоставлять в фильтре по номерам ВАТС поле поиска по
номерам и комментариям.

* 4.2.1. Система должна выполнять поиск по вхождению введённой строки: включать в
  результат номера ВАТС, у которых введённая строка встречается в номере
  телефона или в комментарии.
  * 4.2.1.1. Между полями «номер» и «комментарий» при поиске действует логика
    ИЛИ (совпадение хотя бы по одному полю включает номер в результат).
* 4.2.2. Система должна формировать результирующий список номеров ВАТС по
  введённой строке поиска.
* 4.2.3. При пустой строке поиска система должна отображать полный список
  доступных номеров ВАТС без фильтрации по вхождению.

### 4.3. Мультивыбор и мастер-выбор (FR-03)

4.3. Система должна предоставлять Пользователю выбор нескольких номеров ВАТС в
фильтре.

* 4.3.1. Система должна позволять отметить или снять отметку с отдельного номера
  ВАТС (чекбокс).
* 4.3.2. Система должна предоставлять мастер-выбор (мастер-чекбокс), отмечающий
  или снимающий отметку сразу со всех номеров ВАТС текущего результирующего
  списка поиска.
* 4.3.3. Система должна сохранять ранее отмеченные номера ВАТС при изменении
  строки поиска, чтобы Пользователь мог собрать выбор в несколько заходов по
  разным запросам.
* 4.3.4. Внутри фильтра по номерам ВАТС между выбранными номерами действует
  логика ИЛИ (в отчёт попадают разговоры по любому из выбранных номеров).
* 4.3.5. Система должна применять фильтр по выбранным номерам ВАТС при инициации
  Пользователем действия «Выбрать» и запоминать состояние выбранных номеров.
* 4.3.6. Система должна предоставлять возможность сбросить выбранные номера ВАТС
  и вернуть фильтр в состояние по умолчанию (4.1.4).

### 4.4. Результаты оценки по чек-листам по выбранным номерам (FR-04)

4.4. Система должна предоставлять Пользователю результаты оценки по чек-листам по
выбранному набору номеров ВАТС.

* 4.4.1. Система должна включать в результат отчёта «Анализ по чек-листам» только
  разговоры по выбранным в фильтре номерам ВАТС.
* 4.4.2. Система должна отображать результаты оценки по выбранным номерам ВАТС на
  странице статистики отчёта «Анализ по чек-листам».
* 4.4.3. Состояние по умолчанию: при отсутствии выбранных номеров ВАТС фильтр по
  номерам не применяется, и отчёт показывает данные как в текущем поведении
  (As-Is).

## 6. Особенности реализации

### 6.1. Ограничения

6.1.1. Сотрудники Партнёров не заведены в ВАТС, поэтому фильтрация по сотрудникам
и группам сотрудников не выделяет направление; признак направления выражается
только номером ВАТС и его комментарием.

6.1.2. Номер 8-800 — внутренний канал Заказчика с отдельным чек-листом; он не
относится к продуктовым направлениям (issue #220, Q2) и не помечается
наименованием направления в комментарии.

6.1.3. Корректность разреза по направлению зависит от единообразия комментариев:
во всех номерах одного направления в комментарии должно присутствовать одно и то
же наименование направления. Это организационное соглашение Заказчика, а не
системное правило валидации.

6.1.4. Длина комментария к номеру ограничена в текущей функциональности ЛК ВАТС
(для номеров сторонних операторов — не более 50 символов, `mango-lk-manual/sections/323-nomera.md`);
наименование направления добавляется в пределах этого ограничения.

6.1.5. Путь фильтрации в Варианте 2 на один шаг длиннее, чем в Варианте 1: ввод
строки поиска → мастер-выбор → «Выбрать» вместо выбора готового именованного
направления в один клик. Компромисс согласуется с Заказчиком (issue #255).

### 6.2. Используемые технологии

6.2.1. Продукт «Речевая аналитика» (`speech-analytics-service`) — отчёт «Анализ по
чек-листам» и его блок фильтров.

6.2.2. Комментарий к номеру ВАТС и реестр номеров ВАТС продукта «Виртуальная АТС»
(`mango-virtual-pbx-official`) как источник номеров и комментариев для фильтра.
