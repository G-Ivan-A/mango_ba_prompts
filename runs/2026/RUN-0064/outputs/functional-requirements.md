# Функциональные требования BCREQ-1074: настройка вида отчета

Документ описывает только дельту к текущему разделу «Финансы → Расходы на
связь». Наблюдаемая baseline-функциональность — параметры периода/группировки,
фильтры, график, агрегированная таблица и ссылка `Скачать: CSV` — не становится
новой доработкой.

## 1. Глоссарий

| Термин | Определение |
| --- | --- |
| Классический вид | Текущий вид отчета до включения новых настроек; вид по умолчанию для пользователей без сохраненного выбора. |
| Новый вид | Вид отчета, в котором пользователь управляет видимостью и порядком колонок. |
| Параметры отчета | Существующие период, группировка и дополнительные фильтры; выбранные значения применяются совместно по логическому И. |
| Настройка колонок | Панель, открываемая иконкой шестеренки, с чекбоксами множественного выбора и Drag-and-Drop. |
| Профиль пользователя | Постоянное хранилище выбора вида и конфигурации колонок между сессиями, если оно доступно продукту. |

## 2. Проблема, цель и границы изменения

Текущий отчет имеет фиксированный состав и порядок агрегированных колонок.
Пользователю нужен управляемый новый вид, позволяющий адаптировать таблицу к
задачам внутреннего распределения расходов, не ломая привычный сценарий.

Цель — добавить настраиваемое представление таблицы с явной обратной
совместимостью. В scope не входят изменение алгоритмов тарификации, прав доступа,
существующих фильтров и графика, добавление новых форматов экспорта или агрегация
нескольких ЛС.

## 3. Моделирование верхнеуровневых ФТ

### FR-01. Параметры и состав данных отчета

Новый вид использует результат существующих параметров отчета и предоставляет
базовый набор колонок, трассируемый к бизнес-цели внутреннего распределения расходов.

**Источник:** issue #345, оба скриншота, решения из `1074.json`.

**Бизнес-цель:** сохранить знакомый поиск и дать достаточный контекст одной
строки расхода без выдумывания новой фильтрации.

**Критерии приемки:**

- период, группировка, продукт, линия АТС, сотрудник и услуга продолжают
  ограничивать один результат совместно по логическому И;
- базовый набор нового вида содержит колонки слева направо: **Дата и время
  звонка**, **Номер, инициировавший звонок**, **Номер абонента**, **Название услуги**,
  **Оператор связи**, **Длительность звонка**, **Сумма в рублях**, **Номер договора**;
- наличие «Дата и время звонка» и семантика строки проходят human review до
  передачи в разработку, поскольку исходный запрос перечислял семь полей;
- существующая ссылка `Скачать: CSV` сохраняется; эта задача не меняет формат
  или правила экспорта.

**CBAP/eTOM:** CBAP traceability связывает каждую колонку с целью и source;
eTOM Fulfillment покрывает конфигурацию результата, Assurance — сохранение
семантики фильтров и проверяемого состава.

### FR-02. Управление отображением колонок

Новый вид предоставляет настройку колонок через иконку шестеренки рядом с
таблицей.

**Источник:** прямой контракт issue #345.

**Бизнес-цель:** позволить пользователю подготовить удобное представление без
изменения исходных данных отчета.

**Критерии приемки:**

- нажатие иконки шестеренки открывает панель настройки, повторное нажатие,
  применение или закрытие вне панели закрывает ее без потери уже примененной
  конфигурации;
- каждая доступная колонка имеет чекбокс; чекбоксы поддерживают множественный
  выбор и сразу отражают видимость колонок в preview/таблице;
- система не позволяет скрыть все колонки: при попытке снять последний чекбокс
  действие блокируется с понятным сообщением;
- Drag-and-Drop изменяет порядок колонок экранной таблицы нового вида;
- скрытые колонки не отображаются в экранной таблице; существующая
  **CSV-выгрузка не меняет состав и порядок данных** в рамках этой задачи;
- изменение представления не меняет значения строк, фильтры или агрегаты.

**CBAP/eTOM:** атомарные критерии обеспечивают verification/validation; eTOM
Fulfillment реализует пользовательскую конфигурацию, Assurance проверяет
целостность данных при смене представления.

### FR-03. Обратная совместимость и сохранение настройки

Система предоставляет явный переключатель «Классический вид / Новый вид».

**Источник:** прямой контракт issue #345.

**Бизнес-цель:** внедрить изменение без принудительной миграции существующих
пользователей и дать контролируемый возврат к baseline.

**Критерии приемки:**

- при первом открытии и при отсутствии сохраненного выбора используется
  классический вид;
- новый вид включается только явным действием пользователя;
- при возврате в классический вид его исходный состав и порядок колонок не
  изменяются конфигурацией нового вида;
- выбор вида, видимость и порядок колонок сохраняются минимум в текущей сессии;
- при наличии серверного профиля настройка сохраняется в профиле пользователя
  и восстанавливается в следующей сессии; при отсутствии профиля применяется
  session fallback без заявления о межсессионном хранении;
- недоступная или некорректная сохраненная колонка игнорируется, остальные
  настройки восстанавливаются; если валидных колонок нет, применяется базовая
  конфигурация нового вида.

**CBAP/eTOM:** изменение baseline управляется явным opt-in и обратимым решением;
eTOM Assurance покрывает восстановление и безопасный fallback.

## 4. UI-логика и сценарии использования

```text
[Классический вид — default]
           | пользователь включает «Новый вид»
           v
[Новый вид — базовые колонки] -- шестеренка --> [Панель настройки]
           ^                                      | checkbox / Drag-and-Drop
           |                 применить / закрыть  v
           +------------------------------- [Preview конфигурации]
```

| Состояние | Действие | Результат | Сохранение |
| --- | --- | --- | --- |
| Классический вид | Включить новый вид | Таблица показывает базовую конфигурацию нового вида. | Выбор фиксируется в сессии/профиле. |
| Новый вид | Открыть шестеренку | Показаны все доступные колонки, текущие чекбоксы и порядок. | Данные пока не меняются. |
| Панель открыта | Снять/установить чекбоксы | Preview показывает выбранные колонки; последнюю скрыть нельзя. | При применении. |
| Панель открыта | Выполнить Drag-and-Drop | Preview и итоговая таблица используют новый порядок колонок. | При применении. |
| Новый вид | Переключить классический вид | Возвращается неизмененный baseline. | Конфигурация нового вида сохраняется для возврата. |

Сценарии исключений: недоступность профиля переводит сохранение в текущую
сессию; неизвестная колонка после обновления игнорируется; ошибка сохранения не
отменяет уже показанный отчет и сопровождается уведомлением.

## 5. Нефункциональные требования

НФТ не задаются численно без продуктовых источников. Для human review остаются
время применения настройки, доступность клавиатурного аналога Drag-and-Drop,
контраст/ARIA панели и допустимый объем профиля.

## 6. Ограничения и открытые решения

1. Отчет использует все продукты, попавшие в результат существующих фильтров в
   рамках активного ЛС; отдельная агрегация нескольких ЛС не создается.
2. Фильтры и группировки не дорабатываются; настройки колонок не являются новым
   фильтром или группировкой.
3. Drag-and-Drop и видимость действуют только в новом виде; классический вид не
   изменяется.
4. До product/SA review не утверждены источник полей «Оператор связи» и «Номер
   договора», семантика строки и межсессионное профильное хранилище.
5. Нужна проверка решения включить «Дата и время звонка» как восьмую baseline-
   колонку: это рекомендация по читаемости и идентификации события, а не
   дословное требование Заказчика.
