# Анализ заявки на интеграцию Mango Office ↔ OkDesk

## 1. Понимание проблемы (Problem Statement)

**Бизнес-потребность:**  
Заказчик использует сервис управления сервисными заявками OkDesk и планирует интеграцию с телефонией Mango Office с целью автоматизации регистрации обращений. Ключевое требование: **любой телефонный звонок** (внешний входящий, внутренний, исходящий) должен инициировать создание заявки в OkDesk с прикреплением URL записи разговора.

**Техническое ограничение текущей реализации:**  
Интеграция через решение «Простые звонки» не поддерживает обработку **внутренних звонков**, так как в архитектуре Mango Office внутренние вызовы не генерируют сущность «Лид», которая является триггером для передачи данных во внешние системы [[1]].

**Целевое состояние:**  
Реализация интеграционного контура, обеспечивающего:
- Единый триггер создания заявки в OkDesk по событию завершения звонка (Call End), независимо от направления вызова;
- Корректную передачу метаданных звонка: направление, участники, длительность, URL записи;
- Сопоставление абонентских номеров с сущностями «Компания»/«Контакт» в OkDesk через API-методы поиска [[2]].

| **Триггер события** | Использовать webhook Mango Office `events/call` с фильтром по `status=completed` [[1]] | Гарантирует передачу только завершённых звонков с доступной записью |
| **Идентификация клиента** | Реализовать двухэтапный поиск: сначала по `phone`, затем по `search_string` с нормализацией номера [[2]] | Повышает точность маппинга при разном формате ввода номеров |

| **Логирование** | Фиксировать в отдельном хранилище: `call_id`, `okdesk_issue_id`, `timestamp`, `response_code` | Упрощает аудит и отладку инцидентов |

# Корректировка анализа заявки на интеграцию Mango Office ↔ OkDesk

Благодарю за уточнение. Принято: ограничение находится не на стороне Mango Office, а в модели данных OkDesk. Ниже — актуализированное понимание проблемы, отредактированные вопросы и дополнительные рекомендации.

## 1. Актуализированное понимание проблемы (Problem Statement)

**Бизнес-потребность:**  
Заказчик использует сервис управления сервисными заявками OkDesk и планирует интеграцию с телефонией Mango Office с целью автоматизации регистрации обращений. Ключевое требование: **любой телефонный звонок** (внешний входящий, внутренний, исходящий) должен инициировать создание заявки в OkDesk с прикреплением URL записи разговора.

**Техническая возможность со стороны Mango Office:**  
Модуль интеграции Mango Office получает из шины событий (event bus / webhook) полную телеметрию по всем типам вызовов, включая:
- внешние входящие / исходящие;
- **внутренние звонки** (extension-to-extension);
- метаданные: `call_id`, `from`, `to`, `direction`, `duration`, `recording_url`, `timestamp`.

Передача данных во внешнюю систему возможна через стандартные механизмы: HTTP-запросы к внешнему API, авторизация по токену, формат JSON.

**Реальное ограничение — модель данных OkDesk:**  
Согласно документации API OkDesk [[1]][[2]], сущность «Запись о телефонном разговоре» поддерживает атрибут `direction` только с двумя допустимыми значениями:
- `incoming` — входящий;
- `outgoing` — исходящий.

**Отсутствует нативная поддержка типа `internal`**. Это создаёт семантический разрыв: как корректно отобразить внутренний звонок в системе, где такая сущность не предусмотрена, без искажения бизнес-метрик?

**Целевое состояние:**  
Реализация интеграционного контура, обеспечивающего:
- Единый триггер создания заявки в OkDesk по событию `call_end` для всех типов вызовов;
- Корректный маппинг направления вызова с учётом ограничения модели данных OkDesk;
- Прикрепление `recording_url` и метаданных звонка к созданной заявке;
- Гибкую настройку правил классификации внутренних звонков (через кастомные поля / теги / выбор направления).

# Вопросы для стейкхолдеров (бизнес-уровень)

> *Все формулировки адаптированы для обсуждения с бизнес-заказчиками: без технических атрибутов, на языке бизнес-процессов и результатов.*

## 1. Понимание бизнес-задачи (резюме для согласования)

**Цель интеграции:**  
Обеспечить автоматическое создание обращения в OkDesk по факту любого телефонного разговора (внешнего или внутреннего) с возможностью прослушать запись разговора прямо в карточке обращения.

**Ключевое ограничение со стороны целевой системы:**  
В OkDesk звонки учитываются только в двух форматах: «входящий от клиента» или «исходящий клиенту». Понятие «внутренний разговор между сотрудниками» в системе не предусмотрено.

**Вопрос для согласования:**  
Как бизнесу корректнее учитывать внутренние разговоры в отчётности и рабочих процессах, если технически их нужно «соотнести» с одним из двух доступных типов?

## 2. Вопросы для уточнения требований

### Блок 1: Охват функционала

1. **Какие сценарии звонков критичны для автоматического создания заявок?**  
   - Только внешние звонки от/для клиентов;  
   - Внешние + внутренние разговоры между сотрудниками;  
   - Только отдельные группы сотрудников (например, только техподдержка или продажи).

2. **Должна ли карточка клиента «всплывать» на экране оператора при внутреннем звонке**, как это работает для внешних входящих вызовов?

### Блок 2: Обработка внутренних звонков

3. **Как вы предлагаете отображать внутренние разговоры в отчётах OkDesk?**  
   Учитывая, что система поддерживает только два типа звонков, выберите предпочтительный вариант:
   - Отображать как «входящий от клиента» (просто, но может искажать статистику по клиентским обращениям);  
   - Отображать как «исходящий клиенту» + добавлять пометку «внутренний» в тексте заявки;  
   - Не создавать отдельную заявку, а только прикреплять запись разговора к существующим задачам сотрудника.

4. **Кто должен быть указан как «клиент» в заявке по внутреннему звонку?**  
   - Сотрудник, который принял звонок;  
   - Сотрудник, который инициировал звонок;  
   - Оба участника разговора;  
   - Не указывать конкретного клиента, а создавать общую служебную заявку.

### Блок 3: Состав данных в заявке

5. **Какая информация из разговора должна автоматически попадать в заявку?**  
   Например:  
   - Тема/заголовок заявки (какой шаблон текста использовать);  
   - Ответственный сотрудник (по номеру внутреннего телефона, по группе, по графику);  
   - Категория обращения (техподдержка, продажа, консультация);  
   - Дополнительные пометки (длительность, время, отдел).

6. **Использовали ли вы ранее интеграцию через «Простые звонки»?**  
   Если да — какие данные и в каком виде вас устраивали, что хотелось бы улучшить или изменить?

### Блок 4: Бизнес-правила и фильтрация

7. **Нужно ли создавать заявки по всем внутренним звонкам подряд**, или есть критерии отбора?  
   Например:  
   - Только звонки длительностью более 1 минуты;  
   - Только разговоры с участием определённых отделов;  
   - Только в рабочее время.

8. **Требуется ли раздельная статистика по типам звонков** (внешние / внутренние / исходящие) для управленческой отчётности?  
   Если да — в каком виде вы планируете использовать эти данные (дашборды, еженедельные отчёты, KPI сотрудников)?

### Блок 5: Организация процесса внедрения

9. **Кто с вашей стороны будет отвечать за проверку корректности создания заявок** в тестовом режиме?  
   Готовы ли вы предоставить доступ к тестовой среде OkDesk для отладки интеграции?

10. **Какие критерии вы считаете достаточными для приёмки решения?**  
    Например:  
    - 100% заявок создаются корректно в тестовой серии из 30–50 звонков;  
    - Записи разговоров открываются из карточки заявки без ошибок;  
    - Внутренние звонки отображаются в отчётах согласно выбранному правилу.

## 3. Рекомендации для принятия решения (без технических деталей)

| Бизнес-вопрос | Вариант решения | Последствия для процессов |
|---------------|-----------------|---------------------------|
| **Как учитывать внутренние звонки** | Маппинг на «входящий» | Просто в реализации, но может «загрязнять» статистику по клиентским обращениям |
