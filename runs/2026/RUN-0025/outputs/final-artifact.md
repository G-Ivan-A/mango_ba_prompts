**ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ (версия 1.1)**

**ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ**

Система — Совокупность интегрированных продуктов Mango Office.

AMO CRM (Внешняя система) — Внешняя CRM система, интегрированная с продуктами Mango Office.

Интеграция — Программный модуль Mango Office, обеспечивающий обмен данными и синхронизацию событий между Системой и Внешней системой.

ЛК — Личный кабинет MANGO OFFICE. Интерфейс управления сервисами Mango Office, предоставляющий Заказчику доступ к настройкам, статистике и функционалу продуктов.

Пользователь — Сотрудник Заказчика, наделенный определенной бизнес-ролью с правами администрирования Системы, который имеет (или имел, либо потенциально получит) доступ к системе для выполнения операций в соответствии с правами, назначенными через Личный кабинет Mango Office.

**Правило (интеграции)** — Настройка обработки входящего звонка в таблице «ЛК → Интеграции → AMO CRM → Основные настройки интеграции → вкладка Обработка звонков → раздел Входящие вызовы», содержащая параметры создания Контактов и Сделок в AMO CRM для определённой группы сотрудников, номера телефона или **IVR-схемы**, на которые поступил входящий вызов. Одно Правило может быть привязано только к одному условию (номер, группа или IVR-схема).

**IVR-схема** — Схема распределения звонков (переадресации), содержащая пункты голосового меню (IVR) для навигации звонящих. Включает один или несколько номеров ВАТС, на которые поступают входящие вызовы. Настраивается в разделе «Голосовое меню и распределение звонков» ЛК ВАТС.

**ПРОБЛЕМА, ЦЕЛЬ, ЗАДАЧИ**

Проблема:

Текущий механизм настройки Правил создания контактов и сделок с указанием воронки продаж для входящих вызовов в Интеграции требует индивидуальной конфигурации для каждого номера Виртуальной АТС. При планируемом объеме до 2000 номеров и до 10 воронок продаж в AMO CRM возникает необходимость многократной настройки идентичных Правил, что приводит к избыточным трудозатратам на администрирование Интеграции.

Цель:

Доработать функционал настройки Правил для входящих вызовов через добавление возможности выбора **IVR-схемы** в качестве условия срабатывания **Правила (интеграции)**.

Задачи:

2.3.1. Обеспечить возможность выбора **IVR-схемы** в настройках **Правила (интеграции)**.

2.3.2. Обеспечить применение **Правила (интеграции)** для входящих вызовов, поступающих на номера ВАТС, входящие в выбранную **IVR-схему**.

2.3.3. Обеспечить сохранение текущей логики приоритезации обработки Правил для входящих вызовов.

2.3.4. Обеспечить возможность выбора одной **IVR-схемы** только для одного **Правила (интеграции)**.

**ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ И СЦЕНАРИИ ИСПОЛЬЗОВАНИЯ**

#общее правило по тексту требований: ссылка на родительский пункт (например, 4.1.2) означает выполнение всех его дочерних подпунктов.

4.1. Конфигурация Правил обработки входящих вызовов

4.1.1. Система должна предоставлять Пользователю возможность выбора **IVR-схемы** в качестве условия в **Правиле (интеграции)** в таблице «ЛК → Интеграции → AMO CRM → Основные настройки интеграции → вкладка Обработка звонков → раздел Входящие вызовы».

4.1.2. Выбор **IVR-схемы** должен выполняться как дополнительная опция в списке наряду с существующими:

номером телефона ВАТС;

группой (сотрудников).

4.1.3. В рамках одного **Правила (интеграции)** Система должна предоставлять возможность выбора только одной опции:

номера телефона ВАТС;

номера группы сотрудников;

**IVR-схемы**.

4.1.4. **IVR-схема**, выбранная в одном **Правиле (интеграции)**, не должна отображаться в списке доступных для выбора **IVR-схем** в других **Правилах (интеграции)**.

4.1.5. Настройки вступают в силу только после явного сохранения конфигурации Интеграции.

4.2. Логика обработки входящих вызовов

4.2.1. Система должна применять **Правило (интеграции)**, если входящий вызов поступил на номер ВАТС, входящий в **IVR-схему**, **выбранную в качестве условия в данном Правиле**.

4.2.2. При наличии нескольких Правил обработки входящих вызовов Система должна выполнять обработку входящего вызова строго по первому сработавшему Правилу, расположенному выше в списке (имеющему наибольший приоритет). Последующие Правила для данного входящего вызова не должны анализироваться.

4.2.3. Логика обработки входящих вызовов по **IVR-схеме** должна применяться без изменений текущего функционала обработки вызовов Интеграции.

4.3. Граничные сценарии и обработка состояний

4.3.1. Если **IVR-схема** была удалена или изменена на стороне ВАТС, **Правило (интеграции)** должно сохраняться в конфигурации Интеграции без автоматической модификации.

4.3.2. Изменения конфигурации Правил обработки входящих вызовов применяются только к новым входящим вызовам, поступившим после сохранения настроек Интеграции.
