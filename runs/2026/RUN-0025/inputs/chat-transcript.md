Проблема, цель, задача
Проблема:

Текущий механизм настройки Правил создания контактов и сделок с указанием воронки продаж для входящих вызовов в Интеграции требует индивидуальной конфигурации для каждого номера Виртуальной АТС. При планируемом объеме до 2000 номеров и до 10 воронок продаж в AMO CRM возникает необходимость многократной настройки идентичных Правил, что приводит к избыточным трудозатратам на администрирование Интеграции.

Цель:

Доработать функционал настройки Правил для входящих вызовов через добавление возможности выбора IVR-схемы в качестве условия срабатывания Правила.

Задачи: 

2.3.1. Обеспечить возможность выбора IVR-схемы в настройках Правила.

2.3.2. Обеспечить применение Правила для входящих вызовов, поступающих на номера ВАТС, входящие в выбранную IVR-схему.

2.3.3. Обеспечить сохранение текущей логики приоритезации обработки Правил для входящих вызовов.

2.3.4. Обеспечить возможность выбора одной IVR-схемы только для одного Правила.

4.2. Логика обработки входящих вызовов

4.2.1. Система должна считать Правило обработки входящих вызовов сработавшим, если входящий вызов поступил на номер ВАТС, входящий в IVR-схему, выбранную в Правиле.

4.2.3. Логика обработки входящих вызовов по IVR-схеме должна применяться без изменений текущего функционала обработки вызовов Интеграции.

4.3. Граничные сценарии и обработка состояний

4.3.1. Если IVR-схема была удалена или изменена на стороне ВАТС, Правило обработки входящих вызовов должно сохраняться в конфигурации Интеграции без автоматической модификации.

4.3.2. Изменения конфигурации Правил обработки входящих вызовов применяются только к новым входящим вызовам, поступившим после сохранения настроек Интеграции.

**МОЕ ПОНИМАНИЕ ЗАДАЧИ:**

Заказчик сталкивается с проблемой масштабирования настроек интеграции с AMO CRM. При большом количестве номеров ВАТС (до 2000) и воронок продаж (до 10) текущий механизм требует индивидуальной настройки правил для каждого номера, что создает избыточную административную нагрузку.

**Решение:** Добавить возможность группировки номеров через IVR-схемы, чтобы одно правило применялось ко всем номерам, входящим в схему, вместо настройки каждого номера отдельно.

**АНАЛИЗ ИСХОДНЫХ ФТ:**

**1. Структурные проблемы:**

- Пункт 3 "Бизнес-правила для входящих вызовов" фактически содержит этапы работ (3.1-3.5), а не бизнес-правила. Это противоречит назначению раздела.

- Нумерация задач начинается с 2.3.1, что нарушает логику документа (пропущены 2.1, 2.2).

**2. Дублирование требований:**

Выявлено полное дублирование между разделами 4 и 6:
- 4.1.4 = 6.1.5 (одна IVR-схема только в одном правиле)
- 4.3.1 = 6.1.6 (сохранение правила при удалении/изменении IVR)
- 4.3.2 = 6.1.7 (применение изменений только к новым вызовам)

**3. Терминологические замечания:**

- "ВАТС" используется без расшифровки в тексте требований (хотя есть в терминах)
- "IVR-схема" - термин корректный, но стоит проверить консистентность написания (дефис/тире)
- "Правило" - используется с заглавной буквы, что корректно для обозначения сущности системы

**4. Недостающие требования:**

- Нет требований к отображению названия IVR-схемы в списке выбора
- Нет требований к обработке случая, когда номер входит в несколько IVR-схем (если такое возможно)
- Нет требований к поиску/фильтрации IVR-схем в выпадающем списке (при большом количестве схем)
- Отсутствуют нефункциональные требования (производительность, доступность и т.д.)

**5. Технические уточнения:**

- 4.2.1: требуется уточнить, как система определяет принадлежность номера к IVR-схеме (через API ВАТС, кэш БД, etc.)
- 4.2.2: "расположенному выше в списке" - стоит добавить, что порядок определяется порядком в UI или полем priority в БД

**IVR-схема** — Схема распределения звонков (переадресации), содержащая пункты голосового меню (IVR) для навигации звонящих. Включает один или несколько номеров ВАТС, на которые поступают входящие вызовы. Настраивается в разделе «Голосовое меню и распределение звонков» ЛК ВАТС.
