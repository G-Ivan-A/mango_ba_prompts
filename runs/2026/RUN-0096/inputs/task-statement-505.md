## Решаемая проблема

Прогон задачи 1143 («Подключение SFTP по ключам для передачи записей
разговора») прошёл маршрут Ш-0 → AIN-01…24 → Ш-3 → Ш-4 → Ш-5 на черновиках
после #491/#495. Результат получен, но:

1. Модель на каждом шаге объявляла, что веб-инструмента нет и URL она не
   откроет, хотя в той же сессии трижды выполнила веб-поиск (чат, стр. 1933,
   3932, 4396). БА: «Ассистент по умолчанию при получении ссылок URL должен
   применять инструменты извлечения из вэб» (стр. 780).
2. Маркер ACCESS_GAP и запрос файлов БЗ повторялись на шагах, где они не
   нужны. Фраза «БА — проверить: … дать веб-доступ, приложить файлы»
   «вводит в ступор» (стр. 1647); «Запрос приложения файла на каждом шаге —
   исключить как критическую ошибку» (стр. 1650).
3. Принятые решения терялись. Исключения из AIN-13 не дошли до раздела 2
   (стр. 6214, 6339). Правило нумерации ФТ-NN из AIN-24 не дошло до Ш-3
   (стр. 7335).
4. Предметная ошибка о направлении ключей SFTP прошла от AIN-14 в ФТ-02 и
   UC-01 (стр. 4453, 7466, 8081).
5. Каждый ответ несёт 5–7 служебных блоков. Каждая карточка AIN повторяет
   общий контракт: 17 132 символа из 19–20 тысяч. Это 84–90 % текста карточки.

Требуемый результат — не исправление промптов в этом PR, а **RUN, разбор
проблем для отладки, RFC с обоснованием правок и задача на исполнение RFC**.

## Story

**Как есть:**

- **Кто действует:** БА проходит маршрут BCREQ в чате и копирует промпты с сайта.
- **Что происходит:**
  - модель тратит ходы на объяснения доступа, а не на шаг;
  - БА расшифровывает служебные маркеры;
  - на повторе шага БА заново получает весь результат;
  - решения, принятые в начале чата, к концу чата пропадают.
- **Где долг:**
  - промпты A-IN усиливают отказ от инструментов. Тексты «URL … не являются доступом» и «Промпт не добавляет инструмент» модель читает как запрет;
  - общий контракт повторяется 24 раза;
  - правила вывода противоречат друг другу (раздел ПР-12 анализа).

**Как должно быть:**

- **Кто действует:** тот же БА, те же два формата шагов.
- **Какой результат доступен:**
  - RFC с таблицей «проблема → промпт → правка → почему → как проверить»;
  - анализ избыточного контента с замером;
  - предложения по сайту, инструкциям и этапу 2;
  - issue на исполнение RFC;
  - статусы в бэклоге.
- **Как принимает Пользователь:** merge PR #507 принимает RFC и анализ, решения владельца Р-ОТЛ-1…Р-ОТЛ-6 принимаются в RFC. Комментарий в PR и перезапуск означают доработку этого же PR.
