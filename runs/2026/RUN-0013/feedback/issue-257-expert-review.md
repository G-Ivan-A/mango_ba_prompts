# Issue #257 — экспертное ревью BCREQ-1027 v2

Сводка подготовлена по шести ролям, указанным в issue #257: архитектор, PO и
техлид ВАТС; архитектор, PO и техлид КЦ.

## Согласованная модель

| Тема | Консолидированное решение |
| --- | --- |
| Тип изменения | Новый результат обращения, а не новый lifecycle-статус обращения или сессии. |
| UI-метка | `Обработано без ответа`. |
| API enum | `result = 8`, наименование `Завершено без ответа`. |
| Кнопка оператора | Использовать существующее `Завершить обращение`; новую кнопку не добавлять. |
| Колонка отчета | Использовать существующую колонку `Результат`; новую колонку в `Истории обращений` не добавлять. |
| Настройка | Чекбокс в `ЛК-Диалоги -> Виджет канала` или эквивалентных настройках группы каналов. |
| Default | `выключено` для обратной совместимости. |
| Срабатывание | Только ручное завершение текстового/диалогового обращения оператором при включенной настройке и отсутствии сохраненного ответа оператора. |

## Общие ограничения

- Ответом оператора считается только сообщение сотрудника, сохраненное в
  истории обращения КЦ/Манго Диалогов.
- Автоответы, чат-бот, системные сообщения, сообщение при закрытии, события
  доставки/прочтения и прямые ответы во внешнем мессенджере без сохранения в КЦ
  не считаются ответом оператора.
- `Переведено`, `Спам`, `Запрещена отправка`, таймауты, нераспределенные
  обращения и закрытия внешней системой не должны переопределяться в `8` без
  отдельного решения.
- Исторические обращения не пересчитываются.
- `result = 8` не создает факт первого ответа оператора.

## Затронутые поверхности

| Поверхность | Вывод ревью |
| --- | --- |
| `ЛК-Диалоги` | Требуется чекбокс, заголовок и info-подсказка в настройках виджета/канала. |
| `Мои обращения` | Изменяется только логика результата при существующем завершении обращения. |
| `История обращений` | Новое значение в существующей колонке, фильтре и CSV-экспорте. |
| `Исходящие обращения` | Новое значение в существующей колонке `Результат`. |
| API КЦ | Расширить enum результата обращения до `8`. |
| `POST /vpbx/cc/appeals/create-closed-appeals` | Принимать `result = 8`, если метод создает закрытое обращение с указанным результатом. |
| `POST /events/md/onAppealClose` | Возвращать `result = 8` для закрытого обращения с новым результатом. |
| `POST /vpbx/stats/calls/result` | Расширить `conversion.result`, если API возвращает обращение с новым результатом. |
| `POST /cc/md/session/close` | Не добавлять обязательный `result`; сервер вычисляет результат или внешнее закрытие остается вне scope. |
