# BCREQ-1027. Раздел 4.3: API-методы

## 4.3. API-методы

4.3.1. Система должна использовать метод API ВАТС `POST /vpbx/stats/calls/result` как единственный API-метод раздела 4.3 для получения результатов звонков и связанных с ними данных статистики. Раздел 4.3 не вводит отдельные методы, события или поля для текстовых обращений.

4.3.2. Система должна выполнять обращение к `POST /vpbx/stats/calls/result` с параметрами авторизации API ВАТС и JSON-параметром `key`, полученным при подготовке статистических данных. В рамках данного раздела входной состав метода фиксируется следующим образом:

| Вложенность 1 | Вложенность 2 | Вложенность 3 | Вложенность 4 | Тип | Описание | Примечание |
| --- | --- | --- | --- | --- | --- | --- |
| `key` |  |  |  | string | Ключ подготовленного набора статистики звонков. | Обязателен для получения результата; создается при обработке запроса на построение статистики. |

4.3.3. Система должна обрабатывать ответ `POST /vpbx/stats/calls/result` по полям верхнего уровня `result`, `status` и `data`. Значение `status` определяет состояние подготовки результата: `request`, `work`, `complete`, `cancel`, `error` или `not-found`. Только при `status = complete` массив `data` используется как источник результатов звонков.

| Вложенность 1 | Вложенность 2 | Вложенность 3 | Вложенность 4 | Тип | Описание | Примечание |
| --- | --- | --- | --- | --- | --- | --- |
| `result` |  |  |  | integer | Код результата обработки API-запроса. | Используется без переопределения бизнес-результата звонка. |
| `status` |  |  |  | string | Статус подготовки статистики. | При `complete` данные готовы к обработке. |
| `data` |  |  |  | array | Набор статистики по периодам. | Каждый элемент содержит список звонков и агрегаты периода. |
| `data` | `list` |  |  | array | Массив объектов звонков. | Основной источник детальных результатов звонков. |

4.3.4. Система должна определять результат каждого звонка только по данным объекта звонка из `data.list` и вложенных элементов `context_calls`. Для классификации "с ответом" / "без ответа" используются доступные в ответе признаки `context_status`, `talk_duration`, `call_answer_time`, `call_end_time` и `context_calls[].talk_duration`; новые значения результата или новые поля API в рамках раздела 4.3 не добавляются.

| Условие по данным `POST /vpbx/stats/calls/result` | Интерпретация для BCREQ-1027 |
| --- | --- |
| `context_status = 1` и есть положительная длительность разговора в `talk_duration` или `context_calls[].talk_duration`. | Звонок завершен с ответом. |
| `context_status = 0`, `talk_duration = 0` или отсутствует `call_answer_time` при наличии завершения по `call_end_time`. | Звонок завершен без ответа. |
| Элемент ответа служебный и не содержит времени ответа, завершения или длительности звонка. | Значение не классифицируется; данные остаются в ответе без искусственного результата. |

4.3.5. Система должна сохранять исходные поля API ВАТС без переименования: `entry_id`, `context_type`, `context_status`, `caller_id`, `caller_name`, `caller_number`, `called_number`, `context_start_time`, `duration`, `talk_duration`, `context_calls`, `period`, `total_talks_duration`, `total_calls_duration` и `total_calls_count`. Если в ответе присутствует блок `conversion`, его поле `result` трактуется только как результат связанного обращения из статистики и не заменяет результат звонка.

4.3.6. Система не должна менять правила авторизации API ВАТС, формат подписи запроса, порядок периодического опроса готовности результата, структуру `data.list` и семантику существующих полей `result`, `status`, `context_status` и `context_calls`.

4.3.7. В обязанности Исполнителя не входит доработка внешних систем, которые получают или интерпретируют статистику звонков. Внешние системы используют метод `POST /vpbx/stats/calls/result` и существующие поля ответа после обновления API-документации и требований раздела 4.3.

## Резюме изменений

- Раздел 4.3 переведен на конкретный API ВАТС метод `POST /vpbx/stats/calls/result`.
- Убрана логика добавления нового поля в события и методы для текстовых обращений: она не соответствует целевому API из issue #207.
- Описание запроса и ответа ограничено параметром `key`, статусом подготовки результата и структурой ответа `data.list` / `context_calls`.
- Раздел 3 не формируется. Разделы 1, 2, 4.1, 4.2, 4.4 и 6 не воспроизводятся в этом артефакте.
