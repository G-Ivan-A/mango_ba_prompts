## Почему это не ADR и не `docs/adr/`

Артефакт фиксирует **исследование**, а не решение: часть контракта Mango закрыта публичной документацией лишь частично, гипотеза Г1 не проверена. Индустриальная связка — «spike → ADR»: сначала исследование снижает неопределённость, затем принятое решение фиксируется в ADR. Разбор источников и выбор структуры — [`docs/analysis/2026-08-26-architecture-spike-format-research.md`](../../../../docs/analysis/2026-08-26-architecture-spike-format-research.md).

## Главный вывод

Критический путь описывается по полям **целиком со стороны hh.ru и лишь частично со стороны Mango**: в публичном MDAPI нет метода приёма входящего сообщения клиента из внешнего канала и нет типа канала HH.ru. Рекомендуемое целевое решение — нативный канал по образцу «Авито Работа» (тип 14); middleware на публичном API реализуем, но обращение минует очередь `pending`, из-за чего маршрутизация, автоответы и отчётность КЦ деградируют.

## Чего этот прогон не делает

- Не проверяет гипотезы Г1–Г5 — боевого доступа работодателя к hh.ru нет.
- Не оценивает трудоёмкость: без ответов на вопросы §8.2 объём работ по рекомендуемому варианту не определён.
- Не заменяет ADR по каналу HH.ru — тот уместен после раскрытия внутреннего контракта.
- Не предназначен для передачи внешнему Заказчику.
