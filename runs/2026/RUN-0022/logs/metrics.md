# Метрики прогона 1040 (измеренные)

Issue #271 и [`standards/runs-contract-standard.md`](../../../../standards/runs-contract-standard.md)
требуют фиксировать токены, длительность, `eval`/вердикт и `success_rate`. Ниже —
как они получены.

## Метод измерения

| Метрика | Источник | Метод |
| --- | --- | --- |
| Токены входа/выхода | `content_list[phase == "answer"].usage` реплики ассистента | значения провайдера, **измерены**, не пересчитаны сторонним токенизатором |
| Токены «мышления» | `usage.output_tokens_details.reasoning_tokens` | значения провайдера |
| Латентность генерации | `extra.endTime` − `timestamp` реплики ассистента | секунды |
| Активное время | сумма непрерывных сессий (разрыв > 1 ч считается паузой) | секунды |
| Календарное время | `timestamp` первой реплики — `endTime` последней | секунды |

Отличие от [`RUN-0018`](../../RUN-0018/logs/metrics.md): там токены оценивались
через `tiktoken:cl100k_base` (чужая для Qwen кодировка), здесь выгрузка содержит
собственные счётчики провайдера, поэтому `token_method: provider-usage`.
Значения двух прогонов сопоставимы по порядку, но не побайтово эквивалентны.

Воспроизведение:

```bash
python3 experiments/chat_export_usage_metrics.py \
  runs/2026/RUN-0022/inputs/1040-chat-export-1787301483841.json
```

## Длительность

| Показатель | Значение | Что означает |
| --- | ---: | --- |
| `duration_generation_s` | 300.6 | суммарная работа модели |
| `duration_active_s` | 347 | две непрерывные сессии: 229 с (эпизоды 1–2) + 117 с (эпизод 3) |
| `duration_wall_clock_s` | 522 867 (≈145.2 ч) | 2026-06-25 08:08:42 → 2026-07-01 09:25:06 UTC |

Разрыв между эпизодами 2 и 3 — **6 суток**: за это время БА сменил концепцию
решения вне чата. Календарное время прогона поэтому измеряет процесс БА, а не
работу модели; для сравнения промптов пригодны только первые две строки.
