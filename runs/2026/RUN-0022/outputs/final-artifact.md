## Раздел 4 — версия БА (реплика 24, дословно)

```text
Функциональные требования и сценарии использования  (новый канал HH в МД)

Авторизация во Внешней системе (ФТ-01)

4.1. Система должна предоставлять возможность Пользователю с правами администрирования авторизоваться во Внешней системе (HeadHunter) в процессе настройки интеграции для получения доступа к API чатов Кандидатов.

4.1.1. Авторизация с HeadHunter реализуется через ЛК с использованием OAuth-протокола.

Подключение канала (ФТ-02)

4.2. Система должна предоставлять возможность Пользователю с правами администрирования подключать и настраивать канал HeadHunter в ЛК после успешной авторизации во Внешней системе.

4.2.1. Подключение: "ЛК → Текстовые коммуникации → Каналы → Группа каналов".
4.2.2. Доступно включение и отключение канала.
4.2.3. Отключение канала прекращает прием новых сообщений из HeadHunter, но сохраняет доступ к историческим данным в интерфейсе КЦ.

Настройки канала (ФТ-03)

4.3. Система должна предоставлять возможность Пользователю настраивать маршрутизацию созданных в КЦ Обращений из канала HeadHunter на Рекрутера или группу Рекрутеров единообразно (консистентно) с другими текстовыми каналами МД.

Доступен функционал, аналогичный по функциональности текущим настройкам каналов МД:

4.3.1. Прием и обработка обращений (Кто будет принимать обращения, Распределение обращений);
4.3.2. Автоматические ответы;
4.3.3. Общие настройки (Автоматическое завершение диалогов).

Фильтрация коммуникаций по признаку вакансии (ФТ-04)

4.4. Система должна предоставлять возможность Пользователю настраивать правила фильтрации входящих сообщений Кандидатов из канала HeadHunter в КЦ по признаку Вакансии для обеспечения коммуникации только по Вакансиям на линейный персонал.

4.4.4. Цель: передать в КЦ обработку коммуникаций только по вакансиям на линейный персонал.
4.4.5. Признак фильтрации (например, «Код вакансии»): согласовывается на этапе проектирования.
4.4.6. Сообщения по Вакансиям, не прошедшим фильтр (офисный персонал), не создают Обращений в КЦ. Диалог по таким Вакансиям ведется Рекрутером напрямую в HeadHunter.

Создание и обработка Обращения в КЦ (ФТ-05)
4.5. Система должна обеспечивать создание Обращения в Чате с клиентом КЦ в момент поступления первого входящего сообщения от Кандидата в канале HeadHunter по Вакансии, по которой отсутствует активное Обращение, и передачу в КЦ исторического контекста, накопленного в открытой Сессии по соответствующей Вакансии.

4.5.1. Создание Обращения происходит исключительно по факту отправки Кандидатом текстового сообщения в чат HeadHunter.
4.5.2. Отклики без текста не создают Обращений (является отключаемой продуктовой опцией, по умолчанию выключено).
4.5.3. Система сохраняет сессию чата с клиентом и закрывает сессию одновременно с закрытием Обращения при наступлении одного из условий:
обращение закрыто в соответствии с настройками правил обработки текстовых обращений;
обращение закрыто в соответствии с общими настройками канала;
фактом завершения обращения рекрутером в КЦ.
4.5.5. Обращения по разным Вакансиям от одного Кандидата формируют параллельные независимые диалоги в КЦ.
4.5.6. Новое сообщение по ранее закрытой Вакансии инициирует создание новой Сессии (п.4.5.3) и нового Обращения (п.4.5.1.).
4.5.7. Обработка обращения ...

Двусторонняя синхронизация переписки между системами (ФТ-06)

4.6. Система должна обеспечивать двустороннюю синхронизацию переписки Акторов в чате HeadHunter и Чате с клиентом КЦ в реальном времени при обмене сообщениями, без необходимости авторизации Рекрутера во Внешней системе.

4.6.1. Синхронизации подлежат текстовые сообщения и поддерживаемые форматы вложений.
Форматы вложений подлежат отдельному согласованию.

4.6.2. Система обновляет статус отклика в HeadHunter в зависимости от обработки обращения:
После ответа оператора в КЦ на сообщение Кандидата в HeadHunter - статус отклика в HeadHunter изменяется на статус, соответствующий статусу обработки отклика;
При закрытии обращения в КЦ без ответа - статус отклика в HeadHunter остается неизменным.

Учет нескольких Акторов в чате HeadHunter (ФТ-07)

4.7. Система должна обеспечивать учет и консолидацию сообщений от нескольких Акторов в одном чате HeadHunter в рамках одного Обращения в КЦ, связанного с Кандидатом, при поступлении новых сообщений по паре «Кандидат — Вакансия».

4.7.1. Консолидация сообщений выполняется по уникальной паре «Кандидат + Вакансия» в рамках одной Сессии.
Сообщения, отправленные Рекрутером из КЦ, передаются в HeadHunter от имени авторизованного аккаунта интеграции.
Форматы идентификации Рекрутера при условии коммуникации в чате нескольких Рекрутеров подлежат отдельному согласованию после анализа API HeadHunter и возможностей разработки.
4.7.2. Получение событий о новых сообщениях не зависит от статуса ответственного за Вакансию в HeadHunter Рекрутера.

Передача истории переписки в чате HeadHunter, инициированной до создания Обращения в КЦ (ФТ-08)

4.8. Система должна обеспечивать автоматическую передачу в Чат с клиентом КЦ контекстных данных о Кандидате и Вакансии в момент создания нового Обращения.

4.8.1. При создании Обращения в КЦ передается исторический контекст, накопленный в открытой Сессии по соответствующей Вакансии, включая: 
текст сообщения или нескольких сообщений Акторов по вакансии до взятия Обращения в работу Рекрутером;
название вакансии;
ссылка на вакансию;
ссылка на резюме;
данные кандидата (ФИО; id кандидата в HeadHunter; телефон при наличии).
4.8.2. Исторические данные (коммуникации, вложения), созданные в чате HeadHunter до момента подключения канала, не импортируются в КЦ.

Синхронизация контактов Кандидатов с Адресной книгой (ФТ-09)

4.9.Система должна обеспечивать автоматическое сопоставление, сохранение и актуализацию данных Кандидата в Адресной книге (АК) КЦ в момент создания нового Обращения.

4.9.1. Сопоставление с контактом АК выполняется по следующему приоритету ключей:
Идентификатор в HeadHunter (основной ключ).
Номер телефона (дополнительная проверка).
4.9.2. При отсутствии совпадений создается новая карточка контакта.
4.9.3. При частичном совпадении данных выполняется дополнение карточки:
Совпадение идентификатора HeadHunter при различии телефонов: добавление нового номера.
Совпадение телефона при различии идентификаторов: в карточку контакта добавляем новую запись с данными, идентифицированными для id кандидата в HeadHunter.
4.9.4. При полном совпадении всех ключей обновление карточки не выполняется.

Отчетность и статистика (ФТ-10)

4.10. Система должна предоставлять возможность Пользователю формирования и выгрузки отчетов по взаимодействиям с Кандидатами в Чате с клиентом КЦ в интерфейсе КЦ по результатам обработанных Обращений.

4.10.1. Канал HeadHunter добавляется в следующие отчеты и фильтры отчетов "КЦ → Обращения":
История обращений;
Контроль сотрудников → Текст.
4.10.2. В отчеты передаются только сопоставимые поля из HeadHunter.
Подлежат отдельному согласованию после анализа API HeadHunter и возможностей разработки.
4.10.3. Формирование статистики и выгрузка отчетов реализуются через штатный интерфейс экспорта КЦ.
```
