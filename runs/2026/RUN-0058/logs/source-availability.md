# Доступность источника: почему RUN-0056 не увидел API чатов

## Факт

В RUN-0056 документация hh.ru была недоступна исполнителю, и раздел «Чаты» отсутствовал в рассмотрении. Это привело к разрыву GAP-1 («публичного API чатов не обнаружено») и к вердикту «начинать разработку не рекомендуется».

В RUN-0058 спецификация получена без ограничений: `https://api.hh.ru/openapi/specification/public`, `openapi: 3.0.3`, 1266582 байт, SHA-256 `4349900b6398d462954fadee691305d719e96f3018de929ce069df0e516d383d`.

## Почему источник не был найден раньше

Прямые «ожидаемые» адреса спецификации не работают: `https://api.hh.ru/openapi/openapi.json` отвечает `404`. Человекочитаемая страница `https://api.hh.ru/openapi/redoc` — это HTML-оболочка Redoc: содержательного текста в ней нет, документация подгружается скриптом, а фактический адрес спецификации указан в bootstrap-вызове `Redoc.init('https://api.hh.ru/openapi/specification/public', …)` внутри страницы.

Следствие: инструмент, который извлекает из страницы текст, на `redoc` получает практически пустой результат и может интерпретировать его как «раздела нет». Вывод «публичного API чатов не обнаружено» был артефактом способа доступа, а не свойством API.

## Урок для будущих прогонов

1. Отрицательный вывод об отсутствии возможности в стороннем API MUST опираться на прочитанную машиночитаемую спецификацию, а не на недоступность страницы документации.
2. Для SPA-документации (Redoc, Swagger UI, Stoplight) сначала извлекается адрес спецификации из исходного HTML, и анализируется спецификация.
3. Если источник недоступен, вывод формулируется как «источник недоступен» и сопровождается условием пересмотра. RUN-0056 это правило соблюдал — его feedback прямо предписывал переоценку при появлении API, и именно поэтому переоценка стала возможной без потери контекста.
4. Хеш и размер загруженной спецификации фиксируются в прогоне, чтобы последующая переоценка могла отличить «изменился API» от «изменилась оценка».
