# Статистика human review: проверка ссылок на twin (задача 1090)

Приоритет задачи [#336](https://github.com/G-Ivan-A/mango_ba_prompts/issues/336) — процесс human review в части проверки ссылок на twin: насколько удобно проверять выводы отчёта, переходя по ссылкам, и в чём именно проявляется недостаток однозначности.

Ниже — только измеренные величины. Как они получены и чем воспроизводятся — в [`../logs/experiment-log.md`](../logs/experiment-log.md); полные таблицы проверок — в [`../logs/link-verification.md`](../logs/link-verification.md).

## 1. Что мешает проверке: ссылки на twin в отчёте не адресуют

В отчёте RUN-0057 источники twin записаны текстовыми токенами вида `[twin: scripts/blocks/starting-block]`.

| Показатель | Значение |
| --- | --- |
| Токенов `[twin: …]` в отчёте | 132 |
| Из них токенов-заполнителей (легенда формата) | 1 |
| Упоминаний страниц (токен может называть несколько) | 174 |
| Различных страниц | 79 |
| Токенов, называющих сразу несколько страниц | 32 |
| Кликабельных ссылок (URL) | 0 |
| Токенов с якорем раздела (`#…`) | 0 |
| Токенов с указанием раздела или места на странице | 0 |
| Страниц, процитированных 3 и более раз | 17 |
| Упоминаний, приходящихся на эти 17 страниц | 94 |

Самая цитируемая страница — `scripts/blocks/starting-block`: 17 упоминаний. Это значит, что проверяющий 17 раз открывает одну и ту же страницу и каждый раз ищет на ней нужное место заново: токен не различает, какое из утверждений отчёта откуда взято.

## 2. Асимметрия: источники Mango в том же отчёте адресуют точно

В одном и том же файле два стиля цитирования.

| Источник | Токенов | С указанием раздела (`§`) | С указанием страниц |
| --- | --- | --- | --- |
| `[ROBOTFIL, …]` | 116 | 96 | 92 |
| `[SA, …]` | 106 | 89 | 81 |
| `[twin: …]` | 132 | 0 | 0 |

Ссылки на PDF-документы Mango дают параграф и диапазон страниц, ссылки на вики — только путь страницы. Отсюда наблюдаемая жалоба именно про twin: проблема не в объёме цитирования, а в его разрешающей способности.

## 3. Доступность источников проблемой не является

Проверены все 79 различных страниц, названных в отчёте:

- HTTP 200 — **79 из 79**; неработающих ссылок нет;
- заголовки с якорями публикуют **71 страница из 79** (90%), всего 345 заголовков;
- на страницы с якорями приходится **159 из 173** предметных упоминаний (92%).

То есть техническая возможность указывать место на странице существует почти всегда: нужный якорь уже опубликован вики, отчёт им просто не пользуется.

## 4. Как процесс шёл в диалоге: формат исправили, адресность — нет

Реплика 16 — момент, когда БА отклонил формат ответов как неудобный для проверки. До и после неё:

| Показатель | Реплики 1–15 | Реплики 17–30 |
| --- | --- | --- |
| Реплик модели | 8 | 7 |
| Средний объём ответа, символов | 5944 | 933 (−84%) |
| Ссылок-URL в ответах | 7 | 14 |
| Указаний «Раздел на странице» | 0 | 13 |

Ответы стали короче и обзавелись указанием раздела. Но проверяемость выросла не настолько, насколько выглядит по формату — см. следующий раздел.

## 5. Чем указание раздела оказалось на практике

Проверена 21 ссылка из ответов модели: страница загружена, её заголовки сопоставлены с заявленным разделом.

| Исход | Ссылок |
| --- | --- |
| раздел не указан | 8 |
| названо заглавие страницы, а не раздел | 8 |
| формулировка есть в тексте, но не заголовком | 1 |
| на странице не найдено | 3 |
| заголовок найден, якорь существует | 1 |

Плюс форматные расхождения, каждое из которых стоит проверяющему лишнего шага:

- **0 из 21** ссылок содержат якорь `#…` — переход всегда открывает страницу сверху;
- 2 ссылки идут с префиксом `/ru/`, 19 — без него (вики отвечает 200 на оба варианта, но в отчёте это выглядит как две разные ссылки на один источник);
- 1 ссылка ведёт на индекс раздела `…/scripts/blocks/`, а не на страницу.

Итог: из 13 заявленных разделов реальному заголовку страницы соответствует **один**. Восемь — это пересказ заглавия самой страницы (проверяющий не получает новой информации о месте), три не находятся на странице вовсе (раздел назван по смыслу, а не по тексту вики).

## 6. Содержательное следствие, обнаруженное при проверке

Ни на одной из 79 процитированных страниц (и на индексе `scripts/blocks/`) не встречается упоминание завершения звонка («завершить звонок», «завершение звонка»). Вердикт диалога об уровне покрытия для соответствующего требования опирается на ссылку, которую по отчёту проверить нельзя.

Оговорка о границах: поиск по всей вики не выполнялся — `sitemap.xml` на `wiki.twin24.ai` отсутствует, поэтому проверялись только страницы, названные отчётом и диалогом. Утверждение относится к проверяемости ссылки, а не к отсутствию функции в продукте.

## 7. Что из этого следует для процесса

1. **Узкое место human review — не доступность источника, а адресность.** Все ссылки живые; стоимость проверки создаёт поиск нужного места на странице, особенно на 17 страницах, которые цитируются по 3+ раза.
2. **Требование к формату должно быть проверяемым машинно.** Просьба «указывать раздел» выполнена по форме в 13 случаях из 14 и по существу — в 1 из 13; без автоматической проверки якоря такое требование не держится.
3. **Способ исправления уже доступен:** 92% упоминаний ведут на страницы с опубликованными якорями. Черновик формата ссылки — в [`link-reference-contract-draft.md`](link-reference-contract-draft.md); он не нормативен и вносится отдельной задачей.
