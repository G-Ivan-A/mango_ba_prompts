## Ключевые выводы (TL;DR)

1. **Доминирующий отказ — самовольная перегенерация согласованного текста.**
   Модель раз за разом «улучшала» формулировки, которые человек уже утвердил.
   На чисто механическую операцию в эпизоде 14 (разложить вопросы по шести
   блокам и пронумеровать в формате «Вопрос N.») ушло пять итераций.
2. **Правила, записанные «в долгосрочную память», не удерживаются.** Оба явно
   зафиксированных правила ([32] — субъективное заявление Заказчика не
   документируется как дефект продукта; [60] — удалённое человеком не
   возвращается) были нарушены в последующих репликах ([54], [67], [71]).
3. **Регрессии внутри контекста.** Утверждение о ролевой модели, опровергнутое
   человеком в [24], возвращено моделью в [29].
4. **Фактчек работает только по явному запросу.** Там, где человек прямо
   потребовал ссылки на страницы ([42]), модель дала проверяемый результат
   (тематики КЦ в Битрикс24, с. 118–120). Без такого требования она
   утверждала непроверенное ([8]–[9]) и соглашалась с правками, не сверяясь
   с источником ([11]: «Нет, не перепроверил»).
5. **Наиболее ценный переиспользуемый результат** — приём разметки версий
   маркерами `*[ИЗМЕНЕНИЕ: ...]*` / `*[ДОПОЛНЕНИЕ: ...]*` ([40]–[41]) и
   переформулировка оценочного требования («истинный real-time») в проверяемое
   через фактический интервал обновления Wallboard 5–10 с ([59]).
