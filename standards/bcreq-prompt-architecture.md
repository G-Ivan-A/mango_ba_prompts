# Архитектура промптов BCREQ: Промпт 0, шаблон шага, stepwise и oneshot

> Носитель — [ADR-012](../docs/adr/2026-10-adr-012-bcreq-meta-standards.md).
> Нормативный словарь [RFC 2119](https://www.rfc-editor.org/info/bcp14).
> Именование и frontmatter — [prompt-standard](prompt-standard.md).
> Сами промпты пишет Задача 3 в `prompts/bcreq/`
> ([аудит §3.8](../docs/analysis/2026-10-23-prompts-catalog-audit.md#38-вектор-для-задачи-2)).

Стандарт отвечает на запрос issue #387: Промпт 0 как конституция процесса,
шаблон шагов 2.1–2.14 с позицией «пройдено / текущий / рекомендуемый
следующий», разделение stepwise и oneshot. Он также подтверждает структуру
2.1–2.14 по наблюдениям Н1–Н12 аудита Задачи 1 и предлагает
обоснованные уточнения: БА прямо просил подтвердить структуру или предложить
альтернативу [р. 778, Ч-35](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L69).

## 1. Состав и принципы

| ID | Принцип | Основание |
| --- | --- | --- |
| А1 | Шаг — единица смысла (раздел и вход), файл промпта — единица упаковки. Несколько шагов **МОГУТ** выполняться одним файлом с параметром, если у них один шаблон вывода. | АП5 аудита: варианты одной операции расходятся по содержанию |
| А2 | Промпт 0 задаёт структуру документа и все шаги сразу; остальные промпты его не переопределяют. | [р. 754, Ч-25](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L59) |
| А3 | Каждый промпт, кроме Промпта 0, начинается с напоминания о конституции и пройденных шагах. | [р. 754, Ч-26](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L60) [р. 796, Ч-47](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L81) |
| А4 | Следующий шаг — рекомендация, а не приказ: БА может ввести свою команду. | [р. 766, Ч-32](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L66) |
| А5 | Правила раздела не придумываются в промпте: промпт переносит ID правил мета-стандарта (Р, КС, БС, CB, пункты чек-листа). | единый источник правил — `standards/bcreq-sections/` |
| А6 | Модель не проходит гейты и не ставит статус `ready`. | правило B3, АП2 |
| А7 | Число промптов stepwise и oneshot различается; новый файл появляется, только если поведение отличается. | [р. 796, Ч-46](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L80); issue #387: «анти-инфляция приоритет» |

Почему цепочка, а не один большой промпт. Длинный контекст хуже удерживает
сведения из середины ([Liu et al., 2023](https://arxiv.org/abs/2307.03172)),
поэтому каждый шаг повторяет конституцию и итог пройденных шагов (А3).
Цепочка промптов с проверками между вызовами — базовый шаблон агентных систем
([Anthropic, 2024](https://www.anthropic.com/engineering/building-effective-agents),
«Prompt chaining» с gate). Гейты стадий — человеческие
([контракт гейтов](../docs/contracts/bcreq-stage-gates.md#2-гейты)).

## 2. Промпт 0 — конституция

Промпт 0 запускается один раз на задачу, в одном вызове. Он **ДОЛЖЕН**:

1. Получить карточку задачи — параметры прогона:

   | Параметр | Значения | По умолчанию | Где описан |
   | --- | --- | --- | --- |
   | `режим` | `stepwise` \| `oneshot` | `stepwise` | §4 |
   | `продукты` | профили: ЛК, ВАТС, КЦ, РА, API, оператор | из входа; вопрос БА, если не ясно | [композиция §4](bcreq-composition-standard.md#4-профили-продуктов) |
   | `вариант` | `delta` \| `new` | `delta` | [раздел 3](bcreq-sections/03-functional-requirements.md#варианты-раздела) |
   | `уровень` | `L1` \| `L1+L2` | `L1` | [раздел 5](bcreq-sections/05-solution-description.md#уровни-l1-и-l2) |
   | `альтернативный стандарт` | `нет` \| `TM Forum ODA` | `нет` | [композиция §3](bcreq-composition-standard.md#3-tm-forum-oda--альтернативный-стандарт) |

2. Вывести каркас документа: 8 разделов и подразделы с дополнениями ＋2.5,
   ＋8.4, ＋8.5 ([README §1](bcreq-sections/README.md#1-восемь-разделов)), у каждого —
   статус `пусто`.
3. Закрепить конституцию: общие правила Р1–Р7
   ([README §3](bcreq-sections/README.md#3-общие-правила-для-всех-разделов)), стили
   ([README §2](bcreq-sections/README.md#2-стили)), запреты §7 и карту шагов §3.
4. Вывести блок «Состояние BCREQ» (§3) с `текущий: Ш-0`,
   `рекомендуемый следующий: Ш-1`.

Промпт 0 не генерирует содержание разделов. Он одинаков для обоих режимов.

### Обязательные блоки промпта шага

Каждый промпт, кроме Промпта 0, **ДОЛЖЕН** иметь блоки в этом порядке:

| № | Блок | Содержание |
| --- | --- | --- |
| 0 | Конституция и позиция | «Вспомни конституцию (Промпт 0): структура, стили, правила Р1–Р7, запреты». Затем три строки: **Пройдено** — шаги со статусом и одной строкой итога; **Текущий** — Ш-N, раздел, цель; **Рекомендуемый следующий** — Ш-M или гейт. |
| 1 | Роль | Функция без методологий и сертификатов: «аналитик требований, который …» (АП1). |
| 2 | Вход и остановки | Что нужно на входе; CB-0.x и CB раздела — условия остановки. |
| 3 | Шаги | stepwise: подшаги со стоп-гейтом и ожиданием ответа БА (У2); oneshot: подшаги без ожидания. |
| 4 | Правила раздела | ID и текст правил мета-стандарта раздела (А5). |
| 5 | Формат вывода | Разметка раздела по шаблону мета-стандарта (АП6). |
| 6 | Состояние BCREQ | Обновлённый блок для следующего вызова. |

### Блок «Состояние BCREQ»

БА копирует блок в следующий вызов (stepwise), агент передаёт его сам (oneshot).

```text
Состояние BCREQ
- задача: <ID и название>
- параметры: режим=stepwise; продукты=ЛК, ВАТС; вариант=delta; уровень=L1; альтернативный стандарт=нет
- пройдено: Ш-0 каркас; Ш-1 разделы 1, 2 — draft; Ш-2 ＋2.5 — draft
- гейты: Г-IN — пройден БА 2026-10-23
- текущий: Ш-3 раздел 3
- рекомендуемый следующий: Ш-4 раздел 4
- открытые вопросы: 8.4 — 3 (1 блокирует оценку)
```

Статусы разделов: `пусто | draft | needs-clarification | устарело` выставляет
модель; `ready` — только человек (У5, А6).

## 4. stepwise и oneshot

Семантика — по гипотезе БА [р. 796, Ч-44](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L78) [р. 796, Ч-45](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L79), принятой в issue #387.
БА мета-модель описывает прежде всего автоматизированный прогон, поэтому
oneshot следует стадиям строго, а stepwise — логике ручной работы БА.

| Признак | stepwise | oneshot |
| --- | --- | --- |
| Для кого | ручной прогон БА в чате | ИИ-агент; допустим ручной прогон БА |
| Единица вызова | один шаг Ш-N | одна стадия: A-IN, A-CORE или A-WORK |
| Ожидание ответа | после каждого подшага (стоп-гейт, У2) | нет; вопросы копятся в 8.4 |
| Порядок | рекомендуемый; БА может пропустить, повторить или переставить шаг (А4) | фиксирован стадией |
| Гейты | БА проходит Г-IN; Г-С1 и Г-W — люди из контракта | промпт **НЕ ДОЛЖЕН** пересекать границу гейта: стадия заканчивается отчётом по критериям гейта |
| Возвраты | решает БА (Г1) | агент останавливается и рекомендует точку возврата (Г1) |

**Число промптов** (не обязано совпадать, [р. 796, Ч-46](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L80)):

| Файл (Задача 3, `prompts/bcreq/`) | Шаги | Режим |
| --- | --- | --- |
| `bcreq-constitution-governance-oneshot.md` | Ш-0 | общий для обоих режимов |
| `bcreq-review-validation-oneshot.md` | Ш-В | общий: отдельный вызов второй ролью |
| `bcreq-scenarios-modeling-oneshot.md` | Ш-С (`тип: US \| UC`) | общий: независимая задача в одном вызове |
| `bcreq-context-understanding-stepwise.md` | Ш-1 | stepwise |
| `bcreq-products-impact-analysis-stepwise.md` | Ш-2 | stepwise |
| `bcreq-fr-documentation-stepwise.md` | Ш-3 (`вариант: delta \| new`) | stepwise |
| `bcreq-nfr-documentation-stepwise.md` | Ш-4 | stepwise |
| `bcreq-uc-modeling-stepwise.md` | Ш-5, Ш-8 (`прогон: 1 \| 2`) | stepwise |
| `bcreq-orr-solution-design-stepwise.md` | Ш-6 (`уровень: L1 \| L1+L2`) | stepwise |
| `bcreq-constraints-documentation-stepwise.md` | Ш-7 | stepwise |
| `bcreq-extra-risk-analysis-stepwise.md` | Ш-9 | stepwise |
| `bcreq-in-understanding-oneshot.md` | A-IN: Ш-1, Ш-2 | oneshot |
| `bcreq-core-documentation-oneshot.md` | A-CORE: Ш-3…Ш-5 (`вариант: delta \| new`) | oneshot |
| `bcreq-work-solution-design-oneshot.md` | A-WORK: Ш-6…Ш-9 | oneshot |

Итог: 8 файлов stepwise, 3 файла oneshot по стадиям и 3 общих файла — 14
файлов вместо 28 при схеме «каждый пункт 2.x в двух режимах». Имена
следуют схеме `[домен]-[операция]-[режим]` с операцией из
[таксономии](../docs/taxonomy.md) и доменом из двух сегментов (P1–P3).
Общие файлы помечены `oneshot`, потому что выполняются за один вызов;
БА может запускать их вручную [р. 796, Ч-45](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L79).

Промпты расшифровки встреч остаются вне архитектуры и могут дорабатываться
отдельно [р. 752, Ч-23](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L57) [р. 796, Ч-43](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L77). Промпты каталога, конкурирующие с новыми,
переводятся в `legacy` только после появления замены (аудит §3.8, п. 3).

## 6. Подтверждение структуры 2.1–2.14

## 8. Критерии соответствия

- [ ] Промпт 0 выводит каркас, параметры и блок «Состояние BCREQ»; содержание разделов не генерирует.
- [ ] Каждый промпт шага начинается с блока «Конституция и позиция» с тремя строками: пройдено, текущий, рекомендуемый следующий.
- [ ] Каждый промпт содержит 7 обязательных блоков §3 в указанном порядке.
- [ ] oneshot-промпт покрывает одну стадию и не пересекает гейт.
- [ ] Число файлов соответствует §4; новый файл — только через RFC с доказательством различия поведения.
- [ ] Ни один промпт не нарушает запреты §7.
