# Стандарт базы знаний (KB)

> Контракт-носитель [ADR-007](../docs/adr/007-kb-standard.md). Нормативный словарь
> [RFC 2119](https://www.rfc-editor.org/info/bcp14)
> (**ДОЛЖНО** / **СЛЕДУЕТ** / **МОЖНО**). Версия `draft` до утверждения
> Пользователем (issue #97).

## Стороны и область

Контракт обязывает всех, кто создаёт KB-записи в [`kb/`](../kb/) и кто формирует
цитаты в артефактах/выводах промптов. Термины определяет
[GLOSSARY.md](GLOSSARY.md) (canonical, из Хаба); KB их **использует**, а не
переопределяет.

## 1. Формат цитирования

- **Правило C1.** Каждое нормативное утверждение **ДОЛЖНО** нести цитату одного
  из трёх типов:

  | Тип | Инлайн-форма |
  | --- | --- |
  | KB | `[KB: <slug>](kb/<path>#<anchor>)` |
  | Стандарт | `[<ID>](<полный-URL>)` |
  | Глоссарий | `[Глоссарий: <термин>](standards/GLOSSARY.md#<anchor>)` |

- **Правило C2.** Внешний источник **ДОЛЖЕН** цитироваться **полным URL**
  (НФТ доказуемости; жёсткое требование issue).
- **Правило C3.** Артефакт **ДОЛЖЕН** заканчиваться разделом `## Источники` с
  повтором всех цитат (полный URL для внешних, путь от корня для внутренних).
- **Правило C4.** Источник, который **не находится** (нет реального документа/
  URL, нет записи в KB или реестре стандартов), **НЕ ДОЛЖЕН** цитироваться;
  соответствующее утверждение помечается `needs-clarification`
  ([ba-ontology.md §5](ba-ontology.md)).

### Переиспользуемый блок цитирования (для промптов)

Это «общий блок цитирования KB» из [ADR-006 §3](../docs/adr/006-prompt-naming.md)
— сквозная способность, подключаемая к любому промпту **без** изменения его
имени:

```markdown
## Источники
<!-- Каждое нормативное утверждение выше имеет цитату [KB:…], [<ID>](URL) или
     [Глоссарий:…]. Источник, который не находится, не цитируется —
     утверждение помечается needs-clarification (правило C4). -->
- [<ID/термин/slug>](<полный-URL или путь от корня>)
```

## 2. Синхронизация глоссарий ↔ KB

- **Правило K1.** KB **НЕ ДОЛЖНА** переопределять термин глоссария; только
  ссылаться (тип «Глоссарий», C1).
- **Правило K2.** Термин в KB, отсутствующий в глоссарии, **ДОЛЖЕН** быть
  предложен в глоссарий через issue в Хаб; до принятия — `⚠️ требует уточнения`.
- **Правило K3.** KB-запись, зеркалящая внешний/хабовый материал, **ДОЛЖНА**
  нести `source_sha` (как [GLOSSARY.md](GLOSSARY.md)).
- **Правило K4.** Направление потока: Хаб → `GLOSSARY.md` → KB → артефакты.
  Обратная запись в глоссарий — только через issue в Хаб.

## 3. Pre-RAG механизм (жёсткое требование ФТ-5)

- **Правило R1.** Каждая KB-запись — отдельный файл с frontmatter
  (`id`, `status`, `sources`), пригодный как самостоятельный chunk.
- **Правило R2.** [`kb/README.md`](../kb/README.md) — индекс-карта ручного
  поиска (таблица «тема → файл → когда применять»); заменяет retrieval-шаг до RAG.
- **Правило R3.** Цитата опирается на стабильный адрес (путь от корня + якорь),
  не на эмбеддинги.
- **Правило R4 (RAG-готовность).** Формат цитаты и адресации **ДОЛЖЕН**
  сохраняться при переходе на настоящий RAG (пути/якоря → chunk-id); переписывать
  артефакты не требуется.

## 4. Структура KB

```text
kb/
  README.md                 ← индекс-карта (R2)
  practices/<slug>.md       ← практики (best practices)
  examples/<slug>.md        ← примеры
  references/<slug>.md       ← справочники (не стандарты)
```

- **Правило S1.** KB-файл **НЕ ДОЛЖЕН** дублировать стандарт; при пересечении —
  ссылаться на `standards/*`.

## Критерии соответствия (DoD)

- [ ] Все нормативные утверждения несут цитату (C1) с полным URL для внешних (C2).
- [ ] Есть раздел `## Источники` (C3); несуществующие источники не цитируются (C4).
- [ ] KB не переопределяет термины глоссария (K1); новые термины — через issue (K2).
- [ ] Каждая KB-запись индексирована в `kb/README.md` (R2) и имеет frontmatter (R1).
- [ ] `python3 scripts/validate_issue_97_ontology_standards.py` проходит.
