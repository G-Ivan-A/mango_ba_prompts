# Мета-стандарты разделов BCREQ

> Контракт-носитель [ADR-012](../../docs/adr/2026-10-adr-012-bcreq-meta-standards.md).
> Нормативный словарь [RFC 2119](https://www.rfc-editor.org/info/bcp14)
> (**ДОЛЖНО** / **СЛЕДУЕТ** / **МОЖНО**). Версия `draft` до утверждения
> Пользователем (issue #387).

Мета-стандарт раздела задаёт, **что** должно быть в разделе BCREQ, **каким
языком** он пишется и **как проверить**, что раздел готов. Промпты Задачи 3
(Промпт 0 и шаги 2.1–2.14) ссылаются на эти файлы и не повторяют их текст.
Контекст решений — дословные цитаты чата в
[реестре #387](../../experiments/issue_387/chat-2026-10-22-23-register.md).

### 2.1. Короткий стиль (разделы 2, 5 L1, 6)

БА поручил определить короткий стиль по лучшим практикам читаемости
[р. 796, Ч-36](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L70). Определение собрано из ISO 24495-1:2023
(plain language: текст релевантен, находим, понятен, применим), ASD-STE100
(Simplified Technical English: ≤20 слов в процедурном предложении, ≤25 — в
описательном), правил GOV.UK (предложение длиннее 25 слов делится) и сервиса
Главред (стоп-слова канцелярита). Каждое правило проверяется подсчётом.

| Правило | Требование | Как проверить |
| --- | --- | --- |
| КС1. Главное первым | Первое предложение подраздела отвечает на его вопрос (BLUF). | Прочитать только первые предложения — смысл подраздела ясен. |
| КС2. Короткое предложение | Предложение **ДОЛЖНО** быть ≤20 слов; >25 слов — нарушение. | Подсчёт слов; доля предложений 21–25 слов ≤10 %. |
| КС3. Одна мысль | В предложении одна мысль, в абзаце ≤3 предложений. | Нет «а также», «при этом», «кроме того» внутри одного предложения. |
| КС4. Список и таблица | ≥3 однородных элемента — список; сравнение по ≥2 признакам — таблица. | Нет перечислений через запятую из ≥3 пунктов в строке текста. |
| КС5. Действие глаголом | Действительный залог, глагол вместо отглагольного существительного: «система отправляет», а не «осуществляется отправка». | Нет оборотов из словаря стоп-слов ниже. |
| КС6. Один термин | Термины — только из раздела 1, без синонимов и жаргона (правило О9 анализа 2026-10-20). | Каждый предметный термин есть в разделе 1. |
| КС7. Бюджет объёма | Раздел 2 ≤250 слов, раздел 5 L1 ≤900 слов, раздел 6 ≤250 слов. | Подсчёт слов без таблиц-реестров. |

Словарь стоп-слов КС5 (минимальный, расширяется через RFC): «осуществлять»,
«производить» (в значении «делать»), «являться», «данный», «в рамках», «в целях»,
«в настоящее время», «имеет место», «соответствующий», «необходимо отметить»,
«с целью обеспечения», «в части».

Бюджет КС7 — расчётное допущение, его калибруют прогоны Задачи 3. Расчёт:
issue #387 задаёт цель «читабельность для техлида 5-10 мин» для разделов 2, 5
и 6 вместе.
Средняя скорость чтения нехудожественного текста — 238 слов в минуту
(Brysbaert, 2019, английский язык, разброс 175–300). Для русского технического
текста взято консервативное значение 150 слов в минуту: 1 400 слов ≈ 9 минут.

### 2.2. Бюрократический стиль (разделы 1, 3, 4)

Полные классические формулировки по BABOK, «чтобы не придраться»
[р. 764, Ч-30](https://github.com/G-Ivan-A/mango_ba_prompts/blob/main/experiments/issue_387/chat-2026-10-22-23-register.md?plain=1#L64). Основа — характеристики
требования ISO/IEC/IEEE 29148 (необходимое, однозначное, полное, единичное,
выполнимое, проверяемое, корректное) и шаблоны EARS.

| Правило | Требование |
| --- | --- |
| БС1. Норма | Пункт — полное предложение с модальным «должна/должен»: «Система должна …». |
| БС2. Единичность | Один пункт — одно требование или одно определение. |
| БС3. Полнота | Явно названы субъект, действие, объект и условие; условие — по шаблону EARS: «Когда …», «Пока …», «Если …, то …», «Где …». |
| БС4. Однозначность | Нет местоимений вместо терминов, нет эллипсиса, термин пишется полностью. |
| БС5. Без размытых слов | Нет слов «быстро», «удобно», «по возможности», «как правило», «и т. д.», «минимальный», «оптимальный» без числа и источника. |

Длина предложения в бюрократическом стиле не ограничена, но правило БС2
действует всегда.

### 2.3. Технический и табличный стили (дополнение)

Issue не задаёт стиль для раздела 5 L2 и разделов 7–8. Предлагается:

- **технический** (5 L2) — таблицы и контракты (метод, параметр, тип, ошибка),
  текст только в пояснениях; правила КС2, КС5, КС6 действуют;
- **табличный** (7, 8) — каждая сущность — строка таблицы с идентификатором;
  свободный текст ≤2 предложений в ячейке.

## 3. Общие правила для всех разделов

- **Р1. Источник.** Утверждение о продукте, внешней системе, настройке или
  ограничении **ДОЛЖНО** иметь локатор (документ, раздел, страница, цитата) — по
  [kb-citations](../../docs/contracts/kb-citations.md) и правилу О1 анализа
  2026-10-20. Без локатора утверждение уходит в реестр вопросов (раздел 8.4).
- **Р2. Не выдумывать.** Неизвестное помечается `[ТРЕБУЕТСЯ УТОЧНЕНИЕ: …]`,
  а не заполняется по памяти модели.
- **Р3. Решения БА.** Согласованные БА формулировки, нумерация и журнал решений
  не оспариваются молча (правило О3). Несогласие — отдельным блоком с цитатами.
- **Р4. Индустриальная практика — только рекомендацией.** Предложение «по
  индустриальной практике» выводится отдельным блоком «Рекомендация — на
  решение БА» с источником. В текст раздела оно попадает только после решения
  БА. Так сохраняется правило О8 и выполняется требование подсвечивать и
  рекомендовать ([RFC-387-03](../../docs/rfc/2026-10-bcreq-meta-standards-rfc.md#rfc-387-03)).
- **Р5. Названия методологий.** В тексте разделов 1–6 для Заказчика нет
  названий методологий (правило О10). Источник рекомендации указывается в блоке
  «Проверка решений». Исключение — раздел 5 L2: формат контракта («описание
  методов в формате OpenAPI») — технический факт для разработки.
- **Р6. Антиинфляция.** Избыточность — такой же дефект, как пропуск. Пункт,
  который не трассируется к запросу Заказчика, к границам 2.4.1 или к решению
  БА, удаляется.
- **Р7. Статус ставит человек.** Модель не пишет «согласовано», «готово»,
  «выполнено» (правило О13, правило B3
  [bcreq-process-standard](../bcreq-process-standard.md#3-human-gates-в-ключевых-точках)).

## 4. Общие circuit breakers

Circuit breaker — условие, при котором генерация раздела **ДОЛЖНА**
остановиться и вернуть БА вопрос вместо текста.

| ID | Условие | Действие |
| --- | --- | --- |
| CB-0.1 | Нет запроса Заказчика или он не читается. | Остановиться, запросить запрос. |
| CB-0.2 | Входной артефакт предыдущего шага отсутствует (например, нет раздела 3 для раздела 7). | Остановиться, назвать недостающий шаг. |
| CB-0.3 | Обязательное утверждение раздела не имеет источника и не может быть помечено `[ТРЕБУЕТСЯ УТОЧНЕНИЕ]` без потери смысла раздела. | Остановиться, вывести вопросы. |
| CB-0.4 | Входные данные противоречат друг другу (запрос Заказчика ↔ документация ↔ журнал решений). | Остановиться, привести обе цитаты (правило О5). |
| CB-0.5 | Раздел требует решения, которое принадлежит человеку (гейт, выбор варианта). | Остановиться, дать варианты с одинаковыми критериями (правило О4). |

## 5. Шаблон мета-стандарта раздела

Каждый файл `NN-*.md` в этом каталоге **ДОЛЖЕН** содержать разделы в этом
порядке:

1. `## Назначение` — 1–2 фразы.
2. `## Необходимо и достаточно` — измеримые критерии: что обязано быть и что
   лишнее.
3. `## Стиль` — стиль и его правила.
4. `## Паттерны формулировок` — таблица «Корректно / Некорректно / Почему».
5. `## Circuit breakers` — специфичные для раздела, в дополнение к §4.
6. `## Чек-лист валидации` — от 3 до 7 проверяемых пунктов.
7. `## Источники` — полные URL (правило И2
   [industry-standards-standard](../industry-standards-standard.md)).

Разделы со спецификой добавляют свой блок между «Стиль» и «Паттерны»: механизм
сверки с индустриальными словарями (1), варианты ФТ и правило 5±2 (3), уровни
L1/L2 (5), классификацию UC (7). Структуру файлов проверяет
`scripts/validate_issue_387_bcreq_meta_standards.py`.
