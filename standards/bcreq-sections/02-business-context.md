# Мета-стандарт раздела 2 «Бизнес-контекст»

> Общие правила, стили и шаблон — в [README](README.md). Носитель —
> [ADR-012](../../docs/adr/2026-10-adr-012-bcreq-meta-standards.md).

## Назначение

Раздел 2 объясняет Заказчику в нескольких фразах, зачем нужна доработка и где
она кончается. По нему Заказчик подтверждает, что его поняли правильно.

## Необходимо и достаточно

Структура — по issue #387: 2.1 Контекст, 2.2 Проблема, 2.3 Цель, 2.4 Границы.
Подраздел 2.5 — дополнение с индустриальным обоснованием
([RFC-387-05](../../docs/rfc/2026-10-bcreq-meta-standards-rfc.md#rfc-387-05)).

| Подраздел | Необходимо | Лишнее |
| --- | --- | --- |
| 2.1 Контекст | Сценарий Заказчика: кто действует, в какой ситуации, что делает сейчас. 1–3 предложения. | Описание продукта целиком, история компании Заказчика. |
| 2.2 Проблема | Чего не хватает в текущем поведении продукта для сценария 2.1, в формулировках Заказчика; последствия — только названные Заказчиком, с источником. | Техническая интерпретация вместо слов Заказчика, риски без источника. |
| 2.3 Цель | Одна фраза о результате для Заказчика. Число — только с источником. | Цели команды разработки, KPI без источника. |
| 2.4 Границы | 2.4.1 «Включено» и 2.4.2 «Не включено» — атомарные пункты. 2.4.1 охватывает документацию, тестирование и вывод в эксплуатацию. 2.4.2 содержит исключения Заказчика и БА, а также ограничения платформы и версий (см. ниже). | Пояснения реализации, НФТ, API, форматы данных, штатный функционал. |
| ＋2.5 Продукты и стейкхолдеры | Продукты и модули по [классификации Mango](../product-classification-contract.md) (Domain → Capability), команды, стейкхолдеры: Заказчик, владелец продукта, архитектор. Обязателен при ≥2 продуктах, иначе — одна строка. | Состав команд поимённо, оргструктура. |

**Ограничения платформы и версий.** БА: «это по хорошему в границы надо вносить,
но для старой верссии задач сейачс надо встравить»
{{Ч-27}}. Для новых задач такое ограничение — пункт 2.4.2
«Не включено» (например, «Доработка не включает КЦ Десктоп»). Раздел 6 — только
для задач, начатых по старой структуре. Это расходится с правилом А2.4 анализа
2026-10-20 («ограничения — только в разделе 6»), см.
[RFC-387-07](../../docs/rfc/2026-10-bcreq-meta-standards-rfc.md#rfc-387-07).

**Обоснование 2.5.** arc42 §1.3 «Stakeholders» и BABOK v3 (техника 10.43
«Stakeholder List, Map, or Personas») относят стейкхолдеров к введению
документа. Шаг 2.2 структуры БА («определение продуктовой принадлежности по
таксономиии и определение продуктовой команд») {{Ч-19}}
и выход A-IN («стейкхолдеры, зависимости») иначе не имеют места в документе.

## Стиль

Короткий: правила КС1–КС7 [README §2.1](README.md#21-короткий-стиль-разделы-2-5-l1-6).
Бюджет раздела 2 — ≤250 слов (без таблицы 2.5).

## Паттерны формулировок

| Корректно | Некорректно | Почему |
| --- | --- | --- |
| 2.1: «Супервизор КЦ слушает записи звонков, чтобы оценить операторов. Сейчас он находит нужный звонок вручную по времени.» | «В рамках осуществления деятельности по контролю качества имеет место необходимость…» | Канцелярит, нет актора (КС5). |
| 2.2: «ВАТС не передаёт текст разговора во внешнюю систему Заказчика.» | «Отсутствует интеграционный слой на базе событийной шины.» | Техническая интерпретация вместо слов Заказчика. |
| 2.3: «Заказчик получает текст каждого разговора в своей CRM.» | «Повысить эффективность и удобство работы.» | Нет результата, размытые слова. |
| 2.4.1: «Передача текста разговора во внешнюю систему.» | «Передача текста разговора во внешнюю систему с помощью webhook с повторной доставкой.» | Пояснение реализации в границах. |
| 2.4.2: «Доработка не включает КЦ Десктоп.» | Раздел 6: «Ограничение: КЦ Десктоп не поддерживается» (в новой задаче). | Ограничение платформы — граница, а не особенность реализации. |

## Чек-лист валидации

- [ ] Есть 2.1–2.4; 2.1 называет актора и ситуацию; 2.3 — одна фраза.
- [ ] 2.2 и 2.3 используют формулировки Заказчика; риски и числа имеют источник.
- [ ] 2.4.1 и 2.4.2 атомарны; 2.4.1 включает документацию, тестирование и вывод в эксплуатацию.
- [ ] Ограничения платформы и версий — в 2.4.2 (кроме задач старой структуры).
- [ ] Предложения ≤20 слов, раздел ≤250 слов, нет стоп-слов КС5.
- [ ] При ≥2 продуктах заполнен 2.5 по классификации Mango.
