# Бэклог. Трек А: репозиторий

Карточки задач `BL-2xx`. Порядок, статусы и решения владельца — во входном
документе [`BACKLOG.md`](BACKLOG.md). Здесь — только содержание задач: почему,
что меняется, где это написано, когда готово.

Трек А меняет документы и устройство репозитория: канонические документы,
ADR, RFC, сайт, структуру каталогов, разметку истории. Трек Б
([`backlog-ba-model.md`](backlog-ba-model.md)) меняет процессы и промпты.

Формат источника: ссылка, раздел «…», цитата до 100 символов. Цитаты из
репозитория дословны; проверка — `scripts/validate_issue_418_backlog.py`.
Ссылки на RFC стратегии ведут на PR #419 (закреплённый коммит), пока PR не
слит. Задачи Хаба называются «B-NNN Хаба», чтобы не путать с `BL-NNN`.

## Спринт 2. Канон стратегии

Цель: канонические документы, ADR и сайт говорят одно и то же о пяти этапах,
OpenCode на этапе 2, n8n как стенде этапа 3 и коде на этапе 4.

### BL-201. Перенести RFC стратегии в канонические документы версии 2.0

**Почему.** RFC стратегии (PR #419) меняет состав этапов: этап 4 — код без
n8n, добавлен этап 5. Канонический `docs/roadmap.md` по-прежнему описывает
этап 4 как потоки на сервере для всей команды. Пока перенос не сделан, два
документа противоречат друг другу (КФ-01).

**Что меняется.**
- `docs/vision.md`, `docs/concept.md`, `docs/architecture.md`,
  `docs/roadmap.md`: версия 1.0 → 2.0 по разделу «Перенос» RFC стратегии.
- Roadmap: пять этапов; этап 4 — процессы в коде под собственным
  исполнителем; этап 5 — масштабирование.
- RFC стратегии и его строки в реестре RFC — `accepted`, затем
  `implemented`.

### BL-202. ADR исполнителей этапов 3–4 и перенумерация дубля ADR-017

о четырёх этапах требует юридической проверки n8n до этапа 4, а RFC
стратегии ставит её на этап 3 (КФ-05). Исполнители этапов 3 и 4 изменились
(стенд n8n и код), и это фиксирует новый ADR.

**Что меняется.**

- Новый ADR: этап 3 — стенд n8n, этап 4 — код (DEC-415-09, DEC-415-10);
  ADR-017 о четырёх этапах помечается заменённым в этой части.
