# AI Governance — mango_ba_prompts

Операционный контракт для AI-assisted work в HTOM-команде `mango_ba_prompts`
(HTOM = Hybrid Team Operating Model: гибридная работа человека и ИИ-агентов).

Этот файл — **ядро генома** HTOM-команды: обязателен в корне (жёсткое
ограничение). Он определяет, кто принимает решения, что делает ИИ и где проходят
границы. Контракт помогает гибридной команде действовать предсказуемо, но не
заменяет цель задачи: если правило мешает оптимальному решению, противоречит
международной практике или создаёт архитектурный долг, правило исправляется либо
обходится с явным обоснованием в PR.

HTOM-команда наследует правила Хаба и при конфликте ссылается на источник истины:
[hybrid-Intelligence-lab](https://github.com/G-Ivan-A/hybrid-Intelligence-lab)
(Хаб `hybrid-Intelligence-lab`, документ `AI_GOVERNANCE.md`). Команда не дублирует
знания Хаба, а ссылается на них. Хаб является источником рекомендаций, общих
практик и опыта, но не механическим ограничителем локальных решений этой
HTOM-команды.

## Роли

| Роль | Ответственность |
| --- | --- |
| Пользователь | Vision, priorities, publication boundaries и финальные решения по проекту. |
| Human reviewer | Проверяет структуру, источники, риски и полезность до merge или публикации. |
| Contributor | Создаёт issues, artifacts и pull requests внутри модели проекта. |
| Исполнитель / AI agent | Готовит черновики, проверки, summaries и PR в рамках Operating Mode; в Creative режиме может делать обоснованный обход локального scope, если это нужно для цели задачи. |

## Правила

1. Работа начинается с issue или явного maintainer request.
2. AI agents читают issue, последние comments, relevant files и текущий PR
   context до изменения файлов.
3. AI agents могут предлагать структуру, но humans принимают финальные решения
   по vision, publication, license и sensitive context.
4. Claims, влияющие на решения, связываются с sources, experiments, issues, PRs
   или ADR в `docs/adr/`.
5. Secrets, private client data, credentials и несанитизированные
   production-промпты не коммитятся.
6. Малые reviewable pull requests предпочтительнее широких undocumented rewrites.
7. Структура HTOM-команды не растёт «на вырост»: новый каталог создаётся только
   при доказанной операционной боли (Anti-Inflation principle Хаба).
8. В Creative режиме AI agent может создать ADR, RFC, шаблон или проверку вне
   первоначального списка файлов, если без этого цель задачи останется
   недостигнутой; PR обязан назвать обойдённое правило, причину и артефакт.

## Capability Boundaries

Простая taxonomy границ для AI-агента — конкретная инстанциация хабовой рубрики
«Границы действий» под mango (с реальными путями репозитория). В Structured режиме
при сомнении действует
[fail-closed semantics](AI_QUICK_RULES.md#fail-closed-semantics-критично). В
Creative режиме действует правило обоснованного обхода: агент может выйти за
узкий scope, если это нужно для цели задачи, и обязан зафиксировать причину в PR.

**Можно делать без human review:**

- Читать файлы репозитория.
- Создавать черновики промптов в `prompts/drafts/`.
- Предлагать изменения структуры через issues.

**Требует human review:**

- Изменять существующие промпты в `prompts/`.
- Создавать новые папки.
- Обновлять `AI_GOVERNANCE.md` или `AI_QUICK_RULES.md`.

**Никогда не делать:**

- Публиковать secrets или credentials.
- Удалять файлы без явного разрешения.
- Изменять `standards/GLOSSARY.md` без согласования с Хабом.

## Обоснованный обход в Creative режиме

Creative режим включается только явным issue или maintainer request. В этом режиме
AI agent не обязан останавливаться из-за каждого противоречия правил, если может
решить задачу безопасно и прозрачно.

Допустимый обоснованный обход:

1. Нужен для цели задачи, а не для удобства исполнителя.
2. Минимален по объёму: создаётся только тот ADR/RFC/шаблон/проверка, который
   закрывает конкретную боль.
3. Не нарушает жёсткие запреты: secrets, private data, лицензии, публикационные
   границы, удаление файлов без разрешения, создание `research/` в HTOM-команде.
4. Фиксируется в PR: какое правило или scope обойдены, почему, какой артефакт
   создан и как проверено, что долг не остался скрытым.

Если обход меняет архитектурную практику, решение фиксируется как ADR в
`docs/adr/`. Если обход только предлагает перенос опыта в Хаб, он фиксируется как
RFC или раздел PR; передавать изменения в Хаб можно только отдельной задачей.

## Acceptance и итерации с Конардом

PR от Конарда — итерируемый артефакт с ручным триггером:

- **Пользователь молчит + мержит PR** → молчание = согласие; решения и обоснованные
  обходы приняты.
- **комментарий + ручной перезапуск**: если Пользователь оставляет комментарий и
  вручную перезапускает задачу, комментарий является запросом на доработку;
  Конард читает его при следующем запуске и дописывает коммиты в ту же ветку PR.
- **Пользователь закрывает PR** → решение отклонено полностью.

Draft-статус PR используется как отложенная проверка до финального acceptance.

## Эскалация

В Structured режиме перед продолжением нужно запросить human guidance, если:

- требования противоречат друг другу или правилу Хаба;
- изменение публикует sensitive или private information;
- от HTOM-команды требуют создать `research/` или иной «выключенный ген» по
  умолчанию (см. `AI_QUICK_RULES.md`): назови правило и его источник, предложи
  легитимную альтернативу, а осознанное отклонение зафиксируй как ADR в
  `docs/adr/`;
- AI agent не может проверить важное claim или migration decision.

В Creative режиме противоречие правил само по себе не блокирует работу: агент
делает обоснованный обход и фиксирует его в PR. Human guidance всё равно нужна,
если затронуты жёсткие запреты, sensitive/private context, лицензии, публикация
или claim невозможно проверить.

## Operating Modes

| Mode | Когда использовать |
| --- | --- |
| Structured | По умолчанию для структуры проекта, governance и tooling; fail-closed применяется строго. |
| Creative | Для задач, где issue явно просит выбрать оптимальное решение; допускает обоснованный обход правил с фиксацией в PR. |
| Research | Для source-backed analysis (фундаментальные знания — вкладом в `research/` Хаба, а не в команду). |
| Project | Для prompt, process и knowledge-base context этой HTOM-команды. |

## Definition of Done

Для AI-assisted изменений в HTOM-команде:

- активные файлы находятся в ожидаемых каталогах;
- навигация и ссылки на Хаб обновлены;
- значимое изменение отражено в `CHANGELOG.md` (`## Unreleased`);
- обоснованный обход в Creative режиме описан в PR и, если меняет практику,
  зафиксирован в `docs/adr/`;
- структура соответствует целевой из `docs/audit/initial-state-2026-06.md`;
- PR description объясняет implementation, validation и remaining risks.
