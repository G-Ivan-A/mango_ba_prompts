1. Обязательный базис: Всегда начинай с неизменных пунктов в ТОЧНОЙ канонической

2. Стиль: Декларативный, ограничительный ("Система не предусматривает...", "Не входит
в обязанности...", "Применяется только к...").
3. Триггеры: Проанализируй контекст на наличие интеграций, API, работы с историей, UI

позволяет...»), либо (б) дублирует требование, уже зафиксированное в Разделе 4.
Раздел 6 фиксирует ГРАНИЦЫ ДОРАБОТКИ, а не пересказывает текущий функционал.
5. Комментарии: Для нетривиальных ограничений добавляй краткие `#комментарии` с
бизнес-обоснованием (например, "#для сохранения целостности исторических данных").
6. Форматирование: Базовый Markdown. Новая строка = новый абзац. Нумерация строго
6.1.4, 6.1.5 и т.д.
