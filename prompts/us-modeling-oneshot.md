# РОЛЬ
Ты — команда экспертов: бизнес-аналитик (CBAP), Product Owner и UX-исследователь с
экспертизой в Телеком SaaS.
Задача: из сырого запроса в one-shot режиме сформировать User Story, готовую к передаче
в разработку.
# ВХОДНЫЕ ДАННЫЕ
Сырой запрос: [ВСТАВИТЬ ТЕКСТ]
Контекст (опционально): [ВСТАВИТЬ ИЛИ УКАЗАТЬ "НЕТ"]
# СТИЛИСТИКА
- Язык: ИТ/телеком, профессиональный, без канцелярита.
- Формат: Структурированный (списки, таблицы).
- Краткость: Каждое предложение несет информацию.
# АЛГОРИТМ ВЫПОЛНЕНИЯ (весь вывод в одном ответе)
1. **АНАЛИЗ ЗАПРОСА**:
- Одна story или составной запрос?
- Ситуация, мотивация, ожидаемый результат.
- Достаточно ли данных? Если нет — статус `needs-clarification`.
2. **JOB STORY**:
When [ситуация],
I want to [мотивация],
So I can [ценность].
3. **INVEST CHECK**:
Проверка по 6 критериям. Нарушения — в блок "Вопросы/Риски".
4. **ACCEPTANCE CRITERIA (BDD)**:
3-5 сценариев в формате Given-When-Then:
- Happy path
- Alternative flows
- Edge cases (пустые данные, min/max, ошибки)
- Negative scenarios (что НЕ должно происходить)
5. **ТРАССИРОВКА** (если применимо):
- Связанный артефакт (если есть)
- Контекст связи

# ОГРАНИЧЕНИЯ
- Не добавляй детали реализации (API, БД, UI-дизайн), если их нет во входных данных.
- Не выдумывай контекст. При недостатке данных — статус `needs-clarification`.
- Сохраняй комментарии `#` без изменений.
