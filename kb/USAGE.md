# Как промпт/агент обращается к БЗ — конкретные примеры (ФТ-6)

Здесь — **реальные сниппеты с реальными данными** из извлечённой БЗ
[`kb/processed/mango-cc-manual/`](processed/mango-cc-manual/index.md)
(руководство пользователя КЦ v1.26.23, 614 страниц, 232 раздела; не абстракции).
Все числа токенов измерены [`scripts/kb/tokens.py`](../scripts/kb/tokens.py)
(метод `tiktoken:cl100k_base`) и совпадают с `meta.json`.

> До issue #310 примеры строились на синтетической фикстуре
> `contact-center-manual-sample`. Фикстура из БЗ удалена — примеры переведены на
> реальный документ, поэтому и выигрыш по токенам виден в реальном масштабе.

Базовый цикл агента: **индекс → выбор раздела → загрузка только его → цитата**.

---

## Пример 1 — агент читает индекс БЗ

Агент не грузит документ целиком. Сначала он открывает карту разделов
[`index.md`](processed/mango-cc-manual/index.md):

````text
СИСТЕМНЫЙ ПРОМПТ:
Ты BA-ассистент. Источник истины — БЗ в kb/processed/. Никогда не выдумывай
факты о продукте: бери их только из разделов БЗ и цитируй источник.
Если в разделе стоит маркер «❓ ТРЕБУЕТСЯ ПРОВЕРКА» или «⚠️ ПРОБЕЛ
ИЗВЛЕЧЕНИЯ» — не достраивай значение, верни ссылку на PDF и страницу.

ШАГ 1. Прочитай индекс: kb/processed/mango-cc-manual/index.md
````

Реальное содержимое индекса (фрагмент таблицы, которую видит агент):

```markdown
| № PDF | Раздел | Файл | Стр. | Источник | Токены | Когда обращаться |
| --- | --- | --- | --- | --- | ---: | --- |
| 2.5.1.3.13 | Обработка звонков | sections/31-obrabotka-zvonkov.md | 79 | ч.1 с.79 | 250 | Данная вкладка содержит блоки настроек телефонных номеров. |
| 2.5.1.3.13.1 | Поствызывная обработка | sections/32-postvyzyvnaya-obrabotka.md | 79-81 | ч.1 с.79-81 | 1014 | Поствызывная обработка применяется только после завершения внешних вызовов: |
| 2.5.1.3.13.2 | Работа с пропущенными | sections/33-rabota-s-propuschennymi.md | 81-83 | ч.1 с.81-83 | 710 | Вкладка предназначена для настройки периода отображения пропущенных звонков. |
```

## Пример 2 — агент выбирает релевантный раздел (поиск по саммари)

Вопрос пользователя: **«Сколько условий поствызывной обработки можно завести и
что будет, если оператор состоит сразу в нескольких группах?»**

Агент сопоставляет вопрос с колонкой **«Когда обращаться»**:

````text
ШАГ 2. Выбери релевантный раздел.
Вопрос про «поствызывная обработка / условия / группы» → строка
«Поствызывная обработка» → раздел §2.5.1.3.13.1
(sections/32-postvyzyvnaya-obrabotka.md, стр. 79-81). Грузить только его.
Соседние §2.5.1.3.13 (номера) и §2.5.1.3.13.2 (пропущенные) не нужны.
````

Так агент по одной строке таблицы, а не по 614 страницам документа, находит
нужный чанк.

## Пример 3 — агент грузит полный текст одного раздела

````text
ШАГ 3. Загрузи ТОЛЬКО файл выбранного раздела:
  kb/processed/mango-cc-manual/sections/32-postvyzyvnaya-obrabotka.md
````

Реально загруженный раздел (фрагмент; кириллица извлеклась чисто, таблиц и
картинок раздела хватает для ответа):

```markdown
# 2.5.1.3.13.1. Поствызывная обработка

> Трассировка: PDF §2.5.1.3.13.1 · сквозные стр. 79-81 · источники:
> ч.1 `kb/sources/mango-cc-manual/CC_manual_1.26.23-part-1.pdf` с.79-81.

Кнопка "Добавить условие" открывает поле для добавления нового условия. …
Если оператор состоит более чем в одной группе, и значения для поствызывной
обработки в группах отличаются, то в качестве времени обработки выбирается
максимальное время из значений по группам, в которых он состоит.

Максимальное количество условий – 50.
```

Если бы фактов не хватило — у раздела во frontmatter есть `pages`, а в индексе
видны соседние разделы.

## Пример 4 — агент цитирует источник

Формат проекта (issue #109): `[<Документ>, §<Раздел>, с.<Страница>]`. Код
документа и страницы агент берёт из frontmatter раздела (`doc_code: CC`,
`pages: "79-81"`) и `meta.json`.

````text
ОТВЕТ АГЕНТА:
Максимальное количество условий поствызывной обработки — 50 [CC, §2.5.1.3.13.1, с.81].
Если оператор состоит в нескольких группах с разными значениями, берётся
максимальное время из его групп [CC, §2.5.1.3.13.1, с.80]. Задержка обновления
правил постзвонковой обработки — до 10 минут [CC, §2.5.1.3.13.1, с.80].
````

Для machine-адреса дополнительно можно дать стабильную ссылку на чанк (ADR-007 R3):
`kb/processed/mango-cc-manual/sections/32-postvyzyvnaya-obrabotka.md#2513131-поствызывная-обработка`
(якорь GitHub для заголовка `# 2.5.1.3.13.1. Поствызывная обработка`).

## Пример 5 — расход токенов: весь документ vs только нужный раздел

Числа реальны (метод `tiktoken:cl100k_base`, см. `meta.json` и
`scripts/kb/tokens.py`).

| Что грузит агент в контекст | Токены |
| --- | ---: |
| **Весь документ** (текст всех 232 разделов) | **429951** |
| Только раздел §2.5.1.3.13.1 «Поствызывная обработка» (полезная нагрузка ответа) | **1014** |
| Только раздел §2.5.1.3.13.2 «Работа с пропущенными» | **710** |
| Индекс `index.md` (разовая навигация, переиспользуется на все вопросы) | 22982 |

**Полезная нагрузка одного ответа** — это один раздел: 1014 токенов против
429951 за весь документ → **на 99,8 % меньше** читаемого контента на ответ.
Индекс (22982) — разовая стоимость навигации: его читают один раз и
переиспользуют для всех вопросов про документ; он растёт как одна строка на
раздел, тогда как «весь документ» растёт целиком.

> **Масштабирование (главное).** 429951 токен — это объём, который **просто не
> влезает** в промпт целиком ни на одной массовой модели. Индекс же остаётся
> компактным (строка на раздел), а ответу нужен один раздел на ~700–2500
> токенов. То есть БЗ не столько «экономит проценты», сколько **делает работу с
> большим документом возможной вообще** — при этом качество не страдает: агент
> читает полный, неусечённый раздел.

## Пример 6 — агент не додумывает неоднозначные данные (issue #310)

Разделы, где независимая перепроверка вторым движком не подтвердила значение
или где у страницы нет текстового слоя, размечены маркерами. Агент обязан их
уважать:

```markdown
> ⚠️ **ПРОБЕЛ ИЗВЛЕЧЕНИЯ**: на странице нет текстового слоя
> (скан/изображение) — содержимое не извлечено и не додумано; проверить в
> источнике вручную. (Источник: `MangoOffice_VPBX_API_v1.9.pdf`, стр. 35)
```

````text
ОТВЕТ АГЕНТА:
Значение параметра на стр. 35 не извлечено (страница — изображение без
текстового слоя). Не могу подтвердить его по БЗ: сверьте
MangoOffice_VPBX_API_v1.9.pdf, стр. 35 [VPBXAPI, §…, с.35].
````

Сводка по документу — в `kb/processed/<doc>/verification.md` (уровень доверия,
доля подтверждённых критических токенов, перечень разделов на ручную сверку).

## Почему это устойчиво к драйфу ADR/промптов

Промпты ссылаются на БЗ через **стабильные адреса** (`kb/processed/<doc>/…#anchor`)
и **формат цитаты** `[CC, §N, с.P]`, а не на конкретные формулировки ADR. Когда
ADR/промпты изменятся (issue прямо это предупреждает), извлечённая БЗ и её адреса
останутся валидны: переизвлечение источника не меняет схему путей. Подробнее —
[`docs/kb-experiment-report.md`](../docs/kb-experiment-report.md).
