# Как промпт/агент обращается к БЗ — конкретные примеры (ФТ-6)

Здесь — **реальные сниппеты с реальными данными** из извлечённой БЗ
[`kb/processed/contact-center-manual-sample/`](processed/contact-center-manual-sample/index.md)
(не абстракции). Все числа токенов измерены
[`scripts/kb/tokens.py`](../scripts/kb/tokens.py) (метод `tiktoken:cl100k_base`)
и совпадают с `meta.json`.

Базовый цикл агента: **индекс → выбор раздела → загрузка только его → цитата**.

---

## Пример 1 — агент читает индекс БЗ

Агент не грузит документ целиком. Сначала он открывает карту разделов
[`index.md`](processed/contact-center-manual-sample/index.md):

````text
СИСТЕМНЫЙ ПРОМПТ:
Ты BA-ассистент. Источник истины — БЗ в kb/processed/. Никогда не выдумывай
факты о продукте: бери их только из разделов БЗ и цитируй источник.

ШАГ 1. Прочитай индекс: kb/processed/contact-center-manual-sample/index.md
````

Реальное содержимое индекса (фрагмент таблицы, которую видит агент):

```markdown
| № | Раздел | Файл | Стр. | Токены | Когда обращаться |
| --- | --- | --- | --- | ---: | --- |
| 2 | Рабочее место оператора | sections/02-rabochee-mesto-operatora.md | 3 | 301 | Статусы оператора; Очередь обращений |
| 4 | Обработка обращений | sections/04-obrabotka-obrascheniy.md | 5 | 378 | Контроль обращений; Правила распределения; Каналы обращений |
| 5 | Роли и права доступа | sections/05-roli-i-prava-dostupa.md | 6 | 253 | Права на модуль «Обращения»… |
```

## Пример 2 — агент выбирает релевантный раздел (поиск по саммари)

Вопрос пользователя: **«Сколько текстовых чатов одновременно может вести один
оператор и есть ли связь с голосом?»**

Агент сопоставляет вопрос с колонкой **«Когда обращаться»**:

````text
ШАГ 2. Выбери релевантный раздел.
Вопрос про «текстовые обращения / распределение / лимит» → строка «Правила
распределения» → это раздел №4 (sections/04-obrabotka-obrascheniy.md, стр. 5).
Грузить только его. Раздел №5 (роли) и №2 (статусы) не нужны.
````

Так агент по 6-строчной таблице, а не по всему документу, находит нужный чанк.

## Пример 3 — агент грузит полный текст одного раздела

````text
ШАГ 3. Загрузи ТОЛЬКО файл выбранного раздела:
  kb/processed/contact-center-manual-sample/sections/04-obrabotka-obrascheniy.md
````

Реально загруженный раздел (фрагмент, кириллица извлеклась чисто, таблиц/картинок
раздела хватает для ответа):

```markdown
## 4.2 Правила распределения

Задаётся максимальное количество текстовых обращений, которые может обрабатывать
один сотрудник. … Чекбокс «Не распределять текстовые обращения на операторов,
которые находятся в звонке» — единственная сегодня кросс-канальная связь между
голосом и текстом. Сквозного межканального счётчика и приоритета каналов нет.

![Изображение, стр. 5](../images/04-obrabotka-obrascheniy-1.png)
```

Если бы фактов не хватило — у раздела во frontmatter есть `pages`, а в индексе
видны соседние разделы и их зависимости (напр., §6 «Отчёты» ссылается на §5).

## Пример 4 — агент цитирует источник

Формат проекта (issue #109): `[<Документ>, §<Раздел>, с.<Страница>]`. Код
документа и страницы агент берёт из frontmatter раздела (`doc_code: CC`,
`pages: "5"`) и `meta.json`.

````text
ОТВЕТ АГЕНТА:
Лимит одновременных текстовых обращений на сотрудника задаётся настройкой
«максимальное количество текстовых обращений»; при достижении новые не
распределяются, пока одно не закрыто (0 = без лимита) [CC, §4.2, с.5].
Единственная связь с голосом — чекбокс «не распределять текст на операторов
в звонке»; сквозного межканального счётчика нет [CC, §4.2, с.5].
````

Для machine-адреса дополнительно можно дать стабильную ссылку на чанк (ADR-007 R3):
`kb/processed/contact-center-manual-sample/sections/04-obrabotka-obrascheniy.md#42-правила-распределения`
(якорь GitHub для заголовка `## 4.2 Правила распределения`).

## Пример 5 — расход токенов: весь документ vs только нужный раздел

Числа реальны (метод `tiktoken:cl100k_base`, см. `meta.json` и
`scripts/kb/tokens.py`).

| Что грузит агент в контекст | Токены |
| --- | ---: |
| **Весь документ** (текст всех разделов) | **1587** |
| Только раздел §4 «Обработка обращений» (полезная нагрузка ответа) | **378** |
| Только раздел §5 «Роли и права» (матрица ролей) | **253** |
| Индекс `index.md` (разовая навигация, переиспользуется на все вопросы) | 912 |

**Полезная нагрузка одного ответа** — это один раздел: §4 = 378 токенов против
1587 за весь документ → **на 76 % меньше** читаемого контента на ответ (для §5 —
на 84 % меньше). Индекс (912) — это разовая стоимость навигации: его читают один
раз и переиспользуют для всех вопросов про документ; на реальном объёме он почти
не растёт (одна строка на раздел), тогда как «весь документ» растёт целиком.

> **Масштабирование (главное).** На игрушечной фикстуре из 7 разделов экономия
> уже ощутима, но настоящая выгода — на больших PDF: реальное руководство КЦ
> (десятки страниц) — это **десятки тысяч** токенов, которые часто **просто не
> влезают** в промпт. Индекс же остаётся компактным (≈ строка на раздел), а
> ответу нужен один раздел на ~300–500 токенов. То есть БЗ не столько «экономит
> проценты», сколько **делает работу с большим документом возможной вообще** —
> при этом качество не страдает: агент читает полный, неусечённый раздел.

## Почему это устойчиво к драйфу ADR/промптов

Промпты ссылаются на БЗ через **стабильные адреса** (`kb/processed/<doc>/…#anchor`)
и **формат цитаты** `[CC, §N, с.P]`, а не на конкретные формулировки ADR. Когда
ADR/промпты изменятся (issue прямо это предупреждает), извлечённая БЗ и её адреса
останутся валидны: переизвлечение источника не меняет схему путей. Подробнее —
[`docs/kb-experiment-report.md`](../docs/kb-experiment-report.md).
