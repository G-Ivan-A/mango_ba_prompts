# 4.5.2. Изменение сделки

> Трассировка: PDF §4.5.2 · сквозные стр. 233-234 · источники: ч.1 `kb/sources/vpbx-api/MangoOffice_VPBX_API_v1.9.pdf` с.233-234.

POST /cc/deal/update Назначение: обновляет данные сделки, не учитываются связанные сущности (документы, обращения, задачи). Параметры:

| № | Параметр | Тип | Обяза-<br>тель-<br>ный | Описание |
| --- | --- | --- | --- | --- |
| 1 | deal_id | Число | Да | Уникальный номер сделки |
| 2 | contact_id | Число | Да | Уникальный номер контакта. Его можно получить согласно<br>метод API для работы с адресной книгой. Источник контакта<br>- только адресная книга КЦ, не рассматривается внешняя<br>система работы с адресной книгой (источник контакта и id<br>источника всегда - КЦ) |
| 3 | name | Строка | Да | Название сделки |
| 4 | description | Текст | Нет | Описание сделки |
| 5 | amount | Число | Нет | Сумма сделки |
| 6 | abonent_id | Число | Да | Уникальный номер ответственного за сделку сотрудника<br>Примечание. Для получения ID сотрудника / списка<br>сотрудников, используйте Запрос списка сотрудников ВАТС |
| 7 | funnel_id | Число | Да | Уникальный номер воронки, в которой необходимо создать<br>сделку. Для получения id воронки используется метод<br>получение списка воронок. |
| 8 | step_id | Число | Да | Уникальный номер этапа, на котором находится сделка<br>Примечание. Для получения id воронки используется метод<br>получение списка воронок |
| 9 | custom_fields | Массив | Нет | Обязательность заполнения пользовательского поля зависит<br>от настройки "required", см. Получение списка<br>пользовательских полей. Пользовательские поля, созданные<br>на продукте для сделки |
| 10 | status | Строка | Нет | Доступен один из следующих статусов для выбора:<br>● "in_work" - в работе; |

| № | Параметр | Тип | Обяза-<br>тель-<br>ный | Описание |
| --- | --- | --- | --- | --- |
|  |  |  |  | ● "succeed" - состоялась;<br>● "failed" - не состоялась;<br>● "delete" - удалена |
| 11 | status_change_reason | Строка | Нет | Причина, по которой не состоялась сделка. Доступно только<br>при изменении уже созданной сделки в статусе "не<br>состоялась" - "failed" или при переводе статуса сделки в<br>статус "не состоялась" - "failed". Доступна одна из причин<br>для выбора:<br>● too_expensive - слишком дорого;<br>● bad_condition - не устроили условия;<br>● competitor - выбрали других;<br>● missing_demand - пропала потребность;<br>● alternative – другое. |
| 12 | reason_comment | Строка | Нет | Комментарий к причине отказа, по которой не состоялась<br>сделка. Доступно только при выбранной причине отказа |

| 1 | result | Число | Да | Код результата (см. Список кодов результата) |
