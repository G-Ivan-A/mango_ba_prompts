# Experiment record — Issue #180 (ФТ группового звонка Mango Talker на основе ВКС)

> Запись процесса прогона задачи по issue
> [#180](https://github.com/G-Ivan-A/mango_ba_prompts/issues/180). Артефакты
> прогона оформлены по `runs`-контракту в
> [`runs/2026/RUN-0012/`](../../runs/2026/RUN-0012/); этот файл фиксирует сам
> процесс (шаги, источники, решения) для воспроизводимости.

## Задача

Подготовить комплексный документ функциональных требований (ФТ) на согласование
заказчика для групповых звонков Mango Talker. Ключевое условие — переориентировать
ранее согласованный ФТ по аудиоконференциям на решение, основанное на
видеоконференциях МТ, **сохранив стиль исходного документа**, и включить только
разделы **1, 2, 4, 6** (без разделов 3 и 5).

## Входные данные

| Источник | Назначение | Где зафиксировано |
| --- | --- | --- |
| Постановка задачи + резюме встречи + обратная связь клиента | Бизнес-потребность и решение об изменении области доработки | [`RUN-0012/inputs/01-raw-task-and-change-decision.md`](../../runs/2026/RUN-0012/inputs/01-raw-task-and-change-decision.md) |
| Предыдущий ФТ (аудиоконференции) | Стилевой эталон (тон, терминология, иерархия) | [`RUN-0012/inputs/02-previous-ft-audio-conference.md`](../../runs/2026/RUN-0012/inputs/02-previous-ft-audio-conference.md) |
| Выдержки БЗ (таксономии + продуктовая документация МТ) | Цитирование и привязка к онтологии | [`RUN-0012/inputs/03-kb-extracts.md`](../../runs/2026/RUN-0012/inputs/03-kb-extracts.md) |

> Примечание по подготовке входа: исходное вложение предыдущего ФТ пришло в
> кодировке Windows-1251 и было сконвертировано в UTF-8 (`iconv -f WINDOWS-1251 -t
> UTF-8`) перед использованием как стилевой эталон.

## Процесс (BCREQ)

Соответствие конвейеру [`standards/bcreq-process-standard.md`](../../standards/bcreq-process-standard.md):

1. **П1 — приём/нормализация.** Нормализованы три входа (постановка, резюме встречи,
   обратная связь), зафиксированы в `inputs/`.
2. **П2 — декомпозиция.** Из решения об изменении области доработки и обратной связи
   выделены атомарные требования: точка входа в «Встречи», мультивыбор, список
   участников, динамика, личные группы, звуковые сигналы, переподключение по ссылке.
3. **П3 — моделирование сценариев.** Сценарии перенесены со стилевого эталона
   (аудио) на ВКС-решение с сохранением структуры карточек участников, вкладок
   «Активные»/«Приглашённые», push-обновлений, прокрутки, поворота устройства.
4. **П4 — документирование.** Сформирован ФТ-документ (разделы 1, 2, 4, 6) +
   резюме с метаданными + лог эксперимента.
5. **G1/G2/G3** — человеческие гейты на стороне БА/Заказчика (согласование вне
   данного прогона).

## Решения, повлиявшие на скоуп

- **Отказ от доработки аудиоконференций** → реализация на основе видеоконференций
  МТ (`talker-video-meeting-service`). Зафиксировано в ФТ 2.1, 6.1.3.
- **Чаты МТ отключены политикой Компании** → новая точка входа «Встречи» вместо
  инициации через чат (As-Is §14). Зафиксировано в ФТ 4.1, 6.1.4.
- **Видео допустимо, но не обязательно** (приоритет — голос). Зафиксировано в
  ФТ 4.1.3.1, 6.1.5.
