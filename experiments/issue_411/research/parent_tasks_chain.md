## 0. Короткий вывод

1. Владелец **с июня 2026 года** требовал выделять уроки из прогонов: шаблоны ошибок,
   «как не делать», golden set и критерии успеха. Затем эти уроки должны
   превращаться в правила промптов через контролируемый процесс.
2. Цепочка «урок → правило» реально сработала один раз: в
   [#391](https://github.com/G-Ivan-A/mango_ba_prompts/issues/391) /
   [PR #392](https://github.com/G-Ivan-A/mango_ba_prompts/pull/392). Уроки были
   встроены в 14 промптов сайта `prompts/bcreq-*.md` как АД-1…АД-11. Во всех
   14 файлах есть `АД-`.
3. Следующее поколение, 39 классов ручного конвейера
   ([#403](https://github.com/G-Ivan-A/mango_ba_prompts/issues/403) /
   [PR #404](https://github.com/G-Ivan-A/mango_ba_prompts/pull/404)), **не
   унаследовало эти уроки явно**:
   - в `standards/bcreq-manual-classes/` 0 из 41 файла ссылаются на
     `RUN-00*`, golden, how-not-to-do или `АД-`;
   - в `standards/bcreq-sections/` 0 из 9 файлов;
   - на каждый класс приходится одна обобщённая пара «Корректно/Ошибка»;
   - существующие промпты названы «аналог, не готовая реализация»
     (`standards/bcreq-manual-classes/README.md`, стр. 15).
4. Контура регрессии нет:
   - `standards/evals-contract-standard.md` — копия Хаба в статусе «предложен
     на утверждение»;
   - каталогов `evals/` и `golden/` нет;
   - `pr-ops/prompt-feedback.json` содержит `"entries": []` с 2026-06-16;
   - все промптовые RFC в `docs/rfc/rfc-register.md` (RFC-1027-P1…P5,
     RFC-1025-P1…P5, RFC-MCH, RFC-387-01) остаются в статусе `proposed`.

   В RUN-0078 снижение ошибок не измерялось:
   `runs/2026/RUN-0078/outputs/comparison.md` содержит строки «одна авторская
   имитация», «Нельзя вычитать или считать снижение» и «Разные шкалы, не A/B».
5. **Новая находка: утрата истории.** В текущей истории `main` нет 66 PR,
   влитых в период 2026-06-20…2026-07-01 (#128–#258).
   - Для #112–#126 расхождение merge-SHA с GitHub объясняется переписыванием
     хэшей: их merge-коммиты есть под другими SHA.
   - Merge-коммитов **#128–#258 в текущем `main` нет вовсе.** После
     `0b9a57ac` (2026-06-20) сразу идёт `acc07649` (PR #260, 2026-07-03,
     последствия BFG/force push при очистке LFS, issue #259).
   - Среди потерянного есть контракт жизненного цикла Golden Examples
     ([#211](https://github.com/G-Ivan-A/mango_ba_prompts/issues/211) /
     [PR #213](https://github.com/G-Ivan-A/mango_ba_prompts/pull/213)).
     `kb/golden-examples/CONTRACT.md` на `main` возвращает 404 через GitHub API.
   - Из 13 файлов PR #213 сейчас существуют 3 общих: CHANGELOG, README и
     workflow.
   - Отчёт `docs/report/2026-07-03-kb-state-after-lfs-cleanup.md` оценивал
     только PDF и БЗ, а утрату governance-артефактов не зафиксировал.
6. Запрет на «розовых слонов» из #403/#405/#407 имел разумную цель: не
   подталкивать модель к ошибке и не переобучаться на кейсах. На практике он
   **способствовал** потере конкретных уроков: связь «кейс → правило» нигде не
   сохранили отдельно (см. раздел 4).

## 4. Запрет на «розовых слонов» (#403, #405, #407)

### 4.1. Формулировки

- [#403](https://github.com/G-Ivan-A/mango_ba_prompts/issues/403): «Не ссылайся
  на конкретные провалы чатов в стиле „как в задаче 1131 ИИ ошибся“.
  Формулируй выводы как универсальные паттерны и архитектурные ограничения.»
- [#405](https://github.com/G-Ivan-A/mango_ba_prompts/issues/405): «…не
  ссылаясь на конкретные номера исторических задач (например, „как в задаче
  1131“).»
- [#407](https://github.com/G-Ivan-A/mango_ba_prompts/issues/407)
  (уточнение): запрет действует только «в итоговых обобщенных выводах». ID
  задач, PR и RUNS «допустимы… как сырые данные для внутреннего анализа и
  реестров свидетельств».

### 4.2. Коллизия терминов

В данных прогонов «розовый слон» означает другое. В
`runs/2026/RUN-0076/outputs/success-criteria.md` это SC-65 / категория C20:
«Не фиксировать в документе отсутствие ошибки, которой не было», то есть
ошибка документа, где модель упоминает несуществующую проблему.

В #403 тот же термин обозначает запрет ссылок на исторические кейсы в
стандартах. Оба смысла про «не вносить в текст то, чего быть не должно», но
объекты разные: результат БА и норма промпта. Анализ
`docs/analysis/2026-10-28-bcreq-evolution-failure-analysis.md` (T15, «без
„розового слона“», SPLIT turn 787) относится к первому смыслу.

### 4.3. Внёс ли запрет вклад в потерю конкретных уроков

**Да, косвенно и существенно.** Сам запрет корректен, сбой произошёл при его
исполнении.

1. **Корректная часть.** Отрицательные примеры в тексте промпта могут
   прайминговать модель («не думай о розовом слоне»). Ссылки на номера чатов
   бесполезны исполнителю без доступа к ним. Универсальные паттерны лучше
   переносятся. Эти аргументы совпадают с индустриальной практикой: позитивные
   инструкции, переписанные контрпримеры и вынос кейсов в eval.
2. **Что пошло не так в PR #404.** Исполнитель трактовал запрет как запрет
   *любой* связи «кейс → правило»:
   - в 39 классах нет ни одной ссылки на I-xxx, SC-xx, C01–C20, АД-* или
     RUN-0073…0076;
   - негативный пример на класс один и сформулирован абстрактно;
   - уточнение #407 («ID допустимы в реестрах свидетельств») появилось уже
     после слияния PR #404 и в классы не попало.
3. **Почему это привело к деградации.**
   - Без связи «урок → правило» нельзя проверить, что каждый из 200
     кандидатов golden set и 137 SC покрыт хотя бы одной нормой.
   - Нельзя заметить, что АД-1…АД-11 из 14 промптов не перешли в классы.
   - Нельзя построить регрессионный набор: конкретный кейс был бы его
     тест-кейсом.
   - Обобщение «до паттерна» убрало именно ту конкретику, о которой жалуется
     владелец (ЛК/КЦ, канцелярит, «штатное как новое ФТ», вывод As-Is без
     документации).
4. **Совместный эффект с другими причинами.**
   - Запрет на «розовых слонов» сочетался с тремя факторами: отсутствием
     eval-контура (`standards/evals-contract-standard.md` не реализован),
     отсутствием утверждённого Golden Set (все кандидаты в статусе draft) и
     утратой контракта Golden Examples (#211/PR #213).
   - Поэтому конкретным урокам было **некуда** уйти, кроме текста промпта.
     Когда их запретили в тексте, они исчезли из pipeline целиком.

### 4.4. Вывод для RFC #411 (рекомендация, не реализация)

- Сохранить запрет на ссылки на чаты **в тексте промпта и итоговых выводах**.
- Ввести обязательный **реестр трассировки уроков**: lesson_id → источник
  (RUN/I-xxx/SC-xx) → норма (АД-n / класс Cxx / правило) → eval-кейс →
  статус.
- Конкретные контрпримеры переписывать в нейтральные эталоны «правильно /
  неправильно» без номеров и хранить в golden/eval-наборе. Тогда их можно
  проверять регрессионно.
- Это совмещает #403/#405 (без «розовых слонов» в нормах) и #397/#407/#411
  (без потери опыта и с контролем регрессий).
