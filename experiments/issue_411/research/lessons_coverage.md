# Issue #411: инвентарь уроков и их покрытие в ручном конвейере BCREQ

Черновик исследования, 2026-10-31. Источник данных: [lessons_inventory.json](lessons_inventory.json), сборка — [build_lessons.py](build_lessons.py). Существующие файлы репозитория не изменялись.

Идентификаторы инвентаря — `I-NN` (локальные для этого исследования, оценка на коммите `34e07b06` до вставки блоков уроков). Сопоставление `I-NN` → урок реестра `L-NN` — в [`standards/bcreq-lessons/lessons.json`](../../../standards/bcreq-lessons/lessons.json), поле `inventory.map`.

## Метод

Уроки собраны из обратной связи БА (RUN-0016…RUN-0029, RUN-0077), реестров и статистики RUN-0073…RUN-0076, golden-кандидатов RUN-0074 и аналитических документов. Дубли между прогонами объединены.

Покрытие проверено в четырёх группах:

- **a** — 39 классовых стандартов `standards/bcreq-manual-classes/` и `catalog.json`;
- **b** — `docs/contracts/bcreq-manual-state.md` и `bcreq-stage-gates.md`;
- **c** — 14 промптов `prompts/bcreq-*.md`;
- **d** — мета-стандарты разделов `standards/bcreq-sections/`.

Уровни покрытия:

- **явно** — есть конкретная строка; она приведена с `файл:строка`.
- **общо** — правило покрыто только общей формулировкой шаблона, либо явная строка есть в одном классе, а ошибка возникает во многих.
- **нет** — правило не найдено ни поиском, ни чтением.

Метод — поиск по шаблонам и чтение класс-специфичных строк. Отдельные «нет» могут быть ложными: где это вероятно, в деталях стоит пометка *uncertain*.

Все ссылки `файл:строка` даны по коммиту `34e07b06` (HEAD ветки issue-411). Во время анализа в рабочем дереве параллельно менялись 53 файла классов и промптов (+3949 строк, не закоммичено). Эти изменения здесь не оценивались, и после их фиксации номера строк могут сместиться.

Номера C01…C25 в столбце «C-id» — категории инцидентов RUN-0074. У классов стандартов те же обозначения C01…C39, но это **другая** нумерация. Совпадение обозначений само по себе риск путаницы.

## Ответы на два вопроса

### Есть ли в классах исполняемый вставляемый текст промпта?

**Частично, и не самостоятельный.**

README классов заявляет: «Каждая запись — самостоятельный вставляемый промпт» (`standards/bcreq-manual-classes/README.md:59`). Фактически каждый файл (около 150 строк) устроен так:

- около 95 % текста — общий шаблон, одинаковый во всех 39 классах: Вход/Выход JSON, контекст, 5 из 6 пунктов проверки, общие circuit breakers;
- поведение, специфичное для класса, умещается в одну строку «Алгоритм, шаг 2», один «Специальный стоп», один пункт проверки и пару однострочных «Корректно:/Ошибка:».

Чего в файлах нет:

- роли и инструкции «что сделать», которую модель могла бы выполнить без дополнительных материалов;
- формата текста раздела BCREQ;
- стоп-слов КС/БС;
- few-shot примеров с реальным текстом BCREQ.

Чтобы класс работал, БА должен вставить вместе с ним:

- контракт состояния (`bcreq-manual-state.md:18-23`);
- мета-стандарты;
- полный текст конституции.

Сам класс говорит: «Скопировать контракт и этот стандарт, затем заполнить блок» (`16-fr-delta.md:27-29`). Явные правила против повторяющихся ошибок (АД-1…АД-11, Р1-Р7, КС/БС) остаются в Промпте 0 (`prompts/bcreq-constitution-governance-oneshot.md:110-166`). В классах они не повторены, а их доставка зависит от ручной сборки bundle (класс C36).

### Ссылаются ли классы на уроки прогонов или категории инцидентов?

**Нет.**

- Поиск `RUN-0|SC-[0-9]|АД-[0-9]|инцидент|golden|GS-3` по `standards/bcreq-manual-classes/*.md` и `catalog.json` даёт 0 совпадений.
- Раздел «Основания» каждого класса ссылается только на checkpoint, RFC и README разделов.
- 46 golden-кандидатов RUN-0074 (`runs/2026/RUN-0074/outputs/golden-set-candidates.json`, из них 37 negative с defect_class) не подключены ни к одному классу, контракту или мета-стандарту.

Для сравнения:

- Промпт 0 явно трассирует АД-1…АД-7 к категориям RUN-0075 (`prompts/bcreq-constitution-governance-oneshot.md:131-146`).
- RFC ручного конвейера упоминает RUN-0074 лишь как основу имитации RUN-0078 (`docs/rfc/2026-10-bcreq-manual-pipeline.md:125,171`).
- RUN-0078 — авторская имитация: «тот же автор генерирует и проверяет, исходные Qwen-модели не перезапускались» (`runs/2026/RUN-0078/feedback/review-notes.md:12-14`).

### Автоматические проверки

`scripts/validate_issue_403_manual_pipeline.py:18-49` проверяет у классов только структуру:

- 39 записей;
- 8 заголовков;
- 2 JSON-примера;
- соответствие каталогу.

Поведенческие тесты `check_replay` (`:105-183`) касаются JSON-состояния:

- tombstone требует полномочий;
- release — только человеком;
- двухфакторная апелляция;
- чужая задача отклоняется.

Тест `:155-160` прямо фиксирует: структурная проверка **не обнаруживает** инверсию смысла. Проверка обязательных строк для промптов (c) есть (`scripts/test_issue_395_bcreq.py:31-49`), для 39 классов аналога нет. Регрессионного прогона классов на golden-наборе нет.
