## Вердикт по гипотезе о гейте: подтверждена с уточнением

| № | Утверждение гипотезы | Вердикт |
| --- | --- | --- |
| Г-1 | Гейт бывает человеческим, машинным (код или ИИ-агент) и гибридным | Подтверждено: BPMN 2.0.2 (User / Service / Business Rule Task), Camunda agentic orchestration; в проекте уже есть operation gate `llm`/`гибрид` (правило B3) и `G-mach` runtime |
| Г-2 | «Аналогично гейтам в BPMN» | **Подтверждено с уточнением.** Шлюз BPMN работы не делает: «Gateways do not represent 'work' being done» (§10.6). Поэтому тип гейта — тип **задачи решения** перед шлюзом; выбор ребра (шлюз) от типа не зависит |
| Г-3 | Гейт может исполняться промптом: по правилам определить намерение и ребро | Подтверждено: условие исключающего шлюза; runtime — «системный промпт машинного гейта», рёбра с предикатами, «Ребро «по усмотрению» запрещено» |
| Г-4 | Цель — машинные гейты, кроме ключевых | Подтверждено: Stage-Gate (ключевые решения — у руководителей с полномочием), AI HLEG (HITL на каждом цикле «neither possible nor desirable») |
| Г-5 | На A-IN и далее гейт может быть гибридным | Подтверждено, и **так уже есть**: Г-IN — модель рекомендует, решает БА (П-5, П-7, Г1) |

Что внесено:

- **Определение гейта** (словарь потока, раздел 3.1): точка решения, где решение принимает исполнитель по типу гейта — `человек`, `гибрид`, `llm` или `код`; ключевые гейты — человеческие. Четыре части гейта: К-20 доказательства → решение → К-34 запись → выбор ребра. Тип меняет только исполнителя решения, граф процесса не меняется.
- **Ключевой гейт** — критерии КГ-1…КГ-4: полномочие вне команды БА; необратимый или внешний исход; принятие риска (B3: G1/G2/G3 «НЕ ДОЛЖНЫ проходиться автоматически LLM»); право человека отменить вывод модели (EU AI Act, ст. 14(4)(d)).
- **Правила типов**: fail-closed для машинных; порядок `G-self → G-mach → G-human`; гибрид записывает расхождение «рекомендация ↔ решение» (защита от automation bias); молчание — не согласие; перевод типа — только решением владельца на доказательствах (golden set или журнал К-34).
- **Сейчас** все четыре гейта стадий ключевые: Г-С1, Г-W и выпуск — `человек`, Г-IN — `гибрид`, ключевой по КГ-3. Первый кандидат в неключевые — Г-IN: исход внутренний и обратимый. Поведение потока на этапе 1 не меняется.
- **Документы**: словарь потока, процесс BCREQ (часть 0, правило B3), контракт гейтов, контракт состояния, RFC #427 (**поправка 0.4**, редакционная: статус `accepted` и решения DEC-427 не меняются).
- **Бэклог**: **BL-159 «Типы гейтов во всех документах проекта»** — проверка, что тип гейта явно учтён во всех актуализируемых документах. В карточке — перечень по поиску «human gate» / «G-human» / «человеческий гейт» / «решение человека»: ADR-003 и онтология (значение `код` — решение владельца), ADR-009 и др., governance, стратегия, стандарты классов, промпты через генератор, будущие документы BL-151 / BL-230 / BL-231 / BL-141 и журнал К-34.
