# План и доказательства BL-194

Цель: все незаблокированные требования #509 в PR #511; заблокированные
решениями владельца остаются явно незавершёнными. Прогон двумя моделями —
после деплоя BL-232, как задано issue, а не доказательство статического теста.

| Требование | Реализация и проверка |
| --- | --- |
| RFC 2.4–2.10, 2.12 | Реестр решений, явный допуск, роли интеграции, вывод, формы, порядок, ФТ-NN; validate_issue_509_prompt_debugging.py |
| RFC 2.1–2.3, 2.11 | **Ожидают** Р-ОТЛ-1/2/5: политика доступа, реестр пробелов, ИШ-6, AIN-22/18; прежние правила сохранены |
| RFC 3–4 | Полная и компактная карточки, контракт 0.4; общие фрагменты в обоих форматах, архив неизменён |
| RFC 5–6 | Инструкции, контракт и размер на сайте, переключатель; Playwright и скриншоты до/после |
| Поле «Источники БЗ» и сводка BLOCKED | **Ожидают** Р-ОТЛ-2 и Р-ОТЛ-1 соответственно |
| RFC 7, RG-01…10 | Принципные кейсы и вход BL-131; кейсы, зависящие от решений, помечены pending |
| Чистота и согласованность | Сборщики --check, аудит чистоты, make validate-fast/full, CI для итогового SHA |
| Сокращение ≥60 % | Повторный prompt_redundancy.py и фактическая сумма компактных карточек + контракт |
| Финализация | Main влит, история сохранена, diff проверен, PR по-русски, CI/ревью проверены |

Без решения Р-ОТЛ-3 полная карточка остаётся по умолчанию; компактная —
явный выбор. Р-ОТЛ-4: issue прямо требует одну версию промпта в `КОНЕЦ`.
Р-ОТЛ-6: в этой задаче только подготовка, без деплоя и принятия публикации.
