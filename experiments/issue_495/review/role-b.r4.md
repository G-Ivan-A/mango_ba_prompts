## Замечания (не блокируют)

1. **54 нарушения G-03 на карточках архива.** A-PRIVATE — 42, BP-01 — 12. Критерий группы выполнен, но настоящий исходник строки — файл архива, а не ручной промпт. После правки из раздела выше их стоит отнести туда же, куда и остальные строки карточек архива, чтобы G-03 содержала только копии действующих ручных исходников по происхождению, а не по совпадению строки.
2. **BP-13 стал шире, чем описано в брифе.** Буквенный сегмент теперь необязателен: `(?:[A-ZА-ЯЁ]+[-…])*\d`. Шаблон ловит `ADR-001`, `ADR-017` и `RFC-2119`, `RFC-8259` (в раунде 3 — нет). Для ADR это полезно. Публичный RFC IETF, записанный через дефис, будет считаться внутренним; запись через пробел («RFC 2119») не задевается. В HEAD таких строк нет (аудит — 0). Стоит либо назвать это в стандарте, либо добавить мутацию с ожидаемым поведением. Фраза брифа «счёт базы не изменился» неточна: против раунда 3 счёт вырос на одно нарушение (см. абзац про BP-13 выше).
3. **Границы BP-13.** Длинное тире U+2014 и мягкий перенос U+00AD шаблон не покрывает (`RFC—AIN—001` не ловится); косая черта перед ID допустима, поэтому путь вида `docs/adr/adr-0007-….md` даст второе нарушение рядом с A-SPOKE-PATH. В дереве таких строк нет.
4. **«Промпт 0;» в остальных шагах.** В Ш-А теперь «Конституция — Промпт 0 (Ш-0), принятый в этом чате; в чат её не выводи.» В 25 файлах (ручные промпты, их черновики, системные Ш-1 и Ш-2) осталась разорванная строка «Конституция — / Промпт 0; / защиты АД-1…» — след снятой ссылки (например `prompts/bcreq-nfr-documentation-stepwise.md:17-19`, `prompts/drafts/system/bcreq-context-understanding-system.md:109`). Нарушением это не является, но формулировки одного и того же места расходятся.
5. **Версия стандарта.** `standards/bcreq-prompt-purity.md` поднят с 1.4.0 до 1.4.2; текст стандарта про новую форму BP-13 (строчная запись, не-ASCII дефисы, ID без буквенного сегмента) не говорит — описание есть только в регулярном выражении политики.
