а заменённые редакции — находить в Каталоге с явной маркировкой и трассировкой.

**Как есть.** БА копирует промпты из сайта 2.7.0; ветка содержит 24 новых
файла, но наличие файлов не подтверждает публикацию и доступность архива.
**Как должно быть.** БА видит полные 24 шага в прежних карточках, выбирает
действие и копирует точный текст; архив доступен отдельно с явной заменой.
Владелец оценивает evidence в русском PR, принимает merge либо возвращает
замечания в тот же PR; закрытие означает отказ. Цель — проверенный пакет
ручного деплоя; выполнение гейтов остаётся решением БА.

## Граничные случаи и воспроизведение

Проверяются не только 24 файла, но 35 карточек: Ш-0 и остальные стадии,
переключение прежней редакции и её копирование, 24 полных preview/clipboard,
четыре полных исторических копии. Каталог: 39 по умолчанию, 18 в архиве,
57 при выборе обоих наборов; OR внутри операций/процессов/режимов,
AND между группами, пустая выдача, поиск версии и конфликты прежних фильтров
при deep link. Служебная navigation не открывается и кнопка перехода не
запускает промпт. Доступ к БЗ проверяется по существующему пути без имитации
выполненного поиска моделью; проверка ссылок не доказывает качество retrieval.

Проверки размеров/тем: 1280×960 и 390×844, светлая/тёмная темы, отсутствие
горизонтального overflow; недоступный JSON → явное сообщение → обычный reload
восстанавливает все 24 шага. Тест фильтров выполняется в ограниченном VM;
полный набор валидаторов локально запускается с `--jobs 1`.

`browser-smoke.js` — функция для Playwright MCP `browser_run_code_unsafe`
с `filename` этого файла. Перед запуском: `python3 -m http.server 8768
--bind 127.0.0.1 --directory site` (одна строка). Скрипт сохраняет снимки в
`site/screenshots/issue-476/`; путь каталога снимков настроить под checkout.
Результат — `browser-result.json`. Повторная проверка архивных SHA не требует
live: `python3 scripts/validate_issue_476_site_readiness.py`.

Для повторения первичного захвата `capture_baseline.py` нужны скачанные
`data/test-kit.json` и `data/prompts.json` сайта **2.7.0** в `private/`.
Скрипт проверяет тела против закреплённого source SHA перед сохранением
полных оригиналов. После обновления live старый baseline проверяется через
manifest/git, не перезаписывается новыми текстами.

За исходный scope выходить не потребовалось. Удалён только служебный `.gitkeep`
подготовленного checkout: его явно запрещает существующий merge-hygiene validator;
пользовательских данных он не содержит. Сокращения промптов/норм не выполнялись.
