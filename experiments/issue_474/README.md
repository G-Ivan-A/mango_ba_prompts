## Воспроизведение и проверка

Исходный дефект: технический тезис раньше достаточной проверки превращался
в вопрос БА; прежний текст требовал поиск без строгой проверки канала.
Теперь общий алгоритм целиком встроен в 24 AIN и совместимые входы:
исходный смысл → происхождение → буквальный/функциональный поиск при доступе
→ цитата/применимость/остаток. Нет доступа — точный ACCESS_GAP. Нет evidence
не означает «Нет». Обычные факты не объявляются неоднозначными.

[Контроль «Запись разговоров»](retrieval-smoke.md): текущая модель реально
прочитала runtime, нашла подтверждение и сняла вопрос интеграциям. Версия,
диапазон, цитата, источник и ограничения записаны; одно наблюдение не является
измерением всех моделей или полным маршрутом 01…24.

```bash
python3 scripts/build_bcreq_a_in.py --check
python3 scripts/validate_issue_474_execution.py
python3 experiments/issue_474/retrieval_smoke.py --fetch
make validate-full
```

Focused validator — 8 tests: gate versions/separate call, старые 16 cases,
триада исполнимости без вывода из пустого поиска/гипотезы, общий алгоритм и
отложенный provenance, целостность реального наблюдения, полные 24 текста и
SHA, guards, источники/coverage. Новый validator обнаруживается существующим
CI автоматически. Старые измеренные входы и оценки не переписаны.

Для UI запустить `python3 -m http.server 8768 --directory site` и выполнить
[browser-smoke.js](browser-smoke.js) через Playwright MCP. Результат: 35 карточек,
24/24 полных preview и копии с прежним ID-prefix, сравнение старых редакций,
25 карточек первого этапа, mobile без overflow, отказ fetch → явная ошибка →
успешный reload, pageErrors=[]; существующий внешний виджет иногда даёт
сетевые console errors. Screenshot показывает форму 2.7.0, CSS не менялся.
