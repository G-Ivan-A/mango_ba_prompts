## Task 1: instruction-level scenario review

These are manual checks of the instructions, not fabricated LLM transcripts or a
claim that static tests guarantee every possible model response. Each row was
checked in the identical supplement present in all 14 prompts; the regression
also checks required safeguards and preserves every original byte.

| Input / failure | Required outcome confirmed in the supplement |
| --- | --- |
| Runtime and detailed standards unavailable; constitution in chat | Explicit fallback message with failed URL/cause, built-in R1–R7/AD1–11/styles, unread criteria marked unverified; no claim of full validation. |
| Constitution absent in a fresh session, including Ш-В | Ask BA for the complete constitution if it cannot be read; do not reconstruct rules from memory. |
| As-Is or an interface limit lacks evidence | CB-0.6 stops the dependent claim; question in 8.4. Independent work can continue. Absence of KB does not imply absence of a function. |
| Only three routing classes / hierarchy rules published | Classification remains “требует доработки”; record verified levels, unknown levels and source. Do not treat routing IDs as a complete product catalog. |
| Complete catalog becomes available later | Recheck the actual version against the full-line reference; no permanent assertion that runtime must remain incomplete. |
| Class known, many documents available | README → MAP → product_ids → sections_map → relevant chunks only; aliases/hints are navigation, not evidence. |
| Class unknown | Ask BA; do not read the entire KB to guess the class. |
| BA asks for renewed study | Class check precedes relevant documents; reuse unchanged evidence, record why something was reread. |
| Relevant chunk mentions another product's settings | Record dependency/locator in 8.4; wait for BA initiative before cross-class reading, log that decision in 8.5. |
| BA adds files/text during auto | Merge with existing read evidence; retain product/version/provenance and cite file pages or message quotes. No repeat request for already provided input. |
| Supplement contradicts auto source | Show both quotations, stop the dependent conclusion under CB-0.4, ask BA. No silent source precedence. |
| Auto unavailable, no supplement supplied | Offer files, text or no KB; proceed by default without KB, preserving source-dependent stops and human gates. |
| Auto partly available or supplement already supplied | Keep read sources; identify gaps; use supplied material as manual KB. |
| Gate decision missing / validation standards unavailable | Never cross a human gate or report “ready”; Ш-В reports findings without rewriting the document or claiming unread criteria passed. |

## Scope and source decisions

Task 1 and Task 2 restrictions apply sequentially. CHANGELOG is explicitly required.
For necessary verification, propose the narrow adjustment of allowing regression
scripts and evidence under `scripts/` and `experiments/`, plus three-line additions
to two historical preservation tests. Those tests strip only the new bounded block;
the new regression independently validates the entire original bytes, including
frontmatter. No original assertion is removed. Generated `site/data/prompts.json`
is refreshed so the existing copy buttons distribute the changed prompts.

No standards, original site section bodies, password configuration, workflows,
external runtime or release triggers are modified. The PDF omits formal acceptance
definitions and has obsolete numbering: current eight-section standards take
precedence. The dialogue's BABOK 10.23 goal attribution is corrected rather than
repeated. 5±2 and L1/L2 are explained as project conventions with industry context.

The issue has no project status field or `review` label. The deliverable's review
state is represented by PR 396 being marked ready for review. Actions/publication
remain under the repository's existing controls; no deployment is part of this work.
